JSON є спільною мовою API, конфігурацій і сховищ, а `JSON.stringify` і `JSON.parse` виглядають тривіально. Але модель даних JSON менша, ніж у JavaScript, тож кожне перетворення туди й назад мовчки змінює чи відкидає значення. Знання правил запобігає втраченим полям, хибним типам, а з ненадійними даними й помилкам безпеки.

## Модель даних JSON

JSON має об'єкти (з рядковими ключами), масиви, рядки, числа (лише скінченні), `true`, `false` і `null`. Немає `undefined`, функцій, символів, дат, `Map`/`Set`, `BigInt`, `NaN` чи `Infinity`, коментарів і ком у кінці. Ключі й рядки мають бути в подвійних лапках.

## Що `JSON.stringify` робить із кожним значенням

| Значення | У властивості об'єкта | У масиві | На верхньому рівні |
| --- | --- | --- | --- |
| `undefined`, функція, символ | властивість **пропускається** | стає `null` | повертає `undefined` (не рядок) |
| `NaN`, `Infinity` | `null` | `null` | `"null"` |
| `Date` | рядок ISO (через `Date.prototype.toJSON`) | так само | так само |
| `Map`, `Set`, екземпляри класів | лише власні перелічувані властивості, тож зазвичай `{}` | так само | так само |
| `BigInt` | **кидає** `TypeError` | кидає | кидає |
| циклічне посилання | **кидає** `TypeError` | кидає | кидає |

Властивості з ключами-символами й неперелічувані властивості пропускаються, а гетери викликаються. Порядок властивостей відповідає порядку власних ключів об'єкта (спершу цілочисельні ключі).

## Налаштування результату

- **`toJSON()`**: якщо значення має метод `toJSON`, `stringify` серіалізує його результат. Так `Date` стає рядком, і так можна дати класам стабільний формат для передавання.
- **Функція replacer** `(key, value) => newValue`: викликається для кожного ключа в глибину, з `this`, що дорівнює об'єкту-контейнеру; повернення `undefined` відкидає властивість. Перший виклик має ключ `""` для кореня. Використовуйте її, щоб приховати секрети чи перетворити `BigInt` на рядки.
- **Масив replacer**: білий список назв властивостей для включення.
- **`space`**: число (до 10) чи рядок для відступів.

## Розбір і reviver

`JSON.parse(text, reviver)` кидає `SyntaxError` на некоректних даних, тож загортайте ненадійний текст у `try/catch`. Необов'язкова функція **reviver** викликається знизу вгору для кожного ключа; використовуйте її для відновлення типів (рядки ISO назад у `Date`, позначені значення назад у `BigInt` чи `Map`). Повернення `undefined` з reviver видаляє властивість.

## Ненадійні дані

- **Перевіряйте форму** після розбору. `JSON.parse` гарантує лише синтаксис, тож API все одно може надіслати `{"age": "ten"}`. Використовуйте валідатор схем (Zod, Valibot, Ajv з JSON Schema) на кожній межі: запити, відповіді, `localStorage`, черги.
- **Прототипне забруднення**: `JSON.parse('{"__proto__": {"admin": true}}')` створює власну властивість на ім'я `__proto__`, що саме по собі нешкідливо. Але наївне глибоке злиття, що копіює її через `target[key] = …`, пише в `Object.prototype` і дає **кожному** об'єкту `admin: true`. Пропускайте ключі `__proto__`, `constructor` і `prototype` під час злиття або будуйте результати через `Object.create(null)` чи `Map`.
- **Розмір і глибина**: величезні чи глибоко вкладені дані можуть вичерпати пам'ять чи стек. Обмежуйте розмір тіла запиту на сервері.
- Ніколи не використовуйте `eval` для розбору JSON.

## Великі дані й альтернативи

- `JSON.parse` великих даних блокує головний потік; обробляйте їх потоком (NDJSON, потоковий розбір) чи розбирайте у воркері.
- Числа понад `Number.MAX_SAFE_INTEGER` втрачають точність під час розбору, тож надсилайте 64-бітні ідентифікатори **рядками**.
- `structuredClone` копіює більше типів, але не є форматом для передавання; бінарні формати (MessagePack, Protocol Buffers, CBOR) менші й швидші, але потребують схем чи бібліотек.

## Що перевірити перед співбесідою

- Перелічіть, що `JSON.stringify` відкидає, перетворює на `null` чи на чому кидає помилку, і де (об'єкт, масив, верхній рівень).
- Поясніть `toJSON`, функції й масиви replacer і reviver на прикладі дати чи BigInt.
- Поясніть, чому розібраний JSON треба валідувати і як виникає прототипне забруднення.
- Поясніть, як обробляти цикли, великі числа й великі обсяги даних.
