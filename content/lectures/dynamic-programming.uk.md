Динамічне програмування (DP) розв'язує задачу, поєднуючи розв'язки **менших версій тієї самої задачі** й обчислюючи кожну лише один раз. Воно перетворює багато експоненційних переборів на поліноміальні алгоритми.

## Коли DP застосовне

Дві властивості разом підказують DP:

1. **Оптимальна підструктура**: найкраща відповідь будується з найкращих відповідей для підзадач (найдешевший шлях до C через B використовує найдешевший шлях до B).
2. **Підзадачі, що перекриваються**: наївна рекурсія розв'язує ту саму підзадачу багато разів. Наївна функція Фібоначчі робить понад мільйон викликів для `fib(30)`, хоча різних значень лише кілька десятків.

Якщо підзадачі не перекриваються (сортування злиттям), це звичайне «розділяй і володарюй».

## Рецепт

1. **Стан**: що описує підзадачу? (`dp[i]` = кількість способів дійти до сходинки `i`; `dp[i][j]` = відстань редагування перших `i` і `j` символів.)
2. **Рекурентне співвідношення**: як стан випливає з менших?
3. **Базові випадки**: найменші стани, які відомі напряму.
4. **Порядок**: обчислюйте стани так, щоб залежності були готові (або покладіться на мемоізацію).
5. **Відповідь**: у якому стані результат?

## Згори вниз проти знизу вгору

```js
// Згори вниз: рекурсія + memo (обчислює лише потрібні стани)
const memo = new Map();
function ways(n) {
  if (n <= 1) return 1;
  if (memo.has(n)) return memo.get(n);
  const r = ways(n - 1) + ways(n - 2);
  memo.set(n, r);
  return r;
}

// Знизу вгору: заповнення таблиці в порядку залежностей (без обмеження глибини рекурсії)
function waysTable(n) {
  const dp = [1, 1];
  for (let i = 2; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2];
  return dp[n];
}
```

Ключ мемоізації має містити **кожен** параметр, що впливає на результат: функція з двома аргументами, мемоізована лише за одним, повертає хибні відповіді. Таблиці знизу вгору уникають переповнення стеку на великих входах і часто дають змогу **заощадити пам'ять**: якщо рядку `i` потрібен лише рядок `i - 1`, тримайте два рядки (або один) замість усієї сітки.

## Класичні задачі

| Задача | Стан | Співвідношення |
| --- | --- | --- |
| Сходи (крок 1 або 2) | `dp[i]` способів дійти до `i` | `dp[i-1] + dp[i-2]` |
| Шляхи в сітці (праворуч/вниз) | `dp[r][c]` | `dp[r-1][c] + dp[r][c-1]` |
| Розмін (мінімум монет) | `dp[a]` найменше монет для суми `a` | `min(dp[a - c] + 1)` за монетами |
| Розмін (кількість способів) | `dp[a]` комбінацій | для кожної монети `dp[a] += dp[a - c]` |
| Рюкзак 0/1 | `dp[i][w]` найкраща цінність з перших `i` предметів при місткості `w` | `max(пропустити, взяти)` |
| Відстань редагування | `dp[i][j]` | `min(вставка, видалення, заміна)` |

Щоб **рахувати комбінації** в задачі розміну, перебирайте монети в зовнішньому циклі: так кожна комбінація рахується один раз незалежно від порядку; якщо спершу перебирати суми, рахуються перестановки.

## Жадібний алгоритм проти DP

Жадібний алгоритм робить локально найкращий вибір і ніколи не повертається назад. Він швидкий і правильний для деяких задач (номінали монет США, планування інтервалів), але загалом помиляється: для монет `[1, 3, 4]` і суми 6 жадібний бере `4 + 1 + 1` (3 монети), а DP знаходить `3 + 3` (2 монети). Доведіть, що жадібний підхід працює, або використайте DP.

## Складність

Час ≈ кількість станів × робота на стан. Відстань редагування має складність O(n·m); рюкзак O(n·W) (псевдополіноміальна від місткості). Пам'ять дорівнює розміру таблиці, і часто її можна зменшити на один вимір.

## Що перевірити перед співбесідою

- Назвіть дві властивості й покажіть повторні виклики в дереві рекурсії.
- Сформулюйте вголос стан, співвідношення й базові випадки до написання коду.
- Перетворіть мемоізований розв'язок на таблицю знизу вгору й зменшіть пам'ять.
- Поясніть, чому жадібний алгоритм не працює для розміну з `[1, 3, 4]`.
- Знайте розмін монет, рюкзак, LCS/відстань редагування й шляхи в сітці.
