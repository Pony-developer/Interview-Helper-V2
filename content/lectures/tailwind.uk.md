Tailwind є **утилітарним** (utility-first) CSS-фреймворком: замість написання класу `.card` у таблиці стилів ви складаєте невеликі однопризначені класи прямо в розмітці.

```html
<article class="rounded-2xl border border-slate-200 bg-white p-6 shadow-sm hover:shadow-md md:flex md:gap-6">
  <img class="size-24 rounded-full object-cover" src="…" alt="" />
  <h2 class="mt-4 text-lg font-semibold text-slate-900 md:mt-0">Ada Lovelace</h2>
</article>
```

## Чому команди його використовують

- **Без вигадування назв і мертвого CSS.** Не треба придумувати назви класів, а видалення розмітки видаляє й її стилі.
- **Обмеження.** Утиліти беруться зі спільної шкали (відступи, кольори, розміри шрифтів), тож інтерфейс лишається узгодженим; тема є вашими дизайн-токенами.
- **Локальне міркування.** Усе, що стилізує елемент, видно на самому елементі; зміна одного компонента не зламає інший через каскад.
- **Малий CSS.** Збірка сканує ваші вихідні файли й генерує лише ті класи, які справді використовуються.

Поширені закиди: довгі списки класів у розмітці, час на звикання до назв і HTML, який важче читати без підтримки редактора.

## Варіанти

Префікси застосовують утиліту за умовою:

| Варіант | Значення |
| --- | --- |
| `sm:` `md:` `lg:` | контрольні точки за мінімальною шириною (mobile-first) |
| `hover:` `focus-visible:` `disabled:` | стани елемента |
| `dark:` | темна тема (через медіазапит або стратегію класу/атрибута) |
| `group-hover:` `peer-checked:` | стан батька (`group`) або сусіда (`peer`) |
| `@md:` | контейнерні запити (на батьку з `@container`) |
| `motion-safe:` `print:` | інші медіаознаки |

Варіанти комбінуються: `md:dark:hover:bg-slate-800`.

## Тема й конфігурація

Дизайн-система живе в темі: кольори, відступи, шрифти, контрольні точки, тіні. У Tailwind v4 її визначають у CSS через `@theme { --color-brand-500: …; }`, що також відкриває значення як CSS-змінні; у v3 використовувався `tailwind.config.js`. Розширювати тему краще, ніж розкидати одноразові значення.

Коли справді потрібне одноразове значення, використовуйте **довільні значення**: `top-[117px]`, `grid-cols-[1fr_2fr]`, `bg-[var(--hero)]`. Часті довільні значення сигналізують, що в темі чогось бракує.

## Як зникає невикористаний CSS

Tailwind генерує CSS, **скануючи вихідні файли на назви класів як звичайний текст**. Тож назви класів мають бути записані повністю:

```js
// ✗ ніколи не згенерується: сканер не бачить "bg-red-500"
const cls = `bg-${color}-500`;
// ✓ зіставлення з повними назвами класів
const cls = { red: "bg-red-500", green: "bg-green-500" }[color];
```

## Повторне використання без повторів

- Головний механізм повторного використання: **компоненти** (React, Vue, Angular) або частини шаблонів: список класів пишеться один раз у `<Button>`.
- `@apply` копіює утиліти у власний клас. Це нормально для кількох базових стилів чи сторонньої розмітки, але використання всюди відтворює проблеми з назвами й каскадом, яких Tailwind уникає.
- Компоненти, що приймають проп `className`, потребують **злиття з урахуванням конфліктів**: `"px-4 px-2"` не означає «перемагає останній» (вирішує порядок у CSS, а не порядок класів). Бібліотеки на кшталт `tailwind-merge` (часто з `clsx`) це розв'язують; API варіантів, як-от `cva`, впорядковують варіанти розміру й призначення.

## Доступність і добрі практики

- Утиліти не роблять розмітку доступною: усе одно використовуйте семантичні елементи, підписи й видимий фокус (`focus-visible:ring-2`).
- `sr-only` візуально ховає текст, але лишає його для зчитувачів екрана.
- Віддавайте перевагу кольорам теми з перевіреним контрастом; темна тема потребує власної перевірки контрасту.
- Тримайте порядок класів однаковим (офіційний плагін Prettier сортує класи автоматично).

## Що перевірити перед співбесідою

- Поясніть utility-first і його компроміси порівняно з BEM, CSS Modules чи CSS-in-JS.
- Використайте адаптивні варіанти, варіанти станів, `group`/`peer` і темної теми.
- Поясніть, чому динамічно складені назви класів не працюють.
- Опишіть, як повторно використовувати стилі (компоненти проти `@apply`) і зливати конфліктні класи.
- Поясніть токени теми й коли доречні довільні значення.
