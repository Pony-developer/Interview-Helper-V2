Інкапсуляція означає показувати невеликий, свідомо обраний **публічний API** і тримати все інше приватним, щоб інший код не міг залежати від внутрішніх деталей чи переводити їх у некоректний стан. Задовго до того, як у JavaScript з'явилися модулі чи `#private`, розробники будували її з однієї можливості мови: **замикань**.

## IIFE

Функціональний вираз, що викликається одразу (IIFE), створює область видимості, виконується один раз і не лишає в глобальній області нічого, крім того, що повертає:

```js
const counter = (function () {
  let count = 0; // приватне: дістатися можуть лише повернені функції
  return {
    increment() { return ++count; },
    get value() { return count; },
  };
})();
```

Дужки роблять ключове слово `function` виразом, тож його можна викликати одразу. В епоху тегів script IIFE запобігали глобальним конфліктам між бібліотеками (плагіни jQuery, бандли UMD) і досі трапляються в результатах бандлерів.

## Шаблон модуля та його варіанти

- **Класичний шаблон модуля**: IIFE повертає об'єкт, чиї методи замикають приватні змінні й допоміжні функції. Результатом є **синглтон**: один екземпляр, створений один раз.
- **Шаблон revealing module**: визначте все як приватні функції, а потім поверніть об'єкт, що зіставляє публічні імена з ними: `return { add, remove, list };`. Публічний API видно одразу. Відомий недолік: внутрішні виклики йдуть до приватних функцій, тож заміна публічного методу (наприклад, у тесті) не змінює внутрішню поведінку.
- **Фабрика модулів**: та сама функція без негайного виклику, тож кожен виклик створює незалежний екземпляр: `const a = createCounter(); const b = createCounter();`. Це альтернатива класам на замиканнях: без `this`, без `new`, а методи можна безпечно передавати як колбеки. Ціна в тому, що кожен екземпляр отримує власні копії методів.
- **Впровадження залежностей**: передавайте співпрацівників аргументами (`createStore({ storage, clock })`), а не тягніться до глобальних змінних, і це робить модулі придатними до тестування.

## Чотири способи бути приватним

| Техніка | Наскільки приватно? | Примітки |
| --- | --- | --- |
| Змінні замикання | справді приватно | працює всюди, копії методів для кожного екземпляра, невидимі для інструментів налагодження, крім як через області видимості |
| Поля `#private` | справді приватно | синтаксис класів, перевірка бренду через `#x in obj`, ламаються з `Proxy` |
| `WeakMap` з ключем-екземпляром | приватно для модуля, що тримає мапу | техніка до появи `#private`, не заважає збиранню сміття |
| Ключі `Symbol` | приховано, але не приватно | їх пропускають `Object.keys` і JSON, але видно через `Object.getOwnPropertySymbols` |

Префікс підкреслення (`_cache`) є лише домовленістю, а `private` у TypeScript зникає під час компіляції, тож ні те, ні інше не заважає доступу під час виконання.

## Від шаблону до справжніх модулів

ES-модулі дають кожному файлу власну область видимості: оголошення верхнього рівня приватні, якщо їх не **експортовано**, тіло модуля виконується **один раз** (пізніші імпорти отримують той самий екземпляр, тож модуль зі станом є природним синглтоном), а імпорти є живими зв'язуваннями лише для читання. Модулі CommonJS (`module.exports`) Node загортає у функцію: буквально шаблон модуля. Оскільки модулі вже дають область видимості, IIFE рідко потрібні в сучасному коді, але сама ідея (замикання як межа приватного) досі лежить в основі хуків, middleware і фабрик.

## Поради з проєктування

- Тримайте публічну поверхню малою й стабільною; повертайте копії (чи заморожені представлення) внутрішніх колекцій, щоб той, хто викликає, не міг їх змінити.
- Перевіряйте вхідні дані на публічній межі, а інваріанти тримайте всередині.
- Для всього, що містить стан окремого користувача чи запиту, віддавайте перевагу фабрикам чи класам, а не синглтонам рівня модуля, особливо на серверах, де один екземпляр модуля обслуговує кожен запит.
- Дайте спосіб скинути чи підмінити стан для тестів, а не лізьте у внутрішні деталі.

## Що перевірити перед співбесідою

- Напишіть модуль на IIFE з приватним станом і поясніть, чому це працює.
- Порівняйте шаблон модуля, шаблон revealing module і фабрики модулів.
- Порівняйте замикання, `#private`, `WeakMap` і ключі `Symbol` для приватності.
- Поясніть, як ES-модулі дають ту саму інкапсуляцію і чому стан рівня модуля є синглтоном.
- Поясніть небезпеку прямого повернення внутрішніх масивів чи об'єктів.
