Пошук — найпоширеніший будівельний блок у задачах на співбесідах. Перш ніж писати цикл, поставте собі два питання: **чи відсортовані дані?** і **скільки разів я шукатиму?** Від відповідей залежить вибір: лінійний перегляд, бінарний пошук, хеш-таблиця чи два вказівники.

## Лінійний пошук: O(n)

Проходимо колекцію від початку до кінця й зупиняємося на першому збігу.

```ts
function indexOf<T>(items: T[], target: T): number {
  for (let i = 0; i < items.length; i++) {
    if (items[i] === target) return i;
  }
  return -1;
}
```

Працює на **будь-яких** даних, відсортованих чи ні. Для одного пошуку в невідсортованих даних це оптимально: не можна знати, що елемента немає, не подивившись на кожен. `Array.prototype.indexOf`, `includes` і `find` — лінійні.

Якщо потрібно **багато** пошуків, один раз побудуйте `Set` або `Map` (O(n)), і тоді кожен пошук коштуватиме в середньому O(1).

## Бінарний пошук: O(log n)

На **відсортованих** даних на кожному кроці можна відкинути половину діапазону, що залишився.

```ts
function binarySearch(items: number[], target: number): number {
  let lo = 0;
  let hi = items.length - 1;          // межі включно
  while (lo <= hi) {
    const mid = lo + ((hi - lo) >> 1); // уникає переповнення в інших мовах
    if (items[mid] === target) return mid;
    if (items[mid] < target) lo = mid + 1;
    else hi = mid - 1;
  }
  return -1;
}
```

Інваріант: *якщо елемент існує, він усередині `[lo, hi]`*. Кожна гілка має зберігати це твердження й звужувати діапазон, інакше цикл стане нескінченним.

### Типові помилки

- `while (lo < hi)` з межами включно: останній елемент не перевіряється.
- `lo = mid` замість `lo = mid + 1`: діапазон перестає звужуватися, коли `hi - lo === 1`.
- Бінарний пошук по невідсортованих даних: результат хибний, а помилки немає.
- Сортування лише заради одного пошуку: сортування — O(n log n), гірше за один лінійний прохід.

### Нижня межа: перша позиція ≥ target

Багато задач («позиція вставки», «перша погана версія», «кількість входжень») — варіації *нижньої межі* (lower bound):

```ts
function lowerBound(items: number[], target: number): number {
  let lo = 0;
  let hi = items.length;              // напіввідкритий [lo, hi)
  while (lo < hi) {
    const mid = (lo + hi) >> 1;
    if (items[mid] < target) lo = mid + 1;
    else hi = mid;
  }
  return lo;                          // 0..length
}
```

Кількість `x` у відсортованому масиві = `lowerBound(x + 1) - lowerBound(x)`, тобто O(log n).

### Бінарний пошук за відповіддю

Якщо можна перевірити «чи достатньо X?» і відповідь змінюється з *ні* на *так* рівно один раз зі зростанням X, шукайте бінарно по X. Приклади: мінімальна місткість корабля, щоб доставити вантаж за D днів, або найменший дільник, за якого сума менша за поріг.

## Два вказівники: O(n) на відсортованих даних

Щоб знайти пару з заданою сумою у відсортованому масиві, поставте по вказівнику на кожен кінець:

```ts
function pairWithSum(sorted: number[], sum: number): [number, number] | null {
  let i = 0;
  let j = sorted.length - 1;
  while (i < j) {
    const s = sorted[i] + sorted[j];
    if (s === sum) return [i, j];
    if (s < sum) i++;
    else j--;
  }
  return null;
}
```

Кожен крок відкидає одного кандидата, тож увесь прохід лінійний. На невідсортованих даних використайте `Map` уже побачених значень (теж O(n)).

## Як обрати підхід

| Ситуація | Найкращий інструмент | Вартість |
| --- | --- | --- |
| Один пошук, дані не відсортовані | Лінійний прохід | O(n) |
| Багато пошуків, дані не відсортовані | Побудувати `Set`/`Map` | O(n) один раз, далі O(1) |
| Відсортований масив | Бінарний пошук | O(log n) |
| Задачі на пари/діапазони у відсортованих даних | Два вказівники | O(n) |
| Монотонне питання «так/ні» | Бінарний пошук за відповіддю | O(log діапазону · перевірка) |

## Чек-лист для співбесіди

1. Уточніть, чи відсортовані вхідні дані та чи можливі дублікати.
2. Оберіть межі `[lo, hi]` включно або напіввідкриті `[lo, hi)` і дотримуйтеся їх.
3. Перевірте порожній масив, один елемент, шуканий елемент на обох кінцях і відсутній елемент.
4. Назвіть складність уголос.
