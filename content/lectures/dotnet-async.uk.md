Питання про асинхронність відрізняють кандидата Middle від Junior. Головна думка, яку треба донести: **асинхронне — не те саме, що паралельне**. `async`/`await` звільняє потік на час очікування введення-виведення; паралелізм використовує кілька потоків, щоб обчислювати одночасно.

## Потоки, пул потоків і задачі

`Thread` — це потік ОС із власним стеком (близько 1 МБ зарезервовано), і створювати його дорого. **Пул потоків** тримає набір робочих потоків і перевикористовує їх для коротких завдань. `Task` — це обіцянка результату. Задача може виконуватися в потоці з пулу (`Task.Run`) або представляти введення-виведення, яке під час очікування не займає жодного потоку (`File.ReadAllTextAsync`, `HttpClient.GetAsync`).

Використовуйте `Task.Run` для обчислювальної роботи, яку хочете винести з поточного потоку (наприклад, з UI-потоку). В ASP.NET Core він лише перекладає роботу з одного потоку пулу на інший, тож там не загортайте синхронний код у `Task.Run`.

## Що робить await

Компілятор перетворює `async`-метод на **скінченний автомат**. На кожному `await` незавершеної задачі він зберігає локальні змінні, реєструє продовження й **повертає** керування викликачеві. Коли задача завершиться, продовження відновить метод — у захопленому **SynchronizationContext**, якщо він є (UI-потік у WPF/WinForms), або в потоці з пулу. В ASP.NET Core SynchronizationContext немає.

```csharp
public async Task<int> CountAsync(string url, CancellationToken ct)
{
    var html = await _http.GetStringAsync(url, ct); // жоден потік не заблокований на час очікування
    return html.Length;
}
```

## Класичні помилки

- **Синхронне очікування асинхронного**: `.Result` чи `.Wait()` блокують потік. Із SynchronizationContext це **взаємоблокування**: заблокований UI-потік — саме той, якого чекає продовження. Без нього це все одно марнує потоки пулу й під навантаженням призводить до **голодування пулу потоків**. Будьте асинхронними до самого низу.
- `ConfigureAwait(false)` у коді бібліотек каже «мені не потрібен початковий контекст» — це усуває взаємоблокування й зайвий перехід. Коду застосунку в ASP.NET Core він не потрібен.
- **`async void`**: його не можна дочекатися, а його винятки обвалюють процес. `async void` мають бути лише обробники подій.
- Забутий `await`: задача виконується без нагляду, і її виняток губиться.
- Незалежні виклики один за одним: `await a; await b;` займає суму часу. Запустіть обидва й `await Task.WhenAll(a, b)`.

## Скасування й тайм-аути

Передавайте `CancellationToken` через кожен асинхронний метод. Викликаний метод перевіряє `ct.ThrowIfCancellationRequested()` або передає токен у виклики введення-виведення; викликач скасовує через `CancellationTokenSource`, наприклад `new CancellationTokenSource(TimeSpan.FromSeconds(5))`. В ASP.NET Core `HttpContext.RequestAborted` скасовується, коли клієнт розриває з'єднання.

## ValueTask

`ValueTask<T>` уникає виділення `Task`, коли результат часто доступний синхронно (влучання в кеш). Його можна дочекатися **лише один раз** і не можна чекати конкурентно. За замовчуванням беріть `Task`; `ValueTask` — для виміряних гарячих ділянок.

## Синхронізація

- `lock (obj) { ... }` (`Monitor`) дає взаємне виключення в межах одного процесу. **Усередині `lock` не можна `await`**. Блокуйте приватний об'єкт, ніколи не `this` чи тип.
- `SemaphoreSlim(1, 1)` з `await sem.WaitAsync()` — блокування, дружнє до async; `SemaphoreSlim(n)` обмежує кількість одночасних операцій до n.
- `Interlocked.Increment` / `CompareExchange` дають атомарні операції без блокування. `count++` над спільним полем — це гонка.
- `ReaderWriterLockSlim` пускає багатьох читачів одночасно; `volatile` лише забороняє переставляння й кешування, тож це не блокування.
- Взаємоблокування виникають, коли два блокування беруть у різному порядку. Завжди беріть їх в одному порядку й робіть критичні секції короткими.

## Конкурентні колекції та паралелізм

`ConcurrentDictionary` (з `GetOrAdd` і `AddOrUpdate`; фабрика значення може виконатися більше одного разу), `ConcurrentQueue`, `BlockingCollection` і `System.Threading.Channels` для схеми «виробник — споживач». Для **обчислювального** паралелізму даних — `Parallel.For`/`ForEach` і PLINQ. Для введення-виведення — `Task.WhenAll` або `Parallel.ForEachAsync` з `MaxDegreeOfParallelism`, щоб обмежити одночасність.

## Чекліст для співбесіди

- Поясніть різницю між асинхронним і паралельним, а також між Thread, пулом потоків і Task.
- Опишіть, що відбувається на `await` і чому `.Result` може спричинити взаємоблокування.
- Скажіть, коли використовувати `ConfigureAwait(false)`, `ValueTask` і `Task.WhenAll`.
- Поясніть, чому `async void` небезпечний і як передається скасування.
- Оберіть між `lock`, `SemaphoreSlim`, `Interlocked` і конкурентною колекцією.
