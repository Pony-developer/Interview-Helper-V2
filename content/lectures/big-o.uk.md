Big-O описує, як **зростає** вартість алгоритму зі збільшенням вхідних даних. Вона ігнорує константи й молодші доданки, тож описує масштабування, а не швидкість.

## Поширені класи

| Клас | Назва | Приклад | n = 1 000 000 |
| --- | --- | --- | --- |
| O(1) | стала | доступ за індексом, `Map.get` | 1 крок |
| O(log n) | логарифмічна | бінарний пошук | ~20 |
| O(n) | лінійна | один цикл, `includes` | 10⁶ |
| O(n log n) | лінійно-логарифмічна | хороші сортування | ~2·10⁷ |
| O(n²) | квадратична | вкладені цикли по тих самих даних | 10¹² ✗ |
| O(2ⁿ) | експоненційна | усі підмножини, наївне Фібоначчі | ✗✗ |

Грубе правило: близько 10⁸ простих операцій за секунду. Якщо ваша формула дає більше для реального розміру даних, шукайте кращий алгоритм.

## Як аналізувати код

- **Послідовні блоки додаються**: O(n) + O(n log n) = O(n log n), бо перемагає найбільший доданок.
- **Вкладені цикли множаться**: цикл по `n` усередині циклу по `m` дає O(n·m).
- **Ділення** задачі навпіл на кожному кроці дає O(log n).
- **Рекурсія**: кількість викликів помножена на роботу в кожному. Дві гілки на рівень і n рівнів дають O(2ⁿ).
- Для різних вхідних даних беріть різні літери: порівняння двох списків коштує O(n + m) або O(n·m), а не O(n²).

## Приховані витрати в JavaScript

```js
for (const id of ids) {
  if (list.includes(id)) …     // O(n) усередині циклу → O(n·m)
}
const set = new Set(list);      // побудувати один раз: O(n)
for (const id of ids) if (set.has(id)) … // O(m)
```

Інші пастки: `array.shift()`/`unshift()` коштують O(n); `slice`, spread, `concat` і `JSON.stringify` копіюють усе (O(n)); конкатенація рядків у вкладених циклах; `sort` коштує O(n log n).

## Складність за пам'яттю

Рахуйте додаткову пам'ять понад вхідні дані: нові масиви, Map, глибину рекурсії (стек викликів!). Сортування злиттям використовує O(n) додаткової пам'яті, ітеративний бінарний пошук O(1), рекурсивний DFS по дереву O(висота).

## Амортизована вартість

`array.push` коштує O(1) **амортизовано**. Інколи рушій перевиділяє пам'ять і копіює масив (O(n)), але в середньому на багато push вартість одного залишається сталою.

## Найкращий, середній, найгірший

Quicksort у середньому має O(n log n), але в найгіршому випадку O(n²). Хеш-таблиці в середньому мають O(1), але деградують за великої кількості колізій. Коли питають про складність, уточніть, який випадок маєте на увазі.

## Чек-лист для співбесіди

- Самі називайте складність за часом **і** за пам'яттю.
- Пояснюйте, звідки береться домінантний доданок.
- Прибирайте пошук O(n) з циклу за допомогою Set/Map.
- Згадуйте найкращий, середній і найгірший випадки, коли вони різні.
