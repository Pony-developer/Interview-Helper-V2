HTML надає вмісту значення. Браузери, пошукові системи й допоміжні технології читають це значення, тож вибір правильного елемента є функцією, а не прикрасою.

## Семантична структура

```html
<header>…логотип, навігація сайту…</header>
<nav aria-label="Main">…</nav>
<main>
  <article>
    <h1>Заголовок сторінки</h1>
    <section aria-labelledby="pricing">
      <h2 id="pricing">Ціни</h2>
    </section>
  </article>
  <aside>…пов'язані посилання…</aside>
</main>
<footer>…</footer>
```

- Використовуйте **один `<h1>`** на сторінку й не пропускайте рівні заголовків: користувачі зчитувачів екрана переміщуються саме заголовками.
- Орієнтири (`header`, `nav`, `main`, `aside`, `footer`) дозволяють перестрибувати між частинами сторінки.
- `<button>` для дій, `<a href>` для навігації. `<div onclick>` не отримує фокус, не має ролі й ігнорує Enter/Space.
- `<ul>`/`<ol>` для списків, `<table>` з `<th scope>` для табличних даних (ніколи для верстки), `<time datetime>` для дат.

## Форми

```html
<form>
  <label for="email">Email</label>
  <input id="email" name="email" type="email" autocomplete="email" required
         aria-describedby="email-hint" />
  <p id="email-hint">Ми нікому його не передамо.</p>

  <fieldset>
    <legend>Тариф</legend>
    <label><input type="radio" name="plan" value="free" /> Free</label>
    <label><input type="radio" name="plan" value="pro" /> Pro</label>
  </fieldset>

  <button type="submit">Зареєструватися</button>
</form>
```

- Кожне поле потребує **мітки (label)**. Placeholder не є міткою: він зникає під час введення.
- Правильний `type` (`email`, `tel`, `number`, `date`) дає потрібну мобільну клавіатуру й вбудовану валідацію. `autocomplete` пришвидшує заповнення.
- `<button>` усередині форми за замовчуванням має `type="submit"`, тож іншим кнопкам задавайте `type="button"`.
- Групуйте пов'язані радіокнопки й чекбокси через `<fieldset>` і `<legend>`.

## Як браузер завантажує сторінку

1. HTML розбирається згори донизу в DOM.
2. Звичайний `<script>` **блокує розбір**, доки його не завантажено й не виконано.
3. `<script defer>` завантажується паралельно й виконується після розбору, по порядку. `<script async>` виконується щойно завантажиться, у довільному порядку. Скрипти `type="module"` за замовчуванням відкладені.
4. CSS блокує **відмальовування** (не розбір), бо браузеру потрібні стилі перед малюванням.

Критичний CSS розміщуйте в head, для скриптів застосунку використовуйте `defer`, а зображення нижче першого екрана завантажуйте ліниво через `loading="lazy"`.

## Метадані, що мають значення

`<html lang>`, `<meta charset="utf-8">`, `<meta name="viewport" content="width=device-width, initial-scale=1">`, унікальні `<title>` і meta description, а також текст `alt` для кожного змістовного зображення (`alt=""` для декоративних).

## Глибше

**Нативні діалоги.** `dialog.showModal()` розміщує діалог у верхньому шарі з `::backdrop`, робить решту сторінки інертною й закривається за Escape. `show()` відкриває звичайний немодальний діалог. `<form method="dialog">` усередині закриває його під час надсилання.

**Адаптивні зображення.** `srcset` перелічує кандидатів за шириною (`hero-960.jpg 960w`), а `sizes` каже браузеру, якої ширини буде слот (`(min-width: 800px) 50vw, 100vw`). Браузер множить слот на щільність пікселів і бере найменший файл, що його покриває. Без `sizes` він вважає ширину 100vw і завантажує зайве.

**Пріоритет завантаження.** Тримайте LCP-зображення справжнім `<img>` у HTML, щоб сканер попереднього завантаження знайшов його рано, і додайте `fetchpriority="high"`. Використовуйте `<link rel="preload">` для критичних ресурсів, які виявляються пізно (фони в CSS, шрифти), і ніколи не завантажуйте головне зображення ліниво.

## Чек-лист для співбесіди

- Замініть клікабельні div на кнопки й посилання та поясніть чому.
- Побудуйте форму з мітками й правильними типами полів.
- Поясніть різницю між `defer` і `async`.
- Опишіть орієнтири й порядок заголовків для доступності та SEO.
