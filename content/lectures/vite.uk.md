Браузери вміють завантажувати ES-модулі напряму, то навіщо взагалі збирати? Реальні застосунки мають тисячі модулів і npm-пакетів, написаних на CommonJS, TypeScript, JSX чи як файли Vue/Svelte, плюс CSS і зображення. Інструмент збирання перетворює все це, прибирає невикористаний код і створює кілька оптимізованих файлів, що добре кешуються. **Vite** є типовим інструментом збирання для більшості нових фронтенд-проєктів (на ньому побудовані React, Vue, Svelte, SolidJS, Astro і Vitest).

## Розробка: без збирання, на вимогу

Класичні бандлери (webpack) збирають увесь застосунок, перш ніж dev-сервер зможе відповісти, тож час запуску зростає разом із кодовою базою. Vite віддає вихідні файли як **нативні ES-модулі**:

1. Браузер запитує `/src/main.tsx`; Vite перетворює лише цей файл (TypeScript/JSX через esbuild) і повертає його.
2. Браузер іде за його `import` і запитує лише модулі, потрібні поточній сторінці.
3. **Залежності** з `node_modules` один раз попередньо збираються (CommonJS → ESM, багато дрібних файлів → один) і кешуються, тож `lodash-es` не перетворюється на 600 запитів.

Запуск майже миттєвий і не залежить від розміру застосунку.

## Гаряча заміна модулів (HMR)

Коли ви зберігаєте файл, Vite знає граф модулів і замінює лише змінений модуль і його межу HMR (наприклад, компонент React через React Fast Refresh), зберігаючи стан застосунку. Якщо жодна межа не приймає оновлення, сторінка перезавантажується. Оновлення CSS підставляються на місці.

## Продакшен-збірки

Для продакшену Vite збирає через **Rollup** (у новіших версіях через Rolldown, порт на Rust), бо тисячі незібраних модулів повільно завантажуються в реальних мережах. Збірка виконує:

- **Tree shaking**: невикористані експорти прибираються. Для цього потрібен синтаксис ES-модулів і код без прихованих побічних ефектів; `"sideEffects": false` у `package.json` пакета дає бандлерам змогу повністю викидати невикористані файли.
- **Розбиття коду**: кожен динамічний `import()` стає окремим фрагментом (chunk), що завантажується на вимогу. Розбивайте за маршрутами й за важкими, рідко використовуваними можливостями (редактори, графіки).
- **Мініфікацію** JS і CSS та обробку ресурсів (малі файли вбудовуються, інші копіюються з хешованими назвами).
- **Назви файлів із хешем вмісту** (`index-3f9a1c.js`), тож файли можна кешувати «назавжди» (`Cache-Control: immutable`), а `index.html` живе недовго й після кожного розгортання вказує на нові хеші.

```js
const Settings = lazy(() => import("./routes/Settings")); // окремий фрагмент
```

## Основи конфігурації

```ts
// vite.config.ts
export default defineConfig({
  plugins: [react()],
  resolve: { alias: { "@": "/src" } },
  server: { proxy: { "/api": "http://localhost:8080" } }, // уникнути CORS у розробці
  build: { sourcemap: true },
});
```

- **Змінні оточення**: клієнтському коду доступні лише змінні з префіксом `VITE_`, як `import.meta.env.VITE_API_URL`. Вони вбудовуються **під час збирання**, тож усе, що відкрито так, є публічним; ніколи не кладіть туди секрети. `import.meta.env.MODE`, `DEV` і `PROD` вбудовані.
- **Статичні ресурси**: файли з `public/` віддаються як є з кореня; імпортовані ресурси отримують хешовані URL.
- **Плагіни** використовують інтерфейс плагінів Rollup плюс специфічні для Vite хуки: для фреймворків, імпорту SVG, PWA, підтримки старих браузерів тощо.

## Vite проти webpack

| | Vite | webpack |
| --- | --- | --- |
| Dev-сервер | Нативні ESM, перетворення на вимогу | Спершу збирає все |
| Швидкість | Дуже швидкі запуск і HMR | Повільніший на великих застосунках |
| Конфігурація | Невелика, на домовленостях | Дуже гнучка, багатослівніша |
| Екосистема | Плагіни, сумісні з Rollup | Величезна екосистема лоадерів і плагінів, Module Federation |

webpack (і його наступник на Rust, Rspack) лишається поширеним в наявних застосунках і в мікрофронтендах.

## Налагодження збірки

- Аналізуйте розмір бандла через `rollup-plugin-visualizer` або `vite-bundle-visualizer`; шукайте продубльовані чи несподівано великі залежності.
- Стежте за barrel-файлами (`index.ts`, що реекспортує все), які в деяких налаштуваннях заважають tree shaking.
- Розбіжності між розробкою й збіркою зазвичай виникають через сумісність із CommonJS або змінні оточення; завжди перевіряйте `vite build && vite preview` перед розгортанням.

## Що перевірити перед співбесідою

- Поясніть, навіщо збирати для продакшену, хоча браузери підтримують ES-модулі.
- Опишіть, як працюють dev-сервер Vite і HMR і чому він швидко стартує.
- Поясніть tree shaking, розбиття коду через `import()` і хешовані назви файлів для кешування.
- Поясніть змінні `VITE_` і чому вони публічні.
- Порівняйте Vite і webpack.
