Функціональне програмування (FP) будує програми з **функцій, що перетворюють значення**, а не з кроків, що змінюють спільний стан. JavaScript не є чисто функціональною мовою, але його функції першого класу, методи масивів і патерни незмінних оновлень є основою React, Redux і RxJS.

## Чисті функції

Чиста функція:

1. повертає той самий результат для тих самих вхідних даних і
2. не має **побічних ефектів**: не змінює аргументи чи зовнішні змінні, не виконує введення-виведення, не читає годинник чи випадкові числа.

```js
const total = (items) => items.reduce((sum, i) => sum + i.price * i.qty, 0); // чиста
const addItem = (cart, item) => { cart.push(item); };                     // нечиста: мутує
```

Чисті функції легко тестувати, кешувати (мемоізувати) й виконувати паралельно, бо виклик можна замінити його результатом (**прозорість посилань**). Реальним застосункам потрібні ефекти; FP тримає їх на краях (обробники подій, ефекти, thunk), а ядро лишає чистим.

## Незмінність

Замість зміни даних створюйте нову версію й **повторно використовуйте** те, що не змінилося:

```js
const next = { ...state, user: { ...state.user, name: "Ada" } }; // state.settings використовується повторно
```

Порівняння посилань (`prev !== next`) тоді точно каже React, Redux і мемоізованим селекторам, що змінилося. Мутуючі методи масивів (`sort`, `reverse`, `splice`, `push`) є звичним джерелом багів; використовуйте `toSorted`, `toReversed`, `toSpliced`, `with`, spread, `map` і `filter`. `Object.freeze` дає поверхневий захист під час виконання; Immer дає писати «мутуючий» код, що створює незмінні оновлення.

## Функції вищого порядку і трійка методів масивів

Функції є значеннями: їх можна передавати й повертати. `map` перетворює кожен елемент, `filter` лишає частину, `reduce` згортає список в одне значення. Будьте уважні:

- `["1", "2", "3"].map(parseInt)` → `[1, NaN, NaN]`, бо `map` передає `(item, index)`, а `parseInt` сприймає індекс як основу числення.
- `reduce` без початкового значення кидає помилку на порожньому масиві.
- Створення нового об'єкта на кожному кроці (`reduce((acc, x) => ({ ...acc, [x.id]: x }), {})`) має складність O(n²). Мутувати **локальний** акумулятор цілком нормально: ззовні функція лишається чистою.

## Композиція, каррування й часткове застосування

```js
const pipe = (...fns) => (x) => fns.reduce((v, f) => f(v), x);
const slugify = pipe(trim, toLowerCase, (s) => s.replace(/\s+/g, "-"));
```

`pipe` застосовує функції зліва направо, `compose` справа наліво. **Каррування** перетворює `f(a, b, c)` на `f(a)(b)(c)`; **часткове застосування** фіксує частину аргументів (`const log = logAt("debug")`). Обидва прийоми полегшують поєднання невеликих функцій.

## Лінивість

Генератори створюють значення на вимогу, тож можна описати нескінченні чи дорогі послідовності й брати лише потрібне:

```js
function* naturals() { let n = 1; while (true) yield n++; }
```

Observable у RxJS застосовують ту саму ідею до подій у часі.

## Типові пастки

- Мемоізація нечистої функції повертає застарілі результати.
- Безточковий стиль (point-free) може шкодити читабельності; називайте проміжні кроки, коли це допомагає.
- Глибокі копії (`structuredClone`) на кожне оновлення дорогі; краще спільне використання структури.

## Що перевірити перед співбесідою

- Дайте визначення чистої функції й побічного ефекту з прикладами.
- Оновіть вкладений стан незмінно й поясніть спільне використання структури.
- Поясніть результат `map(parseInt)` і початкове значення `reduce`.
- Реалізуйте `pipe`/`compose` і простий `curry`.
- Поясніть, як ідеї FP проявляються в React (чистий рендер, незмінний стан) і Redux (чисті редʼюсери).
