Більшість розминкових задач є перетвореннями масивів чи рядків. Інтерв'юери шукають ідіоматичний, читабельний код і перевіряють, чи знаєте ви, які методи **змінюють** дані.

## Перетворюйте, а не пишіть цикли вручну

```js
const active = users.filter((u) => u.active);
const names = active.map((u) => u.name);
const total = orders.reduce((sum, o) => sum + o.amount, 0);
const hasAdmin = users.some((u) => u.role === "admin");
const allPaid = orders.every((o) => o.paid);
const firstBig = orders.find((o) => o.amount > 100);
```

Передавайте `reduce` **початкове значення**: без нього метод кидає помилку на порожньому масиві й бере перший елемент як акумулятор.

## Змінюють чи ні

| Змінюють масив | Повертають новий масив |
| --- | --- |
| `push`, `pop`, `shift`, `unshift` | `concat`, spread `[...a, x]` |
| `splice` | `slice`, `toSpliced` |
| `sort`, `reverse` | `toSorted`, `toReversed` |
| `fill`, `copyWithin` | `map`, `filter`, `with(i, v)` |

У стані React чи Redux нічого не змінюйте напряму. `arr.sort()` сортує **на місці** й повертає той самий масив, тож спершу скопіюйте його або використайте `toSorted`.

## Пастки сортування

```js
[10, 9, 1].sort();               // [1, 10, 9]: за замовчуванням порівнюються рядки!
[10, 9, 1].sort((a, b) => a - b); // [1, 9, 10]
names.sort((a, b) => a.localeCompare(b)); // рядки з урахуванням локалі
```

`Array.prototype.sort` стабільний, тож рівні елементи зберігають порядок. Це дозволяє сортувати за кількома ключами по черзі.

## Корисні ідіоми

```js
const unique = [...new Set(items)];
const byId = Object.fromEntries(users.map((u) => [u.id, u]));
const chunks = Array.from({ length: Math.ceil(a.length / n) }, (_, i) => a.slice(i * n, i * n + n));
const counts = words.reduce((m, w) => m.set(w, (m.get(w) ?? 0) + 1), new Map());
```

## Рядки

Рядки незмінні. Кожен метод повертає новий рядок.

- `split`, `join`, `slice`, `trim`, `padStart`, `replaceAll`, `includes`, `startsWith`.
- Розворот: `[...s].reverse().join("")`. Spread розбиває рядок на кодові точки, тож емодзі не ламаються; `split("")` їх ламає.
- **Перевірка анаграми**: порівняти відсортовані літери або, краще, порахувати символи в Map, що дає O(n).
- **Перевірка паліндрому**: нормалізувати (нижній регістр, лише літери й цифри), потім порівняти двома вказівниками.

Побудова довгого рядка через `+=` у циклі цілком нормальна для сучасних рушіїв. Для багатьох частин `array.join` читається краще.

## Розуміння складності

- `includes`/`indexOf` усередині циклу дає O(n²). Спершу побудуйте `Set`.
- `shift`/`unshift` мають складність O(n), бо переіндексовують масив. Для інтенсивної черги потрібна інша структура.

## Чек-лист для співбесіди

- Використовуйте `map`/`filter`/`reduce` і пояснюйте, коли звичайний цикл зрозуміліший.
- Знайте, які методи змінюють масив, і копіюйте перед сортуванням спільних даних.
- Завжди передавайте компаратор у `sort` для чисел.
- Використовуйте Map/Set, щоб перетворити вкладені цикли на лінійні проходи.
