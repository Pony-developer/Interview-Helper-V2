RxJS моделює значення в часі як **observable**. Він займає центральне місце в Angular (HttpClient, форми, маршрутизатор) і зручний усюди, де взаємодіють події, таймери й запити.

## Observable проти промісу

| | Проміс | Observable |
| --- | --- | --- |
| Значення | одне | від нуля до багатьох |
| Лінивість | стартує одразу | стартує при `subscribe` |
| Скасування | ні (якщо не рахувати AbortController) | `unsubscribe()` |
| Оператори | `then`/`catch` | десятки: `map`, `filter`, `debounceTime`… |

```ts
const ticks$ = interval(1000).pipe(take(3), map((n) => n * 10));
const sub = ticks$.subscribe({ next: console.log, complete: () => console.log("done") });
// 0, 10, 20, done
```

## Холодні й гарячі

- **Холодні** observable (`of`, `interval`, `HttpClient.get`) запускають нового виробника для **кожного** підписника. Два `async` pipe на один HTTP-observable означають два запити.
- **Гарячі** observable (події DOM, Subject) ділять одного виробника.
- `share()` / `shareReplay({ bufferSize: 1, refCount: true })` перетворюють холодний потік на спільний.

## Subject

Subject є і observable, і observer: ви передаєте в нього значення через `next()`.

- `Subject`: без початкового значення, пізні підписники пропускають минулі значення.
- `BehaviorSubject`: має поточне значення, і нові підписники одразу його отримують. Простий стор.
- `ReplaySubject(n)`: повторює останні n значень.

Назовні віддавайте `subject.asObservable()`, щоб сторонній код не міг надсилати значення.

## Відображення вищого порядку: ключова тема співбесід

Коли кожне значення запускає внутрішній observable (часто запит), оберіть спосіб «сплющення»:

| Оператор | Поведінка | Типове використання |
| --- | --- | --- |
| `switchMap` | скасовує попередній внутрішній observable | пошук під час введення, параметри маршруту |
| `mergeMap` | виконує всі паралельно | незалежні збереження, аналітика |
| `concatMap` | ставить у чергу, по одному, по порядку | упорядковані записи |
| `exhaustMap` | ігнорує нові значення, поки зайнятий | кнопка «Надіслати», вхід |

Класичний пошук під час введення:

```ts
const results$ = query$.pipe(
  map((q) => q.trim()),
  debounceTime(300),
  distinctUntilChanged(),
  filter((q) => q.length >= 2),
  switchMap((q) => search(q).pipe(catchError(() => of([])))),
);
```

Розміщуйте `catchError` **всередині** `switchMap`. Помилка в зовнішньому потоці завершує його, і пошук перестає працювати.

## Відписка

Нескінченні потоки (інтервали, події, вибірки зі стору) тримають колбеки й компоненти живими, доки ви не відпишетеся:

- у шаблонах Angular обирайте `async` pipe;
- `takeUntilDestroyed()` (Angular 16+) або `takeUntil(destroy$)`;
- скінченні потоки (HTTP, `take(1)`, `first()`) завершуються самі.

## Поєднання потоків

`combineLatest` (останні значення кожного, після того як усі видали значення), `withLatestFrom` (взяти останні значення інших, коли видає головний), `forkJoin` (останні значення, коли всі завершилися, як `Promise.all`), `merge` (переплетення).

## Чек-лист для співбесіди

- Порівняйте observable з промісами та холодні потоки з гарячими.
- Обирайте між switchMap, mergeMap, concatMap і exhaustMap.
- Побудуйте пошук під час введення з debounce, distinct і скасуванням.
- Поясніть, як ви уникаєте витоків підписок.
