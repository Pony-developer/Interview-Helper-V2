JavaScript виконує ваш код в **одному потоці**. Асинхронні API дозволяють почати роботу (мережа, таймери) й продовжити пізніше без блокування.

## Цикл подій на одній картинці

1. Виконати поточний скрипт (**стек викликів**) до кінця.
2. Виконати **всі мікрозадачі**: колбеки промісів, `queueMicrotask`, продовження після `await`.
3. Перемалювати сторінку за потреби (у браузері).
4. Взяти **одну макрозадачу** (таймер, колбек вводу-виводу, подію UI) й повернутися до кроку 1.

```js
console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");
// A, D, C, B
```

Мікрозадачі завжди виконуються до наступної макрозадачі, тому `C` іде перед `B`. Довгий синхронний цикл блокує все, включно з рендерингом.

## Проміси

Проміс буває в стані pending, fulfilled або rejected і завершується лише один раз. `then` повертає **новий** проміс, завдяки чому працюють ланцюжки. Повернені значення передаються далі; кинуті помилки перестрибують до найближчого `catch`.

| Комбінатор | Вирішується, коли | Відхиляється, коли |
| --- | --- | --- |
| `Promise.all` | усі виконані (масив значень) | будь-який відхилено (fail-fast) |
| `Promise.allSettled` | усі завершені (об'єкти статусів) | ніколи |
| `Promise.race` | перший завершився | перший завершився з помилкою |
| `Promise.any` | перший виконався | усі відхилені (`AggregateError`) |

## async/await

Функції `async` завжди повертають проміс. `await` призупиняє лише цю функцію, а решта програми продовжує працювати.

```ts
// Послідовно: загальний час = сума
for (const id of ids) results.push(await load(id));

// Паралельно: загальний час = найповільніший
const results = await Promise.all(ids.map(load));
```

Типові помилки:

- **Забутий `await`**: ви отримуєте проміс замість значення, а помилки стають необробленими відхиленнями.
- **`await` усередині `forEach`**: `forEach` ігнорує повернені проміси. Використовуйте `for…of` або `Promise.all`.
- **Проковтування помилок**: обгортайте `await` у `try/catch` на тому рівні, який справді може їх обробити.

## Обмеження паралельності

Відправити 1000 запитів одночасно означає перевантажити сервер. Натомість запускайте не більше `limit` за раз:

```ts
async function mapLimit<T, R>(items: T[], limit: number, fn: (x: T) => Promise<R>) {
  const results: R[] = new Array(items.length);
  let next = 0;
  async function worker() {
    while (next < items.length) {
      const i = next++;
      results[i] = await fn(items[i]);
    }
  }
  await Promise.all(Array.from({ length: Math.min(limit, items.length) }, worker));
  return results;
}
```

Кожен воркер синхронно бере наступний індекс (гонки немає, бо потік один). Результати зберігають порядок вхідних даних.

## Скасування й тайм-аути

Використовуйте `AbortController` разом із `fetch`. Для тайм-ауту підійде `Promise.race([work, timeoutPromise])`, але пам'ятайте: робота, що програла, продовжується, якщо її не скасувати.

## Чек-лист для співбесіди

- Передбачайте порядок виводу для змішаних таймерів і промісів.
- Обирайте між `all`, `allSettled`, `race` і `any`.
- Перетворюйте послідовний цикл на паралельну роботу чи роботу з обмеженою паралельністю.
- Не залишайте жодного промісу без обробки помилок.
