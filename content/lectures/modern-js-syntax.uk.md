ES2015 і подальші релізи додали синтаксис, що прибирає більшість шаблонного коду, якого потребував старий JavaScript. Кожна можливість сама по собі проста; співбесіди зосереджуються на **крайніх випадках**: коли застосовується значення за замовчуванням, що саме копіює spread і які значення `??` вважає відсутніми.

## Деструктуризація

Деструктуризація витягує значення з масивів (за позицією) та об'єктів (за ключем) у змінні:

```js
const [first, , third = 0, ...others] = list;            // пропуск, значення за замовчуванням, rest
const { id, name: title = "Untitled", ...meta } = post;  // перейменування, значення за замовчуванням, rest
const { author: { email } = {} } = post;                 // вкладена, із запасним значенням
[a, b] = [b, a];                                         // обмін без тимчасової змінної
```

- **Значення за замовчуванням застосовуються лише для `undefined`**, а не для `null`, `0` чи `""`.
- Деструктуризація масивів використовує **протокол ітерації**, тож працює з будь-яким ітерованим об'єктом (рядки, `Map`, генератори), а неітероване значення праворуч кидає `TypeError`.
- Деструктуризація об'єктів читає властивості, зокрема успадковані, і обгортає примітиви (`const { length } = "abc"` працює). Деструктуризація `null` чи `undefined` кидає помилку.
- Деструктуризація вкладеного шляху, якого не існує, кидає помилку, якщо не дати вкладеному шаблону значення за замовчуванням (`= {}`).
- Шаблон присвоєння, що починається з `{`, треба взяти в дужки: `({ a, b } = obj);`. Інакше `{` починає блок.
- Rest об'єкта (`...meta`) копіює в новий звичайний об'єкт лише **власні перелічувані** властивості.

## Spread і rest

Ті самі `...` виконують протилежні задачі: **spread** розгортає ітерований об'єкт чи об'єкт в елементи чи властивості, а **rest** збирає решту в масив чи об'єкт.

```js
const merged = { ...defaults, ...options };   // пізніші ключі перемагають
const copy = [...items];                       // поверхнева копія
Math.max(...numbers);                          // масив → аргументи
function log(level, ...messages) {}            // rest-параметр
```

Копії через spread **поверхневі**: вкладені об'єкти спільні. Spread об'єкта копіює власні перелічувані властивості (зокрема символьні), виконує гетери й зберігає їхні значення та ігнорує `null`/`undefined` (`{ ...null }` дає `{}`). Spread масиву потребує ітерованого значення, тож `[...{}]` кидає помилку. Розгортання величезних масивів в аргументи може перевищити ліміт аргументів рушія, тож там використовуйте цикл чи `reduce`.

## Параметри за замовчуванням

```js
function connect(host, port = 443, url = `https://${host}:${port}`) {}
```

- Значення за замовчуванням обчислюються **під час виклику**, щоразу, і лише коли аргумент `undefined` (тож `connect("a", null)` зберігає `null`).
- Пізніші параметри можуть посилатися на попередні; посилання на пізніший потрапляє в **тимчасову мертву зону** (`function f(a = b, b) {}` кидає помилку, коли `a` не передано).
- Параметри зі значеннями за замовчуванням живуть у власній області видимості, між зовнішньою областю й тілом функції.
- Функція зі значеннями за замовчуванням, rest чи деструктуризацією в параметрах не може містити `"use strict"`, а її `length` рахує лише параметри до першого зі значенням за замовчуванням.

## Шаблонні літерали

Рядки в зворотних лапках підставляють вирази (`${expr}`, перетворені через `String()`), можуть займати кілька рядків і бути **тегованими**: `` tag`a${x}b` `` викликає `tag(["a", "b"], x)`. Масив рядків має версію `.raw` зі збереженими екрануваннями, і це той самий заморожений об'єкт щоразу, коли виконується той самий літерал, тож теги можуть кешувати за ним. Теги лежать в основі безпечного екранування HTML, конструкторів SQL (`` sql`… ${id}` `` з параметрами замість конкатенації рядків), `String.raw`, styled-components і `gql` у GraphQL.

## Optional chaining, nullish coalescing, логічне присвоєння

```js
const city = user?.address?.city;        // undefined, якщо user чи address є null/undefined
const first = list?.[0];
callback?.(result);                       // виклик, лише якщо визначено
const pageSize = options.pageSize ?? 20;  // запасне значення лише для null/undefined
cache[key] ??= compute(key);              // присвоїти, лише якщо відсутнє
```

- `?.` **обриває** решту ланцюжка: якщо `user` є nullish, `user?.address.city` дає `undefined`, не обчислюючи `.city`. Від хибних типів, що не є nullish, він не захищає (`5?.()` усе одно кидає помилку).
- `??` бере запасне значення лише для `null` і `undefined`, на відміну від `||`, що замінює також `0`, `""`, `false` і `NaN`. Змішування `??` з `||` чи `&&` без дужок є `SyntaxError`.
- `a ||= b`, `a &&= b` і `a ??= b` **присвоюють лише за потреби**, тож не викликають сетери (чи оновлення стану React), коли значення вже є.

## Дрібніші зручності

- Скорочені властивості й методи (`{ id, save() {} }`), обчислювані ключі (`{ [key]: value }`).
- Стрілочні функції не мають власних `this`, `arguments`, `super` чи `new.target` і не можуть бути конструкторами.
- `for…of` перебирає значення, а `for…in` перелічувані рядкові ключі (зокрема успадковані).
- Числові роздільники (`1_000_000`), оператор степеня (`2 ** 10`), `Array.prototype.at(-1)`, `Object.hasOwn`, `structuredClone`, `Object.groupBy`.

## Що перевірити перед співбесідою

- Скажіть, коли застосовуються значення за замовчуванням у деструктуризації й параметрах і чому `null` їх не вмикає.
- Поясніть, що копіює spread (поверхнево, власні перелічувані, гетери обчислюються) і відмінність від rest.
- Поясніть область видимості параметрів і TDZ зі значеннями за замовчуванням.
- Напишіть тегований шаблон і поясніть `strings.raw`.
- Поясніть, як `?.` обриває ланцюжок, `??` проти `||` і чому `??=` краще за `x = x ?? y` для сетерів.
