ES-модулі (ESM) є стандартною системою модулів JavaScript. Їх нативно використовують браузери, Node.js і всі сучасні збирачі.

## Синтаксис

```js
// math.js
export const PI = 3.14159;
export function area(r) { return PI * r * r; }
export default class Circle { /* ... */ }

// app.js
import Circle, { area, PI as pi } from "./math.js";
import * as math from "./math.js";       // об'єкт простору імен
export { area } from "./math.js";          // повторний експорт (barrel-файли)
```

- **Іменовані експорти** явні, тож інструменти можуть безпечно прибирати невикористаний код (tree-shaking) і перейменовувати їх під час рефакторингу.
- **Типовий експорт (default)** є єдиним «головним» значенням. Імпортер сам обирає назву, що ускладнює пошук у кодовій базі.

## ESM проти CommonJS

| | ESM | CommonJS |
| --- | --- | --- |
| Синтаксис | `import` / `export` | `require` / `module.exports` |
| Аналіз | статичний, під час розбору | динамічний, під час виконання |
| Завантаження | асинхронне, дозволяє `await` верхнього рівня | синхронне |
| Прив'язки | **живі** (лише для читання) | копії значень |
| Tree-shaking | так | обмежено |

Оскільки імпорти статичні, вони мають бути на верхньому рівні з рядковими літералами. Завдяки цьому збирачі прибирають невикористані експорти.

## Живі прив'язки

```js
// counter.js
export let count = 0;
export function inc() { count++; }

// main.js
import { count, inc } from "./counter.js";
inc();
console.log(count); // 1: імпорт відображає поточне значення модуля
count = 5;          // TypeError: імпорти лише для читання
```

## Порядок виконання

Модуль виконується **один раз**, під час першого імпорту, і всі імпортери ділять той самий екземпляр. Тому модулі природно працюють як синглтони. Залежності виконуються вглиб, раніше за тіло модуля, що їх імпортує.

**Циклічні імпорти** працюють, лише якщо жоден модуль не використовує експорти іншого під час свого виконання на верхньому рівні. Інакше ви отримаєте TDZ (`ReferenceError`) або `undefined`. Розривайте цикли, винісши спільний код у третій модуль.

## Динамічний `import()`

```js
const { Chart } = await import("./chart.js"); // повертає проміс простору імен
```

Використовуйте його для розділення коду (завантажувати важкі функції на вимогу) й умовного завантаження. Збирачі створюють окремий чанк для кожного динамічного імпорту.

## Глибше

**Виконання — це обхід у глибину.** Завантажувач виконує залежності раніше за їхніх імпортерів, у порядку імпортів, і кожен модуль лише раз. Модуль, що ще завантажується, коли його імпортують знову (цикл), пропускається — тому циклічні імпорти можуть бачити неініціалізовані прив'язки.

**await на верхньому рівні.** Модуль з `await` на верхньому рівні змушує все, що від нього залежить, чекати завершення його виконання. Потік не блокується, а незалежні гілки графа все одно виконуються.

**Імпорт CommonJS з ESM (Node.js).** Типовий імпорт — це завжди `module.exports`. Іменовані імпорти працюють лише для імен, які Node може виявити статично (`exports.parse = ...`). Для динамічно створених експортів імпортуйте типовий експорт і деструктуризуйте його.

**Який формат має файл.** `.mjs` — завжди ESM, `.cjs` — завжди CommonJS. Файл `.js` підпорядковується полю `"type"` найближчого `package.json`.

## Чек-лист для співбесіди

- Порівняйте ESM і CommonJS та поясніть, чому статичні імпорти уможливлюють tree-shaking.
- Поясніть живі прив'язки й те, що імпорти лише для читання.
- Опишіть, що відбувається з циклічними залежностями й як це виправити.
- Використовуйте `import()` для лінивого завантаження важкого коду.
