Адаптивний дизайн означає одну кодову базу, що підлаштовується під будь-який екран: телефон на 320 px, планшет у портретній орієнтації, монітор 4K чи браузер із масштабом 200%. Мета не в тому, щоб підігнати кілька розмірів пристроїв, а в тому, щоб зробити макети **гнучкими** й додавати коригування лише там, де вміст починає ламатися.

## Тег viewport

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

Без нього мобільні браузери рендерять сторінку на віртуальній ширині близько 980 px і зменшують її, тож медіазапити ніколи не розпізнають «мобільний». Ніколи не вимикайте масштабування (`user-scalable=no`): це порушує вимоги доступності.

## Медіазапити mobile-first

Пишіть базові стилі для найменшого екрана, а складність додавайте з появою місця:

```css
.cards { display: grid; gap: 1rem; }
@media (min-width: 40rem) { .cards { grid-template-columns: repeat(2, 1fr); } }
@media (min-width: 64rem) { .cards { grid-template-columns: repeat(3, 1fr); } }
```

- Обирайте **контрольні точки за вмістом** (де ламається довжина рядка чи макет), а не за списками пристроїв.
- Використовуйте контрольні точки в `em`/`rem`, щоб вони масштабувалися разом із розміром шрифту користувача.
- Медіаознаки не обмежуються шириною: `prefers-color-scheme`, `prefers-reduced-motion`, `hover: hover` і `pointer: coarse` (сенсорний екран).

## Гнучкий макет без контрольних точок

Сучасному CSS часто взагалі не потрібен медіазапит:

```css
.grid { display: grid; grid-template-columns: repeat(auto-fill, minmax(min(16rem, 100%), 1fr)); }
.sidebar-layout { display: flex; flex-wrap: wrap; }
.sidebar-layout > main { flex: 1 1 30rem; }  /* переноситься під бічну панель, коли вузько */
```

`minmax`, `auto-fill`/`auto-fit`, `flex-wrap` і `flex-basis` дають браузеру самому вирішити, скільки стовпців уміщається.

## Контейнерні запити

Медіазапити питають про **вікно перегляду**, а компонентам важливе **власне місце**. Картка у вузькій бічній панелі й та сама картка в широкій основній колонці потребують різних макетів:

```css
.card-list { container-type: inline-size; }
@container (min-width: 30rem) { .card { display: grid; grid-template-columns: 8rem 1fr; } }
```

Одиниці контейнерних запитів (`cqi`) задають розміри відносно контейнера.

## Одиниці й гнучка типографіка

- `rem` для розмірів шрифту й відступів враховує налаштування шрифту браузера користувача; `px` разом із ним не масштабується.
- `%`, `fr`, `vw`/`vh` для пропорцій. На мобільних `100vh` включає область під адресним рядком браузера; використовуйте `100dvh` (динамічну) або `svh`/`lvh`.
- `clamp(min, preferred, max)` дає гнучкі розміри з обмеженнями: `font-size: clamp(1rem, 0.9rem + 1vw, 1.5rem)`.
- Тримайте довжину рядка читабельною: `max-width: 65ch`.

## Адаптивні зображення

```html
<img src="hero-800.jpg"
     srcset="hero-400.jpg 400w, hero-800.jpg 800w, hero-1600.jpg 1600w"
     sizes="(min-width: 64rem) 50vw, 100vw"
     width="1600" height="900" alt="…" loading="lazy" />
```

`srcset` перелічує варіанти, а `sizes` каже браузеру, якої ширини буде зображення на сторінці, тож він завантажує найменший файл, достатньо чіткий для щільності пікселів екрана. Використовуйте `<picture>` для **арт-дирекції** (інше кадрування на мобільних) чи сучасних форматів (AVIF/WebP із запасними варіантами). Завжди задавайте `width`/`height` (або `aspect-ratio`), щоб уникнути зсуву макета.

## Дотик і введення

- Сенсорні цілі щонайменше близько 44 × 44 CSS px (WCAG 2.2 вимагає мінімум 24 × 24).
- Не ховайте важливі дії за `:hover`; використовуйте `@media (hover: hover)` для покращень, що працюють лише з наведенням.
- Використовуйте правильні типи полів (`type="email"`, `inputmode="numeric"`) для зручніших мобільних клавіатур.

## Тестування

Емуляція пристроїв у браузері є гарним початком, але тестуйте й на справжніх телефонах (дотик, продуктивність, віртуальна клавіатура, що перекриває поля). Перевіряйте ширину 320 px, альбомну орієнтацію, масштаб 200% і великі системні шрифти: вміст має перебудовуватися без горизонтальної прокрутки (критерій WCAG «Reflow»).

## Що перевірити перед співбесідою

- Поясніть метатег viewport і медіазапити mobile-first.
- Побудуйте адаптивну сітку без медіазапитів (`auto-fill` + `minmax`).
- Порівняйте медіазапити й контейнерні запити.
- Поясніть `srcset`/`sizes`, `<picture>` і запобігання зсуву макета.
- Знайте `rem` проти `px`, `clamp()` і `dvh`.
