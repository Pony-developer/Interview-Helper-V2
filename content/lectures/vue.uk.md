Vue є прогресивним фреймворком, побудованим навколо **системи реактивного стану**: ви змінюєте звичайні на вигляд значення JavaScript, а Vue перерендерює саме ті компоненти, що їх використовували. Vue 3 зазвичай пишуть з **однофайловими компонентами** (`.vue`) і **Composition API** у `<script setup>`.

```vue
<script setup lang="ts">
import { computed, ref } from "vue";
const props = defineProps<{ step: number }>();
const emit = defineEmits<{ change: [value: number] }>();
const count = ref(0);
const doubled = computed(() => count.value * 2);
function inc() { count.value += props.step; emit("change", count.value); }
</script>

<template>
  <button @click="inc">{{ count }} × 2 = {{ doubled }}</button>
</template>
```

## Реактивність: `ref` і `reactive`

- `ref(value)` загортає будь-яке значення в об'єкт із властивістю `.value`. У `<script>` ви читаєте й записуєте `.value`; шаблони розгортають ref верхнього рівня автоматично.
- `reactive(object)` повертає **Proxy** об'єкта. Читання відстежуються, а записи запускають оновлення, і це глибоко (вкладені об'єкти загортаються ліниво під час доступу).

Під капотом, коли виконується ефект (рендер компонента, `computed`, `watchEffect`), кожна реактивна властивість, яку він **читає**, записується як залежність. Пізніший запис цієї властивості перезапускає саме ці ефекти. Наслідки:

- Зміни **початкового** об'єкта в обхід проксі не помічаються.
- Деструктуризація `reactive` об'єкта (`const { count } = state`) копіює поточне значення й втрачає реактивність; використовуйте `toRefs(state)` або лишайте `state.count`.
- Заміна всієї змінної `reactive` (`state = reactive({…})`) від'єднує її від шаблону; це одна з причин, чому багато команд всюди віддають перевагу `ref`.

## `computed`, `watch` і `watchEffect`

- `computed(() => …)` обчислює похідне значення. Воно **кешується** й переобчислюється лише тоді, коли змінюється одна з його залежностей, на відміну від методу в шаблоні, що виконується на кожному рендері. Не робіть побічних ефектів у геттерах computed.
- `watch(source, callback)` виконує побічний ефект, коли змінюється конкретне джерело; за замовчуванням він лінивий (`{ immediate: true }`, щоб запустити одразу) і дає старе й нове значення.
- `watchEffect(fn)` виконується одразу й перезапускається, коли змінюється будь-що з прочитаного, з автоматичним відстеженням залежностей.

## Шаблони й директиви

- `v-if` додає чи прибирає елементи (і запускає ініціалізацію та знищення компонентів); `v-show` лише перемикає `display`. Використовуйте `v-show` для частих перемикань, а `v-if` для рідко показуваного чи дорогого вмісту.
- `v-for` потребує стабільного унікального `:key` (id, а не індекс), щоб Vue правильно переміщував наявні DOM-вузли й стан компонентів, коли список змінюється.
- `v-model` є синтаксичним цукром для двостороннього зв'язування: на компоненті це проп `modelValue` плюс подія `update:modelValue` (`defineModel()` у Vue 3.4+).
- Пропси течуть **вниз** і в дочірньому компоненті доступні лише для читання; діти спілкуються **вгору** подіями. Зміна пропса спричиняє попередження й перезаписується під час наступного рендеру батька.

## Оновлення асинхронні

Vue групує зміни стану й оновлює DOM один раз, у мікрозадачі. Одразу після `count.value++` DOM ще показує старе значення; `await nextTick()` чекає на оновлення, коли треба виміряти елемент чи встановити фокус.

## Спільний стан

- `provide`/`inject` передають значення вниз деревом компонентів без «прокидання» пропсів (тема, контекст форми).
- **Pinia** є офіційним стором: `defineStore` зі станом, геттерами й діями, підтримкою DevTools і безпекою для SSR. Він замінив Vuex.

## Що перевірити перед співбесідою

- Поясніть `ref` проти `reactive`, `.value` і чому деструктуризація ламає реактивність.
- Опишіть, як працює відстеження залежностей на Proxy.
- Порівняйте `computed`, `watch` і `watchEffect`.
- Поясніть `v-if` проти `v-show` і навіщо `v-for` потрібні ключі.
- Поясніть односпрямований потік даних через props і emits, `v-model` на компонентах і `nextTick`.
