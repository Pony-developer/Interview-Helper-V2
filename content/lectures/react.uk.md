React перетворює стан на інтерфейс. Більшість питань на співбесіді перевіряють, чи розумієте ви, **коли** компоненти рендеряться і **що** зберігається між рендерами.

## Рендеринг — це виклик вашої функції

Компонент є функцією від пропсів і стану до елементів. React викликає її знову, коли:

- змінюється її стан (`setState` зі значенням, відмінним за `Object.is`),
- ререндериться батьківський компонент (якщо компонент не обгорнуто в `memo` і пропси не однакові поверхнево),
- змінюється контекст, який вона читає.

Рендер має бути **чистим**: жодних підписок, таймерів чи змін зовнішніх змінних під час рендеру. Побічні ефекти розміщуйте в обробниках подій або ефектах.

## Стан — це знімок

```tsx
const [count, setCount] = useState(0);

function handleClick() {
  setCount(count + 1);
  setCount(count + 1); // той самий знімок → count + 1, а не + 2
  setCount((c) => c + 1); // функція-оновлювач бачить останнє значення в черзі
}
```

Оновлення **групуються (batching)** і застосовуються в наступному рендері. Ніколи не змінюйте об'єкти стану напряму: `items.push(x); setItems(items)` залишає те саме посилання, і React може пропустити рендер. Створюйте новий масив: `setItems([...items, x])`.

## Ефекти синхронізують із зовнішнім світом

```tsx
useEffect(() => {
  const id = setInterval(tick, 1000);
  return () => clearInterval(id); // очищення перед повторним запуском і при демонтуванні
}, [tick]);
```

- Без масиву залежностей ефект виконується після кожного рендеру. З `[]` виконується після монтування. З `[a, b]` виконується, коли змінюється `a` або `b`.
- Вказуйте кожне реактивне значення, яке читаєте. Пропущені залежності дають застарілі замикання.
- Часто ефект **не потрібен**. Обчислюйте похідні значення під час рендеру (`const total = items.reduce(...)`), а не копіюйте їх у стан.

## Списки та ключі

Ключі підказують React, який елемент є яким між рендерами:

```tsx
{todos.map((t) => <TodoRow key={t.id} todo={t} />)}
```

Індекс масиву як ключ ламається, коли елементи вставляють чи переставляють: стан і значення полів «прилипають» до хибних рядків. Використовуйте стабільний ID.

## Керовані поля

Кероване поле бере значення зі стану й повідомляє про зміни:

```tsx
<input value={query} onChange={(e) => setQuery(e.target.value)} />
```

Фільтрований список обчислюйте з `query` під час рендеру. Не зберігайте його в окремому стані.

## Інструменти продуктивності

- `memo(Component)`: пропустити ререндер, коли пропси поверхнево однакові.
- `useMemo(fn, deps)`: кешувати дороге обчислення.
- `useCallback(fn, deps)`: зберегти стабільну функцію, наприклад для мемоізованого дочірнього компонента.

Спершу вимірюйте. Зайва мемоізація ускладнює код і нічого не дає.

## Чек-лист для співбесіди

- Поясніть порядок render → commit → effect.
- Використовуйте функції-оновлювачі, коли новий стан залежить від попереднього.
- Обирайте стабільні ключі й поясніть, що ламається з індексами.
- Прибирайте ефекти, які лише перетворюють дані; залишайте ті, що спілкуються із зовнішнім світом.
