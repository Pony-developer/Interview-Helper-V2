Об'єктно-орієнтоване програмування (ООП) об'єднує в об'єкти **дані й поведінку, що з ними працює**. У JavaScript `class` є синтаксисом над прототипами, а TypeScript додає перевірки під час компіляції (`private`, `abstract`, `interface`). На співбесідах зазвичай перевіряють чотири принципи, як вони виглядають у JS, і компроміси.

## Чотири принципи

| Принцип | Ідея | У JS/TS |
| --- | --- | --- |
| Інкапсуляція | Приховати внутрішній стан і тримати його коректним через методи | поля `#private`, гетери, валідація в методах |
| Абстракція | Показувати, *що* робить об'єкт, а не *як* | інтерфейси, `abstract` класи, невеликий публічний API |
| Успадкування | Повторно використати й уточнити поведінку | `class Dog extends Animal`, `super` |
| Поліморфізм | Один виклик, різна поведінка для різних типів | перевизначення методів, качина типізація |

## Інкапсуляція: `#private` проти `private`

```ts
class Account {
  #balance = 0;             // приватне під час виконання: недоступне поза тілом класу
  private audit: string[] = []; // лише TypeScript: зникає після компіляції
  get balance() { return this.#balance; } // ззовні лише для читання
  deposit(amount: number) {
    if (!(amount > 0)) throw new RangeError("Amount must be positive");
    this.#balance += amount;
  }
}
```

`private` і `protected` у TypeScript існують лише для перевірки типів, тож `(acc as any).audit` під час виконання все одно працює. Поля `#` забезпечує сам рушій. Гетер без сетера робить властивість доступною лише для читання, а методи, що перевіряють вхідні дані, зберігають **інваріанти** об'єкта (баланс ніколи не стає від'ємним).

## Успадкування і `super`

```ts
class SavingsAccount extends Account {
  constructor(private rate: number) {
    super(); // має виконатися до використання `this`
  }
}
```

У похідному класі `this` не існує, доки `super()` не завершиться; звернення до нього раніше кидає `ReferenceError`. Методи шукаються вздовж **ланцюжка прототипів**: власні властивості екземпляра, потім `SavingsAccount.prototype`, потім `Account.prototype`, потім `Object.prototype`. Методи живуть у прототипі й спільні для всіх екземплярів; поля класу (зокрема поля-стрілочні функції) створюються в кожному екземплярі.

## Поліморфізм

```ts
abstract class Shape {
  abstract area(): number;
  describe() { return `${this.constructor.name}: ${this.area().toFixed(2)}`; }
}
```

`describe` написано один раз, а `this.area()` викликає ту реалізацію, яка є в конкретного об'єкта. Код, що залежить від `Shape`, працює з кожним підкласом і з будь-яким об'єктом, що має потрібні методи (качина типізація; TypeScript перевіряє форму **структурно**). `abstract` існує лише під час компіляції; щоб заборонити `new Shape()` під час виконання, перевірте в конструкторі `new.target === Shape`.

## Пастка `this`

Тіла класів виконуються в строгому режимі, тож метод, відірваний від об'єкта, отримує `this === undefined`:

```ts
const { deposit } = account;
deposit(5); // TypeError: cannot read private member from undefined
button.addEventListener("click", account.deposit); // та сама проблема
```

Виправлення: `account.deposit.bind(account)`, обгортка `() => account.deposit(5)` або поле класу зі стрілочною функцією (окрема функція на кожен екземпляр).

## Композиція замість успадкування

Глибокі ієрархії негнучкі. Підклас залежить від деталей реалізації батька (проблема **крихкого базового класу**), а реальні категорії рідко утворюють чисте дерево (`Penguin extends Bird`, але не вміє `fly()`). Композиція натомість збирає об'єкти з невеликих частин:

```ts
class Player {
  constructor(private movement: Movement, private weapon: Weapon) {}
  attack(target: Enemy) { this.weapon.hit(target); }
}
```

Поведінку можна підмінити під час виконання, тестувати окремо й вільно комбінувати. Використовуйте успадкування для справжнього відношення «є» (is-a), де підклас може заступити батька будь-де (принцип підстановки Лісков), а композицію («має», has-a) для всього іншого.

## Що перевірити перед співбесідою

- Назвіть чотири принципи й наведіть приклад кожного в JS.
- Поясніть різницю між `#field` і `private` у TypeScript.
- Поясніть, чому `super()` має бути першим і де живуть методи, а де поля.
- Покажіть, як відірваний метод втрачає `this`, і три способи це виправити.
- Аргументуйте, коли ви оберете композицію замість успадкування.
