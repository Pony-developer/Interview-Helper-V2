Angular є повноцінним фреймворком: компоненти, шаблони, впровадження залежностей (DI), маршрутизація та форми в одному пакеті. Співбесіди зосереджуються на потоках даних і виявленні змін.

## Компоненти та шаблони

Компонент є класом із шаблоном. Прив'язки з'єднують їх:

| Синтаксис | Напрям | Приклад |
| --- | --- | --- |
| `{{ value }}` | клас → вигляд (текст) | `{{ user.name }}` |
| `[prop]="expr"` | клас → вигляд (властивість) | `[disabled]="isSaving"` |
| `(event)="handler($event)"` | вигляд → клас | `(click)="save()"` |
| `[(ngModel)]="field"` | двостороння | поля форм |

Структурні директиви змінюють форму DOM: `*ngIf`, `*ngFor` (у нових версіях також блоки `@if` / `@for`).

## Взаємодія батька й дитини

```ts
@Component({ selector: "app-stepper", template: `
  <button (click)="change(-1)" [disabled]="value <= min">−</button>
  <span>{{ value }}</span>
  <button (click)="change(1)">+</button>` })
export class StepperComponent {
  @Input() value = 0;
  @Input() min = 0;
  @Output() valueChange = new EventEmitter<number>();

  change(delta: number) {
    this.valueChange.emit(this.value + delta);
  }
}
```

Батько пише `<app-stepper [(value)]="qty" />`. Пара `value` + `valueChange` дає двосторонню прив'язку «банан у коробці». Для спільного стану між віддаленими компонентами використовуйте сервіс.

## Впровадження залежностей

Сервіси є класами, зареєстрованими в інжекторі:

```ts
@Injectable({ providedIn: "root" })   // один синглтон на застосунок
export class CartService { /* ... */ }

constructor(private cart: CartService) {}  // або: cart = inject(CartService)
```

Провайдери можуть також бути на рівні модуля чи компонента. Провайдер на рівні компонента дає кожному екземпляру компонента власний екземпляр сервісу. DI робить код тестованим: у тестах підставляють фейковий провайдер.

## Хуки життєвого циклу

- `ngOnChanges`: перед `ngOnInit` і щоразу, коли змінюється посилання `@Input`.
- `ngOnInit`: один раз, після встановлення перших вхідних даних. Завантаження даних починайте тут, а не в конструкторі.
- `ngOnDestroy`: відпишіться, очистіть таймери.

## Виявлення змін

Zone.js перехоплює асинхронні API (події, таймери, XHR). Після кожної задачі Angular перевіряє дерево компонентів згори донизу й оновлює змінені прив'язки.

Зі `ChangeDetectionStrategy.OnPush` компонент перевіряється лише коли:

- `@Input` отримує **нове посилання**,
- усередині спрацювала подія,
- `async` pipe видав значення,
- ви викликали `markForCheck()`.

Тож з OnPush ніколи не змінюйте вхідні об'єкти чи масиви: `this.items.push(x)` не оновить дочірній компонент. Замінюйте їх: `this.items = [...this.items, x]`.

Нові версії додали **сигнали**: реактивні значення, що дозволяють оновлювати саме те, що змінилося, і опційний режим без zone.js.

## RxJS в Angular

`HttpClient` повертає Observable. У шаблонах обирайте `async` pipe: він підписується й відписується автоматично. Інакше відписуйтеся в `ngOnDestroy` або використовуйте `takeUntilDestroyed`.

## Чек-лист для співбесіди

- Покажіть `@Input`/`@Output` і поясніть, коли краще використати сервіс.
- Поясніть різницю між `providedIn: "root"` і провайдерами на рівні компонента.
- Опишіть, що перевіряє OnPush і чому важлива незмінність.
- Уникайте ручних підписок там, де впорається `async` pipe.
