Дві ідеї плутають найбільше в JavaScript: `this` і прототипи. Обидві стають передбачуваними, щойно ви знаєте, що **`this` визначається способом виклику функції**, а **об'єкти делегують невдалий пошук властивості своєму прототипу**.

## Як знайти `this`: дивіться на місце виклику

`this` не є самою функцією і не є областю, де її написано. Для звичайної (не стрілочної) функції його встановлює одне з чотирьох правил у момент виклику:

| Правило | Виклик має вигляд | `this` дорівнює |
| --- | --- | --- |
| Прив'язка `new` | `new Fn()` | щойно створеному об'єкту |
| Явна прив'язка | `fn.call(obj)`, `fn.apply(obj)`, `fn.bind(obj)()` | `obj` |
| Неявна прив'язка | `obj.fn()` | `obj` (об'єкту перед крапкою) |
| Типова прив'язка | `fn()` | `undefined` у строгому режимі (модулі, класи); глобальному об'єкту в нестрогих скриптах |

Коли можуть спрацювати кілька правил, порядок таблиці і є **пріоритетом**: `new` сильніший за `bind`, `bind` сильніший за виклик методу, а виклик методу сильніший за простий виклик. Щойно функцію прив'язано через `bind`, `call` і `apply` вже не змінять її `this`, а `new` усе ще може.

Класичний баг: втрачена неявна прив'язка. `const f = obj.method; f()` чи `setTimeout(obj.method, 100)` передають лише функцію, тож у місці виклику немає об'єкта.

```js
function greet(greeting) { return `${greeting}, ${this.name}`; }
const ada = { name: "Ada", greet };
ada.greet("Hi");                   // неявна: "Hi, Ada"
greet.call({ name: "Bo" }, "Hey"); // явна: "Hey, Bo"
const hi = greet.bind(ada, "Hi");  // нова функція з фіксованими this і аргументом
```

`call` передає аргументи по одному, `apply` масивом (`fn.apply(obj, args)`, тепер здебільшого замінений spread), а `bind` повертає нову функцію, не викликаючи її.

## Стрілочні функції: без власного `this`

Стрілочні функції взагалі не мають прив'язки `this`; вони читають `this` з навколишньої області, як будь-яку іншу змінну (лексичний `this`). Це саме те, що треба для колбеків усередині методів (`items.forEach(() => this.count++)`), і саме те, що не треба для методів у літералах об'єктів: `{ count: 0, inc: () => this.count++ }` використовує зовнішній `this`, а не об'єкт. `call`/`bind` не можуть змінити `this` стрілочної функції.

## Що робить `new`

`new Fn(args)`:

1. створює новий об'єкт,
2. прив'язує його прототип до `Fn.prototype`,
3. викликає `Fn` з `this`, що вказує на новий об'єкт,
4. повертає новий об'єкт, **якщо** `Fn` явно не повернула інший об'єкт (повернені примітиви ігноруються).

## Об'єкти й дескриптори властивостей

Кожна властивість має дескриптор: `value`, `writable`, `enumerable`, `configurable` (або `get`/`set` для аксесорів). Літерали об'єктів створюють властивості з усіма прапорцями `true`; `Object.defineProperty` за замовчуванням ставить їх у `false`. `Object.preventExtensions`, `seal` і `freeze` поступово блокують об'єкт, але лише **поверхнево**.

## Ланцюжок прототипів

Кожен об'єкт має внутрішнє посилання `[[Prototype]]` (читайте його через `Object.getPrototypeOf`). Коли ви читаєте `obj.prop`, а в `obj` її немає, пошук продовжується в прототипі, потім у прототипі прототипу, аж до `Object.prototype` і зрештою `null`.

```js
const animal = { speak() { return `${this.name} makes a sound`; } };
const dog = Object.create(animal); // прототип dog дорівнює animal
dog.name = "Rex";
dog.speak(); // знайдено в animal; this досі dog
```

Методи, знайдені в прототипі, усе одно виконуються з `this` = об'єкт, на якому їх викликали. Це і є **делегування**: об'єкти ділять поведінку через посилання, а не копіюють її.

Не плутайте два «прототипи»: `Fn.prototype` є звичайною властивістю функції, що стає прототипом об'єктів, створених через `new Fn()`; `Object.getPrototypeOf(obj)` (або застарілий `obj.__proto__`) є справжнім посиланням конкретного об'єкта.

### Затінення

**Запис** властивості зазвичай створює її на самому об'єкті, затіняючи версію прототипу. `child.count++` читає `count` з прототипу, а потім створює власну `count` у `child`. Два винятки: якщо успадкована властивість **лише для читання**, присвоєння не вдається (`TypeError` у строгому режимі), а якщо це успадкований **сетер**, виконується сетер замість створення властивості.

## `class` є (здебільшого) синтаксисом для прототипів

```js
class Animal {
  constructor(name) { this.name = name; }
  speak() { return `${this.name} makes a sound`; }
}
class Dog extends Animal {
  speak() { return `${super.speak()} (woof)`; }
}
```

`Dog.prototype.speak` живе в прототипі, `Object.getPrototypeOf(Dog.prototype) === Animal.prototype`, а `instanceof` просто проходить ланцюжком прототипів. Що додає `class`: методи неперелічувані, тіло строге, конструктори не можна викликати без `new`, `extends` працює з вбудованими типами на кшталт `Array` і `Error`, плюс приватні поля `#`, статичні блоки й `super`. Зверніть увагу: `super` прив'язаний до об'єкта, де метод **визначено** (його «домашнього об'єкта»), а не до `this`, тож запозичений метод, що використовує `super`, і далі посилається на початкового батька.

## Делегування проти класів

Класи моделюють ієрархії «є» (is-a). Система прототипів дозволяє й легший стиль: звичайні об'єкти, пов'язані через `Object.create`, що делегують одне одному («об'єкти, пов'язані з іншими об'єктами»). У будь-якому разі для спільної поведінки непов'язаних типів обирайте композицію.

## Що перевірити перед співбесідою

- Визначайте `this` для будь-якого місця виклику за чотирма правилами та їхнім пріоритетом.
- Поясніть, чому стрілочні функції поводяться інакше і коли це корисно.
- Опишіть чотири кроки `new`, зокрема правило про повернене значення.
- Поясніть ланцюжок прототипів, `Fn.prototype` проти `Object.getPrototypeOf` і затінення.
- Поясніть, що `class` і `super` додають поверх прототипів.
