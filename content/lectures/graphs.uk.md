Граф є множиною **вершин**, з'єднаних **ребрами**, які можуть бути напрямленими й мати ваги. Фронтенд-розробники зустрічають графи частіше, ніж думають: графи залежностей модулів у бандлерах, порядок збирання в task runner і монорепозиторіях, переходи між сторінками, соціальні чи організаційні схеми і сам DOM (дерево є графом без циклів).

## Представлення

| Представлення | Пам'ять | Перевірити ребро (u, v) | Перебрати сусідів |
| --- | --- | --- | --- |
| Список суміжності (`Map<node, node[]>`) | O(V + E) | O(степінь) | O(степінь) |
| Матриця суміжності (`boolean[V][V]`) | O(V²) | O(1) | O(V) |

Більшість реальних графів розріджені, тож списки суміжності є типовим вибором. Ненапрямлене ребро зберігайте в обох напрямках.

## BFS і DFS

```js
function bfs(graph, start) {
  const seen = new Set([start]);
  const queue = [start];
  for (let i = 0; i < queue.length; i++) {
    for (const next of graph[queue[i]] ?? []) {
      if (!seen.has(next)) { seen.add(next); queue.push(next); } // позначати під час додавання в чергу
    }
  }
  return queue; // вершини в порядку віддаленості від start
}
```

- **BFS** (пошук у ширину) обходить рівень за рівнем за допомогою черги. У незваженому графі він знаходить найкоротші шляхи за кількістю ребер. Позначайте вершини як побачені, коли **додаєте** їх у чергу, інакше та сама вершина може потрапити в чергу багато разів.
- **DFS** (пошук у глибину) спершу йде вглиб (рекурсія чи стек). На ньому побудовані виявлення циклів, топологічне сортування й пошук компонент зв'язності.

Обидва працюють за O(V + E) зі списком суміжності (O(V²) з матрицею).

## Цикли й топологічний порядок

**Топологічний порядок** перелічує вершини напрямленого графа так, що кожне ребро веде вперед: залежності раніше за тих, кому вони потрібні. Він існує лише для **DAG** (напрямленого ациклічного графа).

- **Алгоритм Кана**: порахуйте незадоволені залежності кожної вершини, почніть із тих, що їх не мають, і далі вивільняйте вершини, чий лічильник падає до нуля. Якщо якісь вершини так і не вивільнилися, є цикл.
- **DFS**: після відвідування всіх залежностей вершини додайте її до результату (post-order).

Для виявлення циклу в напрямленому графі однієї множини «відвідані» недостатньо: у ромбі (A→B→D, A→C→D) ви доходите до D двічі без жодного циклу. Відстежуйте вершини **на поточному шляху** («відвідується») окремо від завершених; зустріч вершини, що «відвідується», означає зворотне ребро, тобто цикл.

## Компоненти зв'язності

У ненапрямленому графі запускайте BFS/DFS із кожної ще не побаченої вершини; кожен запуск відкриває одну компоненту. Система неперетинних множин (union-find) відповідає на «чи з'єднані вони?» поступово, у міру надходження ребер.

## Найкоротші шляхи з вагами

**Алгоритм Дейкстри** знаходить найкоротші шляхи, коли всі ваги **невід'ємні**: щоразу беріть найближчу незавершену вершину з **черги з пріоритетом** (мін-купи) і релаксуйте її ребра (`dist[v] = min(dist[v], dist[u] + w)`). З бінарною купою він працює за O((V + E) log V). Пропускайте «застарілі» записи купи, чия відстань більша за найкращу відому. Запам'ятовуйте попередника кожної вершини, щоб відновити шлях.

Від'ємні ваги ламають припущення Дейкстри, що завершена вершина вже не подешевшає; використовуйте Беллмана-Форда (O(V·E)), який також виявляє від'ємні цикли. A* додає евристику, що спрямовує пошук до цілі (карти, ігри).

## Що перевірити перед співбесідою

- Оберіть між списком і матрицею суміжності й назвіть складності.
- Напишіть BFS і DFS і поясніть, чому BFS дає найкоротші шляхи в незваженому графі.
- Побудуйте порядок збирання алгоритмом Кана й повідомте про цикли.
- Поясніть різницю між «відвідується» і «відвідано» у виявленні циклів.
- Поясніть Дейкстру, чому йому потрібні невід'ємні ваги, і його складність із купою.
