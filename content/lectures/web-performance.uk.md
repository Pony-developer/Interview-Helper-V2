Продуктивність є частиною досвіду користувача. Інтерв'юери очікують, що ви знаєте, що вимірювати, чому сторінки сповільнюються і які виправлення мають значення.

## Core Web Vitals

| Метрика | Що вимірює | Добре |
| --- | --- | --- |
| **LCP**, Largest Contentful Paint | коли з'являється основний вміст | ≤ 2,5 с |
| **INP**, Interaction to Next Paint | наскільки швидко сторінка реагує на дії | ≤ 200 мс |
| **CLS**, Cumulative Layout Shift | наскільки «стрибає» вміст | ≤ 0,1 |

Вимірюйте на даних реальних користувачів (CrUX, бібліотека `web-vitals`), а діагностуйте в Lighthouse і на панелі Performance у DevTools.

## Конвеєр рендерингу

JavaScript → **Style** → **Layout** → **Paint** → **Composite**.

- Зміна `width`, `top` чи шрифтів запускає layout, найдорожчий крок.
- Зміна кольорів запускає paint.
- `transform` і `opacity` може обробити сам композитор, тож анімуйте саме їх.
- Довгі задачі (>50 мс) у головному потоці блокують введення, що погіршує INP. Розбивайте роботу, поступайтеся потоком (`await scheduler.yield()` або `setTimeout`) або винесіть її у Web Worker.

## Швидше завантаження (LCP)

- Відправляйте менше JavaScript: розділяйте код маршрутів і важких віджетів (`import()`), прибирайте невикористаний код і зайві залежності.
- Пріоритезуйте головний елемент: `<link rel="preload">` для його зображення, `fetchpriority="high"`, сучасні формати (AVIF/WebP), адаптивний `srcset`.
- Рендерте HTML на сервері чи статично (SSR/SSG), щоб вміст не чекав на JS.
- Агресивно кешуйте ресурси з відбитками в назвах і використовуйте CDN. Задавайте `font-display: swap` і preconnect до критичних джерел.
- Ліниво завантажуйте зображення й iframe нижче першого екрана (`loading="lazy"`).

## Уникнення зсувів (CLS)

Резервуйте місце: задавайте `width`/`height` (або `aspect-ratio`) зображенням і вбудовуванням, робіть скелетони того самого розміру, що й вміст, і ніколи не вставляйте банери над наявним вмістом.

## Менше роботи

**Debounce** чекає, доки події припиняться (пошукове поле, resize). **Throttle** виконує не частіше за раз на інтервал (позиція прокрутки, рух миші):

```js
function debounce(fn, wait) {
  let timer;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), wait);
  };
}
```

У фреймворках уникайте зайвих ререндерів (мемоізуйте дорогі піддерева, тримайте стан локально) і віртуалізуйте довгі списки, щоб рендерилися лише видимі рядки.

## Пам'ять

Витоки виникають через забуті обробники, таймери, від'єднані вузли DOM, які тримають замикання, і кеші, що постійно ростуть. Шукайте їх за знімками купи на панелі Memory.

## Чек-лист для співбесіди

- Назвіть і поясніть LCP, INP і CLS.
- Поясніть, чому анімації через `transform` дешевші за `top`/`left`.
- Перелічіть конкретні оптимізації завантаження для найбільшого елемента.
- Реалізуйте debounce і throttle та скажіть, коли що використовувати.
