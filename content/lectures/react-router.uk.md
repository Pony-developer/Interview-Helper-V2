React Router зіставляє URL з деревом компонентів, тож браузер може змінювати сторінку без повного перезавантаження. Односторінкові застосунки покладаються на нього для кожного посилання, кнопки «назад» і прямого посилання. Сучасні версії також завантажують дані для кожного маршруту до його рендеру, і це виносить багато логіки отримання даних з компонентів.

## Оголошення маршрутів

```tsx
const router = createBrowserRouter([
  {
    path: "/",
    element: <RootLayout />,
    children: [
      { index: true, element: <Home /> },
      { path: "orders/:orderId", element: <Order /> },
    ],
  },
]);
```

`element` маршруту рендериться, коли шлях збігається. **Вкладені маршрути** рендеряться всередині `<Outlet />` батьківського, тож спільний макет (шапка, бічна панель) лишається змонтованим, поки змінюється дочірній маршрут. `index` позначає типовий дочірній маршрут на точному шляху батька.

## Параметри шляху й пошуку

- **Параметри шляху** (`:orderId`) є частиною шляху URL і читаються через `useParams()`. Використовуйте їх для ідентичності: `/orders/42`.
- **Параметри пошуку** (`?status=open`) описують вигляд даних і читаються через `useSearchParams()`. Використовуйте їх для фільтрів, сортування й пагінації, щоб вигляд можна було поділитися і він пережив перезавантаження.

Самостійний розбір параметрів пошуку схильний до помилок: значення завжди рядки, а відсутні чи некоректні потребують значень за замовчуванням. Перевіряйте їх на межі маршруту.

## Loader і action

У data-роутері маршрут може оголосити **loader**, що отримує його дані перед рендером, і **action**, що обробляє надсилання форм:

```tsx
{
  path: "orders/:orderId",
  loader: ({ params }) => fetchOrder(params.orderId),
  element: <Order />,
}
```

Компонент читає результат через `useLoaderData()`. Навігація чекає на loader, тож сторінка ніколи не рендериться напівпорожньою, а паралельні потреби у даних вкладених маршрутів завантажуються разом. Після виконання action loader-и відповідних маршрутів оновлюються автоматично, тож екрани синхронізуються без ручного повторного запиту. Loader-и також можуть перенаправити або показати сторінку помилки для відсутнього запису.

## Навігація та захищені маршрути

Для внутрішніх посилань використовуйте `<Link to="…">`, щоб браузер не перезавантажувався, а `useNavigate()` — для навігації після події. Захищений маршрут — це макет-маршрут, чий елемент перевіряє сесію і рендерить `<Navigate to="/login" />`, коли її немає, за бажання запам'ятовуючи запитану адресу, щоб повернутися до неї після входу. Перевіряйте доступ і на сервері: прихований маршрут не є захищеним.

## Ледаче завантаження

Маршрути можуть завантажувати код компонентів на вимогу через `lazy`, тож перша сторінка не завантажує весь застосунок. Розбивайте код спершу за межами маршрутів, бо саме між ними користувачі справді переходять.

## Типові помилки

- Використання `<a href>` для внутрішніх посилань: це перезавантажує весь застосунок і губить клієнтський стан.
- Зберігання фільтрів у стані компонента, через що спільний URL або перезавантаження показує інші дані.
- Читання параметрів пошуку без значень за замовчуванням, тож відсутній `page` дає `NaN`.
- Отримання даних у `useEffect` в кожному компоненті там, де loader отримав би їх один раз на навігацію.
- Вважати клієнтський guard маршруту безпекою.

## Що перевірити перед співбесідою

- Поясніть, як вкладені маршрути і `<Outlet />` тримають макет змонтованим під час навігації.
- Вирішіть, коли значення належить до параметра шляху, параметра пошуку або стану компонента.
- Поясніть, як loader дає сторінці рендеритися з її даними, і як action оновлює loader-и.
- Опишіть захищений маршрут і чому перевірки на сервері все одно потрібні.
- Назвіть помилки, через які навігація здається зламаною.
