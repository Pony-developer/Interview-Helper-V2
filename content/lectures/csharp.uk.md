Співбесіда з C# починається із системи типів і об'єктної моделі, бо від них залежить майже кожне наступне питання (продуктивність, LINQ, async). Ця лекція охоплює те, що кандидат рівня Junior чи Middle має пояснити без підказок.

## Значущі та посилальні типи

**Значущий тип** (`int`, `double`, `bool`, `DateTime`, будь-яка `struct` чи `enum`) зберігає дані безпосередньо. Присвоєння копіює все значення. **Посилальний тип** (`class`, `string`, масиви, делегати, `record`) зберігає посилання на об'єкт у керованій купі. Присвоєння копіює посилання, тож обидві змінні бачать той самий об'єкт.

```csharp
var a = new Point(1, 2);   // struct
var b = a; b.X = 10;       // a.X досі 1

var p = new Person("Ann"); // class
var q = p; q.Name = "Bob"; // тепер p.Name — "Bob"
```

«Значущі типи живуть у стеку» — лише половина правди: поле значущого типу в класі живе всередині цього об'єкта в купі.

**Пакування** (boxing) загортає значущий тип в об'єкт у купі (`object o = 42;`); **розпакування** копіює його назад (`int i = (int)o;`). Кожне пакування — це виділення пам'яті, тож пакування в гарячому циклі (неузагальнений `ArrayList`, `string.Format` зі значущими типами в старому коді) коштує пам'яті й часу GC. Дженерики цього уникають.

## class, struct, record

| | `class` | `struct` | `record` / `record struct` |
|---|---|---|---|
| Вид | посилальний | значущий | посилальний / значущий |
| Рівність | за посиланням | за полями (повільна рефлексія, якщо не перевизначено) | за значенням, генерується |
| Успадкування | так | ні | записи — лише від записів |
| Типове застосування | сутності, сервіси | малі незмінні значення | DTO, повідомлення, об'єкти-значення |

Робіть структури малими й незмінними (`readonly struct`), інакше копії вас здивують. Записи додають вирази `with`: `var older = person with { Age = 31 };`.

## Інтерфейси проти абстрактних класів

**Інтерфейс** — це контракт: клас може реалізувати багато інтерфейсів. Починаючи з C# 8 інтерфейс може мати реалізації методів за замовчуванням, але не стан екземпляра. **Абстрактний клас** може мати поля, конструктори й спільну логіку, а клас успадковує лише один. Емпіричне правило: інтерфейс — для здатності (`IComparable`, `IDisposable`), абстрактний базовий клас — для родини, що ділить код.

## virtual, override, new

`virtual` дозволяє похідному класу перевизначити метод через `override`, і виклик диспетчеризується за **фактичним** типом під час виконання. `new` натомість *приховує* член базового класу: виклик визначається **оголошеним** типом змінної під час компіляції. `sealed override` забороняє подальше перевизначення.

```csharp
Base b = new Derived();
b.Virt();   // Derived.Virt (override)
b.Hidden(); // Base.Hidden  (new приховує, поліморфізму немає)
```

## Дженерики та обмеження

Дженерики дають безпеку типів без пакування. Обмеження кажуть, що вміє `T`: `where T : class`, `struct`, `new()`, базовий клас чи інтерфейс (`where T : IComparable<T>`). Варіантність працює лише для інтерфейсів і делегатів: `out T` — коваріантність (`IEnumerable<string>` є `IEnumerable<object>`), `in T` — контраваріантність (`Action<object>` підходить як `Action<string>`).

## Делегати, лямбди та події

**Делегат** — типобезпечне посилання на метод; `Func<>`, `Action<>` і `Predicate<>` покривають більшість потреб. Лямбда, що використовує зовнішню змінну, **захоплює** її (замикання): змінна спільна, а не скопійована. **Подія** — це делегат, який зовнішній код може лише `+=` і `-=`, тож підписники не можуть її викликати чи стерти список. Забута відписка від довгоживучого видавця — класичний витік пам'яті.

## Винятки

Перехоплюйте конкретні винятки й лише там, де можете їх обробити. `throw;` перекидає виняток і **зберігає** стек викликів; `throw ex;` його скидає. `finally` виконується завжди (окрім випадку, коли процес помирає). Фільтри винятків (`catch (HttpRequestException e) when (e.StatusCode == 404)`) ухвалюють рішення без розмотування стека. Не використовуйте винятки для звичайного потоку керування — шаблон `TryParse` існує не просто так.

## Сучасний C#, який варто згадати

- **Nullable-посилальні типи**: `string?` проти `string`, з попередженнями компілятора замість `NullReferenceException` під час виконання.
- **Зіставлення зі зразком**: вирази `switch`, шаблони властивостей (`order is { Total: > 100, Status: Status.Paid }`), реляційні шаблони й шаблони списків.
- Оголошення `using var`, простори імен на рівні файлу, первинні конструктори, вирази колекцій (`int[] xs = [1, 2, 3];`).

## Чекліст для співбесіди

- Поясніть значущі й посилальні типи на прикладі присвоєння та покажіть, де відбувається пакування.
- Оберіть між class, struct і record та обґрунтуйте вибір.
- Покажіть різницю між `override` і `new` через змінну базового типу.
- Знайте різницю між `throw;` і `throw ex;` та навіщо фільтр винятків.
- Поясніть помилку із захопленням змінної в замиканні та витік через підписку на подію.
