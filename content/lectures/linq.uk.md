Питання про LINQ виглядають простими, але ховають пастки. Інтерв'юер хоче знати, коли запит насправді виконується, скільки це коштує і де він виконується: у пам'яті чи в базі даних.

## Два синтаксиси, один запит

```csharp
var adults = from p in people where p.Age >= 18 orderby p.Name select p.Name;
var same   = people.Where(p => p.Age >= 18).OrderBy(p => p.Name).Select(p => p.Name);
```

Синтаксис запитів компілюється у виклики методів. Він зручніший для з'єднань і `let`; у синтаксисі методів є всі оператори (`Take`, `Distinct`, `Chunk`…).

## Відкладене виконання

Більшість операторів (`Where`, `Select`, `OrderBy`, `GroupBy`, `Take`…) нічого не роблять у момент виклику. Вони будують конвеєр ітераторів, і нічого не відбувається, доки щось його не **перебере**: `foreach`, `ToList()`, `ToArray()`, `Count()`, `First()`, `Sum()`.

```csharp
var list = new List<int> { 1, 2, 3 };
var big = list.Where(x => x > 1); // ще нічого не виконано
list.Add(4);
Console.WriteLine(big.Count());   // 3: запит бачить новий елемент
```

Наслідки:

- **Повторне перебирання**: якщо перебрати той самий `IEnumerable` двічі, весь конвеєр виконається двічі (а для запиту до бази — підуть два запити). Матеріалізуйте через `ToList()`, якщо результат знадобиться ще раз.
- Виняток усередині лямбди з'являється там, де запит перебирають, а не там, де його написали.
- Лямбда, що захопила змінну, бачить її значення на момент перебирання.

`Where`/`Select` **передають** елементи потоково, по одному; `OrderBy`, `GroupBy` і `Reverse` спершу мають **буферизувати** все джерело.

## Оператори, які треба знати напам'ять

- `Select` перетворює один до одного; `SelectMany` розгортає вкладені послідовності (замовлення → рядки замовлень).
- `GroupBy` повертає групи з `Key`; `ToLookup` робить те саме негайно.
- `Join` — внутрішнє з'єднання; ліве з'єднання — це `GroupJoin` + `SelectMany(... DefaultIfEmpty())` або `LeftJoin` у .NET 10.
- `First` кидає виняток на порожній послідовності, `FirstOrDefault` повертає `default`; `Single` додатково кидає виняток, якщо збігів більше одного.
- `Any()` зупиняється на першому елементі; `Count() > 0` може пройти все. Використовуйте `Any`.
- `Distinct`, `Union`, `Intersect`, `Except` спираються на `Equals`/`GetHashCode`; варіанти `...By` приймають селектор ключа.
- `Aggregate` — загальна згортка; `Sum`, `Min`, `Max`, `Average` — її типові випадки.

## IEnumerable проти IQueryable

Оператори `IEnumerable<T>` приймають **делегати** (`Func<T, bool>`) і виконуються у вашому процесі. Оператори `IQueryable<T>` приймають **дерева виразів** (`Expression<Func<T, bool>>`) — структури даних, що описують код, які провайдер на кшталт Entity Framework перекладає в SQL.

```csharp
db.Orders.Where(o => o.Total > 100).ToList();               // WHERE у SQL
db.Orders.AsEnumerable().Where(o => o.Total > 100).ToList(); // завантажує всі замовлення й фільтрує в пам'яті
```

Тож саме тип змінної визначає, де виконається фільтр. Методи, які провайдер не може перекласти, в EF Core кидають виняток під час виконання (а не мовчки завантажують таблицю, як старий EF). Тримайте `IQueryable`, доки запит не готовий, і матеріалізуйте один раз. Стежте за **N+1**: звернення до навігаційної властивості в циклі породжує окремий запит на кожен рядок; використовуйте `Include` або проєкцію через `Select`.

## Дерева виразів

`Expression<Func<...>>` можна дослідити, поєднати й скомпілювати (`.Compile()`). Так будують динамічні фільтри (поєднуючи предикати через `Expression.AndAlso`), і так ORM, проєкції AutoMapper і бібліотеки валідації читають ваші лямбди.

## Власний оператор

LINQ to Objects — це просто методи розширення над `IEnumerable<T>` з `yield return`:

```csharp
public static IEnumerable<T> WhereNot<T>(this IEnumerable<T> source, Func<T, bool> predicate)
{
    foreach (var item in source)
        if (!predicate(item)) yield return item;
}
```

Перевірки аргументів у методі-ітераторі виконуються лише під час перебирання; щоб кидати виняток одразу, розділіть метод на два (обгортка з перевірками й локальна функція-ітератор).

## Чекліст для співбесіди

- Поясніть відкладене виконання на прикладі, де джерело змінюється, і ціну повторного перебирання.
- Знайте, які оператори потокові, а які буферизують.
- Обирайте `Any` замість `Count` і поясніть `First` проти `Single` проти `...OrDefault`.
- Поясніть `IEnumerable` проти `IQueryable` і проблему N+1.
- Напишіть `Select` чи `Where` самостійно через `yield return`.
