`class` часто називають «синтаксичним цукром над прототипами». Здебільшого це так: методи й далі живуть у `Class.prototype`, а екземпляри делегують йому. Але класи додають і те, чого звичайні функції-конструктори не вміють: поля із семантикою визначення, справді приватні члени, `super` із фіксованим домашнім об'єктом і похідні конструктори, чий `this` не існує, доки не поверне `super()`.

## Що робить оголошення класу

```js
class Account {
  static #count = 0;                 // статичне приватне поле
  balance = 0;                       // публічне поле екземпляра
  #history = [];                     // приватне поле екземпляра

  constructor(owner) {
    this.owner = owner;
    Account.#count++;
  }
  deposit(amount) {                  // в Account.prototype, неперелічуваний
    this.#history.push(amount);
    this.balance += amount;
    return this;
  }
  get history() { return [...this.#history]; }
  static get count() { return Account.#count; }
}
```

- Тіло виконується в **строгому режимі**.
- Оголошення класів спливають, але лишаються в **тимчасовій мертвій зоні**, тож використати клас до його оголошення не вийде.
- Виклик класу без `new` кидає `TypeError`.
- Методи **неперелічувані**, тож `for…in` по екземпляру їх не показує.
- `typeof Account` дає `"function"`: клас є функцією-конструктором із додатковими правилами.

## Поля й порядок ініціалізації

Поля екземпляра створюються на **кожному екземплярі** із семантикою *визначення*, як `Object.defineProperty`, а не присвоєння. Тож поле не викликає сетер, успадкований від батьківського класу, а затінює його.

Порядок створення для `class B extends A`:

1. `new B()` виконує конструктор B до `super(...)`. До того `this` перебуває в TDZ, тож звернення до нього кидає `ReferenceError`.
2. `super()` виконує конструктор A: спершу ініціалізуються поля A, потім тіло конструктора A.
3. Після повернення з `super()` ініціалізуються **поля B**, а потім виконується решта конструктора B.

Тож якщо конструктор A викликає метод, який B перевизначає, цей метод бачить поля B як `undefined`: класична помилка. Ініціалізатор поля може використовувати `this` і поля, оголошені вище.

**Поля-стрілочні функції** (`handleClick = () => {…}`) створюються для кожного екземпляра з лексично прив'язаним `this`, що зручно для колбеків. Але вони не в прототипі, тож підкласи не можуть викликати їх через `super.handleClick()`, тести не можуть шпигувати за прототипом, а кожен екземпляр має власну копію.

## Приватні члени

Поля, методи й аксесори `#name` є **справді приватними**: їх можна використовувати лише в тілі класу, що їх оголошує, але не в підкласах, `Object.keys`, `JSON.stringify`, `Reflect.ownKeys` чи `obj["#name"]`. Читання `#x` з об'єкта, що його не має, кидає `TypeError`, а `#x in obj` є безпечною **перевіркою бренду**:

```js
class Point {
  #x;
  static isPoint(value) { return #x in value; }
}
```

Приватні імена шукаються на **самому об'єкті**, а не через ланцюжок прототипів. Тому `Proxy` навколо екземпляра ламає методи, що використовують `#поля`: усередині методу `this` є проксі, який не має приватного слоту. Ключове слово `private` у TypeScript, натомість, є лише перевіркою під час компіляції.

## Статичні члени й статичні блоки

Статичні поля й методи живуть на самому класі. Усередині статичного методу `this` є класом, на якому його викликали, тож підкласи успадковують статичні члени, бо `B.__proto__ === A`. Блок `static { … }` виконується один раз під час визначення класу й може ініціалізувати складні статичні члени чи поділитися приватним доступом з кодом, визначеним поруч.

## extends і super

- `extends` приймає будь-який вираз, що обчислюється в конструктор (чи `null`), і саме так працюють міксини.
- `super.method()` викликає метод прототипу батька з поточним `this`. Він знаходиться через фіксований **домашній об'єкт** методу, тож копіювання методу в інший об'єкт не змінює значення `super`.
- Наслідування вбудованих типів працює з класами (на відміну від старих шаблонів `Parent.call(this)`): екземпляри `class Stack extends Array` мають «магічний» `length`, а `class NotFound extends Error` отримує правильний стек. Задайте `this.name` (чи поле `name`), щоб журнали показували назву підкласу.
- Методи на кшталт `map` і `filter` у підкласі `Array` повертають екземпляри підкласу через `Symbol.species`.

## Шаблони

- **Міксини**: `const Timestamped = (Base) => class extends Base { createdAt = Date.now(); };`, а потім `class User extends Timestamped(Model) {}`. Вони дають повторне використання, схоже на множинне наслідування, без глибокої ієрархії.
- **Абстрактні класи**: `if (new.target === Shape) throw new TypeError("Shape is abstract");` у базовому конструкторі.
- **Фабрики** (`static from(json)`) і приватні конструктори через приватний для модуля токен.
- Для поведінки, що змінюється незалежно, віддавайте перевагу **композиції**; тримайте ієрархії неглибокими.

## Що перевірити перед співбесідою

- Поясніть, чим класи відрізняються від функцій-конструкторів: TDZ, строгий режим, обов'язковий `new`, неперелічувані методи, поля, `#private`, `super`.
- Пройдіть порядок створення й помилку «перевизначений метод викликано з базового конструктора».
- Поясніть семантику визначення проти присвоєння для полів і компроміси полів-стрілочних функцій.
- Використайте `#x in obj` і поясніть, чому Proxy й `#private` не поєднуються.
- Напишіть міксин і абстрактний базовий клас.
