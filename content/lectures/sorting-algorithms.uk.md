У продакшн-коді сортування рідко пишуть вручну, але на співбесідах воно перевіряє розуміння підходу «розділяй і володарюй», складності та стабільності.

## Загальна картина

| Алгоритм | Середній | Найгірший | Додаткова пам'ять | Стабільний |
| --- | --- | --- | --- | --- |
| Вставками | O(n²) | O(n²) | O(1) | так (швидкий на майже відсортованих даних) |
| Злиттям | O(n log n) | O(n log n) | O(n) | **так** |
| Швидке (quicksort) | O(n log n) | O(n²) | O(log n) стеку | ні |
| Пірамідальне (heapsort) | O(n log n) | O(n log n) | O(1) | ні |
| Підрахунком / розрядне | O(n + k) | O(n + k) | O(n + k) | так |

Сортування порівнянням не може бути кращим за **O(n log n)** у найгіршому випадку. Сортування підрахунком і розрядне не використовують порівнянь, тож для малого діапазону цілих чисел можуть бути лінійними.

## Сортування злиттям

Розділити масив навпіл, рекурсивно відсортувати обидві половини, потім злити дві відсортовані частини:

```ts
function mergeSort<T>(a: T[], cmp: (x: T, y: T) => number): T[] {
  if (a.length <= 1) return a.slice();
  const mid = a.length >> 1;
  const left = mergeSort(a.slice(0, mid), cmp);
  const right = mergeSort(a.slice(mid), cmp);
  const out: T[] = [];
  let i = 0, j = 0;
  while (i < left.length && j < right.length) {
    out.push(cmp(right[j], left[i]) < 0 ? right[j++] : left[i++]); // при рівності беремо лівий → стабільно
  }
  return out.concat(left.slice(i), right.slice(j));
}
```

Воно передбачуване (O(n log n)), стабільне й чудово підходить для зв'язних списків і зовнішнього сортування. Ціна: O(n) додаткової пам'яті.

## Швидке сортування

Обрати опорний елемент, розбити елементи на «менші» й «більші», потім рекурсивно обробити обидві частини. Швидке на практиці й сортує на місці. Невдалий опорний елемент на вже відсортованих даних дає O(n²); випадковий опорний елемент або медіана трьох цього уникають.

## Стабільність

**Стабільне** сортування зберігає рівні елементи в початковому порядку. Це важливо, коли сортують за кількома ключами: спершу за другорядним ключем, потім стабільно за основним.

## `sort` у JavaScript

- Без компаратора порівнює **рядки**: `[10, 9, 1].sort()` дає `[1, 10, 9]`.
- Компаратор повертає від'ємне число, нуль або додатне число. `(a, b) => a - b` сортує за зростанням.
- Починаючи з ES2019 сортування гарантовано **стабільне**. V8 використовує TimSort, гібрид злиття та вставок.
- Сортує **на місці**. Використовуйте `toSorted` або спершу копіюйте масив, якщо це спільний стан.

```js
users.toSorted((a, b) => a.age - b.age || a.name.localeCompare(b.name));
```

## Чек-лист для співбесіди

- Поясніть, чому сортування злиттям стабільне, а швидке ні.
- Знайте нижню межу O(n log n) для сортувань порівнянням і коли сортування підрахунком її обходить.
- У JavaScript завжди передавайте числовий компаратор.
- Опишіть, як сортувати за кількома ключами.
