`for…of`, spread (`[...x]`), деструктуризація, `Array.from`, `Promise.all`, `new Map(entries)`: усе це працює з будь-яким об'єктом, що дотримується **протоколу ітерації**. Генератори є найпростішим способом писати такі об'єкти, а ще це функції, що можуть **ставати на паузу** й **продовжуватися**, і саме з цього в JavaScript виріс async/await.

## Протокол ітерації

- **Ітерований об'єкт** (iterable) має метод `[Symbol.iterator]()`, що повертає ітератор.
- **Ітератор** має `next()`, що повертає `{ value, done }`. Необов'язково він має `return()` (викликається, коли споживач зупиняється раніше) і `throw()`.

```js
const countdown = {
  from: 3,
  [Symbol.iterator]() {
    let n = this.from;
    return { next: () => (n > 0 ? { value: n--, done: false } : { value: undefined, done: true }) };
  },
};
[...countdown]; // [3, 2, 1]
```

Масиви, рядки (за кодовими точками), `Map`, `Set`, `arguments` і NodeList ітеровані; звичайні об'єкти ні (використовуйте `Object.entries`). Кожен виклик `[Symbol.iterator]()` має давати новий ітератор, тож ітерований об'єкт можна перебирати багато разів, а **ітератор** одноразовий.

## Генератори

```js
function* idGenerator(prefix) {
  let i = 1;
  while (true) yield `${prefix}-${i++}`;
}
const ids = idGenerator("user");
ids.next().value; // "user-1"
```

Виклик функції-генератора **нічого не виконує**: він повертає об'єкт-генератор (і ітератор, і ітерований об'єкт). Кожен `next()` виконує тіло до наступного `yield`, який ставить його на паузу й видає значення; локальний стан функції зберігається між викликами. Значення з `return` з'являється як останнє `{ value, done: true }`, яке `for…of` і spread ігнорують.

Оскільки значення створюються на вимогу, генератори описують **ліниві** й навіть нескінченні послідовності; обчислюється лише те, що бере споживач. Конвеєри з невеликих генераторів (`take(filter(map(source)))`) обробляють по одному елементу, не будуючи проміжних масивів.

## Двобічне спілкування

`yield` є виразом: аргумент **наступного** виклику `next(value)` стає його результатом. Перший `next()` запускає генератор, і його аргумент ігнорується.

```js
function* conversation() {
  const name = yield "What's your name?";
  const lang = yield `Hi ${name}! Favourite language?`;
  return `${name} likes ${lang}`;
}
```

`it.throw(error)` кидає помилку **в місці призупиненого `yield`**, тож `try/catch` усередині генератора може її обробити; `it.return(value)` завершує генератор достроково.

## Делегування через `yield*`

`yield* other` видає всі значення іншого ітерованого об'єкта чи генератора, перенаправляє йому `next`/`throw`/`return` і обчислюється в значення, яке повернув делегований генератор. Корисно для рекурсії (обхід дерев) і компонування генераторів.

## Дострокове завершення й очищення

Коли `for…of` зупиняється раніше (`break`, `return`, виняток), він викликає `return()` ітератора. Для генераторів це виконує всі блоки `finally`, що очікують, і це добре місце звільняти ресурси (закрити файл, скасувати підписку). Ітератори масивів не мають `return()`, тож частково використаний ітератор масиву можна продовжити пізніше, а генератор, закритий так, завершено назавжди.

## Асинхронна ітерація

**Асинхронний генератор** (`async function*`) може і `await`, і `yield`; споживачі використовують `for await…of`. Це підходить для даних, що надходять із часом: API з пагінацією, потоки (`ReadableStream` у сучасних середовищах асинхронно ітерований), повідомлення WebSocket.

```js
async function* fetchAll(url) {
  while (url) {
    const page = await (await fetch(url)).json();
    yield* page.items;
    url = page.next;
  }
}
for await (const item of fetchAll("/api/items")) render(item);
```

## Генератори як корутини

Виконавець, що чекає на кожен виданий проміс і надсилає результат назад через `next(result)` (або помилку через `throw(error)`), перетворює генератор на асинхронний код, що виглядає послідовним. Саме так працюють бібліотеки на кшталт `co` і Redux-Saga, і саме це згодом вбудували в мову як `async`/`await`. Redux-Saga досі використовує генератори, бо видані *описи* ефектів можна тестувати, не виконуючи їх.

## Що перевірити перед співбесідою

- Поясніть протоколи iterable та iterator і зробіть власний об'єкт ітерованим.
- Поясніть, що виклик генератора нічого не виконує, і як `yield`/`next` ставлять на паузу й продовжують.
- Використовуйте `next(value)`, `throw()`, `return()` і `yield*`.
- Поясніть лінивість і чому `take` не повинен брати зайве значення.
- Використовуйте асинхронні генератори з `for await…of` і пов'яжіть генератори з async/await.
