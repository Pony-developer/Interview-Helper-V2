Регулярний вираз описує **шаблон тексту**. У JavaScript це об'єкт `RegExp`, записаний літералом (`/\d+/g`) або побудований з рядка (`new RegExp("\\d+", "g")`). Регулярні вирази чудово підходять для валідації, пошуку й нескладного розбору. Для вкладених структур на кшталт HTML чи JSON використовуйте справжній парсер.

## Будівельні блоки

| Синтаксис | Значення |
| --- | --- |
| `.` | будь-який символ, крім переносу рядка (будь-який узагалі з прапорцем `s`) |
| `\d` `\w` `\s` | цифра, символ слова `[A-Za-z0-9_]`, пробільний символ (`\D` `\W` `\S` заперечують) |
| `[abc]` `[^abc]` `[a-z]` | клас символів, заперечений клас, діапазон |
| `^` `$` | початок і кінець вхідних даних (кожного рядка з прапорцем `m`) |
| `\b` | межа слова |
| `*` `+` `?` `{2,5}` | 0+, 1+, 0–1, від 2 до 5 повторень |
| `(…)` `(?<year>…)` `(?:…)` | група із захопленням, іменована група, група без захоплення |
| `a\|b` | альтернатива |
| `\1` `\k<year>` | зворотне посилання на групу |
| `(?=…)` `(?!…)` `(?<=…)` `(?<!…)` | перевірка вперед, заперечна вперед, перевірка назад, заперечна назад |

Спеціальні символи екрануйте зворотною скісною рискою: `\.` `\(` `\?`. У рядку, що передається в `new RegExp`, саму риску теж треба екранувати (`"\\."`).

## Прапорці

`g` (глобальний: знайти всі збіги), `i` (без урахування регістру), `m` (багаторядкові якорі), `s` (dotAll), `u` (Unicode: кодові точки, екранування властивостей `\p{…}`), `v` (покращений `u` з операціями над множинами), `y` (sticky: збіг рівно з позиції `lastIndex`), `d` (індекси збігів).

## Жадібний і лінивий збіг

Квантифікатори **жадібні**: беруть якомога більше, а потім відступають. Доданий `?` робить їх **лінивими**: якомога менше.

```js
"<b>a</b><b>c</b>".match(/<b>.*<\/b>/)[0];  // "<b>a</b><b>c</b>"
"<b>a</b><b>c</b>".match(/<b>.*?<\/b>/)[0]; // "<b>a</b>"
```

Заперечений клас часто зрозуміліший і швидший за лінивість: `/<b>[^<]*<\/b>/`.

## Методи

```js
/^\d{4}$/.test("2025");                      // true
"2025-03-15".match(/(\d+)-(\d+)-(\d+)/);    // ["2025-03-15", "2025", "03", "15"], index, groups
"a1b22c333".match(/\d+/g);                   // ["1", "22", "333"] (з g без груп)
[..."a1b22".matchAll(/(?<n>\d+)/g)].map((m) => m.groups.n); // ["1", "22"]
"2025-03-15".replace(/(?<y>\d+)-(?<m>\d+)-(?<d>\d+)/, "$<d>.$<m>.$<y>"); // "15.03.2025"
"Hello World".replace(/o/g, (match, offset) => match.toUpperCase());     // "HellO WOrld"
"a, b,c".split(/\s*,\s*/);                    // ["a", "b", "c"]
```

`replaceAll` вимагає прапорця `g`, якщо передано регулярний вираз. `str.search(re)` повертає індекс першого збігу або `-1`.

## Пастка `lastIndex`

Регулярний вираз із `g` чи `y` **має стан**: `test` і `exec` починають пошук із `re.lastIndex` і оновлюють його після збігу. Повторне використання такого виразу для різних рядків дає змінні результати:

```js
const re = /a/g;
re.test("a"); // true  (lastIndex тепер 1)
re.test("a"); // false (пошук почався з 1; lastIndex скинуто до 0)
```

Не використовуйте `g` з `test` або створюйте вираз усередині функції. `match`, `matchAll`, `replace` і `split` дбають про `lastIndex` самі.

## Регулярні вирази з даних користувача

`new RegExp(userInput)` сприймає `.`, `*`, `+`, `(` тощо як синтаксис: `"c++"` кидає «Nothing to repeat», а `"a.b"` збігається й з `"axb"`. Спершу екрануйте дані:

```js
const escapeRegExp = (s) => s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
new RegExp(escapeRegExp(query), "gi");
```

## Unicode

Без `u` регулярний вираз працює з кодовими одиницями UTF-16: `/^.$/.test("😀")` дає `false`, бо емодзі займає дві одиниці. З `u` крапка відповідає повній кодовій точці, і стають доступні екранування властивостей на кшталт `\p{L}` (будь-яка літера, зокрема кирилиця) і `\p{Emoji}`: `/^\p{L}+$/u.test("Київ")` дає `true`.

## Продуктивність: катастрофічний бектрекінг

Вкладені квантифікатори над тими самими символами, як-от `/^(a+)+$/`, можуть працювати експоненційний час на даних, що майже збігаються (`"aaaa…a!"`), заморожуючи головний потік. З даними, які контролює користувач, це стає вразливістю до відмови в обслуговуванні (**ReDoS**). Уникайте вкладених і перекривних квантифікаторів, прив'язуйте шаблони якорями, віддавайте перевагу конкретним класам замість `.*` і обмежуйте довжину вхідних даних.

## Що перевірити перед співбесідою

- Читайте й пишіть типові шаблони (цифри, слова, якорі, групи, альтернативи).
- Поясніть жадібні й ліниві квантифікатори.
- Використовуйте іменовані групи, шаблони заміни чи функції заміни.
- Поясніть пастку `lastIndex` з `g` і `test`.
- Екрануйте дані користувача в динамічних виразах і знайте, коли важливий прапорець `u`.
- Розпізнавайте шаблони з ризиком катастрофічного бектрекінгу.
