TypeScript перевіряє ваш JavaScript до запуску. Інтерв'юери хочуть побачити, що ви вмієте точно моделювати дані без `any`.

## Структурна типізація

Типи сумісні, коли збігається їхня **форма**, незалежно від назв типів:

```ts
type Point = { x: number; y: number };
const p = { x: 1, y: 2, label: "A" };
const q: Point = p; // OK: у p є щонайменше x та y
```

Для об'єктних літералів, присвоєних напряму, діє *перевірка зайвих властивостей*: `const r: Point = { x: 1, y: 2, z: 3 }` дає помилку.

## `unknown` проти `any`

- `any` вимикає перевірку й непомітно поширюється кодом.
- `unknown` приймає будь-що, але змушує **звузити** тип перед використанням. Обирайте `unknown` для зовнішніх даних, як-от JSON і помилки в `catch`.

## Об'єднання та звуження

```ts
type Shape =
  | { kind: "circle"; r: number }
  | { kind: "rect"; w: number; h: number };

function area(s: Shape): number {
  switch (s.kind) {             // дискримінант
    case "circle": return Math.PI * s.r ** 2;
    case "rect":   return s.w * s.h;
    default: {
      const never: never = s;   // помилка компіляції, якщо випадок пропущено
      return never;
    }
  }
}
```

Звуження працює з `typeof`, `instanceof`, `in`, перевірками рівності, істинності та **type guards**:

```ts
function isString(v: unknown): v is string {
  return typeof v === "string";
}
```

## Дженерики

Дженерики дозволяють одній функції працювати з різними типами, зберігаючи зв'язок між входом і виходом:

```ts
function first<T>(items: T[]): T | undefined {
  return items[0];
}

function pick<T, K extends keyof T>(obj: T, keys: K[]): Pick<T, K> {
  const out = {} as Pick<T, K>;
  for (const k of keys) out[k] = obj[k];
  return out;
}
```

`K extends keyof T` є **обмеженням**: `K` має бути назвою властивості `T`.

## Утилітні типи, які варто знати

| Тип | Значення |
| --- | --- |
| `Partial<T>` / `Required<T>` | усі властивості необов'язкові / обов'язкові |
| `Readonly<T>` | властивості не можна перевизначати |
| `Pick<T, K>` / `Omit<T, K>` | залишити / прибрати властивості |
| `Record<K, V>` | об'єкт із ключами `K` і значеннями `V` |
| `ReturnType<F>` / `Parameters<F>` | витягнути з типу функції |
| `Awaited<T>` | розгорнути тип Promise |
| `NonNullable<T>` | прибрати `null` і `undefined` |

## `type` проти `interface`

Обидва описують форму об'єкта. `interface` можна **зливати** й розширювати через `extends`. `type` вміє об'єднання, кортежі, відображені (mapped) та умовні типи. Оберіть одну домовленість для кодової бази.

## Чек-лист для співбесіди

- Моделюйте стани дискримінованими об'єднаннями, а не необов'язковими прапорцями.
- Для неперевірених даних використовуйте `unknown` і звуження.
- Поясніть, що гарантує обмеження дженерика.
- Пам'ятайте, що типи стираються під час виконання: валідуйте зовнішній вхід кодом (наприклад, zod).
