Багато помилок походить з питання, яке ніхто не поставив: **чи тримає ще хтось посилання на цей об'єкт?** Відсортований масив, що заодно переставляє оригінал, «копія» налаштувань, вкладені значення якої змінюються разом, компонент React, що не перерендерюється після зміни: усе це наслідки того, як JavaScript працює зі значеннями й посиланнями.

## Примітиви й посилання

Примітиви (`string`, `number`, `bigint`, `boolean`, `undefined`, `null`, `symbol`) є **незмінними значеннями**: методи рядків повертають нові рядки, а змінити `5` не можна. Об'єкти (зокрема масиви, функції, Map і дати) є значеннями, які змінні тримають **за посиланням**:

```js
const a = { n: 1 };
const b = a;      // копіює посилання: один об'єкт, два імені
b.n = 2;          // a.n теж дорівнює 2
const c = { n: 2 };
a === c;          // false: рівність порівнює ідентичність, а не вміст
```

JavaScript **передає за значенням**, але для об'єктів передане значення є посиланням. Функція може **змінити** об'єкт, який ви їй дали (`list.push(x)` видно тому, хто викликав), але не може **перев'язати** вашу змінну (`list = []` усередині функції змінює лише її локальний параметр). `const` забороняє перев'язування, а не зміну.

## Методи, що змінюють дані

| Змінює на місці | Альтернатива без змін |
| --- | --- |
| `sort`, `reverse`, `splice` | `toSorted`, `toReversed`, `toSpliced` (ES2023) або спершу копія: `[...arr].sort()` |
| `arr[i] = x` | `arr.with(i, x)` |
| `push`, `pop`, `shift`, `unshift`, `fill`, `copyWithin` | spread, `slice`, `concat` |
| `Object.assign(target, …)` | `{ ...a, ...b }` чи `Object.assign({}, …)` |
| сетери `Date` | створити новий `Date` |

## Поверхневі й глибокі копії

- **Поверхневі копії** (`{ ...obj }`, `[...arr]`, `Object.assign({}, obj)`, `Array.from`, `slice`) дублюють лише верхній рівень; вкладені об'єкти спільні.
- **`structuredClone(value)`** робить **глибоку** копію й обробляє цикли, `Map`, `Set`, `Date`, `RegExp`, типізовані масиви, `Blob` і помилки. Вона **кидає помилку** на функціях і вузлах DOM та **відкидає** прототипи (екземпляри класів повертаються звичайними об'єктами), гетери (копіюються як значення) і неперелічувані властивості.
- **`JSON.parse(JSON.stringify(value))`** втрачає більше: `undefined` і функції зникають, `Date` стає рядком, `Map`/`Set` стають `{}`, `NaN` і `Infinity` стають `null`, а цикли кидають помилку.
- Бібліотеки (`cloneDeep` з lodash) чи власне рекурсивне клонування з `WeakMap` для циклів дають контроль над екземплярами класів.

Глибоке копіювання всього марнотратне; зазвичай треба копіювати лише **шлях, який ви змінюєте**.

## Незмінні оновлення й структурне спільне використання

Щоб незмінно «змінити» вкладені дані, скопіюйте кожен об'єкт уздовж шляху, а все інше використайте повторно:

```js
const next = {
  ...state,
  user: { ...state.user, address: { ...state.user.address, city: "Lviv" } },
};
next.settings === state.settings; // true: незмінені гілки спільні
```

Це **структурне спільне використання** (structural sharing): оновлення коштують O(глибина), а не O(розмір), а незмінені частини зберігають свою ідентичність. Тому фреймворки можуть використовувати дешеву **рівність посилань** для виявлення змін: оновлення стану й `memo` у React, селектори Redux, залежності `useEffect`, `OnPush` в Angular. Зміна на місці їх ламає: посилання лишається тим самим, тож нічого не перерендерюється (чи мемоїзоване значення застаріває).

**Immer** дає писати код зі змінами над чернеткою (`produce(state, (draft) => { draft.user.address.city = "Lviv"; })`) і створює незмінний результат зі структурним спільним використанням. Redux Toolkit використовує його під капотом.

## Заморожування

`Object.freeze` робить власні властивості об'єкта доступними лише для читання й забороняє додавання, але він **поверхневий**; заморожуйте рекурсивно для констант чи в режимі розробки, щоб ловити випадкові зміни. У строгому коді записи в заморожені об'єкти кидають помилку, і це перетворює приховані зміни на видимі помилки. Заморожування має невелику ціну, а `readonly` і `as const` у TypeScript дають захист під час компіляції без витрат під час виконання.

## Рівність

- `===` і `Object.is` порівнюють **ідентичність** об'єктів.
- Глибока рівність (`isEqual` з lodash, `assert.deepStrictEqual` у Node, `toEqual` у тестових фреймворках) порівнює вміст; вона корисна в тестах, але дорога в гарячих шляхах.
- З незмінними даними глибока рівність потрібна рідко: якщо посилання не змінилося, то й вміст теж.

## Що перевірити перед співбесідою

- Поясніть примітиви проти посилань і «передавання посилання за значенням» на прикладі функції.
- Перелічіть методи масивів, що змінюють дані, і їхні альтернативи з ES2023 без змін.
- Порівняйте spread, `structuredClone` і перетворення через JSON, зокрема що кожен втрачає.
- Напишіть незмінне вкладене оновлення й поясніть структурне спільне використання.
- Поясніть, чому фреймворки покладаються на рівність посилань і що ламає зміна на місці.
