JavaScript автоматично перетворює значення між типами («неявне приведення», implicit coercion) щоразу, коли оператору чи API потрібен певний тип. Правила повністю описані в специфікації, тож «дивні» результати стають передбачуваними, щойно ви знаєте кілька перетворень, що за ними стоять.

## Типи

Є сім примітивних типів: `string`, `number`, `bigint`, `boolean`, `undefined`, `symbol` і `null`. Усе інше (масиви, функції, дати, звичайні об'єкти) є **об'єктами**. `typeof` здебільшого їх розрізняє, з двома особливостями: `typeof null === "object"` (історична помилка) і `typeof function () {} === "function"`. Для масивів використовуйте `Array.isArray`, а для null перевірку `value === null`.

## Три перетворення

**ToBoolean.** Рівно вісім значень є **хибними** (falsy): `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined` і `NaN`. Усе інше істинне, зокрема `"0"`, `"false"`, `[]` і `{}`.

**ToNumber.**

| Значення | Число |
| --- | --- |
| `""`, `"  "` | `0` |
| `" 42 "` | `42` (пробіли обрізаються) |
| `"42px"`, `"abc"` | `NaN` |
| `"0x1F"`, `"1e3"` | `31`, `1000` |
| `true` / `false` | `1` / `0` |
| `null` | `0` |
| `undefined` | `NaN` |
| `[]`, `[7]`, `[1, 2]` | `0`, `7`, `NaN` (через рядки `""`, `"7"`, `"1,2"`) |

`parseInt` і `parseFloat` працюють інакше: вони читають числовий префікс і зупиняються (`parseInt("42px") === 42`). Завжди передавайте основу числення в `parseInt`.

**ToString.** `null` → `"null"`, `[1, [2, 3]]` → `"1,2,3"`, `{}` → `"[object Object]"`, `-0` → `"0"`. Символи кидають помилку під час неявного перетворення (`"" + Symbol()`), а `String(Symbol("x"))` працює.

## Об'єкти → примітиви (ToPrimitive)

Коли об'єкт зустрічається з оператором, JavaScript просить у нього примітив із **підказкою** (hint):

1. Якщо є `[Symbol.toPrimitive](hint)`, викликається він (`hint` дорівнює `"number"`, `"string"` або `"default"`).
2. Інакше для підказки `"string"` пробуються `toString()`, потім `valueOf()`; для `"number"` і `"default"` спершу `valueOf()`, потім `toString()`. Перемагає перший, що повернув примітив.

Звичайні об'єкти й масиви повертають себе з `valueOf`, тож зрештою використовують `toString`. Шаблонні рядки й `String(x)` використовують підказку `"string"`; `+x`, `*`, `-` і `<` використовують `"number"`; бінарний `+` і `==` використовують `"default"`. Дати сприймають `"default"` як `"string"`.

## Оператор `+`

`a + b` спершу перетворює обидва операнди на примітиви. Якщо **хоч один** є рядком, відбувається конкатенація; інакше числа додаються. Усі інші арифметичні оператори завжди перетворюють на числа.

```js
"5" + 3    // "53"
"5" - 3    // 2
[1, 2] + [3] // "1,23"
1 + null   // 1
1 + undefined // NaN
```

Змішування `bigint` і `number` в арифметиці кидає `TypeError`; перетворюйте явно.

## Рівність

- `===` (строга): без перетворень. Різні типи ніколи не рівні. `NaN !== NaN`, а `0 === -0`.
- `Object.is`: як `===`, але `Object.is(NaN, NaN)` дорівнює `true`, а `Object.is(0, -0)` дорівнює `false` (так React порівнює стан).
- `==` (нестрога): однакові типи порівнюються строго. `null == undefined` дає `true`, і ні те, ні інше не дорівнює нічому іншому (тож `null == 0` дає `false`). Інакше булеві значення стають числами, рядок і число порівнюються як числа, а об'єкти перетворюються на примітиви. Так `[] == false` і `"0" == false` дають `true`.

Єдине загальноприйняте використання `==` — це `value == null`, що перевіряє і `null`, і `undefined`.

## Порівняння

`<`, `>`, `<=`, `>=` порівнюють **рядки лексикографічно** за кодовими одиницями UTF-16, коли обидва боки рядки (`"10" < "9"`, `"Z" < "a"`), і числово в інших випадках (`10 > "9"`). Будь-яке порівняння з `NaN` дає `false`. `null >= 0` дає `true` (null стає 0), хоча `null == 0` дає `false`, бо `>=` і `==` працюють за різними алгоритмами.

## `||` проти `??`

`a || b` підставляє запасне значення для будь-якого хибного `a`, тож губить цілком законні `0` і `""`. `a ?? b` підставляє його лише для `null` чи `undefined`. Для значень за замовчуванням використовуйте `??`: `const limit = options.limit ?? 10`.

## Явне перетворення

- Віддавайте перевагу `Number(x)`, `String(x)` і `Boolean(x)` (або `!!x`), а не покладайтеся на оператори.
- Перевіряйте розібрані числа через `Number.isFinite` і пам'ятайте, що `Number("")` дорівнює `0`, а не `NaN`.
- Використовуйте `Number.isNaN(x)`; глобальна `isNaN("abc")` спершу приводить тип.
- TypeScript ловить багато помилок, але значення з форм, URL, JSON і `localStorage` під час виконання є рядками чи `unknown`, тож перетворюйте їх на межі.

## Що перевірити перед співбесідою

- Перелічіть хибні значення й примітивні типи (і особливість `typeof null`).
- Поясніть `"5" + 3` проти `"5" - 3`, а також `[] + {}`.
- Покажіть, чому `[] == false` дає `true` і чому `null == 0` дає `false`, а `null >= 0` дає `true`.
- Поясніть `valueOf`, `toString`, `Symbol.toPrimitive` і підказки.
- Оберіть між `||` і `??`, а також між `Number` і `parseInt`.
