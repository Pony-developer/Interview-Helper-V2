Node.js виконує JavaScript поза браузером на V8, а **libuv** забезпечує цикл подій, пул потоків і неблокувальний ввід-вивід. Фронтенд-розробники стикаються з ним в інструментах, SSR (Next.js) і BFF API.

## Неблокувальний ввід-вивід

Node обслуговує тисячі з'єднань в одному потоці JavaScript, бо ввід-вивід не блокує: він запускає операцію, реєструє колбек і продовжує обслуговувати інші запити. Зворотний бік: **CPU-важка робота блокує всіх**. Перетворення JSON на 2 секунди заморожує кожен запит.

```js
const data = fs.readFileSync("big.json");        // ✗ блокує цикл подій
const data = await fs.promises.readFile("big.json"); // ✓ неблокувально
```

Виносьте CPU-роботу у **worker threads**, окремий сервіс або чергу.

## Фази циклу подій

libuv проходить фази по колу: **timers** (`setTimeout`/`setInterval`) → pending callbacks → **poll** (ввід-вивід) → **check** (`setImmediate`) → close callbacks. Між колбеками Node виконує мікрозадачі: спершу `process.nextTick`, потім колбеки промісів.

```js
setTimeout(() => console.log("timeout"), 0);
setImmediate(() => console.log("immediate"));
Promise.resolve().then(() => console.log("promise"));
process.nextTick(() => console.log("nextTick"));
// nextTick, promise, далі timeout/immediate (їхній порядок у головному модулі може відрізнятися)
```

Рекурсивний `process.nextTick` може «заморити голодом» ввід-вивід, тож щоб поступитися потоком, обирайте `setImmediate`.

## Модулі

Node підтримує **CommonJS** (`require`, `module.exports`) і **ES-модулі** (`import`, `"type": "module"` або `.mjs`). ESM може імпортувати CJS; CJS завантажує ESM через динамічний `import()` (нові версії також підтримують `require` синхронних ESM). Вбудовані модулі мають префікс `node:`: `import fs from "node:fs/promises"`.

## Потоки й зворотний тиск

Потоки (streams) обробляють дані частинами, а не завантажують усе в пам'ять:

```js
import { pipeline } from "node:stream/promises";
await pipeline(fs.createReadStream("in.log"), zlib.createGzip(), fs.createWriteStream("in.log.gz"));
```

`pipeline` обробляє **зворотний тиск (backpressure)**: призупиняє швидкого читача, коли повільний записувач не встигає, а також передає помилки й прибирає ресурси. Ручні ланцюжки `.pipe()` помилок не передають.

## Обробка помилок

- Async/await з `try/catch`; завжди обробляйте відхилення промісів. Необроблене відхилення в сучасному Node завершує процес.
- Операційні помилки (мережа недоступна, некоректний вхід) треба обробляти. Помилки програміста (баги) мають завершувати процес із перезапуском через менеджер процесів.
- Подія "error" в `EventEmitter` без слухача кидає виняток.

## Використання всіх ядер

Один процес Node використовує одне ядро для JavaScript. Масштабуйтеся кількома процесами (модуль `cluster`, PM2, контейнери за балансувальником) і тримайте процеси без стану, а сесії в Redis чи базі даних.

## Конфігурація й безпека

Читайте конфігурацію зі змінних середовища (`process.env`), валідуйте її під час запуску, ніколи не логуйте секрети, оновлюйте залежності (`npm audit`) і задавайте тайм-аути для вихідних запитів.

## Чек-лист для співбесіди

- Поясніть, чому Node швидкий для вводу-виводу й повільний для CPU-задач.
- Розставте по порядку `nextTick`, проміси, таймери та `setImmediate`.
- Обробляйте великі файли потоково через `pipeline` і поясніть зворотний тиск.
- Опишіть, як масштабуватися на кілька ядер і безпечно обробляти помилки.
