Коли ви передаєте масив у метод, метод отримує **копію посилання**. Він бачить той самий масив, що й той, хто викликав, і це має два наслідки.

## 1. Зміна елементів видима для того, хто викликав

```csharp
static void Double(int[] numbers)
{
    for (int i = 0; i < numbers.Length; i++)
    {
        numbers[i] *= 2;
    }
}

static void Main()
{
    int[] data = { 1, 2, 3 };
    Double(data);
    Console.WriteLine(data[0] + " " + data[1] + " " + data[2]);   // 2 4 6
}
```

Метод нічого не повернув, але `data` змінився, бо `numbers` і `data` — два імені одного масиву.

Порівняйте з параметром `int`, який є **копією значення**: `static void AddOne(int x) { x++; }` ніколи не змінить змінну того, хто викликав.

## 2. Перепризначення параметра не видиме

Якщо параметр починає посилатися на інший масив, змінюється лише власна копія посилання в методі:

```csharp
static void Replace(int[] numbers)
{
    numbers = new int[] { 99 };   // numbers тепер вказує на новий масив
}

int[] data = { 1, 2, 3 };
Replace(data);
Console.WriteLine(data[0]);   // 1: той, хто викликав, досі має старий масив
```

Якщо ви хочете, щоб викликач отримав новий масив, **поверніть** його:

```csharp
static int[] Replace()
{
    return new int[] { 99 };
}

data = Replace();
```

(Є ще ключове слово `ref`, яке передає саму змінну, але повернення значення зазвичай зрозуміліше.)

## Два стилі методів

| Стиль | Сигнатура | Поведінка |
| --- | --- | --- |
| **Змінює масив на місці** | `static void Reverse(int[] a)` | швидко, без додаткової пам'яті, але оригінал зникає |
| **Будує новий масив** | `static int[] Reversed(int[] a)` | оригінал не чіпають, ціною нового масиву |

Обирайте свідомо й нехай назва та коментар кажуть, який саме. Метод `Sorted` чи `GetSquares` не повинен потай змінювати свій аргумент, а метод `Sort` чи `Fill` — повинен.

Приклад на місці: обернення через обмін двох кінців:

```csharp
static void Reverse(int[] a)
{
    for (int i = 0, j = a.Length - 1; i < j; i++, j--)
    {
        int temp = a[i];
        a[i] = a[j];
        a[j] = temp;
    }
}
```

А це версія, що будує новий масив:

```csharp
static int[] Reversed(int[] a)
{
    int[] result = new int[a.Length];
    for (int i = 0; i < a.Length; i++)
    {
        result[i] = a[a.Length - 1 - i];
    }
    return result;
}
```

## Повернення масиву

Метод може створити масив потрібного розміру й повернути його:

```csharp
static int[] Range(int count)
{
    int[] result = new int[count];
    for (int i = 0; i < count; i++) result[i] = i;
    return result;
}

int[] numbers = Range(4);   // 0 1 2 3
```

## params: довільна кількість аргументів

Параметр із позначкою `params` дозволяє викликачеві перелічити значення замість створення масиву:

```csharp
static int Sum(params int[] numbers)
{
    int total = 0;
    foreach (int n in numbers) total += n;
    return total;
}

Console.WriteLine(Sum(1, 2, 3));        // 6
Console.WriteLine(Sum());               // 0: порожній масив
Console.WriteLine(Sum(new[] { 4, 5 })); // 9: масив теж підходить
```

`params` має бути **останнім** параметром, і він може бути лише один.

## Остерігайтеся несподіваних вхідних даних

- Викликач може передати `null`: тоді `numbers.Length` кине `NullReferenceException`. Вирішіть, чи має ваш метод перевіряти, чи задокументуйте, що аргумент не може бути null.
- Масив може бути порожнім. Чи працює ваш метод для нього?
- Якщо масив потрібно зберегти після повернення з методу, зберігайте **копію**. Інакше викликач може змінити ваші дані за вашою спиною.
