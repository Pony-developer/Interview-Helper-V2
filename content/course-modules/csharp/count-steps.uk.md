Твердження про складність стає реальним, коли ви **рахуєте**. Реалізуйте три методи, що повертають кількість кроків, і подивіться, як ростуть числа.

1. `LinearSteps(sorted, value)` виконує лінійний пошук від початку масиву. Він дивиться на елементи по одному й зупиняється на **першому збігу** або в кінці. Поверніть, на скільки елементів він подивився.
2. `BinarySteps(sorted, value)` виконує двійковий пошук і повертає, скільки разів виконалося **тіло циклу**. Використайте саме таку форму, щоб підрахунки збіглися:

   ```csharp
   int left = 0, right = sorted.Length - 1;
   while (left <= right)
   {
       steps++;
       int middle = left + (right - left) / 2;
       if (sorted[middle] == value) return steps;
       if (sorted[middle] < value) left = middle + 1;
       else right = middle - 1;
   }
   ```

   (Крок рахується **перед** порівнянням, тож значення, знайдене з першого погляду, займає 1 крок.)
3. `PairCount(n)` повертає, скільки пар `(i, j)` з `i < j` є серед `n` елементів, тобто скільки разів виконується тіло двох вкладених циклів: `for i in 0..n-1`, `for j in i+1..n-1`. Результат — `long`. Зверніть увагу, що `n` у `Main` сягає 100 000, тож підрахунок циклами зайняв би близько 5 · 10⁹ кроків: знайдіть натомість **формулу**.

`Main` створює відсортований масив `1, 2, ..., 1000` і друкує кількість кроків для кількох значень. Подивіться, що це показує: лінійний пошук потребує до 1 000 кроків, а двійковий — ніколи більше 10. `Main` не змінюйте. Очікуваний вивід:

```text
1
500
1000
1000
1
9
10
10
45
499500
4999950000
```

Перші чотири рядки — це `LinearSteps` для значень 1, 500, 1000 та 5000 (якого немає). Наступні чотири — `BinarySteps` для 500, 1, 1000 і 5000. Останні три — `PairCount` для 10, 1000 та 100 000.

Підказка: кількість пар — це `n · (n − 1) / 2`. Не забудьте обчислити її в `long`, бо `n · (n − 1)` для `n = 100 000` не вміщується в `int`.
