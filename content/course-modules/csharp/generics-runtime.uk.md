У Java узагальнення існують лише для компілятора: під час виконання `List<String>` і `List<Integer>` — той самий клас. У .NET вони **реїфіковані**: середовище виконання знає справжні аргументи типу. Це має кілька помітних наслідків.

## Кожен закритий тип — окремий тип

`List<int>` і `List<string>` — два різні типи. `typeof(T)` усередині узагальненого методу дає справжній тип, а `items is List<int>` — справжня перевірка.

```csharp
static string Describe<T>(T value) => typeof(T).Name;

Describe(42);      // "Int32"
Describe("hi");    // "String"
```

## Код спільний для посилань і окремий для значень

JIT компілює одну спільну версію `List<T>` для **всіх посилальних типів** (посилання завжди має однаковий розмір, тож код однаковий). Для **кожного значущого типу** він компілює окрему, спеціалізовану версію. Тому `List<int>` зберігає звичайні `int` без пакування, а старий `ArrayList` пакував кожне число.

## Статичні поля належать кожному закритому типу

```csharp
class Counter<T>
{
    public static int Count;
}

Counter<int>.Count++;
Counter<int>.Count++;
Counter<string>.Count++;
Console.WriteLine(Counter<int>.Count);    // 2
Console.WriteLine(Counter<string>.Count); // 1
```

Цим користуються як швидким кешем для кожного типу (так побудовано `EqualityComparer<T>.Default`), і це ж класична пастка на співбесідах.

## `default(T)` і рівність

`default(T)` дає `null` для посилальних типів, `0` для чисел, `false` для `bool` і заповнену нулями структуру для інших значущих типів. Починаючи з C# 7.1 можна писати просто `default`.

Оператор `==` заборонений для `T` без обмежень, бо компілятор не знає, який `==` викликати. Використовуйте компаратор:

```csharp
static int IndexOf<T>(T[] items, T value)
{
    var comparer = EqualityComparer<T>.Default;   // використовує IEquatable<T>, якщо T його має: без пакування
    for (int i = 0; i < items.Length; i++)
        if (comparer.Equals(items[i], value)) return i;
    return -1;
}
```

## Виведення типів

Компілятор виводить аргументи типу **методу** з його аргументів: `Max(3, 7)` означає `Max<int>`. Він не виводить їх із типу результату і не виводить їх для **конструкторів**: `new List<int>()` завжди потребує `<int>`. Саме тому існують допоміжні методи на кшталт `Tuple.Create(1, "a")`.

## Правило

Думайте про `Foo<int>` і `Foo<string>` як про два окремі класи, написані за одним шаблоном: у них власні статичні поля, власний `typeof`, а для значущих типів — власний скомпільований код.
