`OrderBy` сортує послідовність за ключем, а `Distinct` прибирає повторювані елементи.

```csharp
var words = new[] { "pear", "fig", "apple", "kiwi", "fig" };

var byLength = words.OrderBy(w => w.Length);             // fig, fig, pear, kiwi, apple
var byLengthDesc = words.OrderByDescending(w => w.Length);
var unique = words.Distinct();                           // pear, fig, apple, kiwi
```

## Кілька ключів

Коли два елементи мають однаковий перший ключ, порядок вирішує `ThenBy`:

```csharp
var sorted = words.OrderBy(w => w.Length).ThenBy(w => w);
// fig, fig, kiwi, pear, apple  (однакові довжини: за алфавітом)
```

`ThenBy` і `ThenByDescending` можна повторювати скільки потрібно. Перший `OrderBy` — головний ключ.

## Стабільність

`OrderBy` **стабільний**: елементи з однаковими ключами зберігають початковий порядок. Тому `fig` опиняється на тому самому місці, що й раніше. На це можна покластися, коли сортуєте в кілька кроків.

## Distinct з ключем

`Distinct()` порівнює цілі елементи. Щоб прибрати дублікати за частиною елемента, згрупуйте за цією частиною й візьміть перший з кожної групи або використайте `DistinctBy` у новіших версіях .NET. У старому коді звичний спосіб — `GroupBy(...).Select(g => g.First())`.

## Вартість

Сортування займає близько `n log n` порівнянь. `Distinct` пам'ятає бачені елементи, тож працює з хешами, як `HashSet`: для ваших власних класів йому потрібні `GetHashCode` і `Equals`.

## Порядок після Distinct

`Distinct` зберігає першу появу кожного елемента, тож порядок перших входжень зберігається. Але не покладайтеся на порядок словника чи множини: методи LINQ, що їх будують, порядку не обіцяють.
