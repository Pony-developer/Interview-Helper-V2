До появи дженериків універсальний контейнер мусив зберігати `object`. Така черга приймає що завгодно, але кожен елемент виходить як `object`, і щоб його використати, треба **привести його вниз**:

```csharp
class ObjectQueue
{
    private readonly List<object> items = new List<object>();

    public void Enqueue(object item) { items.Add(item); }

    public object Dequeue()
    {
        object first = items[0];
        items.RemoveAt(0);
        return first;
    }
}

var q = new ObjectQueue();
q.Enqueue(5);
q.Enqueue("five");

int n = (int)q.Dequeue();      // добре
int s = (int)q.Dequeue();      // InvalidCastException під час виконання: "five" — це рядок
```

Цей дизайн має дві проблеми:

- **Нічого не зупиняє помилку** до часу виконання. Компілятор приймає `q.Enqueue("five")` у черзі, призначеній для чисел.
- **Кожне значення упаковується** (див. лекцію про boxing), і кожне читання потребує приведення вниз.

## Приведення вниз — це симптом

Приведення вниз означає «я знаю, що це за об'єкт, повір мені». Коли таких приведень багато, дизайн втратив інформацію. Тип елементів був відомий, коли їх клали, але контейнер його викинув.

## Узагальнене рішення

Узагальнена черга зберігає тип, і компілятор перевіряє кожне використання:

```csharp
var q = new Queue<int>();
q.Enqueue(5);
// q.Enqueue("five");          // помилка компіляції одразу
int n = q.Dequeue();           // без приведення, і без boxing для int
```

Приведення вниз потрібне й далі, коли дизайн справді працює з базовим типом (наприклад, `Animal` у списку змішаних тварин). Для цього вживайте `is` або `as`, як у лекціях про успадкування. Але контейнер одного відомого типу має бути узагальненим.
