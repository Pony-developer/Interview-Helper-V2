**Абстракція** — це вміння **залишати важливе й ігнорувати решту**. Мапа міста не показує кожне дерево, бо водієві важливі дороги. Мапа для мандрівника показує дерева й ховає світлофори. У того самого міста дві різні абстракції, і кожна гарна для своєї **мети**.

## Абстракція в повсякденному коді

Ви користуєтеся абстракціями постійно:

```csharp
Console.WriteLine("Hello");                 // ви не знаєте, як з'являються пікселі
list.Sort();                                // ви не знаєте, який алгоритм працює
File.ReadAllText(path);                     // ви не знаєте про диски, буфери й кодування
```

Кожен рядок каже, **що** робиться, і ховає, **як**. Якби «як» не існувало як прихованої деталі, кожна програма мала б мати справу з драйверами екрана й блоками диска.

Абстракція працює на кількох рівнях:

| Рівень | Що приховує | Приклад |
|---|---|---|
| Метод | Кроки операції | `Math.Sqrt(x)` |
| Клас | Дані й код, що обслуговують одну ідею | `List<T>`, `StringBuilder` |
| Інтерфейс | Навіть **який клас** використано | `IEnumerable<T>`, `IComparable<T>` |
| Шар чи бібліотека | Усю галузь системи | Бібліотека доступу до бази даних |

## Модель залежить від мети

Коли ви проєктуєте клас, ви будуєте **модель** реальної речі. Додавайте лише те, що потрібне **задачі**:

```csharp
// Для бібліотечної програми книжка — це:
class Book
{
    public string Title { get; }
    public string Author { get; }
    public bool IsBorrowed { get; private set; }
}

// Для книгарні та сама річ — це щось інше: ISBN, ціна, кількість на складі.
```

Жодна з них не є «справжньою книжкою». Якби в бібліотечний клас додали вагу, колір обкладинки та запах паперу, його стало б **важче вживати**, а не краще. Гарна абстракція — **мала**.

## Контракт

Абстракція корисна, бо дає **контракт**: що потрібно операції, що вона повертає і коли вона зазнає невдачі. Той, хто викликає, залежить **лише від контракту**:

```csharp
/// Повертає позицію значення або -1, якщо такого значення немає.
/// Масив має бути відсортований за зростанням.
static int BinarySearch(int[] sortedValues, int value) { ... }
```

Тому, хто викликає, байдуже, двійковий пошук, лінійний чи стрибковий, поки обіцянку дотримано. Автор може замінити алгоритм завтра, і ніхто цього не помітить. Ця свобода — причина створювати абстракції.

## Абстракція та інкапсуляція

Ці дві ідеї сусідні, і їх часто плутають:

- **Абстракція** відповідає: **що** бачить користувач цієї речі? Вона про **дизайн інтерфейсу**: добра назва, малий набір операцій, чіткий контракт.
- **Інкапсуляція** відповідає: **як** захищено середину? Вона про **механізми**: `private`, властивості й інваріанти.

Абстракція вибирає, що показати, а інкапсуляція гарантує, що **лише до цього** можна дістатися.

## Що таке гарна абстракція?

- **Одна ідея**: клас можна пояснити одним реченням без слова «і».
- **Чітка назва**: `OrderRepository`, а не `DataManager`.
- **Повна для мети**: користувачеві не потрібно зазирати всередину.
- **Мала**: кожен зайвий публічний член — це обіцянка, яку треба тримати роками.
- **Не протікає**: користувача не змушують знати деталі. Якщо, щоб правильно користуватися «списком», треба знати, що він пов'язаний, абстракція **протікає**.

## Чим допомагає C#

У C# є особливі інструменти для побудови абстракцій, і модуль їх показує:

- **абстрактні класи**: базовий тип, який не можна створити й який описує **частину** поведінки;
- **інтерфейси**: чистий контракт без коду;
- **шаблонні методи**: фіксований алгоритм із частинами, які заповнюють похідні класи.
