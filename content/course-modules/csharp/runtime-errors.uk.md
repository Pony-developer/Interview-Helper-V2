Помилка виконання трапляється після успішної компіляції, поки програма працює. Середовище виконання зупиняє звичайний перебіг і **кидає виняток**. Якщо ніхто його не обробить, програма аварійно завершується.

## Поширені винятки

| Виняток | Типова причина |
| --- | --- |
| `FormatException` | `int.Parse("abc")`: текст не є числом |
| `OverflowException` | `int.Parse("99999999999")`: число не вміщується |
| `DivideByZeroException` | цілочисельне ділення на нуль: `10 / zero` |
| `IndexOutOfRangeException` | `"abc"[5]` або `numbers[10]`: позиції не існує |
| `ArgumentOutOfRangeException` | `"abc".Substring(5)`: аргумент поза допустимим діапазоном |
| `NullReferenceException` | виклик методу на `null`: `string s = null; s.Length` |
| `ArgumentException` | метод отримав аргумент, який не може прийняти |

## Трасування стека

Коли програма аварійно завершується, вона друкує тип винятку, повідомлення та **трасування стека**: ланцюжок викликів методів, що привів до збою.

```text
Unhandled Exception:
System.DivideByZeroException: Attempted to divide by zero.
  at Program.Average (System.Int32 sum, System.Int32 count) in prog.cs:8
  at Program.Main () in prog.cs:14
```

Читайте згори. Перший рядок, що вказує на **ваш** код (`prog.cs:8`), — це місце, де кинуто виняток. Рядки нижче показують, хто кого викликав, тобто як програма туди потрапила. Точний вигляд відрізняється в різних середовищах виконання, але суть та сама.

## try / catch / finally

Виняток можна перехопити й відреагувати на нього замість аварійного завершення:

```csharp
try
{
    int n = int.Parse(text);
    Console.WriteLine(n * 2);
}
catch (FormatException)
{
    Console.WriteLine("Not a number");
}
catch (OverflowException)
{
    Console.WriteLine("Number is too big");
}
finally
{
    Console.WriteLine("Done");   // виконається незалежно від того, чи був виняток
}
```

- Код у `try` виконується, доки не виникне виняток; решта блоку пропускається.
- Виняток обробляє перший `catch`, чий тип підходить. Кілька блоків `catch` перевіряються згори донизу.
- `finally` виконується завжди, тому це правильне місце для звільнення ресурсів.
- Щоб побачити подробиці, напишіть `catch (FormatException ex)` і скористайтеся `ex.Message`.

## Кидаємо власні винятки

Метод може відмовитися від хибних даних, кинувши виняток:

```csharp
static int Half(int x)
{
    if (x < 0) throw new ArgumentException("x must not be negative");
    return x / 2;
}
```

## Розумно користуйтеся винятками

- **Перехоплюйте лише те, що вмієте обробити.** `catch (Exception)` з порожнім тілом ковтає всі помилки, зокрема й ваші власні баги, і програма мовчки робить не те. Це гірше за аварійне завершення.
- **Не використовуйте винятки для звичайних ситуацій.** Якщо хибні дані очікувані, як текст, введений користувачем, перевіряйте їх через `int.TryParse`, а не чекайте на `FormatException`.
- **Якщо це баг, усувайте причину.** `NullReferenceException` або `IndexOutOfRangeException` зазвичай означає помилку у вашому коді. Перехоплення ховає її, а не усуває.
