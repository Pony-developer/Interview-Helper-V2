`List<T>` і `Dictionary<TKey, TValue>` **не потокобезпечні**. Два потоки, що одночасно додають у той самий словник, не просто втрачають елемент: вони можуть зіпсувати його внутрішні масиви, після чого читання кидає дивні винятки або зациклюється. Або захищайте їх блокуванням, або використовуйте колекції з `System.Collections.Concurrent`.

## `ConcurrentDictionary`

Кожна окрема операція атомарна, а читання взагалі не бере блокувань.

```csharp
var counts = new ConcurrentDictionary<string, int>();

Parallel.ForEach(words, word =>
{
    counts.AddOrUpdate(word, 1, (key, old) => old + 1);   // атомарне «додати або збільшити»
});
```

Основні методи: `TryAdd`, `TryGetValue`, `TryRemove`, `TryUpdate`, `AddOrUpdate`, `GetOrAdd`.

**Пастка «перевір, потім дій».** Два окремі виклики разом не атомарні, навіть для конкурентної колекції:

```csharp
if (!cache.ContainsKey(key))      // інший потік може додати ключ саме тут
    cache[key] = Load(key);
```

Використовуйте один виклик, що робить обидва кроки: `cache.GetOrAdd(key, k => Load(k))`.

**Пастка `GetOrAdd`.** Фабрика виконується **поза** внутрішнім блокуванням. Якщо два потоки одночасно просять відсутній ключ, `Load` може виконатися **двічі** (збережено буде лише один результат). Коли фабрика дорога або має виконатися один раз, зберігайте `Lazy<T>`:

```csharp
var cache = new ConcurrentDictionary<string, Lazy<Report>>();
Report report = cache.GetOrAdd(key, k => new Lazy<Report>(() => Build(k))).Value;
// може бути створено кілька об'єктів Lazy, але Build виконає лише збережений
```

## Черги, стеки та «мішки»

- `ConcurrentQueue<T>`: `Enqueue`, `TryDequeue`; перший прийшов — перший вийшов.
- `ConcurrentStack<T>`: `Push`, `TryPop`.
- `ConcurrentBag<T>`: невпорядкований набір елементів; швидкий, коли ті самі потоки і додають, і забирають.

## `BlockingCollection<T>`: виробник і споживач

Обгортка над конкурентною чергою, що змушує споживачів **чекати** на елементи, а виробників — за бажанням — чекати на вільне місце:

```csharp
var queue = new BlockingCollection<Order>(boundedCapacity: 100);

// виробник
foreach (var order in incoming) queue.Add(order);   // чекає, якщо в черзі вже 100 елементів
queue.CompleteAdding();                              // «більше елементів не буде»

// споживач (їх може працювати кілька паралельно)
foreach (var order in queue.GetConsumingEnumerable())   // чекає на елементи, закінчується після CompleteAdding
    Process(order);
```

Під час очікування вона блокує потоки. В асинхронному коді натомість використовуйте канали (наступні лекції).

## Незмінні колекції

`ImmutableList<T>`, `ImmutableDictionary<TKey, TValue>` (у `System.Collections.Immutable`) ніколи не змінюються: «додавання» повертає нову колекцію, яка ділить більшу частину пам'яті зі старою. Будь-яка кількість потоків може читати їх без блокувань, що пасує для конфігурації та знімків, які змінюються рідко.

## Правило

Ніколи не діліть `List` чи `Dictionary` між потоками без блокування. З конкурентними колекціями робіть кожен логічний крок **одним** викликом (`AddOrUpdate`, `GetOrAdd`) і пам'ятайте, що фабрика `GetOrAdd` може виконатися більше одного разу.
