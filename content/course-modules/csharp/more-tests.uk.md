Один тест краще, ніж жодного, але методу з десятком можливих поведінок потрібно більше, ніж один. Питання в тому, **які** тести додавати, бо перебрати всі вхідні дані неможливо.

## Класи еквівалентності та межі

Вхідні дані розпадаються на групи, які код трактує **однаково**. Одного представника кожної групи досить. А от помилки живуть на **межах** між групами, тож перевіряйте значення по обидва боки від кожної межі.

Візьмімо ціну квитка: діти до 6 років безкоштовно, до 17 включно платять 5, дорослі платять 10, а від 65 років — 7.

```text
вік:      ...  5 | 6 ...... 17 | 18 ...... 64 | 65 ...
ціна:          0     5            10            7
```

| Група | Представник | Межі |
| --- | --- | --- |
| безкоштовно | 3 | 5 та 6 |
| дитина | 10 | 6 та 17 |
| дорослий | 30 | 17 та 18 |
| пенсіонер | 70 | 64 та 65 |

Граничні тести `5, 6, 17, 18, 64, 65` ловлять `<`, написане замість `<=`, а це найпоширеніша помилка в такому коді.

Не забудьте про **некоректну** групу: від'ємний вік або 200. Що має статися? Помилка чи відповідь? Запишіть рішення й протестуйте його.

## Типові випадки, які варто пам'ятати

- **Порожнє**: `""`, порожній масив, `0`.
- **Один** елемент.
- **Багато** елементів і випадок, коли всі однакові.
- **Від'ємні** числа та нуль.
- **Найбільше** й **найменше** значення (`int.MaxValue` може переповнитися).
- **Порядок**: уже відсортований, зворотний, довільний.
- **Дублікати** і випадок, коли нічого знаходити.
- **Спеціальні символи**: пробіли, табуляції, переведення рядків, Unicode, великі та малі літери.
- `null`, якщо код його приймає.

## Позитивні й негативні тести

**Позитивний** тест перевіряє, що коректні дані дають правильний результат. **Негативний** тест перевіряє, що **некоректні** дані обробляються як слід: виняток, повідомлення про помилку, значення за замовчуванням. Набір лише з позитивних тестів нічого не каже про те, що буде, коли щось піде не так, а саме звідти беруться інциденти на продакшні.

## Таблиця випадків

Зберіть випадки в таблицю, і сам тест лишиться коротким. Тоді нова помилка коштує один новий рядок:

```csharp
string[] inputs   = { "hello",  "a", "Already", "",  " x" };
string[] expected = { "Hello",  "A", "Already", "",  " x" };

for (int i = 0; i < inputs.Length; i++)
{
    string actual = Capitalize(inputs[i]);
    string status = actual == expected[i] ? "ok" : "FAIL";
    Console.WriteLine(status + ": \"" + inputs[i] + "\" -> \"" + actual + "\"");
}
```

У фреймворку та сама таблиця — це рядки `[InlineData(...)]` над `[Theory]`.

## Властивості замість прикладів

Іноді не можна перелічити правильні відповіді, але відомо щось, що має виконуватися **завжди**:

- дворазове обернення рядка повертає оригінал;
- відсортований масив має ту саму довжину й ті самі елементи, що й вхідний, а кожен елемент не більший за наступний;
- `Encrypt`, за яким іде `Decrypt`, повертає початковий текст;
- знижка ніколи не робить ціну від'ємною.

Таке правило можна перевірити на багатьох вхідних даних, навіть згенерованих. З **фіксованим** зерном, щоб збій можна було повторити:

```csharp
var random = new Random(42);
for (int i = 0; i < 1000; i++)
{
    int n = random.Next(0, 10000);
    if (ReverseNumber(ReverseNumber(n)) != n && n % 10 != 0)
    {
        Console.WriteLine("FAIL: " + n);
    }
}
```

## Тести, що змінюють вхідні дані

Перевірте, що метод не псує отримані дані. Функція, яка сортує копію, має лишити оригінал недоторканим, і тест для неї порівнює масив до й після:

```csharp
int[] data = { 3, 1, 2 };
int[] sorted = SortedCopy(data);
// data має лишитися { 3, 1, 2 }
```

## Помилка — це тест, якого у вас не було

Щоразу, виправляючи помилку, спершу додайте тест, що її відтворює. Він провалиться (червоний). Виправте код, і тест пройде (зелений). Набір росте саме там, де код виявився слабким, і та сама помилка не повернеться непоміченою.

## Коли досить?

Числа немає. Питайте себе:

- Чи виконується кожна **гілка** (`if`, `else`, `case`) методу в якомусь тесті?
- Чи кожну **межу** перевірено з обох боків?
- Чи є тест на кожен **різновид збою**, про який метод може повідомити?
- Якби я десь у коді замінив `<` на `<=` чи `+` на `-`, чи почервонів би якийсь тест?

Останнє питання найчесніше, і наступні лекції до нього повернуться.
