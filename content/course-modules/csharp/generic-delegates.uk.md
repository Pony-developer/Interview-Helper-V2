Тип делегата може мати параметри типу, як узагальнений клас. Тоді один тип делегата працює для будь-якого типу елементів:

```csharp
delegate T Maker<T>();                    // «метод, що нічого не приймає і повертає T»

static int MakeNumber() { return 42; }
static string MakeText() { return "hi"; }

Maker<int> a = MakeNumber;
Maker<string> b = MakeText;
Console.WriteLine(a() + 1);               // 43
Console.WriteLine(b());                   // hi
```

## Два типи делегатів зі стандартної бібліотеки

Ви вже зустрічали їх через методи списків. Фреймворк визначає їх для поширених випадків:

- `Predicate<T>`: `delegate bool Predicate<in T>(T obj);` — перевірка, що для елемента відповідає так чи ні.
- `Comparison<T>`: `delegate int Comparison<in T>(T x, T y);` — порівняння, що повертає від'ємне, нуль або додатне.

```csharp
var numbers = new List<int> { 5, 12, 7, 30 };
Predicate<int> isBig = n => n > 10;           // делегат стандартного типу
Console.WriteLine(numbers.Find(isBig));       // 12
numbers.Sort((x, y) => y.CompareTo(x));       // Comparison<int>: за спаданням
```

Лямбда-вирази в останньому рядку пояснюються в наступних лекціях.

## Навіщо потрібні узагальнені делегати

Делегат, написаний раз для `T`, замінює багато делегатів, написаних для кожного типу. Метод, що працює з елементами будь-якого виду, приймає `Predicate<T>` або `Func<T, bool>`, а правило вирішує викликаючий.

## Ключові слова варіантності

`in` і `out` у оголошеннях дозволяють використати делегат із ширшим типом там, де очікують вужчий. Писати їх самим на цьому етапі не потрібно; важливо, що стандартні делегати вже налаштовано правильно.
