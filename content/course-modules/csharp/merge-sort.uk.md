Лекція про «розділяй і володарюй» познайомила з сортуванням злиттям. Тут ми розглядаємо його як **алгоритм сортування**: як працює злиття, чому воно **стабільне**, скільки коштує і де є найкращим вибором.

## Крок злиття

Два **відсортовані** масиви можна злити в один відсортований за один прохід. Тримайте вказівник у кожному масиві, завжди беріть **менший** із двох передніх елементів і пересувайте цей вказівник:

```text
left:  [1  4  9]            right: [2  3  10]
        ^                            ^

беремо 1 (1 <= 2)    результат: 1                 лівий вказівник -> 4
беремо 2             результат: 1 2               правий вказівник -> 3
беремо 3             результат: 1 2 3             правий вказівник -> 10
беремо 4             результат: 1 2 3 4           лівий вказівник -> 9
беремо 9             результат: 1 2 3 4 9         ліві елементи вичерпано
копіюємо решту right: 10      результат: 1 2 3 4 9 10
```

Кожен елемент береться рівно один раз, тож злиття масивів розмірів `a` і `b` коштує **O(a + b)**.

```csharp
static int[] Merge(int[] left, int[] right)
{
    int[] result = new int[left.Length + right.Length];
    int i = 0, j = 0, k = 0;

    while (i < left.Length && j < right.Length)
    {
        if (left[i] <= right[j])          // "<=": за рівності беремо з ЛІВОГО
            result[k++] = left[i++];
        else
            result[k++] = right[j++];
    }
    while (i < left.Length) result[k++] = left[i++];   // те, що лишилося в одного з них
    while (j < right.Length) result[k++] = right[j++];
    return result;
}
```

## Весь алгоритм

```text
MergeSort(array):
    якщо в масиві 0 або 1 елемент: він відсортований
    розділити його на дві половини
    відсортувати кожну половину через MergeSort
    злити дві відсортовані половини
```

Версія, що працює з **індексами** в одному спільному масиві, щоб не виділяти нові малі масиви на кожному рівні:

```csharp
static void MergeSort(int[] a)
{
    int[] temp = new int[a.Length];       // один допоміжний масив, виділений раз
    Sort(a, temp, 0, a.Length);
}

static void Sort(int[] a, int[] temp, int from, int to)    // діапазон [from, to)
{
    if (to - from < 2) return;

    int middle = from + (to - from) / 2;
    Sort(a, temp, from, middle);
    Sort(a, temp, middle, to);

    int i = from, j = middle, k = from;                    // зливаємо в temp, потім копіюємо назад
    while (i < middle && j < to)
        temp[k++] = a[i] <= a[j] ? a[i++] : a[j++];
    while (i < middle) temp[k++] = a[i++];
    while (j < to) temp[k++] = a[j++];
    for (k = from; k < to; k++) a[k] = temp[k];
}
```

## Вартість

Дерево рекурсії має `log₂ n` рівнів. На кожному рівні злиття разом торкаються **усіх `n` елементів** один раз. Тож:

```text
T(n) = 2 · T(n / 2) + O(n)   =>   O(n log n)
```

На відміну від швидкого сортування й бульбашки, **не має значення, як виглядають дані**: найкращий, середній і найгірший випадки — усі **O(n log n)**. Для мільйона елементів близько 2 · 10⁷ кроків.

Ціна — **пам'ять**: допоміжний масив розміру `n`, тобто **O(n)** додатково. Глибина рекурсії — `log₂ n`, тож стек не проблема.

## Стабільність

Сортування **стабільне**, якщо елементи з рівними ключами лишаються в тому порядку, який мали на вході. Це важливо, коли ви сортуєте за одним полем після іншого:

```text
Сортуємо спершу за іменем, потім за оцінкою (стабільно):

  (Ann, 5)  (Bo, 4)  (Cy, 5)  (Di, 4)       уже відсортовано за іменем
  після стабільного сортування за оцінкою:
  (Bo, 4)  (Di, 4)  (Ann, 5)  (Cy, 5)       рівні оцінки зберігають порядок імен
```

Сортування злиттям стабільне завдяки `<=` у злитті: за рівності першим іде елемент із **лівої** половини, який на вході був раніше. З `<` воно перестало б бути стабільним.

## Варіанти

**Висхідне сортування злиттям** не потребує рекурсії. Спершу зливають кожну пару сусідів (блоки по 1), потім блоки по 2, 4, 8, ..., доки один блок не охопить увесь масив. Воно робить ті самі злиття в циклі.

**Природне сортування злиттям** починає з уже відсортованих **серій**, які містять дані. Для майже відсортованих даних воно значно швидше. Ця ідея — ядро **Timsort**, стандартного сортування Python та Java для об'єктів.

## Підрахунок інверсій: бонус

**Інверсія** — пара у хибному порядку. Підрахунок їх перевіркою всіх пар займає O(n²). Сортування злиттям рахує їх безкоштовно: коли злиття бере елемент із **правої** половини, поки в лівій ще лишилося `m` елементів, цей елемент менший за всі ці `m` елементів, тож дає `m` інверсій. Додайте їх, і ви отримаєте загальну кількість за **O(n log n)**.

## Де воно сяє

- **Зв'язні списки**: злиттю не потрібен довільний доступ і додаткова пам'ять, якщо перев'язувати вузли.
- **Величезні дані на диску** (**зовнішнє сортування**): сортуйте шматки, що вміщуються в пам'ять, і зливайте їх як потоки.
- Коли потрібні **стабільність** і **гарантоване O(n log n)**.
- **Паралельне** сортування: дві половини незалежні.

Слабкі місця: потрібна **O(n)** додаткової пам'яті, а для малих масивів сталі множники й виділення пам'яті роблять його повільнішим за добре сортування на місці.
