**Рефакторинг** — це поліпшення структури коду **без зміни того, що він робить**. Вивід лишається тим самим, а код стає легшим для читання, змін і тестування.

Це не те саме, що виправлення помилки чи додавання функції. Робіть їх окремо: якщо змішати, неможливо зрозуміти, яка зміна щось зламала.

## Правила безпечного рефакторингу

1. **Майте спосіб перевірити поведінку**: тест або хоча б відомі вхідні й вихідні дані, які можна порівняти.
2. **Робіть малі кроки** і запускайте перевірку після кожного.
3. **Зупиніться, коли код достатньо зрозумілий**, а не коли він досконалий.

## Поширені рефакторинги

**Перейменування**: замініть `d` на `discount`, а `Calc` — на `CalculateTotal`.

**Заміна магічного числа константою**:

```csharp
// до
int vat = price * 20 / 100;

// після
const int VatPercent = 20;
int vat = price * VatPercent / 100;
```

**Пояснювальна змінна**: розбийте щільний вираз на іменовані частини.

```csharp
// до
double result = (a * a + b * b) * 3.14159 / 2;

// після
double squares = a * a + b * b;
double half = squares / 2;
double result = half * Math.PI;
```

**Виділення методу**: найважливіший із них.

## Виділення методу

Коли одні й ті самі рядки з'являються в кількох місцях або блок заслуговує на ім'я, перенесіть його в метод. Тут та сама логіка записана тричі, і в одній копії одруківка:

```csharp
int vatA = priceA * 20 / 100;
Console.WriteLine("Laptop: " + priceA + " + VAT " + vatA);

int vatB = priceB * 20 / 100;
Console.WriteLine("Mouse: " + priceB + " + VAT " + vatB);

int vatC = priceC * 2 / 100;     // ой: 2 замість 20
Console.WriteLine("Cable: " + priceC + " + VAT " + vatC);
```

Після виділення логіка існує в єдиній копії, тож є лише одне місце, де потрібно не схибити:

```csharp
const int VatPercent = 20;

static void PrintWithVat(string name, int price)
{
    int vat = price * VatPercent / 100;
    Console.WriteLine(name + ": " + price + " + VAT " + vat);
}

PrintWithVat("Laptop", priceA);
PrintWithVat("Mouse", priceB);
PrintWithVat("Cable", priceC);
```

Кроки механічні:

1. Виділіть повторюваний код і вирішіть, що **різниться** між копіями: це й будуть параметри.
2. Дайте методу назву, що каже, що він робить.
3. Усе, що код обчислює для того, хто викликає, стає значенням, яке повертається.
4. Замініть кожну копію викликом.

Вирішити, коли це робити, допоможе **правило трьох**: скопіюйте один раз, якщо мусите, а втретє — виділяйте метод.

## Який метод добрий

- Він робить **одну справу**, і назва каже, яку.
- Він достатньо короткий, щоб прочитати одним поглядом.
- Він має мало параметрів (до трьох-чотирьох — комфортно).
- Він **обчислює або друкує, але не те й інше разом.** Метод, що повертає значення, можна протестувати; той, що друкує напряму, не перевіриш, не прочитавши екран. Обчислюйте в одному методі, друкуйте в іншому.

```csharp
static int PriceWithVat(int price) => price + price * VatPercent / 100;   // обчислює
static void PrintPrice(string name, int price) { /* ... */ }              // друкує
```

## Коли не варто рефакторити

- Коли код неможливо перевірити й ви не здатні зрозуміти, чи зламали його.
- Коли код викинуть завтра.
- Коли виникає спокуса «поліпшити» все й одразу. Оберіть одне, що найбільше заважає сьогодні.
