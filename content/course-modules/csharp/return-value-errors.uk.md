Метод мусить повідомити дві речі: **результат** і чи операцію **вдалося** виконати. Є два поширені способи.

## Спосіб 1: виняток

```csharp
static int Divide(int a, int b)
{
    if (b == 0)
    {
        throw new DivideByZeroException("The divisor is zero");
    }
    return a / b;
}

try
{
    Console.WriteLine(Divide(10, 0));
}
catch (DivideByZeroException)
{
    Console.WriteLine("cannot divide");
}
```

Вживайте виняток для **несподіваної** проблеми: помилки чи зламаного стану, який викликаючий не мав спричинити. Його не можна проігнорувати, бо програма зупиниться, доки хтось його не зловить.

## Спосіб 2: шаблон Try

Для **очікуваної** невдачі, наприклад коли користувач вводить текст, що не є числом, метод повертає `bool`, а результат віддає через параметр `out`. Так працює `int.TryParse`:

```csharp
static bool TryDivide(int a, int b, out int result)
{
    if (b == 0)
    {
        result = 0;
        return false;
    }
    result = a / b;
    return true;
}

int q;
if (TryDivide(10, 0, out q))
{
    Console.WriteLine(q);
}
else
{
    Console.WriteLine("cannot divide");
}
```

Параметр `out` мусить бути присвоєний на кожному шляху, зокрема на шляху невдачі, тому `result = 0` є в гілці `false`.

## Вибір

| Ситуація | Кращий вибір |
|---|---|
| Поганий аргумент від програміста | Виняток |
| Некоректне введення користувача, яке очікуване | `bool` з `out` (шаблон Try) |
| Невдача, яку викликаючому, можливо, треба пояснити | Виняток з чітким повідомленням |

Не вживайте винятки для звичайного керування потоком. Кидання й перехоплення коштують часу, а цикл, що спирається на винятки, важко читати.
