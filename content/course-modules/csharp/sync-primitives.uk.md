`lock` відповідає на одне питання: «лише один потік за раз». Інші задачі потребують інших інструментів.

## `SemaphoreSlim`: щонайбільше N одночасно

Семафор має лічильник вільних місць. `Wait` займає місце (і чекає, якщо місць немає), `Release` повертає його.

```csharp
private static readonly SemaphoreSlim slots = new SemaphoreSlim(3);   // 3 місця

static async Task<string> DownloadAsync(string url)
{
    await slots.WaitAsync();          // чекає, не блокуючи потік
    try
    {
        return await http.GetStringAsync(url);
    }
    finally
    {
        slots.Release();              // завжди повертаємо місце
    }
}
```

Тепер тисяча викликів виконується щонайбільше з трьома завантаженнями одночасно: сервер не перевантажено, і пул потоків не заблоковано.

`new SemaphoreSlim(1, 1)` — це блокування, що працює з `await`. Воно **не** реентерабельне: якщо той самий потік виконання двічі викличе `WaitAsync` без `Release`, він вічно чекатиме сам на себе.

## `Mutex`: блокування між процесами

Іменований `Mutex` видно всім процесам на машині. Типове застосування — «може працювати лише одна копія програми»:

```csharp
using var mutex = new Mutex(true, "MyApp.SingleInstance", out bool isFirst);
if (!isFirst) return;   // інша копія вже працює
```

Він набагато повільніший за `lock`, тож використовуйте його лише тоді, коли мають взаємодіяти процеси.

## `ReaderWriterLockSlim`: багато читачів, один письменник

Коли дані читають дуже часто, а змінюють рідко, звичайне блокування змушує читачів даремно чекати одне одного. `ReaderWriterLockSlim` пускає разом будь-яку кількість читачів, а письменник отримує дані одноосібно:

```csharp
rw.EnterReadLock();  try { return cache[key]; } finally { rw.ExitReadLock(); }
rw.EnterWriteLock(); try { cache[key] = value; } finally { rw.ExitWriteLock(); }
```

Перш ніж його використовувати, вимірюйте: для коротких критичних секцій простий `lock` часто швидший.

## Сигнали: `ManualResetEventSlim` і `CountdownEvent`

Вони не захищають дані; вони дають змогу одному потоку **чекати на подію** в іншому.

- `ManualResetEventSlim`: ворота. `Wait()` блокує, поки вони зачинені; `Set()` відчиняє їх для всіх; `Reset()` знову зачиняє.
- `CountdownEvent`: відчиняється після того, як `Signal()` викликали N разів, наприклад «зачекати, доки всі 5 працівників будуть готові».

В асинхронному коді ту саму роль грає `TaskCompletionSource<T>`: одна сторона очікує `tcs.Task`, інша викликає `tcs.SetResult(value)`.

## Що обрати

| Потреба | Інструмент |
|---|---|
| Один потік за раз, синхронний код | `lock` |
| Один за раз, з `await` усередині | `SemaphoreSlim(1, 1)` |
| Щонайбільше N одночасно | `SemaphoreSlim(N)` |
| Між процесами | іменований `Mutex` |
| Багато читачів, рідкісні письменники | `ReaderWriterLockSlim` |
| Чекати на сигнал | `ManualResetEventSlim`, `TaskCompletionSource` |
| Один лічильник чи прапорець | `Interlocked` |

## Правило

Обирайте інструмент за питанням, на яке відповідаєте: «хто може ввійти», «скільки може ввійти» чи «коли можна продовжити». Завжди звільняйте у `finally`.
