**Хеш-функція** бере дані будь-якого розміру й повертає число фіксованого розміру, наприклад 32 біти. Той самий вхід завжди дає те саме число, а різні входи зазвичай дають різні числа:

```csharp
Console.WriteLine("apple".GetHashCode() == "apple".GetHashCode());   // True
Console.WriteLine("apple".GetHashCode() == "apples".GetHashCode());  // False (майже завжди)
```

Число називають **хешем** або **хеш-кодом**. Воно значно коротше за дані, тож два різні входи можуть дати той самий хеш. Це **колізія**. Добра хеш-функція робить колізії рідкими й рівномірно розподіляє значення.

## Навіщо потрібні хеші

Головне застосування — **хеш-таблиця**: структура, де хеш-код каже, в якій комірці (кошику) зберігається елемент. Пошук тоді означає: обчислити хеш, зазирнути в цей кошик і порівняти лише кілька елементів там. Саме так `Dictionary` і `HashSet` швидкі: пошук займає приблизно однаковий час, незалежно від кількості елементів.

```text
hash("Ann") = 17   ->  кошик 17: [Ann]
hash("Bob") = 42   ->  кошик 42: [Bob]
hash("Cy")  = 17   ->  кошик 17: [Ann, Cy]   колізія: обидва в кошику 17
```

## Що робить хеш класу добрим

- **Рівні об'єкти дають рівні хеші.** Це правило, яке `GetHashCode` має дотримувати разом з `Equals`.
- **Швидкий розрахунок.** Він виконується щоразу, коли шукають елемент.
- **Розподіл.** Схожі об'єкти мають давати різні числа.
- **Заснований на тих самих полях, що й `Equals`.** Поле, яке `Equals` ігнорує, не повинно впливати й на хеш.

Типовий спосіб поєднати кілька полів: `hash = hash * 31 + поле` для кожного поля в блоці `unchecked`, щоб переповнення було дозволене.

## Застереження про рядки

У .NET Core і пізніших версіях `string.GetHashCode()` навмисно рандомізований для кожного запуску програми, щоб захиститися від атак. Той самий рядок може дати різні хеш-коди в двох запусках. Тож ніколи не зберігайте значення `GetHashCode()` у файлі чи базі даних і не порівнюйте хеші між програмами. Наступна лекція розглядає стабільні хеші, створені для безпеки.
