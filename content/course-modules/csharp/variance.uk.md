`string` — це `object`. А чи є `List<string>` списком `List<object>`? **Ні**, і на те є причина:

```csharp
List<string> names = new List<string>();
List<object> things = names;   // помилка компіляції, і ось чому:
things.Add(42);                // це поклало б int у список рядків
```

Список і **видає** елементи (`names[0]`), і **приймає** їх (`Add`). Дозволене перетворення зламало б один із двох напрямків. Такий тип називається **інваріантним**.

## Коваріантність: `out T`

`IEnumerable<T>` лише **видає** елементи: методу `Add` у нього немає. Тож послідовність рядків безпечно вважати послідовністю об'єктів:

```csharp
IEnumerable<string> names = new List<string> { "Ann", "Bob" };
IEnumerable<object> things = names;   // OK: IEnumerable<out T>
```

Інтерфейс оголошено як `IEnumerable<out T>`. Ключове слово `out` обіцяє, що `T` трапляється лише у **вихідних** позиціях (значеннях, що повертаються). Компілятор перевіряє цю обіцянку: метод `void Add(T item)` у такому інтерфейсі — помилка.

Коваріантність зберігає напрямок успадкування: з `string` → `object` випливає `IEnumerable<string>` → `IEnumerable<object>`.

## Контраваріантність: `in T`

`Action<T>` лише **приймає** `T`. Дія, яка вміє обробити будь-який `object`, точно впорається з `string`:

```csharp
Action<object> print = x => Console.WriteLine(x);
Action<string> printName = print;     // OK: Action<in T>
printName("Ann");
```

Ключове слово `in` обіцяє, що `T` трапляється лише у **вхідних** позиціях (параметрах). Напрямок обертається: з `string` → `object` випливає `Action<object>` → `Action<string>`. Інший приклад — `IComparer<in T>`: компаратор тварин уміє порівнювати собак.

`Func<in T, out TResult>` використовує обидва: приймає `T` і видає `TResult`.

## Обмеження

- Варіантність працює лише для **інтерфейсів і делегатів**, не для класів: `List<T>` ніколи не може бути варіантним.
- Вона працює лише для **посилальних типів**: `IEnumerable<int>` не є `IEnumerable<object>`, бо `int` потребував би пакування.
- Масиви коваріантні (`string[]` → `object[]`), але це старий **небезпечний** виняток: запис `int` у такий масив кидає `ArrayTypeMismatchException` під час виконання.

## Власні оголошення

```csharp
interface IProducer<out T> { T Produce(); }          // лише видає T
interface IConsumer<in T>  { void Consume(T item); } // лише приймає T
```

Як запам'ятати: **out** — значення виходить **назовні**, тож його можна бачити як загальніший тип; **in** — значення **заходить усередину**, тож отримувач може приймати загальніший тип, ніж потрібно.

## Правило

Позначайте параметр типу `out`, коли ваш інтерфейс лише повертає його, і `in`, коли лише приймає. Тоді викликаючі отримують очікувані перетворення, а компілятор гарантує, що вони безпечні.
