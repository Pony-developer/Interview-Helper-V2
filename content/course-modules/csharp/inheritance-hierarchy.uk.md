Похідні класи можуть мати власні похідні класи. Класи утворюють **дерево**, **ієрархію успадкування**, а в його корені завжди стоїть `object`:

```csharp
class Person { public string Name; }
class Student : Person { public int Course; }
class Graduate : Student { public string Thesis; }
```

```text
object
 └── Person
      └── Student
           └── Graduate
```

`Graduate` **є** `Student`, який **є** `Person`, який **є** `object`. Його предки — усі класи вище, і кожен із них є типом, як який можна використовувати цей об'єкт.

## Два типи: статичний і динамічний

Змінна посилального типу має **оголошений** тип (**статичний**), а об'єкт, на який вона посилається, має **справжній** тип (**динамічний**). Вони можуть різнитися, якщо справжній тип є оголошеним типом **або походить від нього**:

```csharp
Person p = new Graduate();                 // статичний тип Person, динамічний Graduate
object o = new Student();                  // статичний тип object, динамічний Student
```

Компілятор перевіряє код за **статичним** типом. Тож через `p` доступні лише члени `Person`:

```csharp
p.Name = "Ann";                            // добре
// p.Thesis = "...";                       // помилка: у Person немає члена Thesis
```

Справжній тип можна дізнатися під час виконання:

```csharp
Console.WriteLine(p.GetType().Name);       // Graduate
```

## Приведення вгору й вниз

**Приведення вгору**: від похідного типу до його предка. Воно завжди безпечне, тому **неявне** (без особливого синтаксису):

```csharp
Student s = new Graduate();
Person p = s;                              // добре
object o = p;                              // добре
```

**Приведення вниз**: від предка назад до спеціальнішого типу. Воно може бути хибним, бо компілятор не знає справжнього типу. Тому його пишуть **явно**, а перевірка відбувається **під час виконання**:

```csharp
Person p = new Graduate();
Graduate g = (Graduate)p;                  // добре: p справді Graduate

Person q = new Student();
Graduate bad = (Graduate)q;                // InvalidCastException під час виконання
```

Приведення **ніколи не змінює** об'єкт. Воно змінює лише те, як на нього дивиться компілятор. Об'єкт `Student` залишається `Student`, навіть якщо змінна має тип `object`.

## Безпечні приведення: `is` та `as`

Щоб уникнути винятку, **спершу запитайте**:

```csharp
if (p is Student)                          // true для Student і для Graduate
{
    Student s = (Student)p;
}

Student s2 = p as Student;                 // те саме приведення, але замість винятку дає null
if (s2 != null)
{
    Console.WriteLine(s2.Course);
}
```

У C# 7 перевірку й приведення об'єднано в один крок за допомогою **шаблону**:

```csharp
if (p is Student st)                       // якщо p є Student, то st — змінна типу Student
{
    Console.WriteLine(st.Course);
}
```

- `x is T` дорівнює `true`, коли об'єкт **є** `T` або **походить** від `T`. Для `null` — `false`.
- `x as T` повертає об'єкт як `T` або **`null`**. Працює лише для посилальних типів.
- `(T)x` повертає об'єкт як `T` або кидає **`InvalidCastException`**.

## Що вміє кожен об'єкт

Оскільки всі класи походять від `object`, усі об'єкти мають його члени:

| Член | Що робить |
|---|---|
| `ToString()` | Текст для об'єкта. За замовчуванням — назва його типу. |
| `Equals(object)` | Рівність. За замовчуванням для класів — **той самий об'єкт** (те саме посилання). |
| `GetHashCode()` | Число, яке використовують `Dictionary` і `HashSet`. |
| `GetType()` | Справжній тип об'єкта. |

Два з них можна **перевизначити** у власному класі, щоб `ToString()` друкував щось корисне. Ми зробимо це наприкінці модуля, у лекції про віртуальні методи.

## `object` як універсальний тип

Змінна чи параметр типу `object` приймає **будь-що**, навіть `int` (його **пакують**: загортають в об'єкт). Так `Console.WriteLine(object)` друкує будь-яке значення. Ціна: щоб знову використати значення як конкретний тип, потрібне **приведення вниз**, і ви втрачаєте допомогу компілятора. У новому коді віддавайте перевагу конкретному базовому класу або інтерфейсу замість `object`.
