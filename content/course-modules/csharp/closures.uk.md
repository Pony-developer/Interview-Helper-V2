Лямбда, що використовує локальну змінну з оточення, є **замиканням** (closure). Вона **захоплює** змінну: лямбда тримає зв'язок із самою змінною, а не з копією її значення, і змінна живе, доки живе лямбда.

```csharp
static Func<int> MakeCounter()
{
    int count = 0;                       // локальна змінна MakeCounter
    return () =>
    {
        count++;                         // лямбда змінює захоплену змінну
        return count;
    };
}

Func<int> next = MakeCounter();
Console.WriteLine(next());               // 1
Console.WriteLine(next());               // 2
Console.WriteLine(next());               // 3
```

Коли `MakeCounter` повертає результат, його локальна змінна `count` мала б зникнути. Але вона не зникає: лямбда її використовує, тож змінна живе стільки ж, скільки делегат. Кожен виклик `MakeCounter` створює власну змінну:

```csharp
Func<int> other = MakeCounter();
Console.WriteLine(other());              // 1: новий лічильник, свій count
Console.WriteLine(next());               // 4: перший лічильник продовжує
```

## Захоплення за посиланням

Замикання бачить **поточне** значення змінної щоразу, коли виконується:

```csharp
int limit = 10;
Func<int, bool> below = x => x < limit;
Console.WriteLine(below(5));             // True
limit = 3;
Console.WriteLine(below(5));             // False: використовується нове значення limit
```

## Що можна захопити

Локальні змінні, параметри методу-оточення і `this` в методі екземпляра. Лямбда не може захопити параметр `ref` чи `out`. Це рідкісний випадок.

## Чому це важливо

Замикання — причина, чому код лямбди може жити далі після того, як метод, що її написав, завершився. Їх використовують скрізь: в обробниках подій, LINQ і асинхронному коді. Наступна лекція показує, як компілятор їх реалізує, а лекція після неї — найпоширенішу помилку.
