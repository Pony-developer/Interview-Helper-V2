**Лінійний пошук** — найпростіший пошук: дивитися на елементи по одному від початку, доки не знайдете значення або не закінчаться елементи.

```csharp
static int LinearSearch(int[] a, int value)
{
    for (int i = 0; i < a.Length; i++)
    {
        if (a[i] == value)
            return i;          // знайшли: одразу зупиняємося
    }
    return -1;                 // подивилися на все, не знайдено
}
```

Йому **не** потрібна підготовка: масив може бути в будь-якому порядку. У цьому його сила.

## Підрахунок роботи

«Операція», яку ми рахуємо, — це **порівняння** `a[i] == value`. Скільки їх робиться для масиву з `n` елементів?

| Випадок | Коли | Порівнянь |
| --- | --- | --- |
| **Найкращий** | значення — перший елемент | **1** |
| **Найгірший** | значення — останній елемент або його **немає** | **n** |
| **Середній** | значення є, на випадковій позиції | близько **(n + 1) / 2** |

**Середній.** Якщо значення з однаковою ймовірністю може бути на будь-якій з позицій від 1 до n, кількість порівнянь — 1, 2, ..., n з однаковим шансом, а середнє цих значень —

```text
(1 + 2 + ... + n) / n = n · (n + 1) / 2 / n = (n + 1) / 2
```

Для `n = 1000` близько 500 порівнянь. Якщо значення **немає**, завжди `n`. Тож середнє залежить від того, як часто пошук успішний.

## Складність

І найгірший, і середній випадки зростають **пропорційно n**: алгоритм **O(n)**, лінійний. Удесятеро більший масив потребує вдесятеро більше роботи.

| n | найгірший випадок | середній (значення є) |
| --- | --- | --- |
| 10 | 10 | 5.5 |
| 1 000 | 1 000 | 500.5 |
| 1 000 000 | 1 000 000 | 500 000.5 |
| 1 000 000 000 | 1 000 000 000 | близько 5 · 10⁸ |

Пам'ять — **O(1)**: кілька змінних.

## Ранній вихід на відсортованих даних

Якщо дані відсортовані, невдалий пошук можна зупинити **раніше**: щойно ви зустріли елемент, більший за значення, далі його бути не може.

```csharp
for (int i = 0; i < a.Length; i++)
{
    if (a[i] == value) return i;
    if (a[i] > value) return -1;     // відсортовано: після цієї точки його бути не може
}
return -1;
```

Це в середньому вдвічі зменшує роботу для відсутніх значень, але все одно O(n). Двійковий пошук на відсортованих даних працює набагато краще.

## Прийом зі вартовим

Цикл вище робить **дві** перевірки на елемент: індекс і значення. Перевірку індексу можна прибрати, поставивши саме значення в кінець масиву (**вартовий**), щоб пошук гарантовано зупинився:

```csharp
// у масиві є одна вільна клітинка в кінці, a[n] вільна
a[n] = value;
int i = 0;
while (a[i] != value) i++;
return i < n ? i : -1;               // дійшли до вартового: не знайдено
```

Це заощаджує сталий множник, а не зростання O(n). Це класичний приклад різниці між **складністю** (зростанням) і **сталою** (швидкістю).

## Пошук за умовою

Лінійний пошук не лише для рівності. Можна шукати **перший** елемент, що задовольняє будь-яке правило:

```csharp
// перше від'ємне число
for (int i = 0; i < a.Length; i++)
    if (a[i] < 0) return i;
return -1;
```

Для таких умов двійковий пошук не застосовний, якщо в даних немає відповідного порядку. Бібліотека пропонує `Array.IndexOf(a, value)`, а також `list.IndexOf(value)`, `list.Contains(value)`, які є лінійними пошуками. Та сама ідея для рядків — `s.IndexOf("text")`.

## Лінійний пошук у найгіршому випадку, у реальному світі

Лінійний пошук — O(n), але він **не поганий**:

- Для **малих** масивів (до кількох десятків елементів) він часто найшвидший: жодного налаштування, простий цикл, а процесор читає пам'ять по порядку.
- Для даних, що **не відсортовані** й у яких шукають лише **раз**, це найкраще, що можна зробити: будь-якому розумнішому методу потрібно спершу відсортувати дані, а сортування коштує O(n log n), що більше за один прохід.
- Він працює з **будь-якою** послідовністю, зокрема зі зв'язним списком, файлом, прочитаним від початку до кінця, і результатом обчислення.

## Коли це пастка

Ціна проявляється, коли ви шукаєте **багато разів**. Наступний код виглядає невинно:

```csharp
foreach (int x in queries)             // k запитів
    if (Array.IndexOf(data, x) >= 0)   // кожен O(n)
        count++;
```

Загалом **O(k · n)**. З `k = n = 100 000` це 10¹⁰ операцій: хвилини. Способи виправити:

- **Відсортувати один раз** (O(n log n)), а потім для кожного запиту використати двійковий пошук (O(log n)): загалом O((n + k) log n).
- Або покласти дані в `HashSet<int>`: кожен запит — O(1) у середньому, загалом O(n + k).

Точка беззбитковості: сортування окупається, коли кількість пошуків більша за приблизно `log n`. Для мільйона елементів це лише близько 20 пошуків.
