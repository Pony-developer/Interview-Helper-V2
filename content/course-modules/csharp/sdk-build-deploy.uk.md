Остання частина платформи — інструменти: що встановлюють на машину розробника, що — на сервер, що створює збирання і як можна постачати застосунок.

## SDK і середовище виконання

- **Середовище виконання** (runtime) запускає застосунки: CLR плюс спільні фреймворки. Серверам і машинам користувачів потрібне лише воно (для вебзастосунків — **ASP.NET Core Runtime**; для IIS — **Hosting Bundle**).
- **SDK** збирає застосунки: CLI `dotnet`, компілятори Roslyn, MSBuild, NuGet, шаблони проєктів і середовище виконання, щоб запускати зібране. Він потрібен на машинах розробників і в CI.

Версії в них окремі: SDK 10.0.100 збирає застосунки для .NET 10 (і старших цілей), а його функціональна смуга (feature band: `1xx`, `2xx`) змінюється кілька разів на рік. Файл **`global.json`** у репозиторії фіксує версію SDK, тож кожен розробник і CI збирають однаково:

```json
{ "sdk": { "version": "10.0.100", "rollForward": "latestFeature" } }
```

## CLI dotnet

| Команда | Що робить |
| --- | --- |
| `dotnet new console -n MyApp` | створює проєкт із шаблону |
| `dotnet restore` | завантажує пакети NuGet (інші команди запускають її самі) |
| `dotnet build` | компілює в `bin/Debug/<tfm>/` |
| `dotnet run` | збирає і запускає |
| `dotnet test` | запускає тести |
| `dotnet publish` | готує застосунок до розгортання (з .NET 8 за замовчуванням у Release) |
| `dotnet pack` | створює пакет NuGet із бібліотеки |
| `dotnet add package X` | додає `PackageReference` |
| `dotnet tool install -g dotnet-ef` | встановлює інструмент .NET |

## Файл проєкту і MSBuild

Збирання виконує **MSBuild**. Файл проєкту в стилі SDK короткий, бо SDK задає значення за замовчуванням: компілюється кожен файл `.cs` у теці, а версія C# відповідає цільовому фреймворку (`net10.0` означає C# 14).

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>
</Project>
```

Файл `Directory.Build.props` застосовує спільні налаштування до кожного проєкту нижче своєї теки.

## Що створює збирання

```text
bin/Release/net10.0/
  MyApp.dll                   IL і метадані: ваш код
  MyApp.exe                   apphost: нативний запускач (MyApp на Linux)
  MyApp.deps.json             залежності і де їх шукати
  MyApp.runtimeconfig.json    спільний фреймворк і версія, на якій запускатися
  Serilog.dll                 збірки пакетів NuGet
```

`runtimeconfig.json` каже хосту завантажити, наприклад, `Microsoft.NETCore.App` 10.0. За замовчуванням застосунок запускається на **найновішому встановленому патчі** цієї мажорної версії (10.0.x), тож щомісячне оновлення безпеки середовища виконання доходить до нього без перезбирання. На новішу мажорну версію він не переходить, якщо ви не дозволите це через `<RollForward>Major</RollForward>` або `LatestMajor`.

## Способи розгортання

| Режим | Як | Результат |
| --- | --- | --- |
| **Framework-dependent** (залежний від фреймворку) | `dotnet publish` | малий; потребує відповідного середовища виконання на машині; той самий вивід працює на будь-якій ОС |
| **Self-contained** (самодостатній) | `dotnet publish -r linux-x64 --self-contained` | несе власне середовище виконання (близько 70 МБ); нічого не треба встановлювати; окрема збірка під кожну платформу |
| **Single file** (один файл) | `-p:PublishSingleFile=true` | один виконуваний файл, який достатньо скопіювати |
| **Trimmed** (обрізаний) | `-p:PublishTrimmed=true` | прибирає невикористаний код із самодостатнього застосунку; може зламати рефлексію |
| **ReadyToRun** | `-p:PublishReadyToRun=true` | заздалегідь скомпільований код для швидшого старту |
| **Native AOT** | `<PublishAot>true</PublishAot>` | один нативний виконуваний файл, без JIT, найшвидший старт |
| **Образ контейнера** | `dotnet publish -t:PublishContainer` | образ OCI без написання Dockerfile (.NET 8+) |

**Ідентифікатор середовища виконання** (runtime identifier, RID) називає платформу: `win-x64`, `linux-x64`, `linux-musl-x64` (Alpine), `linux-arm64`, `osx-arm64`.

## Відповідь для співбесіди

SDK потрібен для збирання (CLI, компілятори, MSBuild, NuGet), а середовище виконання — для запуску; серверу потрібне лише середовище виконання. Збирання створює збірку застосунку разом із `deps.json` і `runtimeconfig.json`, які кажуть хосту, які залежності і який спільний фреймворк завантажувати; застосунок переходить на найновіший патч своєї мажорної версії. Framework-dependent розгортання мале, але потребує встановленого середовища виконання; self-contained несе середовище виконання для однієї платформи; обрізання, один файл, ReadyToRun і Native AOT міняють гнучкість збирання на розмір і швидкість старту.
