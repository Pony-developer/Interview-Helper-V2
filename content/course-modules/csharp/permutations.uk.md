**Перестановка** — це впорядкування всіх елементів множини. Для `a, b, c` їх шість: `abc`, `acb`, `bac`, `bca`, `cab`, `cba`. Для `n` елементів їх **n!**: `n` виборів для першої позиції, `n − 1` для другої і так далі.

| n | n! |
| --- | --- |
| 3 | 6 |
| 5 | 120 |
| 8 | 40 320 |
| 10 | 3 628 800 |
| 12 | 479 001 600 |
| 15 | близько 1.3 · 10¹² |
| 20 | близько 2.4 · 10¹⁸ |

Факторіал зростає швидше за все, що ми бачили. Перебирати всі перестановки реалістично лише для приблизно `n ≤ 10` чи 11.

## Побудова порядку позиція за позицією

Рекурсивна думка: оберіть, **який елемент іде першим**, а потім розташуйте **решту** усіма можливими способами.

```csharp
static void Permute(string prefix, string rest, List<string> result)
{
    if (rest.Length == 0)                    // нічого розміщувати
    {
        result.Add(prefix);
        return;
    }
    for (int i = 0; i < rest.Length; i++)
    {
        // беремо rest[i] як наступний елемент і лишаємо інші
        Permute(prefix + rest[i], rest.Remove(i, 1), result);
    }
}

var result = new List<string>();
Permute("", "abc", result);
```

`result` — це `abc, acb, bac, bca, cab, cba` саме в такому порядку: для кожного вибору першої літери решту розташовано в тому самому порядку.

Дерево рішень для `abc`:

```text
                 ("", "abc")
            /        |        \
        a            b          c
    ("a","bc")   ("b","ac")  ("c","ab")
      /    \       /    \       /    \
    ab      ac   ba      bc   ca      cb
   ("ab","c")  ...
     |
    abc
```

## Те саме з прапорцями «використано»

Для більших вхідних даних і для масивів дешевше не створювати нові рядки. Тримайте **один** спільний масив, що позначає, які елементи вже використано, і **спільний** префікс. Це класичне **повернення назад** (backtracking): зробіть вибір, рекурсивно викличте й **скасуйте** вибір.

```csharp
static void Permute(string letters, bool[] used, string prefix, List<string> result)
{
    if (prefix.Length == letters.Length)
    {
        result.Add(prefix);
        return;
    }
    for (int i = 0; i < letters.Length; i++)
    {
        if (used[i]) continue;               // уже в префіксі

        used[i] = true;                      // робимо вибір
        Permute(letters, used, prefix + letters[i], result);
        used[i] = false;                     // СКАСОВУЄМО його для інших гілок
    }
}
```

Останній рядок — серце повернення назад. Після рекурсивного виклику елемент має знову стати доступним, бо **наступна** ітерація циклу починає іншу гілку, у якій цьому елементові дозволено стояти на поточній позиції.

Якщо забути `used[i] = false;`, перестановок не вистачатиме: перша гілка вичерпає літери для всіх.

## Обмін на місці

Інший спосіб: переставляти **масив** обмінами й по черзі ставити кожен елемент на поточну позицію.

```csharp
static void Permute(int[] a, int position, List<string> result)
{
    if (position == a.Length)
    {
        result.Add(string.Join(" ", a));
        return;
    }
    for (int i = position; i < a.Length; i++)
    {
        Swap(a, position, i);                // обираємо a[i] для позиції
        Permute(a, position + 1, result);
        Swap(a, position, i);                // скасовуємо
    }
}
```

Він не використовує додаткової пам'яті, але порядок результатів **не** лексикографічний.

## Вартість

Результатів `n!`, і кожен будується чи копіюється за `n` кроків: загалом близько **O(n · n!)**. Глибина рекурсії лише `n`, тож пам'ять стека не проблема. Проблема — кількість результатів.

## Дублікати

Коли деякі елементи рівні, `"aab"` має лише **3** різні перестановки, а не 6. Два поширені розв'язки:

- **Відсортуйте** літери й пропускайте в циклі літеру, якщо вона дорівнює попередній **і попередню не використано** на цій позиції:

```csharp
if (i > 0 && letters[i] == letters[i - 1] && !used[i - 1]) continue;
```

- Або покладіть усі результати в `HashSet<string>`, щоб прибрати дублікати (просто, але все одно генерує всі `n!`).

## Де це використовується

- **Перебір** усіх порядків: задача комівояжера для малої кількості міст, розклад завдань, порядок операцій.
- **Головоломки**: анаграми, криптарифми (`SEND + MORE = MONEY`), задача про N ферзів (перестановка стовпчиків).
- **Тестування** кожного порядку деяких вхідних даних.

## Наступна перестановка без рекурсії

Порядок перестановок у списку вище називається **лексикографічним**. Є короткий цикл, що створює наступну перестановку в цьому порядку безпосередньо з поточної (це ідея за `std::next_permutation` у C++):

1. Знайдіть найбільше `i`, таке що `a[i] < a[i + 1]`. Якщо такого немає, це була остання перестановка.
2. Знайдіть найбільше `j`, таке що `a[j] > a[i]`.
3. Поміняйте місцями `a[i]` та `a[j]`.
4. Обверніть частину після позиції `i`.

Це дає змогу проходити перестановки по одній, не зберігаючи всі.
