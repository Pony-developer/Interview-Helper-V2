Властивості вміють більше, ніж «повернути поле». Ось шаблони, якими ви користуватиметеся постійно.

## Обчислювані властивості

Для властивості поле зовсім не потрібне. Вона може **обчислювати** значення з інших даних:

```csharp
class Rectangle
{
    public int Width { get; }
    public int Height { get; }

    public Rectangle(int width, int height) { Width = width; Height = height; }

    public int Area => Width * Height;                      // обчислюється щоразу, коли її читають
    public bool IsSquare => Width == Height;
}
```

`=>` тут — скорочена форма `{ get { return ...; } }`. Велика перевага: значення **не може застаріти**. Якби `Area` було збереженим полем, кожна зміна `Width` потребувала б перерахунку, а одне забуте оновлення дає хибну відповідь. Обчислювана властивість завжди правильна, бо їй немає чого синхронізувати.

```csharp
// збережений варіант: пастка
public int Area;                                            // хто оновить його, коли зміниться Width?
```

## Різний доступ для `get` і `set`

Дві частини можуть мати різні рівні доступу. Найкорисніша комбінація: **читають усі, пише лише клас**:

```csharp
class Counter
{
    public int Value { get; private set; }                  // зовнішній код не може її змінити

    public void Increment() { Value++; }                    // змінює лише клас
}
```

```csharp
var c = new Counter();
c.Increment();
Console.WriteLine(c.Value);                                  // 1
// c.Value = 100;                                            // помилка: метод доступу set недоступний
```

## Перевірка, нормалізація та логіка «змінилося»

Сеттер — добре місце не лише для перевірок, а й для **зберігання даних у зручному вигляді**:

```csharp
private string name = "";

public string Name
{
    get { return name; }
    set
    {
        if (string.IsNullOrWhiteSpace(value))
        {
            throw new ArgumentException("The name cannot be empty", "value");
        }
        name = value.Trim();                                 // завжди без зайвих пробілів
    }
}
```

Тримайте сеттер **коротким**. Важка робота всередині робить простий рядок `x.Name = "..."` повільним і несподіваним.

## Ініціалізатори об'єктів

Коли клас має властивості з сеттерами, об'єкт можна створити й заповнити одним виразом:

```csharp
var order = new Order { Quantity = 2, PricePerItem = 9.99m };
```

Це викликає конструктор без параметрів, а потім кожен `set`, **тож перевірки все одно працюють**. Якщо якесь значення погане, виняток виходить тут. Наступна лекція показує, коли краще конструктор із параметрами.

## Статичні властивості

Властивість може бути `static`: вона належить класові, а не об'єкту. Наприклад, `DateTime.Now`, `Environment.NewLine`, `Math.PI` (константа). Вживайте їх для значень, що **не залежать від конкретного об'єкта**.

## Властивості в інтерфейсах

Інтерфейс теж може вимагати властивість:

```csharp
interface IShape
{
    double Area { get; }                                     // той, хто реалізує, обирає: обчислювана чи збережена
}
```

## Рецепт

1. Почніть з **автовластивості**: `public int X { get; set; }`.
2. Якщо значення не повинно змінюватися ззовні, зробіть `{ get; private set; }` або `{ get; }`.
3. Якщо його треба перевіряти, перетворіть на **повну властивість** з полем-сховищем.
4. Якщо його можна обчислити, зробіть **обчислюваною** і приберіть поле.

На всіх кроках код, що **вживає** властивість, залишається тим самим.
