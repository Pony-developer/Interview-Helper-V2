Виключення всередині задачі не зупиняє програму одразу. Задача зберігає виключення і завершується у стані **з помилкою** (faulted). Виключення з'являється, коли хтось дивиться на результат:

```csharp
static async Task<int> DivideAsync(int a, int b)
{
    await Task.Delay(10);
    return a / b;                             // DivideByZeroException, коли b дорівнює 0
}

Task<int> bad = DivideAsync(1, 0);
// програма тут не падає: виключення зберігається в задачі
```

## Як виключення виходить назовні

- `await bad` перекидає **початкове** виключення, тож звичайний `try/catch` працює:

```csharp
try
{
    int value = await DivideAsync(1, 0);
}
catch (DivideByZeroException)
{
    Console.WriteLine("cannot divide");
}
```

- `bad.Result` і `bad.Wait()` кидають `AggregateException`, що обгортає початкове. Його `InnerException` — справжня помилка, а `Flatten()` дає всі вони, коли їх кілька.

## Кілька задач: WhenAll

`Task.WhenAll` чекає на кожну задачу, і якщо кілька впали, виключення, яке він кидає, містить **усі** помилки. Очікування результату кидає лише першу, тож щоб побачити кожну невдачу, перевіряйте задачі по одній або використайте властивість `Exception` від `Task.WhenAll(...)`.

## Перехоплення кожної невдачі окремо

Коли одна невдача не має зупиняти інші, перехоплюйте всередині кожної задачі:

```csharp
static async Task<int> SafeDivideAsync(int a, int b)
{
    try
    {
        return await DivideAsync(a, b);
    }
    catch (DivideByZeroException)
    {
        return 0;                             // невдача стає звичайним значенням
    }
}
```

## Правило

Очікування задачі — звичайний спосіб обробити її виключення. Ніколи не ігноруйте виключення задачі: задача, яку ніхто не очікує і яка падає, повністю приховує свою помилку.
