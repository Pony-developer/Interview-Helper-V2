`IEnumerable<T>` і `IQueryable<T>` виглядають схоже, і обидва працюють з методами LINQ, як `Where` і `Select`. Але роботу вони виконують у **різних місцях**, і для баз даних ця різниця дуже важлива.

## IEnumerable: робота відбувається у вашій програмі

`IEnumerable<T>` виконує запит **у пам'яті**. Кожен `Where` — це функція, яку ваша програма викликає для кожного елемента:

```csharp
IEnumerable<int> numbers = new[] { 5, 12, 7, 30 };
IEnumerable<int> big = numbers.Where(n => n > 10);   // лямбда виконується в цій програмі
Console.WriteLine(string.Join(" ", big.ToArray())); // 12 30
```

Дані мають уже бути в пам'яті (або надходити через `yield return`, як показують наступні лекції).

## IQueryable: запит перекладається

`IQueryable<T>` **не** виконує лямбду. Він записує запит як **дерево виразу** (expression tree): структуру даних, що описує `n => n > 10`. **Провайдер** (наприклад, Entity Framework) читає це дерево й перекладає його на запит до бази даних:

```csharp
IQueryable<Order> orders = db.Orders.Where(o => o.Total > 100);
// Доступу до бази ще немає: запит лише описано.

List<Order> result = orders.ToList();
// Тепер провайдер будує SQL, приблизно: SELECT ... FROM Orders WHERE Total > 100
// Мережею надходять лише рядки, що пасують.
```

З `IEnumerable` база передала б **усі** замовлення вашій програмі, а програма відфільтрувала б їх сама. З `IQueryable` фільтр виконується всередині бази даних.

## Той самий синтаксис, два значення

```csharp
var a = list.Where(o => o.Total > 100);     // IEnumerable: виконується тут, елемент за елементом
var b = db.Orders.Where(o => o.Total > 100); // IQueryable: стає SQL пізніше
```

Код виглядає однаково. Тип вирішує, де він виконується. Тому метод, що приймає запит, має уважно вибирати тип параметра.

## Чого не вміє IQueryable

Провайдер розуміє лише вирази, які вміє перекласти. Виклик вашого власного методу C# усередині запиту зазвичай дає помилку:

```csharp
static bool IsLarge(Order o) { return o.Total > 100; }

db.Orders.Where(o => IsLarge(o));    // зазвичай помилка: провайдер не перекладе IsLarge
db.Orders.Where(o => o.Total > 100); // добре: перекладається в SQL
```

## Перехід між ними

- `AsEnumerable()` перетворює `IQueryable` на `IEnumerable`. Усе після нього виконується в пам'яті. Вживайте його свідомо, коли база не може виконати останній крок.
- `ToList()` або `ToArray()` **виконують** запит і повертають результати.

`IQueryable<T>` походить від `IEnumerable<T>`, тож `IQueryable` можна використати всюди, де очікують `IEnumerable`. Зворотне неправильне: у `IEnumerable` немає провайдера.

## Практичне правило

Вживайте `IEnumerable<T>` як тип **параметра** методу, що лише читає дані. Вживайте `IQueryable<T>`, коли викликаючий має мати змогу додати ще фільтри, які виконає **база даних**.
