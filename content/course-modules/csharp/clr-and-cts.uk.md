**CLR** (Common Language Runtime, загальномовне середовище виконання) — це віртуальна машина, яка виконує код .NET. Код, що працює під її контролем, називають **керованим** (managed); усе інше (операційна система, бібліотеки на C++) — **некерований** або **нативний** код.

## Що робить CLR

- **Завантажує збірки** і будує в пам'яті опис їхніх типів (завантажувач типів).
- **Компілює IL** у нативний код за допомогою JIT (див. попередній урок).
- **Керує пам'яттю**: розміщує об'єкти в керованій купі і звільняє їх збирачем сміття.
- **Забезпечує типобезпеку**: не можна вважати `string` масивом `int[]`, прочитати за межами масиву чи викликати метод на неправильному типі; порушення стають винятками (`InvalidCastException`, `IndexOutOfRangeException`), а не пошкодженням пам'яті.
- **Обробляє винятки**: розкручує стек, виконує блоки `finally`, знаходить відповідний `catch`.
- **Керує потоками**: пул потоків, синхронізація, продовження `async`.
- **Взаємодіє з нативним кодом**: P/Invoke (`[DllImport]`, `[LibraryImport]`) і COM interop.

Реалізацій кілька: оригінальний CLR із .NET Framework, **CoreCLR** із .NET Core і .NET 5+, середовище виконання **Mono** (мобільні платформи і WebAssembly), а також маленьке середовище, яке Native AOT вбудовує у виконуваний файл. Усі вони дотримуються одного стандарту — **ECMA-335** (Common Language Infrastructure, CLI).

## Спільна система типів (CTS)

**CTS** (Common Type System) визначає, що таке тип, для кожної мови .NET: класи, структури, інтерфейси, переліки, делегати; поля, методи, властивості, події; видимість; правила наслідування (один базовий клас, багато інтерфейсів).

Її головний поділ:

- **Значущі типи** (value types) походять від `System.ValueType`: `int`, `double`, `bool`, `DateTime`, будь-яка `struct` чи `enum`. Змінна містить саме значення.
- **Посилальні типи** (reference types): класи, інтерфейси, масиви, делегати, `string`. Змінна містить посилання на об'єкт у купі.

Кожен тип, зокрема значущий, зрештою походить від `System.Object`. Тому `int` можна передати як `object` (його **упаковують**, boxing, в об'єкт у купі).

## Ключові слова C# — це псевдоніми

Вбудовані назви типів C# — лише ключові слова для типів CTS:

| C# | Тип CTS | | C# | Тип CTS |
| --- | --- | --- | --- | --- |
| `int` | `System.Int32` | | `bool` | `System.Boolean` |
| `long` | `System.Int64` | | `char` | `System.Char` |
| `double` | `System.Double` | | `decimal` | `System.Decimal` |
| `string` | `System.String` | | `object` | `System.Object` |

`int` і `System.Int32` — **той самий тип**: той самий IL, той самий розмір (завжди 32 біти, на будь-якому процесорі). Зазвичай пишуть ключове слово. `DateTime`, `Guid` і `List<T>` ключових слів не мають.

## Загальномовна специфікація (CLS)

**CLS** (Common Language Specification) — це підмножина CTS, яку зобов'язана підтримувати кожна мова .NET. Бібліотеку, що дотримується її у своєму **публічному** API, можна використовувати з будь-якої мови. Наприклад, у CLS немає беззнакових цілих (`uint`, `ulong`) і не можна мати двох публічних імен, що відрізняються лише регістром. З `[assembly: CLSCompliant(true)]` компілятор C# попереджає про порушення.

## Узагальнення реальні під час виконання

В IL узагальнений тип має свою арність в імені: `List<T>` — це `` List`1 ``, `Dictionary<TKey, TValue>` — це `` Dictionary`2 ``. На відміну від Java, аргументи типу **не стираються**: `List<int>` і `List<string>` — різні типи під час виконання, і рефлексія бачить `int` усередині `List<int>`.

```csharp
Console.WriteLine(typeof(List<int>).Name);                         // List`1
Console.WriteLine(typeof(List<int>) == typeof(List<string>));      // False
Console.WriteLine(typeof(List<int>).GetGenericArguments()[0]);     // System.Int32
Console.WriteLine(typeof(int?) == typeof(Nullable<int>));          // True
```

`int?` так само — лише синтаксис C# для узагальненої структури `Nullable<int>`.

## Ізоляція: AppDomain більше немає

.NET Framework міг розділити один процес на кілька **AppDomain** і вивантажувати їх. У сучасному .NET AppDomain лише один; для плагінів, які треба завантажувати й вивантажувати, є **`AssemblyLoadContext`**. Для справжньої ізоляції використовуйте окремі процеси чи контейнери.

## Відповідь для співбесіди

CLR — це середовище виконання .NET: воно завантажує збірки, компілює IL через JIT, керує пам'яттю за допомогою GC, забезпечує типобезпеку, обробляє винятки й потоки і викликає нативний код. CTS визначає типи, спільні для всіх мов .NET, з поділом на значущі й посилальні, і всі вони походять від `System.Object`; ключові слова C# на кшталт `int` — псевдоніми типів CTS на кшталт `System.Int32`. CLS — це підмножина CTS, якою бібліотека має обмежити свій публічний API, щоб ним могла користуватися будь-яка мова.
