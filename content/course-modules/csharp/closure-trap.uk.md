Найпоширеніша помилка із замиканнями: лямбда захоплює **змінну циклу**, і всі лямбди ділять одну й ту саму змінну.

```csharp
var actions = new List<Action>();
for (int i = 0; i < 3; i++)
{
    actions.Add(() => Console.Write(i + " "));
}

foreach (Action a in actions)
{
    a();                                 // 3 3 3, а не 0 1 2
}
```

Кожна лямбда захоплює **ту саму** змінну `i`, яка одна для всього циклу. Коли цикл закінчується, `i` дорівнює 3, і кожна лямбда друкує 3.

## Виправлення: копія всередині циклу

Створіть нову змінну всередині кожної ітерації й захоплюйте її:

```csharp
for (int i = 0; i < 3; i++)
{
    int copy = i;                        // нова змінна на кожній ітерації
    actions.Add(() => Console.Write(copy + " "));
}
// 0 1 2
```

Тепер кожна ітерація має власний `copy`, і кожна лямбда тримає свій.

## foreach працює інакше

Починаючи з C# 5, змінна циклу `foreach` — нова змінна на кожній ітерації, тож пастки там немає:

```csharp
foreach (int n in new[] { 0, 1, 2 })
{
    actions.Add(() => Console.Write(n + " "));
}
// 0 1 2
```

Обережним треба бути з циклом `for`.

## Інші місця, де з'являється пастка

- лямбда в циклі, що захоплює змінну, оголошену поза циклом і змінювану в ньому;
- обробники подій, створені в циклі;
- завдання чи потоки, запущені в циклі без передачі значення як аргумента.

## Правило

Коли лямбда виконається пізніше, а змінна, яку вона захоплює, може змінитися, спершу скопіюйте змінну в нову локальну. Запитайте себе: «яке значення побачить ця лямбда, коли виконається?»
