Хеш-коди `GetHashCode` швидкі, але вони **не безпечні**. Їх створено, щоб розподіляти значення в таблиці, а не для захисту від зловмисника. Для безпеки хеш має бути **криптографічним**, наприклад SHA-256:

```csharp
using System.Security.Cryptography;
using System.Text;

byte[] data = Encoding.UTF8.GetBytes("password123");
using (SHA256 sha = SHA256.Create())
{
    byte[] hash = sha.ComputeHash(data);
    Console.WriteLine(BitConverter.ToString(hash));   // 64 шістнадцяткові цифри, 32 байти
}
```

## Три властивості криптографічного хешу

- **Стійкість до прообразу:** маючи хеш, практично неможливо знайти вхід, що його дає.
- **Стійкість до другого прообразу:** маючи вхід, практично неможливо знайти інший вхід з тим самим хешем.
- **Стійкість до колізій:** практично неможливо знайти будь-які два входи з однаковим хешем.

Крихітна зміна входу повністю змінює результат: `"password123"` і `"password124"` дають хеші, які виглядають не пов'язаними. Це **лавинний ефект**.

## Де їх використовують

- **Зберігання паролів:** сервер зберігає хеш, а не пароль. Коли користувач входить, сервер хешує введений пароль і порівнює. Викрадена база тоді не розкриває паролі (принаймні не прямо).
- **Перевірка, що файл не змінено:** завантаження поставляється з його SHA-256 хешем, і ви обчислюєте хеш отриманого файлу.
- **Цифрові підписи й сертифікати.**

## Паролям потрібно більше, ніж простий хеш

Два користувачі з однаковим паролем отримають однаковий хеш, а зловмисники готують таблиці хешів поширених паролів. Тому пароль хешують разом із випадковою **сіллю** (salt), яка зберігається поруч із хешем. Спеціальні функції хешування паролів (наприклад PBKDF2, bcrypt чи Argon2) також повторюють роботу тисячі разів, щоб підбирання було повільним.

## Головне

`GetHashCode` — для хеш-таблиць усередині програми. Криптографічний хеш — для безпеки, і він набагато повільніший. Ніколи не використовуйте `GetHashCode` для захисту даних.
