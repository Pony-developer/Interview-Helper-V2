«Поліморфізм» означає «багато форм», і в C# це слово охоплює **три різні механізми**. Їх часто плутають, тому варто їх розділити.

## 1. Перевантаження: вибір під час компіляції

Кілька методів з **однаковою назвою** і **різними параметрами**. Компілятор вибирає один із них **під час компіляції** за **оголошеними типами** аргументів:

```csharp
static string Show(int n) { return "int:" + n; }
static string Show(double d) { return "double:" + d; }
static string Show(string s) { return "string:" + s; }
static string Show(object o) { return "object:" + o; }

Console.WriteLine(Show(5));            // int:5
Console.WriteLine(Show(5.5));          // double:5.5
Console.WriteLine(Show("hi"));         // string:hi

object o = "hi";
Console.WriteLine(Show(o));            // object:hi    <- оголошений тип object, хоча об'єкт — рядок
```

Останній рядок найважливіший: для перевантаження **справжній тип об'єкта не має значення**. Компілятор знає лише, що `o` оголошено як `object`, і вибирає `Show(object)`.

Як вирішує компілятор:

1. Він бере всі методи з такою назвою, чиї параметри **приймають** аргументи (типи збігаються або є неявне перетворення).
2. Серед них він вибирає **найкращий**: той, що потребує «меншого» перетворення. Точний збіг — найкращий. Якщо `int` можна перетворити на `double`, а `double` на `int` не можна, то для значення `int` кращий цільовий тип — `int`.
3. Якщо **єдиного найкращого** методу немає, це помилка компіляції («The call is ambiguous»).

```csharp
Show('x');        // char: перетворюється на int (і на double, і на object); найкращий int -> "int:120"
Show(5L);         // long: перетворюється на double та object, а на int ні; кращий double -> "double:5"
```

Тип значення, що повертається, і **назви** параметрів у виборі не беруть участі. Два методи не можуть відрізнятися **лише** типом значення, що повертається.

## 2. Перевизначення: вибір під час виконання

Метод `virtual` у базовому класі, а **похідні класи його замінюють**. Вибір робиться **під час роботи програми** за **справжнім типом** об'єкта:

```csharp
Animal a = new Dog();
Console.WriteLine(a.Sound());          // версія з Dog, хоча оголошений тип — Animal
```

Це протилежність перевантаженню: тут **оголошений тип не має значення**, а **справжній** — має. Саме це зазвичай мають на увазі під «поліморфізмом» в об'єктно-орієнтованому програмуванні. Його також називають **поліморфізмом підтипів**: похідний об'єкт можна вжити всюди, де очікують базовий.

| | Перевантаження | Перевизначення |
|---|---|---|
| Вибір робиться | Компілятором, до запуску | Середовищем виконання, під час запуску |
| Залежить від | **Оголошених** типів аргументів | **Справжнього** типу об'єкта |
| Потребує | Однакова назва, різні параметри | `virtual` / `abstract` і `override` або інтерфейс |
| Також називають | Статичним або «ad hoc» поліморфізмом | Динамічним або поліморфізмом підтипів |

## 3. Узагальнення: один код для багатьох типів

Третій вид — **параметричний поліморфізм**. Код пишуть один раз **для будь-якого типу**, який є параметром:

```csharp
List<int> numbers = new List<int>();
List<string> words = new List<string>();      // той самий клас List<T>, з різними T

static T Larger<T>(T a, T b) where T : IComparable<T>
{
    return a.CompareTo(b) >= 0 ? a : b;
}
Console.WriteLine(Larger(3, 7));              // 7
Console.WriteLine(Larger("pear", "apple"));   // pear
```

Ви щодня користуєтеся узагальненнями в колекціях. Написання власних узагальнених методів і класів — тема для пізніше, але пам'ятайте, що `List<T>` і `Dictionary<K, V>` теж є поліморфізмом.

## Пастка: перевантаження, змішане з успадкуванням

```csharp
class Animal { }
class Dog : Animal { }

static string Describe(Animal a) { return "animal"; }
static string Describe(Dog d) { return "dog"; }

Animal pet = new Dog();
Console.WriteLine(Describe(pet));              // animal! Оголошений тип — Animal
Console.WriteLine(Describe(new Dog()));        // dog
```

Програміст, що чекає «dog», думає про **перевизначення**, а написав **перевантаження**. Якщо поведінка залежить від об'єкта, зробіть її **віртуальним методом** об'єкта (`pet.Describe()`), а не покладайтеся на перевантаження зовнішньої функції.

## Необов'язкові параметри й перевантаження

У C# є також **типові значення** параметрів: `static void Print(string text, int times = 1)`. Вони — альтернатива парі перевантажень (`Print(text)` і `Print(text, times)`) і коротші, коли друга форма лише підставляє типове значення. Вживайте перевантаження, коли відрізняється **поведінка**, а типові значення — коли бракує лише **значення**.

## Оператори — теж перевантаження

`a + b` для чисел і `a + b` для рядків — це два різні методи, які компілятор вибирає за типами. Для власних типів можна визначати оператори (`public static Vector operator +(Vector a, Vector b)`), як у практичній задачі про вектори. Це знову вибір **під час компіляції**.
