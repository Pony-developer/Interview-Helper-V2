Тип значення, що повертає метод, визначає, що викликаючий може робити з `async`-методом:

| Тип значення | Викликаючий може | Винятки |
|---|---|---|
| `async Task` | `await` його, чекати, поєднати з `WhenAll` | доходять до викликаючого |
| `async Task<T>` | `await` його і отримати значення | доходять до викликаючого |
| `async void` | лише запустити й забути | **зупиняють програму**, якщо їх не перехопили всередині |

## Чому async void небезпечний

```csharp
static async void Risky()
{
    await Task.Delay(10);
    throw new InvalidOperationException("boom");   // ніхто не може це перехопити
}

Risky();                                  // викликаючий не отримує задачу для спостереження
```

Виняток виникає в пулі потоків, коли ніхто не чекає, тож його не можна перехопити, і процес завершується. `async void` також не дає способу дізнатися, коли робота завершилась.

## Єдине дозволене місце

Обробники подій мають сигнатуру `void Handler(object sender, EventArgs e)`, тому обробники кнопок WinForms і WPF — `async void`. Усередині них перехоплюйте кожен виняток, що може статися, бо нічого вище за обробник його не перехопить.

```csharp
private async void saveButton_Click(object sender, EventArgs e)
{
    try
    {
        await SaveAsync();
    }
    catch (Exception ex)
    {
        MessageBox.Show(ex.Message);       // обробляємо тут, інакше застосунок падає
    }
}
```

## Очікування в потоці UI: взаємне блокування

`task.Result` або `task.Wait()` у потоці UI блокують його. Якщо код, на який чекають, хоче повернутися в потік UI, щоб продовжити, обидва чекатимуть один на одного вічно. Всередині `async`-методу завжди використовуйте `await`, а не блокування.

## ConfigureAwait

`await task.ConfigureAwait(false)` каже, що коду не потрібно повертатися в початковий контекст (наприклад, у потік UI). Бібліотечний код його використовує, щоб уникнути взаємного блокування та зайвої роботи. Код застосунку у вікні зазвичай потребує контексту UI, тож лишайте типову поведінку.
