У потоку UI є одна робота, яку він ніколи не має припиняти: він обробляє повідомлення від користувача (кліки, введення тексту, малювання вікна). Якщо він виконує довгу операцію, то не може обробляти ці повідомлення, і вікно **завмирає**: не перемальовується, не реагує, а Windows може показати «Не відповідає».

```csharp
// обробник кнопки WinForms. Цей код не виконується в консолі.
private void calculateButton_Click(object sender, EventArgs e)
{
    Thread.Sleep(5000);                     // вікно завмерло на п'ять секунд
    resultLabel.Text = "done";
}
```

## Що відбувається під час завмирання

- вікно перестає перемальовуватися, тож коли над ним перетягують інше вікно, лишається порожня ділянка;
- кліки й натискання клавіш стають у чергу, а потім виконуються всі разом, коли потік звільняється;
- користувач думає, що програма зламалася.

## Наївне виправлення не працює

Перенесення роботи у фоновий потік і запис результату напряму в `resultLabel.Text` — помилка: з міткою може працювати лише потік UI. Наступні лекції показують правильні способи: `BeginInvoke` для маршалінгу, `BackgroundWorker` для роботи з прогресом і `async/await` для сучасного стилю.

## Правило

Тримайте потік UI вільним. Кожна операція довша за приблизно 50 мілісекунд має виконуватися деінде, а її результат має повертатися в потік UI безпечним каналом.
