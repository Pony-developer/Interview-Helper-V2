Порівнювати цілі числа просто: `3 == 3` істинне, `3 == 4` хибне. З `double` та `float` ситуація інша.

## Чому `==` підводить

Комп'ютери зберігають числа у двійковому вигляді. Багато десяткових дробів, як-от `0.1`, не мають точного двійкового запису, так само як `1/3` не має точного десяткового. `double` зберігає найближче значення, яке може, і в обчислення закрадаються крихітні похибки:

```csharp
Console.WriteLine(0.1 + 0.2 == 0.3);     // False
Console.WriteLine(0.1 + 0.2);            // 0.30000000000000004 у сучасному .NET
Console.WriteLine(1.0 - 0.9 == 0.1);     // False
Console.WriteLine(0.5 + 0.25 == 0.75);   // True, бо ці числа у двійковому вигляді точні
```

(Старіші середовища виконання округлюють відображення до 15 цифр і показують `0.3`, але порівняння все одно `False`.)

Похибка мала, десь на 16-й значущій цифрі, але `==` вимагає, щоб кожен біт збігався. Тому **не** порівнюйте значення `double` через `==` чи `!=`, коли вони є результатами обчислень.

## Порівнюйте з допуском

Вирішіть, наскільки близько означає «досить рівні», і перевіряйте, що різниця менша:

```csharp
const double Epsilon = 1e-9;   // 0.000000001

static bool AreEqual(double a, double b)
{
    return Math.Abs(a - b) < Epsilon;
}

Console.WriteLine(AreEqual(0.1 + 0.2, 0.3));   // True
```

`1e-9` — це експоненційний запис числа 10⁻⁹. Допуск залежить від задачі: для відстаней у метрах цілком вистачить `1e-6` (мікрометр).

Для дуже великих чи дуже малих чисел абсолютний допуск вводить в оману: різниця `0.001` величезна поруч із `0.0001` і нікчемна поруч із `1e12`. Тоді порівнюйте **відносну** різницю:

```csharp
Math.Abs(a - b) <= 1e-9 * Math.Max(Math.Abs(a), Math.Abs(b))
```

## Інший підхід: спершу округлити

Якщо вас цікавлять лише два знаки після коми, округліть обидва значення перед порівнянням:

```csharp
Math.Round(a, 2) == Math.Round(b, 2)
```

Це годиться для питань на рівні відображення, але має особливі випадки біля межі округлення, тож допуск зазвичай надійніший.

## Гроші: використовуйте decimal

`decimal` зберігає десяткові дроби точно, тому підходить для цін і залишків:

```csharp
Console.WriteLine(0.1m + 0.2m == 0.3m);   // True
```

Він повільніший за `double` і не має `Math.Sin` та подібного, тож беріть його для грошей, а не для фізики.

## Нерівності — не проблема

`<`, `>`, `<=` та `>=` не потребують допуску, коли крихітна похибка не змінює рішення. Але якщо значення може опинитися просто на межі (результат на кшталт `2.9999999999999996`, де ви очікуєте `3`), порівняння може хибно хитнутися в інший бік. Подумайте про граничний випадок і додайте допуск, якщо це важливо.

## Особливі значення

- `double.NaN` («не число», з `0.0 / 0`) не дорівнює нічому, **навіть собі**: `double.NaN == double.NaN` — це `False`. Перевіряйте через `double.IsNaN(x)`.
- Ділення ненульового `double` на нуль дає `double.PositiveInfinity` або `double.NegativeInfinity`. Перевіряйте через `double.IsInfinity(x)`.
- `double`, що містить ціле число, як-от `3.0`, точний, і `d == 3` спрацює. Проблеми починаються з результатів обчислень.
