Писати новий тип делегата для кожного випадку — нудно. Фреймворк надає дві родини узагальнених делегатів, які покривають майже всі потреби:

- **`Func<..., TResult>`**: метод, що **повертає** значення. `Func<int, int, int>` приймає два int і повертає int.
- **`Action<...>`**: метод, що **нічого не повертає** (`void`). `Action<string>` приймає рядок.

```csharp
Func<int, int, int> add = (a, b) => a + b;     // повертає int
Action<string> print = s => Console.WriteLine(s);   // нічого не повертає

Console.WriteLine(add(2, 3));                  // 5
print("hello");                                // hello
```

Останній параметр типу `Func` завжди є типом значення, що повертається. Кожен попередній — параметр. `Action` має лише параметри. Обидві родини мають версії для від 0 до 16 параметрів:

| Тип | Значення |
|---|---|
| `Func<TResult>` | без параметрів, повертає `TResult` |
| `Func<T, TResult>` | один параметр типу `T` |
| `Action` | без параметрів, нічого не повертає |
| `Action<T1, T2>` | два параметри, нічого не повертає |

## Навіщо їх вживати

- Не треба оголошувати тип делегата для кожної сигнатури: `Func<int, bool>` достатньо для «перевірки int».
- Інший код і бібліотеки одразу розуміють їх, бо вони спільні.
- `Predicate<T>` — те саме, що `Func<T, bool>`, а `Comparison<T>` — те саме, що `Func<T, T, int>`, хоча методи списків використовують власні назви.

## Практичне правило

Якщо делегат повертає значення, використовуйте `Func`. Якщо ні — `Action`. Оголошуйте власний тип делегата лише тоді, коли його назва робить код зрозумілішим: наприклад, `delegate int Operation(int a, int b);` каже читачеві більше, ніж `Func<int, int, int>`.
