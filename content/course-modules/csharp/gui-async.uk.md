Виправлення для завислого вікна — виконувати довгу роботу **асинхронно**: потік UI запускає роботу і одразу повертається до обробки повідомлень, а результат приходить пізніше, коли він готовий.

Шаблон має три частини:

1. Потік UI запускає роботу в іншому потоці (або в пулі потоків).
2. Робота повідомляє про прогрес або результат.
3. Повідомлення доставляється в потік UI, який оновлює елементи керування.

```csharp
// WinForms, ілюстрація. Робота виконується в потоці пулу, оновлення — у потоці UI.
private void calculateButton_Click(object sender, EventArgs e)
{
    resultLabel.Text = "working...";
    Task.Run(() => Compute())                       // запускаємо в іншому потоці
        .ContinueWith(t => resultLabel.Text = t.Result.ToString(),
                      TaskScheduler.FromCurrentSynchronizationContext());   // доставляємо в потік UI
}

private int Compute()
{
    Thread.Sleep(5000);                             // тепер безпечно: потік UI продовжує працювати
    return 42;
}
```

## Важливі ідеї

- Обробник кнопки повертається швидко, тож вікно лишається чутливим протягом п'яти секунд.
- `TaskScheduler.FromCurrentSynchronizationContext()` змушує продовження виконатися в потоці UI, де можна змінювати мітку.
- Асинхронну роботу в інтерфейсі також називають фоновою: програма продовжує показувати вікно та його прогрес.

Наступна лекція показує ту саму ідею, записану через `async` і `await`, що тримає код в одному читабельному шматку.
