Досі ви змушували проходити чужі тести. Тепер тести пишете ви, а програма перевіряє, **наскільки вони добрі**.

`Clamp(value, min, max)` обмежує число діапазоном: повертає `min`, якщо значення нижче за нього, `max`, якщо вище, і саме значення в іншому разі.

У `Main` є **сім реалізацій** `Clamp`. Одна правильна, а шість мають типову помилку:

| Назва | Помилка |
| --- | --- |
| `ClampCorrect` | немає |
| `NoLowerBound` | забуває підняти значення, що занадто мале |
| `NoUpperBound` | забуває знизити значення, що занадто велике |
| `ExclusiveMax` | трактує `max` так, ніби воно недопустиме: повертає `max - 1` |
| `SwappedBounds` | повертає `max` для малого значення й `min` для великого |
| `ReturnsMinInside` | повертає `min`, коли значення всередині діапазону |
| `WrongLowerValue` | повертає `min + 1` для занадто малого значення |

Ваше завдання — метод `TestsAccept(clamp)`. Він отримує реалізацію, яку можна викликати як звичайний метод, `clamp(5, 0, 10)`, і запускає для неї **ваші власні тести**. Він повертає `true`, якщо **всі** ваші тести проходять для цієї реалізації, і `false`, щойно один провалюється.

Добрий набір тестів:

- **приймає** правильну реалізацію, тобто жоден тест не очікує хибної відповіді;
- **відхиляє** кожну із шести хибних.

`Main` друкує вердикт для кожної реалізації. `Main` не змінюйте. Очікуваний вивід:

```text
ClampCorrect: accepted
NoLowerBound: rejected
NoUpperBound: rejected
ExclusiveMax: rejected
SwappedBounds: rejected
ReturnsMinInside: rejected
WrongLowerValue: rejected
```

Початковий код приймає все, бо в ньому немає тестів. Додайте їх:

```csharp
if (clamp(5, 0, 10) != 5) return false;     // значення всередині діапазону лишається без змін
```

Подумайте, які **види вхідних даних** виявляють кожну помилку: значення всередині діапазону, нижче за нього, вище за нього та рівно на кожній межі. Це те саме мислення, що й у лекціях про більше тестів і про покриття: добрий тест — той, що падає, коли код хибний.
