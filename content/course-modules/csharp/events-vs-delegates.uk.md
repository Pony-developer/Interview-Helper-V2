Подія і делегат — обидва «список методів для виклику». Різниця — хто що може робити з цим списком.

| | Поле-делегат | Подія |
|---|---|---|
| Підписка через `+=` | так | так |
| Відписка через `-=` | так | так |
| Присвоєння через `=` ззовні | так: замінює **всіх** підписників | ні |
| Виклик ззовні | так | ні |
| Читання списку ззовні | так | ні |

## Чому ця різниця важлива

Припустімо, клас публікує поле-делегат замість події:

```csharp
class Market
{
    public Action<decimal> PriceChanged;     // поле: будь-хто може робити з ним що завгодно
}

var market = new Market();
market.PriceChanged += p => Console.WriteLine("chart: " + p);
market.PriceChanged = p => Console.WriteLine("only me: " + p);   // графік мовчки зник
market.PriceChanged.Invoke(10m);                                 // сторонні можуть підняти подію
```

Другий рядок видаляє всіх інших підписників, а третій піднімає подію, яку сам ринок ніколи не піднімав. З `event` обидва рядки — помилки компіляції.

## Що обрати

- **Події** — коли інші класи підписуються й не мусять заважати одне одному.
- **Поле-делегат або властивість типу делегата** — коли один об'єкт дає одну поведінку, яку можна замінити, наприклад порівняння, яким користується клас сортування. Стратегія — це делегат; сповіщення — подія.
