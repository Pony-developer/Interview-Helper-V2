Іноді блок `catch` щось робить (пише в лог, прибирає за собою), а потім пропускає виняток далі. Є три способи це зробити, і лише два з них правильні.

## `throw;` проти `throw ex;`

```csharp
try
{
    LoadOrders();
}
catch (Exception ex)
{
    logger.Log("Loading failed");
    throw;        // правильно: той самий виняток іде далі з початковим стеком викликів
    // throw ex;  // неправильно: стек викликів тепер починається ТУТ, справжнє місце втрачено
}
```

`throw ex;` кидає той самий об'єкт знову, але скидає його `StackTrace` до поточного рядка. У лозі буде видно, що помилка сталася в блоці `catch`, а не глибоко в `LoadOrders`, де вона насправді сталася. Це одне з найчастіших питань про винятки на співбесідах.

## Обгортання: додаємо контекст

Низькорівневий виняток часто нічого не означає на вищому рівні. `SqlException: timeout` не каже, **яка** операція не вдалася. Обгорніть його винятком свого шару і передайте оригінал як `InnerException`:

```csharp
try
{
    return repository.Load(userId);
}
catch (DbException ex)
{
    throw new UserLoadException("Cannot load user " + userId, ex);   // ex стає InnerException
}
```

`ToString()` нового винятку друкує весь ланцюжок — внутрішній виняток після `--->` — з обома стеками викликів. Ніколи не обгортайте, не передавши внутрішній виняток: так ви викидаєте причину.

Обгортайте на **межах шарів** (шар даних, зовнішній сервіс), а не в кожному методі.

## Повторне кидання пізніше: `ExceptionDispatchInfo`

Щоб кинути перехоплений виняток пізніше, з іншого місця, не втративши стек викликів:

```csharp
ExceptionDispatchInfo saved = null;
try { Work(); }
catch (Exception ex) { saved = ExceptionDispatchInfo.Capture(ex); }
// ... пізніше
saved?.Throw();   // початковий стек збережено, з позначкою, де виняток кинуто повторно
```

Саме цим механізмом `await` повторно кидає виняток задачі.

## Два антипатерни

- **Ковтання**: `catch (Exception) { }` ховає помилки. Програма працює далі в зламаному стані, і ніхто не знає чому.
- **Лог і повторне кидання на кожному рівні**: одна помилка з'являється в лозі п'ять разів. Або обробіть виняток (запишіть у лог **і** зупиніть його), або пропустіть його вгору. Пишіть у лог один раз — там, де його остаточно оброблено.

## Правило

Використовуйте `throw;`, щоб пропустити виняток далі, обгортайте його з внутрішнім винятком, щоб додати контекст на межі шару, і ніколи не пишіть `throw ex;`.
