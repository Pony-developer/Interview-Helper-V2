Помилка компіляції означає, що компілятор не зміг зрозуміти ваш код, тож програми не з'явилося взагалі. Це найкращий різновид помилок: ви дізнаєтеся про неї одразу, а компілятор вказує, де вона.

## Як читати повідомлення

```text
prog.cs(7,19): error CS0103: The name 'Course' does not exist in the current context
```

- `prog.cs(7,19)`: файл, рядок 7, стовпчик 19.
- `error`: помилка блокує збирання. **Попередження** (warning) не блокує (про це нижче).
- `CS0103`: стабільний код помилки. Формулювання повідомлення в різних компіляторах може відрізнятися, а код лишається тим самим, і за ним можна знайти сторінку документації.

Позиція вказує, де компілятор **помітив** проблему, а це іноді на рядок пізніше за місце, де ви помилилися. Якщо загубилася крапка з комою, дивіться на кінець **попереднього** рядка.

## Спершу виправляйте першу помилку

Одна помилка може збити компілятор, і він неправильно прочитає все далі та видасть десяток помилок. Виправте **першу**, скомпілюйте знову й подивіться ще раз. Нерідко більшість решти зникає.

## Помилки, які трапляються найчастіше

| Код | Типове повідомлення | Звична причина |
| --- | --- | --- |
| `CS1002` | `; expected` | забули крапку з комою |
| `CS1026` | `) expected` | не закрито дужку |
| `CS1513` | `} expected` | не закрито фігурну дужку |
| `CS0103` | the name does not exist in the current context | одруківка в імені змінної, інший регістр літер або використання поза її областю видимості |
| `CS0117`, `CS1061` | type does not contain a definition for `X` | одруківка в імені методу: `Console.Writeline` замість `Console.WriteLine` |
| `CS0246` | type or namespace name could not be found | одруківка в назві типу або відсутній `using` |
| `CS0029` | cannot implicitly convert type | значення не того типу, наприклад `string`, присвоєний `int` |
| `CS0165` | use of unassigned local variable | змінну читають до того, як вона отримала значення |
| `CS0161` | not all code paths return a value | метод із типом результату може завершитися без `return` |
| `CS1501`, `CS7036` | неправильна кількість аргументів | виклик не відповідає параметрам методу |

Пам'ятайте, що C# **чутливий до регістру**: `Console.writeline`, `console.WriteLine` та `Console.WriteLine` — це три різні імена.

## Попередження

Попередження означає «це компілюється, але виглядає підозріло»:

```csharp
int unused = 5;   // warning CS0219: assigned but its value is never used
```

Не ігноруйте попередження. Вони часто вказують на справжню помилку, наприклад на змінну, яку ви хотіли використати. Хороша звичка — збирати проєкт без жодного попередження.

## Звички, що запобігають помилкам компіляції

- Пишіть потроху, компілюйте, повторюйте. Одну нову помилку знайти легко; серед п'ятдесяти нових рядків — важко.
- Користуйтеся редактором: він підкреслює помилки червоним, поки ви друкуєте, і підказує імена.
- Закривайте кожну `(`, `{` та `"` одразу, щойно відкрили.
- Тримайте форматування охайним. Правильні відступи роблять пропущену дужку помітною.
