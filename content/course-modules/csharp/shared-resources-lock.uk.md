Коли два потоки змінюють одну змінну, результат може бути хибним. Розгляньмо `counter++`, що насправді складається з трьох кроків: прочитати, додати, записати. Два потоки можуть прочитати те саме старе значення і обидва записати його плюс один:

```csharp
int counter = 0;

var a = new Thread(() => { for (int i = 0; i < 100000; i++) counter++; });
var b = new Thread(() => { for (int i = 0; i < 100000; i++) counter++; });
a.Start(); b.Start();
a.Join(); b.Join();
Console.WriteLine(counter);             // часто менше за 200000: інкременти загубилися
```

Ця ситуація називається **гонкою** (race condition): результат залежить від часу роботи потоків.

## lock: один потік одночасно

Оператор `lock` дозволяє виконувати блок лише одному потоку одночасно. Потоки ділять приватний об'єкт, який слугує замком:

```csharp
int counter = 0;
object sync = new object();              // приватний об'єкт, що слугує лише замком

var a = new Thread(() => { for (int i = 0; i < 100000; i++) { lock (sync) counter++; } });
var b = new Thread(() => { for (int i = 0; i < 100000; i++) { lock (sync) counter++; } });
a.Start(); b.Start();
a.Join(); b.Join();
Console.WriteLine(counter);              // завжди 200000
```

## Правила для замків

- Блокуйте на **приватному, readonly** об'єкті, щоб жоден інший код не заблокував його помилково.
- Тримайте заблокований блок **коротким**. Інші потоки чекають, поки ви тримаєте замок.
- Не викликайте повільні операції (файли, мережа, введення користувача) всередині замка.
- Для одного інкременту `Interlocked.Increment(ref counter)` швидший і не потребує замка.

## Взаємне блокування (deadlock)

Якщо потік A тримає замок 1 і чекає на замок 2, а потік B тримає замок 2 і чекає на замок 1, обидва чекають вічно. Це **взаємне блокування**. Звичайне ліки — завжди брати кілька замків в одному порядку.
