`NullReferenceException` — найпоширеніший виняток у C#. Його першопричина в тому, що будь-яка змінна посилального типу може містити `null`, а тип не каже, чи це очікувано. **Nullable reference types** (C# 8) дають типу змогу це сказати.

## Як увімкнути

У файлі проєкту (у нових проєктах це ввімкнено за замовчуванням):

```xml
<Nullable>enable</Nullable>
```

або в одному файлі: `#nullable enable`. Після цього:

- `string` означає «ніколи не null»;
- `string?` означає «може бути null».

```csharp
string name = null;          // попередження CS8600: null у змінну, що не допускає null
string? nickname = null;     // усе гаразд

Console.WriteLine(nickname.Length);   // попередження CS8602: можливе розіменування null

if (nickname != null)
    Console.WriteLine(nickname.Length);   // гаразд: компілятор знає, що тут не null
```

Компілятор стежить за потоком виконання: після перевірки на `null`, після `is not null`, після присвоєння він знає, які змінні безпечні.

У класі властивість, що не допускає null, має отримати значення в конструкторі, інакше буде попередження CS8618. Розв'язують це `required` або значення за замовчуванням.

## Лише перевірка під час компіляції

На відміну від `int?`, який є справжнім окремим типом (`Nullable<int>`), `string?` і `string` під час виконання — **той самий тип**. Ця можливість лише видає **попередження**. Код, що їх ігнорує, код без цієї можливості або дані з JSON і баз даних однаково можуть покласти `null` туди, де оголошено `string`. Тож публічні методи все одно перевіряють аргументи.

Багато команд перетворюють ці попередження на помилки: `<WarningsAsErrors>nullable</WarningsAsErrors>`.

## Оператори-помічники

```csharp
int? length = user?.Address?.City?.Length;   // ?. зупиняється на першому null і дає null
string city = user?.Address?.City ?? "unknown";   // ?? дає запасне значення для null
cache ??= new Dictionary<string, int>();          // ??= присвоює, лише якщо там null
string sure = FindName()!;                        // ! «я знаю, що тут не null»: вимикає попередження
```

Оператор `!` (null-forgiving) нічого не робить під час виконання: він лише вимикає попередження. Кожен `!` — обіцянка, яку доведеться дотримати, тож використовуйте його рідко.

## Атрибути для аналізу

Іноді компілятор не бачить логіки, і атрибути з `System.Diagnostics.CodeAnalysis` йому підказують:

```csharp
public bool TryFind(int id, [NotNullWhen(true)] out User? user) { ... }

if (TryFind(5, out var user))
    Console.WriteLine(user.Name);   // без попередження: true означає, що user не null
```

Інші: `[MaybeNull]`, `[NotNull]`, `[MemberNotNull(nameof(field))]`.

## Як увімкнути в старому проєкті

Вмикайте файл за файлом через `#nullable enable`, починаючи з коду з найменшою кількістю залежностей, і виправляйте попередження поступово.

## Правило

Пишіть `?` там, де `null` — допустиме значення, і більше ніде; нехай компілятор знаходить місця, де ви забули перевірку; і все одно перевіряйте аргументи публічних методів, бо ця перевірка існує лише під час компіляції.
