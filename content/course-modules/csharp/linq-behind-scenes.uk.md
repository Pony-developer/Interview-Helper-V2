LINQ здається магією, але механізм простий: кожен метод — **ітератор**, побудований через `yield return`, а запит — ланцюжок таких ітераторів, кожен огортає попередній. Читання результату проштовхує елементи через весь ланцюжок.

## Як працює Where приблизно

```csharp
static IEnumerable<T> MyWhere<T>(IEnumerable<T> source, Func<T, bool> keep)
{
    foreach (T item in source)
    {
        if (keep(item))
        {
            yield return item;
        }
    }
}
```

`Where` майже точно такий. Під час виклику `Where` нічого не фільтрується; цикл працює лише тоді, коли викликаючий починає читати.

## Відкладене виконання

```csharp
var numbers = new List<int> { 1, 2, 3 };
var big = numbers.Where(n => n > 1);          // нічого не виконано

numbers.Add(10);                              // джерело змінилося
Console.WriteLine(big.Count());               // 3: 2, 3 і 10, читаються зараз
```

Запит виконується **щоразу**, коли його читають. Два цикли `foreach` по `big` двічі запускають фільтр. Збережіть результат через `ToList()`, коли потрібен фіксований знімок.

## Захоплені змінні

Лямбда LINQ може використовувати змінну ззовні (лекція про замикання це пояснювала). Змінну читають у момент виконання запиту, а не тоді, коли запит написали:

```csharp
int limit = 2;
var q = numbers.Where(n => n > limit);
limit = 9;
Console.WriteLine(q.Count());                 // використовує limit = 9
```

## Приховані витрати

- Запит із `Where` над великим файлом читає файл щоразу, коли його перелічують.
- `Count()` над запитом `Where` читає все, навіть якщо треба знати лише «чи є хоч один».
- `GroupBy`, `OrderBy` і `ToLookup` читають усе джерело, перш ніж віддати перший елемент.

## IQueryable

З базою даних ті самі методи можуть працювати з `IQueryable`. Тоді запит перекладається на SQL і виконується базою, як пояснювала лекція про `IEnumerable` і `IQueryable`. Код виглядає так само, але робота відбувається деінде.

## Практичні правила

1. Прочитайте запит один раз у список, коли результати потрібні більше ніж раз.
2. Не змінюйте джерело посеред побудови запиту, якщо ви не хочете, щоб зміна з'явилася в результатах.
3. Віддавайте перевагу одному проходу замість кількох: `Any`, `Count`, `Sum` кожен читає всю послідовність.
