Стек — природний інструмент для **перевірки дужок**. Кожна відкриваюча дужка чекає в стеку. Закриваюча дужка мусить відповідати **найновішій** відкритій, а це якраз те, що дає LIFO.

Текст `(a + [b * {c}])` правильний, а `(a + [b)]` — ні:

```csharp
static bool IsBalanced(string text)
{
    var open = new Stack<char>();
    foreach (char c in text)
    {
        if (c == '(' || c == '[' || c == '{')
        {
            open.Push(c);                         // чекаємо на закриваючу дужку
        }
        else if (c == ')' || c == ']' || c == '}')
        {
            if (open.Count == 0)
            {
                return false;                     // закриваюча дужка без відкритої
            }
            char last = open.Pop();
            if (!Matches(last, c))
            {
                return false;                     // закрили не ту дужку
            }
        }
    }
    return open.Count == 0;                       // те, що лишилося відкритим, — помилка
}

static bool Matches(char open, char close)
{
    return (open == '(' && close == ')')
        || (open == '[' && close == ']')
        || (open == '{' && close == '}');
}
```

Розгляньмо `([)]`: `(` і `[` кладуться в стек. Приходить `)`, але на верхівці `[`, тож `Matches` не спрацьовує, і відповідь `false`. Одного лічильника недостатньо, бо він побачив би дві відкриваючі й дві закриваючі дужки.

## Чому стек, а не лічильник

Лічильник каже, **скільки** дужок відкрито, але не **які**. Стек зберігає порядок, а порядок вирішує, чи правильно вкладені дужки. Цей шаблон є в компіляторах (перевірка коду), у редакторах (підсвічування) і в розбирачах формул.
