Тепер застосуймо правила. Читайте код, знайдіть, що таке `n`, знайдіть цикли й стежте за вартістю, прихованою у викликах методів.

## Метод оцінювання

1. **Що таке `n`?** Довжина масиву, довжина тексту, розмір числа?
2. **Які цикли залежать від `n`?** Порахуйте проходи кожного.
3. **Вкладені чи послідовні?** Множте або додавайте.
4. **Скільки коштують виклики?** `Contains`, `Sort`, `Substring`, доступ до словника...
5. **Який випадок?** Найгірший, якщо питання не каже іншого.
6. **Лишіть домінантний доданок** і відкиньте сталі.

## Приклади для практики

**A.** Один прохід.

```csharp
int max = a[0];
for (int i = 1; i < a.Length; i++)
    if (a[i] > max) max = a[i];
```

**O(n)**.

**B.** Цикл, потім ще один (не вкладений).

```csharp
for (int i = 0; i < n; i++) Step1();
for (int i = 0; i < n; i++) Step2();
```

n + n = 2n, отже **O(n)**.

**C.** Кожна пара.

```csharp
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        Compare(a[i], a[j]);
```

n(n − 1)/2 проходів: **O(n²)**.

**D.** Лічильник подвоюється.

```csharp
for (int i = 1; i < n; i *= 2)
    Work();
```

**O(log n)**.

**E.** Лінійний цикл із логарифмічним усередині.

```csharp
for (int i = 0; i < n; i++)
    for (int j = 1; j < n; j *= 2)
        Work();
```

**O(n log n)**.

**F.** Внутрішній цикл обмежений зовнішнім, але той ділиться навпіл.

```csharp
for (int i = n; i >= 1; i /= 2)
    for (int j = 0; j < i; j++)
        Work();
```

Внутрішній цикл виконується `n`, потім `n/2`, потім `n/4`, ...: сума `n + n/2 + n/4 + ... < 2n`. Це **O(n)**, а не O(n log n): пастка, якої слід уникати.

**G.** Цикл до квадратного кореня.

```csharp
for (int d = 2; d * d <= n; d++)
    if (n % d == 0) return false;
```

**O(√n)**.

**H.** Три вкладені цикли.

```csharp
for (i...n) for (j...n) for (k...n) Work();
```

**O(n³)**.

## Приховані витрати в бібліотеці

| Виклик | Складність |
| --- | --- |
| `array[i]`, `list[i]` | O(1) |
| `list.Add(x)` | O(1) амортизовано |
| `list.Insert(0, x)`, `list.RemoveAt(0)` | O(n): зсуває елементи |
| `list.Contains(x)`, `list.IndexOf(x)` | O(n) |
| `list.Sort()`, `Array.Sort(a)` | O(n log n) |
| `Array.BinarySearch` (відсортований) | O(log n) |
| `dict[key]`, `dict.ContainsKey(key)`, `set.Contains(x)` | O(1) у середньому |
| `string.Length`, `s[i]` | O(1) |
| `s.Contains(t)`, `s.IndexOf(t)`, `s.Substring(a, b)` | O(довжина) |
| `s + t` | O(довжина s + довжина t) |

«**Амортизовано**» O(1) означає, що один виклик іноді може бути дорогим (списку потрібно зрости), але вартість, **усереднена за багатьма викликами**, стала.

## Приклади з прихованою вартістю

**I.** Пошук у списку всередині циклу.

```csharp
foreach (int x in a)
    if (list.Contains(x)) count++;      // Contains — це O(m)
```

**O(n · m)**, тобто O(n²), коли розміри схожі. З `HashSet` замість списку — **O(n + m)**.

**J.** Складання рядка.

```csharp
string s = "";
for (int i = 0; i < n; i++)
    s += "x";                           // копіює весь s на кожному проході
```

Копії мають довжини 1, 2, ..., n, тож **O(n²)**. З `StringBuilder` — **O(n)**.

**K.** Спершу сортування.

```csharp
Array.Sort(a);                          // O(n log n)
for (int i = 1; i < n; i++)             // O(n)
    if (a[i] == a[i - 1]) return true;
return false;                           // разом: O(n log n)
```

Пошук дублікатів через попереднє сортування — O(n log n), краще за порівняння кожної пари, що є O(n²). `HashSet` робить це за O(n) у середньому.

**L.** Рекурсія.

```csharp
static long Fib(int n) => n < 2 ? n : Fib(n - 1) + Fib(n - 2);
```

Кожен виклик робить ще два, тож кількість викликів зростає експоненційно: близько 1.6ⁿ, що ми записуємо як **O(2ⁿ)**. З циклом, що пам'ятає два останні числа, — **O(n)**.

**M.** Рекурсія з діленням навпіл.

```csharp
static int Count(int n) => n <= 1 ? 0 : 1 + Count(n / 2);
```

**O(log n)** викликів.

## Найкращий, найгірший, середній

```csharp
static int IndexOf(int[] a, int value)
{
    for (int i = 0; i < a.Length; i++)
        if (a[i] == value) return i;
    return -1;
}
```

Найкращий випадок O(1), найгірший O(n), середній близько n/2, тобто O(n). Коли ми кажемо «лінійний пошук — O(n)», ми маємо на увазі найгірший випадок.

## Простір

Додаткову пам'ять рахують так само:

- кілька змінних: O(1);
- новий масив чи список розміру `n`: O(n);
- таблиця `n × n`: O(n²);
- рекурсія, що йде на `n` рівнів углиб, використовує O(n) стека.
