**LINQ** (Language Integrated Query) — це набір методів для роботи з колекціями: фільтрувати їх, перетворювати, сортувати й групувати. Замість циклу з `if` і тимчасовим списком ви описуєте, **що** хочете отримати:

```csharp
int[] numbers = { 3, 8, 5, 10, 1, 6 };

// спосіб з циклом
var evens = new List<int>();
foreach (int n in numbers)
{
    if (n % 2 == 0) evens.Add(n * n);
}

// спосіб LINQ: той самий результат, описаний одним рядком
var evenSquares = numbers.Where(n => n % 2 == 0).Select(n => n * n).ToList();
```

Обидва дають `64, 100, 36`. Версія з LINQ читається як опис результату: візьми парні числа, піднеси їх до квадрата, зроби список.

## Два синтаксиси

LINQ можна писати в **синтаксисі методів** (вище) або в **синтаксисі запитів**, який схожий на SQL:

```csharp
var evenSquares = from n in numbers
                  where n % 2 == 0
                  select n * n;
```

Компілятор перетворює синтаксис запитів на виклики методів, тож обидва однакові. Більшість програмістів використовує синтаксис методів: він працює з будь-яким методом і будь-яким оператором, і його легше ланцюжити.

## Звідки береться LINQ

Методи — **методи розширення** `IEnumerable<T>`, визначені в `System.Linq`. Будь-яка колекція, що реалізує `IEnumerable<T>`, їх отримує: масиви, списки, словники, рядки і ваші власні ітератори. Тому модуль про `yield return` був важливим: запит LINQ будується з ітераторів.

```csharp
using System.Linq;
```

## Головна ідея

Метод LINQ не змінює колекцію, до якої його викликали. Він повертає **нову послідовність**, що описує результат. Справжня робота відбувається під час читання послідовності. Лекція «Що залишилось за кадром» пояснює це докладно.
