`Equals` вирішує, чи рівні два об'єкти. Його типова поведінка слабка: для класу він порівнює **посилання**, тобто «чи це той самий об'єкт». Для класів, що поводяться як значення, його треба перевизначити, щоб він порівнював **вміст**:

```csharp
class Point
{
    public int X;
    public int Y;

    public override bool Equals(object obj)
    {
        Point other = obj as Point;      // null, якщо obj не Point
        if (other == null) return false;
        return X == other.X && Y == other.Y;
    }

    public override int GetHashCode()
    {
        return X * 31 + Y;               // мусить узгоджуватися з Equals (наступні лекції пояснюють чому)
    }
}

var a = new Point { X = 1, Y = 2 };
var b = new Point { X = 1, Y = 2 };
Console.WriteLine(a.Equals(b));          // True
Console.WriteLine(a == b);               // False: == досі порівнює посилання, див. нижче
```

## Правила коректного Equals

- **Рефлексивність:** `a.Equals(a)` дорівнює `true`.
- **Симетричність:** `a.Equals(b)` дає ту саму відповідь, що й `b.Equals(a)`.
- **Транзитивність:** якщо `a` дорівнює `b`, а `b` дорівнює `c`, то `a` дорівнює `c`.
- **Узгодженість:** відповідь не змінюється, поки об'єкти не змінюються.
- **Безпечність щодо null:** `a.Equals(null)` дорівнює `false` і ніколи не кидає виняток.

Перевірка `obj as Point` з подальшим `if (other == null)` виконує останні два правила.

## Equals і ==

`Equals` і `==` — окремі речі. Якщо ви не визначили оператор `==`, клас для `==` використовує порівняння посилань. Список, `Contains` і словники викликають `Equals`, тож `Contains` тепер знаходить рівну точку. Оператор `==` розглядається в наступних лекціях.
