Підписка утримує підписника живим. Видавець тримає посилання на кожен обробник, тож поки подія існує, підписника не може прибрати збирач сміття, навіть якщо ніхто інший його не використовує. Це найпоширеніша помилка з подіями — **витік пам'яті**.

```csharp
class Logger
{
    public Logger(Button button)
    {
        button.Clicked += OnClicked;       // тепер кнопка посилається на цей логер
    }

    private void OnClicked() { Console.WriteLine("click"); }
}

var button = new Button();                  // видавець живе довго
for (int i = 0; i < 1000; i++)
{
    var logger = new Logger(button);        // кожен логер підписаний і ніколи не відписується
}
// 1000 логерів лишаються в пам'яті, і кожен досі виконується на кожному кліку
```

## Виправлення: відписка

Видаліть обробник через `-=`, з тією самою групою методів:

```csharp
class Logger : IDisposable
{
    private readonly Button button;

    public Logger(Button button)
    {
        this.button = button;
        button.Clicked += OnClicked;
    }

    private void OnClicked() { Console.WriteLine("click"); }

    public void Dispose()
    {
        button.Clicked -= OnClicked;       // кнопка більше не тримає цей логер живим
    }
}
```

Шаблон той самий, що й для інших ресурсів: підписника створюють, використовують і потім звільняють.

## Лямбду не можна прибрати новою лямбдою

Лямбда створює новий об'єкт делегата щоразу, коли її записують, тож `-=` з новою лямбдою нічого не видаляє. Тримайте посилання на обробник, якщо може знадобитися відписка:

```csharp
Action handler = () => Console.WriteLine("click");
button.Clicked += handler;
button.Clicked -= handler;                  // працює: видаляється той самий об'єкт
```

## Чому це важливо

Забута підписка робить три речі одночасно: тече пам'ять, продовжується робота для об'єкта, який уже не використовують, і може викликатися обробник, що залежить від уже звільнених об'єктів.
