**Статичний клас** — це клас, що має лише статичні члени. Об'єкт такого класу ви ніколи не створюєте: це **контейнер для функцій** та констант, що належать разом.

```csharp
static class Geometry
{
    public const double Pi = 3.14159;

    public static double CircleArea(double radius) => Pi * radius * radius;
    public static double Hypotenuse(double a, double b) => Math.Sqrt(a * a + b * b);
}

Console.WriteLine(Geometry.CircleArea(2));      // 12.56636
```

## Правила

- Ключове слово `static` перед `class`.
- **Усі** його члени мають бути `static` (компілятор це перевіряє).
- Створити об'єкт не можна: `new Geometry()` — помилка.
- Його не можна **успадковувати**, і він не може успадковувати інший клас (окрім `object`).
- Він може мати **статичний конструктор** для налаштування своїх статичних даних.

Відомі статичні класи: `Math`, `Console`, `Convert`, `File`, `Directory`, `Path`, `Array`, `Enumerable` (LINQ).

## Для чого вони

**1. Чисті функції.** Обчислення, що залежать лише від своїх аргументів: без стану, та сама відповідь для тих самих даних.

```csharp
static class MathTools
{
    public static int Gcd(int a, int b) => b == 0 ? a : Gcd(b, a % b);
    public static bool IsPrime(int n) { /* ... */ return true; }
}
```

**2. Константи**, згруповані під назвою:

```csharp
static class Limits
{
    public const int MaxNameLength = 50;
    public const int MaxRetries = 3;
}
```

**3. Методи розширення**, які **мусять** жити в статичному класі (див. попередні лекції).

**4. Фабрики та помічники**, що створюють чи перетворюють об'єкти:

```csharp
static class Converters
{
    public static Point FromText(string text) { /* розібрати "3,4" */ return null; }
}
```

## Слово застереження: ціна статичного

Статичні класи легко писати, і їх спокусливо використовувати надто часто. З ними приходять три проблеми.

**1. Прихований глобальний стан.** Якщо статичний клас має **змінювані статичні поля**, це глобальна змінна в маскуванні:

```csharp
static class Session
{
    public static string CurrentUser;       // будь-хто може змінити її звідки завгодно
}
```

Поведінка іншого коду тепер залежить від того, що **хтось інший** зробив раніше. Звідси беруться помилки типу «окремо працює, а в програмі падає».

**2. Важко тестувати.** Метод, що **напряму** викликає `File.ReadAllText`, `DateTime.Now` чи `Console.ReadLine`, не можна протестувати без справжнього файлу, справжнього годинника й справжньої людини за клавіатурою. Зі статичним класом його не можна замінити підробкою.

**3. Важко розширювати.** Статичний клас не може реалізувати інтерфейс, не може бути переданий як аргумент і не може бути замінений іншою реалізацією.

## Коли статичний клас — правильний інструмент

- Функції **чисті**, без стану й залежностей: `Math`, `Gcd`, `Distance`.
- Дані **константні**.
- Це набір **методів розширення**.
- Це **невеликий** помічник, який не може розумно варіюватися.

## Коли він неправильний

Коли є **стан**, що змінюється, **залежність** від зовнішнього світу (файл, база даних, годинник, мережа) або можливо уявити **кілька реалізацій**. Тоді користуйтеся **звичайним класом**, який ви створюєте й передаєте далі.

## Рефакторинг статичного класу у звичайний

Статичний клас часто росте, накопичуючи **стан**, який методи передають одне одному або ділять через статичні поля. Типові симптоми:

- той самий параметр передається в **кожен** метод (`Bank.Deposit(balance, amount)`, `Bank.Withdraw(balance, amount)`);
- кілька статичних методів працюють зі **спільною** статичною змінною;
- ви хотіли б мати **два** таких із окремими даними й не можете.

Ліки — перетворити параметр, що повторюється, і спільні дані на **поля об'єкта**, а статичні методи — на **методи екземпляра**.

До:

```csharp
static class Bank
{
    public static decimal Deposit(decimal balance, decimal amount) => balance + amount;
    public static decimal Withdraw(decimal balance, decimal amount) => balance - amount;
}

decimal balance = 100;
balance = Bank.Deposit(balance, 50);        // той, хто викликає, мусить носити баланс
balance = Bank.Withdraw(balance, 30);
```

Після:

```csharp
class Account
{
    public decimal Balance { get; private set; }

    public Account(decimal balance) { Balance = balance; }

    public void Deposit(decimal amount) { Balance += amount; }
    public bool Withdraw(decimal amount)
    {
        if (amount > Balance) return false;
        Balance -= amount;
        return true;
    }
}

var account = new Account(100);
account.Deposit(50);                        // об'єкт носить власний баланс
account.Withdraw(30);
```

Переваги:

- дані та правила для них — в **одному місці**;
- можна забезпечити **інваріанти** (баланс не може впасти нижче нуля);
- можна мати **багато** рахунків, кожен із власними даними;
- клас **легко тестувати**: створіть об'єкт, викличте метод, перевірте властивість.

Кроки рефакторингу:

1. Знайдіть **дані**, які методи ділять або постійно передають: це стан нового класу.
2. Створіть клас із цими даними в полях (властивостях) і **конструктором**.
3. Перенесіть статичні методи, приберіть параметр, що повторюється, і зробіть їх методами екземпляра.
4. Оновіть тих, хто викликає: створіть об'єкт і викликайте методи на ньому.
5. Зберігайте поведінку тією самою й перевіряйте її **після кожного кроку**.

## Одинак: золота середина

Іноді справді має бути **один** екземпляр, як-от об'єкт налаштувань. Шаблон **одинака** (singleton) дає один об'єкт звичайного класу зі статичним доступом до нього:

```csharp
class AppSettings
{
    public static AppSettings Instance { get; } = new AppSettings();
    private AppSettings() { }                 // ніхто інший не може створити
    public string Theme { get; set; } = "light";
}

Console.WriteLine(AppSettings.Instance.Theme);
```

Це все одно глобальний стан, тож користуйтеся ним дуже помірковано. Передавати об'єкт тим, кому він потрібен (**впровадження залежностей**), чистіше, і саме так роблять сучасні застосунки .NET.

## Підсумок

- Статичний клас — це **контейнер статичних членів**, що не створюється.
- Він правильний для **чистих функцій, констант і методів розширення**.
- Він неправильний для **стану** і для **залежностей**: користуйтеся звичайним класом.
- Для рефакторингу перетворіть параметр, що повторюється, на **поля**, а статичні методи — на **методи екземпляра**.
