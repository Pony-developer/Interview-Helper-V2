Розбір тексту через `Substring` і `Split` створює новий рядок для кожного шматка. На сервері, що розбирає мільйони рядків, це мільйони об'єктів для GC. `Span<T>` (C# 7.2, .NET Core 2.1) дає змогу працювати з **частиною наявної пам'яті, не копіюючи її**.

## `Span<T>` і `ReadOnlySpan<T>`

Span — це «вікно» над неперервним блоком пам'яті: масивом, частиною масиву, рядком, пам'яттю на стеку чи нативною пам'яттю. Він зберігає лише посилання на початок і довжину.

```csharp
string date = "2024-05-17";
ReadOnlySpan<char> span = date.AsSpan();

int year  = int.Parse(span.Slice(0, 4));   // жодних нових рядків не створено
int month = int.Parse(span.Slice(5, 2));
int day   = int.Parse(span.Slice(8, 2));
```

`Slice` створює нове вікно над тією самою пам'яттю, тож нічого не коштує. Більшість методів розбору й форматування в сучасному .NET (`int.Parse`, `TryFormat`, `Encoding.GetBytes`, потоки) приймають span.

## `stackalloc`

Невеликий тимчасовий буфер може жити на стеку, де він узагалі не завдає роботи GC:

```csharp
Span<byte> buffer = stackalloc byte[256];
int written = Encoding.UTF8.GetBytes("hello", buffer);
```

Тримайте буфери на стеку малими (сотні байтів, щонайбільше кілька кілобайтів): стек має лише близько 1 МБ.

## Чому в span суворі правила

Span може вказувати на стек. Якби він міг пережити метод, то вказував би на пам'ять, яку вже використано повторно. Тому `Span<T>` — це `ref struct`, і компілятор гарантує, що він лишається на стеку:

- він не може бути полем класу чи звичайної структури;
- його не можна запакувати чи зберегти як `object`;
- його не можна захопити лямбдою;
- він не може жити через `await`.

## `Memory<T>`

Коли вікно над пам'яттю треба зберігати в полі або використовувати в `async`-методі, беріть `Memory<T>` (чи `ReadOnlyMemory<T>`). Він не має обмежень стека, бо може вказувати лише на купу. Для самої роботи беріть `memory.Span` усередині синхронного коду.

## `ArrayPool<T>`

Великі тимчасові буфери краще орендувати, ніж виділяти:

```csharp
byte[] buffer = ArrayPool<byte>.Shared.Rent(64 * 1024);
try { /* користуємося buffer; він може бути більшим, ніж просили */ }
finally { ArrayPool<byte>.Shared.Return(buffer); }
```

## Коли це все потрібно

У гарячому коді: парсерах, серіалізаторах, мережевих протоколах, високонавантажених серверах. У звичайному бізнес-коді краще простий і зрозумілий код із рядками та списками. Ці типи недоступні в компіляторі C# 7, на якому виконуються практики курсу; спробуйте їх у локальному проєкті на .NET 8.

## Правило

Спершу вимірюйте. Коли вузьке місце — виділення пам'яті, використовуйте span, щоб уникати копій, `stackalloc` — для малих буферів, а `ArrayPool` — для великих.
