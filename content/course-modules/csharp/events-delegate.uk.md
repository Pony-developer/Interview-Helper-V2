Поле-делегат і подія виглядають майже однаково, але ключове слово `event` захищає список підписників:

```csharp
class Publisher
{
    public Action Handler;                // звичайне поле-делегат
    public event Action Changed;          // подія
}

var p = new Publisher();
p.Handler = () => Console.WriteLine("a");
p.Handler = null;                         // видаляє ВСІХ обробників: зовнішній код так може
p.Handler();                              // ...і може викликати обробник напряму

// p.Changed = null;                      // помилка компіляції: подію не можна присвоїти ззовні
// p.Changed();                           // помилка компіляції: подію не можна піднімати ззовні
p.Changed += () => Console.WriteLine("b");   // дозволено: підписка
p.Changed -= () => Console.WriteLine("b");   // інша лямбда, тож це НЕ відписує (див. далі)
```

## Що ключове слово забороняє ззовні класу

- присвоювати поле через `=`, що замінило б усіх підписників;
- піднімати подію ззовні, що має робити лише видавець;
- читати список підписників як звичайне значення.

Зовнішній код може лише додавати (`+=`) і видаляти (`-=`) свій обробник. Саме це і є контракт публікації й підписки.

## Усередині класу

Усередині класу подія поводиться як поле, тож клас піднімає її через `Changed?.Invoke(...)`. Оператор `?.` пропускає виклик, коли підписників немає, і прибирає гонку, за якої останній підписник відписується між перевіркою та викликом.

## Практичне правило

Оголошуйте публічну подію щоразу, коли клас мусить повідомляти інших, і ніколи не відкривайте публічне поле-делегат для повідомлень.
