Саме середовище виконання лише виконує код; вашому коду потрібні ще й **бібліотеки**. Частина постачається разом із .NET, решта приходить із NuGet, а **цільовий фреймворк** визначає, якими з них можна користуватися.

## BCL

**Base Class Library** (базова бібліотека класів) — стандартна бібліотека, що постачається з кожним .NET: `System.Object`, `string`, примітивні типи, колекції (`System.Collections.Generic`), LINQ, файли й потоки даних (`System.IO`), потоки виконання і задачі, `HttpClient`, `System.Text.Json`, регулярні вирази, криптографія та багато іншого.

Її найглибша частина, **`System.Private.CoreLib`** (`mscorlib` у .NET Framework), прив'язана до середовища виконання: вона визначає `Object`, `String`, `Int32`, `Array`, `GC`, `Thread`. Решта лежить у звичайних збірках на кшталт `System.Collections.dll` і `System.Net.Http.dll`.

У .NET Framework BCL разом із WinForms, WPF, ASP.NET, ADO.NET та іншим називали **FCL** (Framework Class Library).

## Спільні фреймворки

Сучасний .NET встановлює BCL як **спільні фреймворки** (shared frameworks) — теки збірок, які застосунки завантажують зі встановленого середовища виконання:

| Спільний фреймворк | Містить | Хто використовує |
| --- | --- | --- |
| `Microsoft.NETCore.App` | середовище виконання і BCL | кожен застосунок |
| `Microsoft.AspNetCore.App` | ASP.NET Core, Kestrel, логування, конфігурацію, DI | вебзастосунки (`Sdk="Microsoft.NET.Sdk.Web"`) |
| `Microsoft.WindowsDesktop.App` | WinForms, WPF | десктопні застосунки, лише Windows |

`dotnet --list-runtimes` показує, які з них (і яких версій) є на машині.

## NuGet

Усе інше приходить як **пакети NuGet** з nuget.org чи приватного джерела. Пакет (`.nupkg`) — це zip-файл зі збірками в теках для кожного цільового фреймворку (`lib/net8.0/`, `lib/netstandard2.0/`) і переліком власних залежностей.

```xml
<ItemGroup>
  <PackageReference Include="Serilog" Version="4.2.0" />
</ItemGroup>
```

або `dotnet add package Serilog`. Що варто знати:

- залежності **транзитивні**: ви отримуєте й пакети, від яких залежать ваші пакети;
- `dotnet restore` завантажує пакети в глобальний кеш (`~/.nuget/packages`), а не в проєкт;
- **централізоване керування пакетами** (`Directory.Packages.props`) тримає версії всього рішення в одному файлі;
- restore попереджає про пакети з відомими вразливостями (NuGet audit), а `dotnet list package --vulnerable` / `--outdated` показує їх.

## Монікер цільового фреймворку

**TFM** (target framework moniker) у файлі проєкту каже, під який фреймворк збирається код, а отже, які API він може використовувати:

| TFM | Означає |
| --- | --- |
| `net10.0`, `net8.0` | сучасний .NET |
| `net8.0-windows` | сучасний .NET плюс API, що є лише у Windows |
| `netcoreapp3.1` | .NET Core 3.1 |
| `net48`, `net472` | .NET Framework 4.8, 4.7.2 |
| `netstandard2.0`, `netstandard2.1` | .NET Standard |

Бібліотеку можна зібрати одразу під кілька фреймворків, а відмінності розв'язати умовною компіляцією:

```xml
<TargetFrameworks>netstandard2.0;net10.0</TargetFrameworks>
```

```csharp
#if NET8_0_OR_GREATER
    return string.Create(length, state, Fill);   // швидкий сучасний API
#else
    return BuildTheOldWay(length, state);
#endif
```

## .NET Standard

**.NET Standard** — не середовище виконання, а **специфікація**: перелік API, які обіцяють мати кілька реалізацій. Бібліотека, зібрана під `netstandard2.0`, працює на всіх них:

| | .NET Standard 2.0 | .NET Standard 2.1 |
| --- | --- | --- |
| .NET Framework | 4.6.1+ (рекомендовано 4.7.2+) | **не підтримується** |
| .NET Core | 2.0+ | 3.0+ |
| .NET 5+ | так | так |
| Mono, Unity, Xamarin | так | новіші версії |

Після 2.1 нових версій .NET Standard не буде: з .NET 5 є один .NET, і цю роль грають його TFM (`net8.0`, `net10.0`). Практичне правило: нові бібліотеки збирайте під `net8.0` або новіший, а `netstandard2.0` додавайте, лише якщо ними має користуватися код на .NET Framework чи Unity.

## Хто кого може підключити

Проєкт може підключити бібліотеку, якщо кожен API, потрібний бібліотеці, є у фреймворку проєкту:

- **сучасний .NET → сучасний .NET чи .NET Core**: коли версія бібліотеки така сама або нижча (`net10.0` може використати бібліотеку під `net8.0`, але не навпаки);
- **будь-що → .NET Standard**: коли фреймворк реалізує цю версію .NET Standard (див. таблицю);
- **.NET Framework → .NET Framework**: така сама або нижча версія;
- **сучасний .NET → .NET Framework**: NuGet дозволяє це з попередженням **NU1701**; це працює, лише якщо бібліотека не використовує API, що є тільки у Windows і .NET Framework, тож це тимчасове рішення на час міграції;
- **.NET Framework → сучасний .NET**: неможливо.

## Відповідь для співбесіди

BCL — стандартна бібліотека, що постачається з .NET; у сучасному .NET вона встановлюється як спільний фреймворк `Microsoft.NETCore.App`, а ASP.NET Core і десктопні стеки Windows — як окремі спільні фреймворки. Сторонній код приходить пакетами NuGet. Монікер цільового фреймворку визначає, які API може використовувати проєкт, а отже, які бібліотеки він може підключити; .NET Standard 2.0 — спільний знаменник між .NET Framework і сучасним .NET.
