Код читають набагато частіше, ніж пишуть, і нерідко це ви самі, через півроку. **Стилістична помилка** — це не баг: програма працює. Але нечитабельний код ховає справжні баги й сповільнює кожну зміну.

Порівняйте:

```csharp
static double f(double a,double b){double c=a*b*0.2;return a*b+c;}
```

```csharp
static double PriceWithVat(double unitPrice, int quantity)
{
    const double VatRate = 0.2;

    double net = unitPrice * quantity;
    double vat = net * VatRate;
    return net + vat;
}
```

Обидва обчислюють те саме. Але зрозуміти за п'ять секунд можна лише один.

## Імена

- Типи, методи та константи пишуть у **PascalCase**: `Program`, `PriceWithVat`, `VatRate`.
- Локальні змінні та параметри — у **camelCase**: `unitPrice`, `quantity`.
- Ім'я має казати, **чим** річ є або **що** вона робить. Методи — це дієслова чи питання (`PrintReport`, `IsEven`), а змінні — іменники (`totalPrice`).
- Імена змінних типу `bool` читаються як твердження: `isReady`, `hasDiscount`.
- Уникайте однолітерних імен (окрім короткого лічильника циклу чи математичної формули), незрозумілих скорочень на кшталт `tmp2` або `cnt` та нумерованих імен, як-от `value1`, `value2`.
- Не змішуйте мови чи стилі в одному проєкті.

## Розмітка

- Одна інструкція на рядок.
- Робіть відступ у чотири пробіли для кожного блоку. У C# відкривальну `{` традиційно ставлять на окремому рядку, вирівнявши з кодом, якому належить блок.
- Лишайте порожній рядок між логічними групами інструкцій і пробіли навколо операторів: `a * b + c`.
- Тримайте рядки достатньо короткими, щоб їх можна було читати без прокрутки вбік.
- Довіряйте форматування редактору: у Visual Studio натисніть `Ctrl+K, Ctrl+D`.

## Магічні числа

**Магічне число** — це літерал, сенс якого неочевидний:

```csharp
double total = price * 1.2;      // що таке 1.2?
if (age >= 18) { /* ... */ }     // чому 18?
```

Дайте йому ім'я:

```csharp
const double VatMultiplier = 1.2;
const int AdultAge = 18;
```

## Коментарі

- Коментуйте **чому**, а не **що**. `// add one to i` — це шум, а `// the API counts pages from 1` — корисно.
- Якщо коментар потрібен, щоб пояснити, що робить блок, подумайте про метод із доброю назвою.
- Видаляйте закоментований код. Система контролю версій пам'ятає його за вас.
- Застарілі коментарі гірші за відсутність: оновлюйте їх разом із кодом.

## Домовленості спільні

Команда погоджує один стиль і доручає інструментам його контролювати (`.editorconfig`, аналізатори, форматувальники). Який саме стиль — менш важливо, ніж те, щоб усі користувалися одним. Microsoft публікує власні домовленості щодо коду C#, і слідувати їм — надійний вибір за замовчуванням.
