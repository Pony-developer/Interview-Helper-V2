Багато коду переносить **дані**: запити, відповіді, повідомлення, координати. Для таких типів потрібні рівність за значенням, зрозумілий `ToString` і незмінність. Написати все це вручну для класу — десятки рядків. **Record** (C# 9) отримує це одним рядком:

```csharp
public record Person(string Name, int Age);
```

Компілятор генерує:

- конструктор `Person(string Name, int Age)`;
- властивості `Name` і `Age` лише з `init`;
- **рівність за значенням**: `Equals`, `GetHashCode`, `==` і `!=` порівнюють усі поля;
- `ToString()`: `Person { Name = Ann, Age = 30 }`;
- `Deconstruct`: `var (name, age) = person;`;
- підтримку виразу `with`.

```csharp
var ann = new Person("Ann", 30);
var same = new Person("Ann", 30);
Console.WriteLine(ann == same);          // True: значення рівні
Console.WriteLine(ReferenceEquals(ann, same)); // False: два об'єкти

var older = ann with { Age = 31 };       // копія зі зміненою властивістю
Console.WriteLine(ann.Age);              // 30: оригінал не змінився
```

`with` — це **неруйнівна зміна**: замість змінювати об'єкт ви створюєте змінену копію. Тому records безпечно ділити між потоками і використовувати як ключі словника.

## Record class і record struct

- `record` або `record class` — **посилальний** тип із рівністю за значенням.
- `record struct` (C# 10) — значущий тип із тими самими зручностями. Його властивості змінні, якщо не написати `readonly record struct`.

```csharp
public readonly record struct Money(decimal Amount, string Currency);
```

## Пастки

**Колекції всередині records порівнюються за посиланням.** `record Order(int Id, List<string> Items)`: два замовлення з однаковими списками товарів **не** рівні, бо сам `List<T>` має рівність за посиланням.

**`with` робить поверхневу копію.** Копія та оригінал ділять той самий об'єкт списку.

**Records можуть успадковуватися лише від records.** Рівність також перевіряє точний тип, тож record `Student` ніколи не дорівнює record `Person` з тими самими полями.

## Що коли використовувати

| Тип | Для чого |
|---|---|
| `class` | об'єкти з ідентичністю і поведінкою, що змінюються з часом: сервіси, сутності, які відстежує Entity Framework |
| `record` | незмінні дані: DTO, запити й відповіді API, повідомлення, події, об'єкти-значення |
| `struct` / `record struct` | малі значення (приблизно до 16 байтів), які копіюють: точки, гроші, діапазони |

## Правило

Коли тип — переважно дані, і два об'єкти з однаковими даними мають бути рівними, зробіть його record. Тримайте його незмінним і змінюйте через `with`.
