У C# є дві пари операторів «і» та «або» для значень `bool`, і різниця між ними полягає в тому, **чи завжди обчислюється правий операнд**.

| Скорочені | Повні | Значення |
| --- | --- | --- |
| `a && b` | `a & b` | і |
| `a \|\| b` | `a \| b` | або |

## Скорочені: `&&` та `||`

Вони обчислюють праву частину, лише якщо вона ще може змінити відповідь:

- у `a && b`, якщо `a` хибне, результат хибний за будь-якого `b`, тож `b` **пропускається**;
- у `a || b`, якщо `a` істинне, результат уже істинний, тож `b` **пропускається**.

## Повні: `&` та `|`

Вони завжди обчислюють **обидві** частини, а тоді поєднують результати.

Різниця стає помітною, коли права частина щось робить. Цей метод повідомляє, що його викликали:

```csharp
static bool Check(string name, bool result)
{
    Console.WriteLine("checking " + name);
    return result;
}
```

```csharp
bool x = Check("A", false) && Check("B", true);
// checking A                 (B пропущено)

bool y = Check("A", false) & Check("B", true);
// checking A
// checking B                 (обчислено обидві)
```

І `x`, і `y` хибні. Відрізняються лише побічні ефекти.

## Чому скорочене обчислення важливе

Лівий операнд може **охороняти** правий, щоб той виконувався, лише коли це безпечно:

```csharp
// ніколи не ділить на нуль
if (count != 0 && total / count > 10) { /* ... */ }

// ніколи не звертається до null-рядка
if (text != null && text.Length > 0) { /* ... */ }

// та сама ідея з ||
if (text == null || text.Length == 0) { Console.WriteLine("empty"); }
```

Поміняйте операнди місцями або візьміть `&`, і перший приклад аварійно завершиться з `DivideByZeroException`, коли `count` дорівнює `0`, а другий кине `NullReferenceException`, коли `text` дорівнює `null`.

```csharp
string text = null;
Console.WriteLine(text != null & text.Length > 0);   // NullReferenceException
```

Тож порядок умов — частина логіки: спершу ставте охоронну перевірку, а потім ту, що від неї залежить.

## Що обрати

Майже завжди `&&` і `||`. Вони швидші та безпечніші. `&` та `|` для `bool` беріть лише тоді, коли справді хочете, щоб виконалися обидві частини, наприклад коли кожна виконує перевірку й повідомляє про проблему, а ви хочете побачити всі проблеми одразу. Але й тоді багато розробників воліють розписати виклики по окремих рядках.

## `&` та `|` для цілих чисел

Для цілих чисел ті самі символи — це **побітові** оператори. Вони працюють з кожним бітом чисел і не мають жодного стосунку до умов:

```csharp
Console.WriteLine(6 & 3);   // 2   (110 і 011 дають 010)
Console.WriteLine(6 | 3);   // 7   (110 або 011 дають 111)
```

Умова на кшталт `x & 1 == 0` — помилка: `==` зв'язує сильніше за `&`, тож вираз спершу порівнює `1 == 0`, а потім не компілюється. Поставте дужки: `(x & 1) == 0`.

## Умовний оператор теж ледачий

У `condition ? a : b` обчислюється лише обрана гілка:

```csharp
int result = divisor != 0 ? total / divisor : 0;   // безпечно
```
