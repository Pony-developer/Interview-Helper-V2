Університетська програма зберігає студентів і викладачів. І ті, й ті — люди, тож обидва мають ім'я та рік народження, і обидва можуть представитися. Без успадкування ви пишете два окремі класи:

```csharp
class Student
{
    public string Name;
    public int BirthYear;
    public int Course;

    public string Introduce()
    {
        return "I am " + Name + ", born in " + BirthYear;
    }
}

class Teacher
{
    public string Name;
    public int BirthYear;
    public string Subject;

    public string Introduce()
    {
        return "I am " + Name + ", born in " + BirthYear;
    }
}
```

Поля `Name`, `BirthYear` і метод `Introduce` **скопійовано**. Це працює, і саме такий код пізніше створює проблеми.

## Проблема 1: копії розходяться

Завтра університет захоче, щоб у представленні був вік. Ви змінюєте `Introduce` у `Student` і забуваєте про `Teacher`. Тепер та сама дія поводиться по-різному для двох видів людей, а програма нічого не підказує. Якщо таких класів десять, одна зміна означає десять правок, і рано чи пізно одну з них пропустять.

## Проблема 2: класи чужі одне одному

Вам потрібен метод, що друкує представлення **будь-кого**:

```csharp
static void Greet(Student person) { Console.WriteLine(person.Introduce()); }
static void Greet(Teacher person) { Console.WriteLine(person.Introduce()); }   // те саме знову
```

Для компілятора `Student` і `Teacher` не мають нічого спільного, хоча код у них однаковий. Їх не можна покласти й в один масив:

```csharp
// Student[] people = { new Student(), new Teacher() };   // не компілюється
```

Кожен новий вид людини (гість, бібліотекар) потребує власної копії методу та власного масиву.

## Чого ми хочемо

Ми хочемо сказати це **один раз**:

- уся **спільна** частина (`Name`, `BirthYear`, `Introduce`) живе в **одному** місці;
- `Student` і `Teacher` її **повторно використовують** і додають лише те, що **їхнє** (`Course`, `Subject`);
- програма може розглядати студента й викладача як **«людину»**, коли важлива лише спільна частина.

Саме це робить **успадкування**. У наступній лекції той самий приклад стане коротшим, а метод `Greet` доведеться написати лише раз.

## Не єдиний інструмент

Успадкування — не ліки від будь-якого повторення. Якщо спільна частина — лише допоміжне обчислення, краще **статичний метод** або окремий клас, яким користуються обидва (**композиція**: «студент *має* візитку»). Успадкування доречне, коли один тип справді **є різновидом** іншого: студент *є* людиною. До цього питання ми повернемося наприкінці модуля.
