Програма на C# проходить **дві** компіляції, перш ніж її виконає процесор. Знання обох пояснює час запуску, «розігрів», те, чому працює рефлексія, і що змінює Native AOT.

## Крок 1: з C# в IL

Компілятор C# (**Roslyn**) не створює машинного коду. Він створює **збірку** (assembly): файл `.dll` (файл формату Windows PE на будь-якій ОС), що містить

- **IL** (Intermediate Language, також CIL або MSIL): інструкції для абстрактної стекової машини, однакові для будь-якого процесора;
- **метадані**: таблиці, що описують кожен тип, метод, поле, параметр і атрибут, а також кожне посилання на інші збірки;
- **маніфест**: ім'я збірки, версію, культуру, відкритий ключ і перелік залежностей;
- ресурси (вбудовані файли, локалізовані рядки).

```csharp
static int Add(int a, int b) => a + b;
```

компілюється в

```text
.method private hidebysig static int32 Add(int32 a, int32 b) cil managed
{
    ldarg.0     // покласти a на стек
    ldarg.1     // покласти b на стек
    add         // зняти обидва, покласти a + b
    ret         // повернути верхівку стека
}
```

F# і Visual Basic компілюються в той самий IL, тому вони можуть користуватися бібліотеками одне одного. Навіть консольний застосунок — це `.dll`: маленький `MyApp.exe` поруч із нею — лише нативний запускач (**apphost**).

Саме метадані роблять можливими **рефлексію** (`typeof(T).GetMethods()`), IntelliSense, серіалізатори та контейнери впровадження залежностей: опис коду подорожує разом із кодом. Подивитися IL і метадані можна в **ILSpy**, `dotnet-ildasm` або на **sharplab.io**.

## Крок 2: з IL у машинний код, вчасно

Під час виконання **JIT-компілятор** (Just-In-Time, у сучасному .NET він зветься **RyuJIT**) перетворює IL на нативний код для поточного процесора:

1. Кожен метод починає як маленька заглушка (stub).
2. Під час **першого виклику** заглушка викликає JIT, той компілює метод і підміняє заглушку переходом на новий код.
3. Наступні виклики йдуть одразу в нативний код.

Тож перший виклик методу повільніший, а застосунок, що на старті торкається тисяч методів, платить за їх компіляцію. Натомість JIT знає точний процесор (може використати AVX-512, якщо він є) і реальні значення полів `static readonly`.

## Багаторівнева компіляція

Якісна оптимізація потребує часу, тож сучасний .NET компілює **рівнями** (tiered compilation, увімкнено за замовчуванням з .NET Core 3.0):

- **Рівень 0** (tier 0): швидка компіляція без оптимізацій, щоб застосунок швидко стартував.
- Метод, який викликають часто (приблизно 30 разів), перекомпільовується на **рівні 1** з повною оптимізацією у фоновому потоці. Ті, хто його викликає, переходять на новий код.
- **OSR** (on-stack replacement): метод, що застряг у довгому циклі, може перейти на оптимізований код посеред циклу.
- **Dynamic PGO** (оптимізація за профілем, увімкнена за замовчуванням з .NET 8): код рівня 0 записує, які типи й гілки трапляються насправді, а рівень 1 використовує цей профіль, наприклад, щоб викликати віртуальний чи інтерфейсний метод напряму, коли там майже завжди один і той самий клас.

Ось чому .NET-сервіс стає швидшим у перші секунди чи хвилини роботи, і чому **бенчмаркам потрібен розігрів** (BenchmarkDotNet робить його за вас).

## Попередня компіляція (AOT)

| Варіант | Що робить | Компроміс |
| --- | --- | --- |
| **ReadyToRun** (`PublishReadyToRun`) | Зберігає заздалегідь скомпільований нативний код у збірці поруч з IL | Швидший старт, більші файли; гарячі методи все одно перекомпільовуються JIT на рівні 1 |
| **Native AOT** (`PublishAot`, .NET 7+) | Компілює весь застосунок в один нативний виконуваний файл; під час виконання немає ні JIT, ні IL | Дуже швидкий старт, мало пам'яті; немає `Reflection.Emit`, завантаження збірок під час виконання, рефлексія обмежена, окрема збірка під кожну ОС і процесор |

Native AOT підходить для утиліт командного рядка, serverless-функцій і малих контейнерів. Бібліотекам, що генерують код під час виконання, потрібні натомість генератори коду (source generators): наприклад, вони є в `System.Text.Json` і `Regex`.

## Порівняння з Java

Ідея та сама, що в байткоду Java і JVM. Дві відмінності, які люблять на співбесідах: узагальнення .NET існують в IL і під час виконання (Java їх стирає), і в .NET є користувацькі значущі типи (`struct`).

## Відповідь для співбесіди

Roslyn компілює C# в IL і метадані, що зберігаються у збірці. Під час виконання JIT із CLR компілює кожен метод у нативний код під час першого виклику; багаторівнева компіляція спершу створює швидкий код, а згодом перекомпільовує гарячі методи з повною оптимізацією і даними профілю. ReadyToRun компілює код заздалегідь, щоб пришвидшити старт, а Native AOT зовсім прибирає JIT ціною динамічних можливостей.
