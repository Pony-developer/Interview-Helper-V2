**Рекурсія** — це коли метод викликає **сам себе**, щоб розв'язати меншу версію тієї самої задачі. Звучить як замкнене коло, але працює, доти, доки ланцюжок менших задач десь закінчується.

## Ідея на одному прикладі

Факторіал числа: `5! = 5 · 4 · 3 · 2 · 1`. Зверніть увагу, що `5! = 5 · 4!`, а `4! = 4 · 3!` і так далі. Задача описується через меншу копію самої себе:

```csharp
static long Factorial(int n)
{
    if (n <= 1)                    // базовий випадок: відповідь відома
    {
        return 1;
    }
    return n * Factorial(n - 1);   // рекурсивний випадок: менша задача
}
```

Кожен рекурсивний метод має ці дві частини:

1. **Базовий випадок**: найпростіші вхідні дані, для яких відповідь дається напряму, без подальших викликів. Без нього виклики ніколи не припиняються.
2. **Рекурсивний випадок**: метод викликає сам себе з **меншими** вхідними даними й використовує результат.

## Що відбувається під час виконання

Виклик `Factorial(4)`:

```text
Factorial(4)
  = 4 * Factorial(3)
        = 3 * Factorial(2)
              = 2 * Factorial(1)
                    = 1                 <- базовий випадок
              = 2 * 1 = 2
        = 3 * 2 = 6
  = 4 * 6 = 24
```

Спершу виклики йдуть **вниз** до базового випадку, а потім результати повертаються **вгору**, і кожен рівень множить власне `n` на те, що отримав. Жоден виклик не завершується, доки не повернеться виклик нижче.

## Стек викликів

Як комп'ютер пам'ятає, де він був? Кожен виклик отримує власний **кадр стека**: невеликий блок пам'яті з параметрами та локальними змінними цього виклику. Новий виклик кладе кадр, а повернення його знімає. Для `Factorial(4)` у найглибший момент на стеку чотири кадри, кожен зі своїм `n`.

Стек невеликий. Якщо глибина зростає надто сильно, виникає **переповнення стека** (`StackOverflowException`), і програма одразу завершується: перехопити його неможливо. Зазвичай це стається на глибині кількох десятків тисяч викликів.

```csharp
static int Bad(int n)
{
    return Bad(n + 1);     // немає базового випадку: це ніколи не закінчується
}
```

## Три правила написання рекурсивного методу

1. **Спершу напишіть базовий випадок.** Які найменші вхідні дані і яка їхня відповідь?
2. **Просувайтеся.** Кожен рекурсивний виклик має бути **ближчим** до базового випадку: менше число, коротший рядок, менший діапазон.
3. **Довіряйте виклику.** Припустіть, що рекурсивний виклик повертає правильну відповідь для менших даних, і думайте лише про те, як з неї побудувати відповідь для поточних даних. Не намагайтеся прослідкувати всі рівні в голові.

## Ще кілька малих прикладів

**Сума чисел 1..n**

```csharp
static int SumTo(int n)
{
    if (n == 0) return 0;
    return n + SumTo(n - 1);
}
```

**Степінь**

```csharp
static long Power(long x, int p)
{
    if (p == 0) return 1;
    return x * Power(x, p - 1);
}
```

**Кількість цифр**

```csharp
static int CountDigits(int n)
{
    if (n < 10) return 1;                // одна цифра
    return 1 + CountDigits(n / 10);      // відкидаємо останню цифру
}
```

**Обернення рядка**

```csharp
static string Reverse(string s)
{
    if (s.Length <= 1) return s;
    return Reverse(s.Substring(1)) + s[0];
}
```

**Паліндром**: перший і останній символи мають збігатися, а те, що посередині, має бути паліндромом.

```csharp
static bool IsPalindrome(string s)
{
    if (s.Length <= 1) return true;
    if (s[0] != s[s.Length - 1]) return false;
    return IsPalindrome(s.Substring(1, s.Length - 2));
}
```

Подивіться, що в них спільного: **простий базовий випадок** (`0`, `1`, одна цифра, порожній рядок) і виклик для **менших** даних (`n - 1`, `n / 10`, коротший рядок).

## Рекурсія чи цикл?

Будь-яку рекурсію можна записати циклом і навпаки. Для `Factorial` цикл коротший і швидший. Рекурсія — правильний вибір, коли задача **природно самоподібна**:

- тека, що містить теки;
- вираз із підвиразами в дужках;
- «спробувати вибір, потім розв'язати те, що лишилося», як для підмножин, перестановок і головоломок (наступні лекції);
- «поділити навпіл і розв'язати кожну половину» (розділяй і володарюй).

Для таких задач рекурсивний код слідує структурі задачі, а версії з циклом знадобився б власний явний стек.

## Вартість

- Кожен виклик коштує **часу** та **кадру** стека. Цикл на мільйон проходів — це нормально, а рекурсія на мільйон рівнів углиб — ні.
- C# не обіцяє усунути зростання стека, коли рекурсивний виклик — останнє, що робить метод (**оптимізація хвостового виклику**, яка є в деяких інших мовах). Тож не розраховуйте на неї.
- Та сама підзадача може розв'язуватися багато разів (лекція про дерево рекурсії показує, як, і що з цим робити).

## Типові помилки

- **Немає базового випадку** або базовий випадок недосяжний (наприклад, виклик іде з `n + 1`, а базовий випадок — `n == 0`).
- **Хибний базовий випадок**: `Factorial(0)`, що повертає `0`, робить усе `0`.
- **Немає просування**: виклик із тими самими аргументами.
- **Забути використати чи повернути результат** рекурсивного виклику.
- **Надто глибока рекурсія** для великих вхідних даних: там використайте цикл.

Коли рекурсія поводиться хибно, друкуйте аргументи з **відступом за глибиною**, і ви побачите виклики як дерево:

```csharp
static long Factorial(int n, int depth = 0)
{
    Console.WriteLine(new string(' ', depth * 2) + "Factorial(" + n + ")");
    if (n <= 1) return 1;
    return n * Factorial(n - 1, depth + 1);
}
```
