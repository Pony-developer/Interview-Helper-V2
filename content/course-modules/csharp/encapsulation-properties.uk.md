Методи на кшталт `GetBalance()` та `SetQuantity(...)` працюють, але їх багато, а виклики виглядають важко: `order.SetQuantity(order.GetQuantity() + 1)`. У C# є кращий інструмент — **властивість**. Ззовні вона схожа на поле, а всередині працює як пара методів.

## Синтаксис

```csharp
class Order
{
    private int quantity;                          // поле, що стоїть за властивістю: приховане

    public int Quantity                            // властивість: публічна
    {
        get { return quantity; }                   // виконується, коли значення ЧИТАЮТЬ
        set                                        // виконується, коли значення ЗАПИСУЮТЬ
        {
            if (value < 0)
            {
                throw new ArgumentOutOfRangeException("value", "The quantity cannot be negative");
            }
            quantity = value;                      // "value" — те, що присвоїв той, хто викликає
        }
    }
}

var order = new Order();
order.Quantity = 5;                                // викликає set, де value == 5
Console.WriteLine(order.Quantity);                 // викликає get: 5
order.Quantity += 1;                               // get, потім set: 6
// order.Quantity = -3;                            // ArgumentOutOfRangeException, прямо тут
```

Для того, хто викликає, `order.Quantity` просте, як поле. Для класу це місце, де живуть **правила**. Той, хто викликає, не може пропустити перевірку й не може сказати (і не мусить знати), що перевірка взагалі є.

- `get` повертає значення, і він мусить зробити `return` значення типу властивості;
- у `set` є прихований параметр **`value`**: значення з правого боку присвоєння;
- **поле-сховище** (`quantity`) — `private`, а властивість (`Quantity`) — `public`. За домовленістю властивість починається з великої літери, а поле — з малої.

## Лише читання й лише запис

Властивість може мати лише одну частину:

```csharp
public int Quantity { get { return quantity; } }       // лише читання: ззовні ніхто не може її записати
```

Така властивість — правильний спосіб **показати** значення, яке зовнішній код не повинен змінювати. Сам клас усе ще може змінювати поле у своїх методах.

## Автовластивості

Більшість властивостей не мають жодних правил: це просто «поле з публічним обличчям». Для них C# може написати поле за вас:

```csharp
public string Name { get; set; }                       // приховане поле створює компілятор
public int Id { get; }                                 // лише читання: задається лише в конструкторі
public int Count { get; private set; }                 // читають усі, пише лише клас
```

Це коротше за публічне поле й **краще**: це властивість, тож пізніше можна додати перевірку (перетворивши її на повну властивість), і **жоден зовнішній код не зміниться**. Публічне поле не можна замінити властивістю, не зламавши код, що його вживає.

## Властивість — не метод, але це код

Властивість схожа на поле, але `get` і `set` — справжній код, що виконується. Добра властивість:

- **швидка**: вона не шукає в базі даних чи файлі;
- **чесна**: двічі поспіль прочитана, дає той самий результат, якщо нічого не змінилося;
- **без сюрпризів**: читання ніколи не змінює об'єкт.

Якщо робота важка або операція часто може не вдатися, зробіть її **методом** (`LoadReport()`), а не властивістю.

## Іменування й стиль

```csharp
public decimal Balance { get; private set; }           // PascalCase для властивостей
private decimal balance;                               // camelCase для приватних полів
```

Звичне практичне правило відтепер: **поле приватне, а зовнішній світ бачить лише властивості та методи**.
