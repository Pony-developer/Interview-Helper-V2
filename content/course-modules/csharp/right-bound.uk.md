**Права межа** (**верхня межа**) — партнер лівої межі. У відсортованому масиві це **перший індекс `i`**, для якого `sorted[i] > x` (строго більше). Якщо жоден елемент не більший за `x`, це `sorted.Length`.

Це позиція одразу **після останнього входження** `x`. Різниця між двома межами — зручне число: вона дорівнює **тому, скільки разів `x` трапляється**:

```text
CountOccurrences(a, x) = UpperBound(a, x) − LowerBound(a, x)
```

Обидві можна знайти за O(log n), тож підрахунок виконується без проходу по повторюваних значеннях, яких може бути мільйон.

Реалізуйте два методи:

- `UpperBound(sorted, x)`: найменший індекс із `sorted[i] > x` або `sorted.Length`.
- `CountOccurrences(sorted, x)`: скільки елементів дорівнюють `x`.

Метод `LowerBound` з попереднього завдання **уже написано** в початковому коді, тож ним можна користуватися.

Для `{ 1, 2, 2, 2, 5, 8, 8, 10 }`:

| x | `UpperBound` | `CountOccurrences` |
| --- | --- | --- |
| 1 | 1 | 1 |
| 2 | 4 | 3 |
| 3 | 4 | 0 |
| 8 | 7 | 2 |
| 11 | 8 | 0 |

Єдина відмінність у пошуку — порівняння. Для нижньої межі «замале» — це `sorted[mid] < x`. Для верхньої — `sorted[mid] <= x`.

`Main` не змінюйте. Очікуваний вивід:

```text
0 -> 0
1 -> 1
2 -> 4
3 -> 4
5 -> 5
8 -> 7
9 -> 7
10 -> 8
11 -> 8
3
2
0
1
0
```

Перші дев'ять рядків — `UpperBound` для значень 0, 1, 2, 3, 5, 8, 9, 10 та 11. Останні п'ять — `CountOccurrences` для 2, 8, 4, 1 і 11.

Підказка: скопіюйте структуру `LowerBound` і змініть `<` на `<=` в одному місці.
