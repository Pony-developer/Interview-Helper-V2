Як компілятор робить замикання робочим? Захоплена змінна не може жити лише в стеку, бо мусить пережити метод, що її створив. Тому компілятор переносить її в купу, всередину маленького прихованого об'єкта, що тримає всі захоплені змінні.

## Вихідний код

```csharp
static Func<int> MakeCounter()
{
    int count = 0;
    return () => ++count;
}
```

## Що створює компілятор (спрощено)

```csharp
class HiddenClosure
{
    public int count;                    // захоплена змінна стала полем

    public int Lambda()
    {
        return ++count;
    }
}

static Func<int> MakeCounter()
{
    var closure = new HiddenClosure();   // один об'єкт для змінних цього виклику
    closure.count = 0;
    return closure.Lambda;               // делегат запам'ятовує об'єкт
}
```

## Картина

```text
стек                              купа
----                              ----
next  ------------------------>   [делегат: метод = Lambda, ціль = closure]
                                          |
                                          v
                                  [HiddenClosure: count = 2]
```

Змінна `count` більше не живе в стеку. Вона — поле об'єкта в купі, а делегат утримує цей об'єкт живим.

## Спільні змінні

Дві лямбди, що захоплюють ту саму змінну, ділять один об'єкт. Обидві бачать той самий `count`:

```csharp
static void MakePair(out Func<int> get, out Action increment)
{
    int value = 0;
    get = () => value;
    increment = () => value++;
}

Func<int> read;
Action add;
MakePair(out read, out add);
add();
add();
Console.WriteLine(read());               // 2: обидві лямбди використовують одну змінну
```

## Вартість

Захоплення змінної додає виділення пам'яті в купі. Нічого не захоплювати дешевше: тоді компілятор створює делегат один раз і повторно його використовує. Це оптимізація, яку компілятор робить за вас, і вона не змінює поведінку.
