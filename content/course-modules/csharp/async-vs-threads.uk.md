"Асинхронність" і "багатопотоковість" часто вживають так, ніби вони означають одне й те саме. Вони розв'язують різні задачі, і програмі часто потрібне одне, друге або обидва.

- **Багатопотоковість** означає виконання кількох речей одночасно в кількох потоках, щоб процесор із кількома ядрами міг працювати над ними паралельно. Це про **швидшу роботу** або про те, щоб програма лишалася чутливою, поки деяка робота виконується деінде.
- **Асинхронність** означає неочікування: програма запускає операцію і продовжує роботу, а результат дізнається пізніше. Це про **неблокування під час очікування**.

## Очікування — ключова різниця

Більшу частину часу програма, що завантажує файл, читає базу даних або запитує веб-сервер, **чекає**, а не обчислює. Асинхронна операція такого типу не потребує потоку під час очікування: операційна система завершує операцію, а потім код продовжує роботу.

```csharp
// Асинхронний ввід-вивід: під час очікування жоден потік не простоює
string text = await File.ReadAllTextAsync("notes.txt");

// Багатопотоковість: потік виконує обчислення
int total = await Task.Run(() => SlowCalculation());
```

`await Task.Delay(1000)` чекає секунду і не займає жодного потоку. `Thread.Sleep(1000)` теж чекає секунду, але блокує потік, у якому виконується, а це марнотратно.

## Асинхронний метод — не потік

Це найпоширеніша помилка. `async`-метод виконується в викликаючому потоці **до свого першого `await`**. Якщо всередині немає `await`, нічого не переходить в інший потік:

```csharp
static async Task<int> NotParallel()
{
    return SlowCalculation();                 // досі виконується в потоці викликаючого
}

static Task<int> Parallel1()
{
    return Task.Run(() => SlowCalculation()); // ось цей справді виконується в потоці пулу
}
```

## Порівняння

| | Асинхронність | Багатопотоковість |
|---|---|---|
| Мета | не блокувати під час очікування | виконувати роботу одночасно |
| Чого чекає | ввід-вивід: файли, мережі, бази даних, таймери | процесор: обчислення |
| Потоки | зазвичай жодного під час очікування | один потік на кожну частину роботи |
| Типові інструменти | `await`, `Task.Delay`, асинхронні методи вводу-виводу | `Task.Run`, `Parallel`, `Thread` |

## Що обрати

- Програма, що **чекає** на зовнішній світ (ввід-вивід): використовуйте асинхронність, бо очікування майже нічого не коштує.
- Програма, що **інтенсивно обчислює**: використовуйте багатопотоковість, щоб розподілити роботу між ядрами.
- Користувацький інтерфейс: використовуйте асинхронність, щоб вікно лишалося чутливим, а важкі обчислення виносьте в інший потік через `Task.Run`.
- Часто поєднують обидва: чекайте завантажень через `await`, а обробку кожного результату виконуйте в пулі потоків.

Наступні лекції детально показують інструменти, починаючи із задач.
