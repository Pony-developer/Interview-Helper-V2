Алгоритм **Рабіна–Карпа** використовує хеш, щоб швидко порівнювати шаблон із кожним вікном тексту. Замість порівняння символів він порівнює **значення хешів**. Для цього потрібен трюк: хеш кожного вікна мусить оновлюватися за сталий час, коли вікно зсувається на один символ. Це **ковзний хеш** (rolling hash).

## Ідея

1. Обчисліть хеш шаблону.
2. Обчисліть хеш першого вікна тексту (перші `m` символів).
3. Для кожного вікна, якщо його хеш дорівнює хешу шаблону, **перевірте символи** напряму, бо два різні рядки можуть мати однаковий хеш.
4. Зсуньте вікно: оновіть його хеш, віднявши символ, що виходить, і додавши той, що входить.

```csharp
static int RabinKarp(string text, string pattern)
{
    const int Base = 256;
    const int Mod = 1000000007;
    int m = pattern.Length;
    if (m == 0) return 0;
    if (m > text.Length) return -1;

    long patternHash = 0, windowHash = 0, highest = 1;
    for (int i = 0; i < m - 1; i++) highest = (highest * Base) % Mod;

    for (int i = 0; i < m; i++)
    {
        patternHash = (patternHash * Base + pattern[i]) % Mod;
        windowHash = (windowHash * Base + text[i]) % Mod;
    }

    for (int start = 0; start + m <= text.Length; start++)
    {
        if (windowHash == patternHash && text.Substring(start, m) == pattern)
        {
            return start;                              // перевірка виключає колізії
        }
        if (start + m < text.Length)
        {
            // прибираємо символ, що виходить, і додаємо той, що входить
            windowHash = (windowHash - text[start] * highest % Mod + Mod) % Mod;
            windowHash = (windowHash * Base + text[start + m]) % Mod;
        }
    }
    return -1;
}
```

## Чому оновлення швидке

Хеш вікна — число, зібране з його символів, де кожен символ помножено на степінь `Base`. Коли вікно зсувається, внесок старого першого символу віднімається, а новий останній додається. Це сталий обсяг роботи, а не перерахунок усього хешу з `m` символів.

## Навіщо потрібна перевірка

Два вікна з різним текстом можуть мати однаковий хеш. Така **хибна відповідність** рідка, але трапляється, і пряме порівняння `text.Substring(start, m) == pattern` робить відповідь правильною. Хеш лише вирішує, які позиції перевірити.

## Вартість

У середньому пошук займає близько `n + m` кроків. У найгіршому випадку багато хибних відповідностей роблять його таким же повільним, як наївний пошук, але з добрим хешем це рідко.

Що запам'ятати: хеш — це фільтр. Збіг хешу означає «можливо тут», а лише символи вирішують «так, тут».
