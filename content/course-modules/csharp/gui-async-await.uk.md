Ключові слова `async` і `await` дозволяють тому самому коду GUI читатися як звичайний послідовний код, при цьому не блокуючи потік UI:

```csharp
// WinForms, ілюстрація.
private async void calculateButton_Click(object sender, EventArgs e)
{
    resultLabel.Text = "working...";
    int result = await Task.Run(() => Compute());   // потік UI вільний, поки виконується Compute
    resultLabel.Text = result.ToString();           // після await знову в потоці UI
}
```

## Що робить await

Коли виконання доходить до `await`, метод **повертається** до викликаючого, тож потік UI продовжує обробляти повідомлення. Коли задача, на яку чекають, завершується, решта методу виконується знову. У застосунку з графічним інтерфейсом ця решта виконується в потоці UI, тому мітку можна оновлювати напряму.

```text
обробник кліку починається
  resultLabel.Text = "working..."
  await Task.Run(...)      -> повертається до циклу UI; вікно лишається чутливим
  ... через п'ять секунд задача завершена ...
  resultLabel.Text = "42"  -> знову виконується в потоці UI
```

## Єдиний виняток: async void

Обробник кнопки — єдине поширене місце для `async void`, бо сигнатура події не має типу значення, що повертається. Скрізь інде використовуйте `async Task` або `async Task<T>`, щоб викликаючий міг дочекатися результату й побачити винятки. Винятки в `async void` викликаючий не може перехопити, і вони можуть зупинити програму.

## Підсумок

`await` замінює зворотні виклики `ContinueWith` з попередньої лекції звичайним кодом. Останній модуль курсу, про async і задачі, пояснює механізм докладно.
