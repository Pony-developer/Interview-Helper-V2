Ключове слово `ref` перед параметром означає: метод отримує **посилання на саму змінну викликаючого**, а не копію. Зміни в методі видно викликаючому.

```csharp
static void Double(ref int x)
{
    x = x * 2;                 // змінює змінну викликаючого
}

int n = 5;
Double(ref n);                 // у виклику теж потрібне слово
Console.WriteLine(n);          // 10
```

Два правила:

- **І оголошення, і виклик пишуть `ref`.** Компілятор нічого не вгадує.
- **Змінна мусить мати значення перед викликом**, бо метод може його прочитати.

```csharp
int m;
// Double(ref m);              // помилка CS0165: use of unassigned local variable
m = 4;
Double(ref m);
```

## ref зі структурою

`ref` найкорисніший для структур: він дозволяє методу змінити структуру без створення копії:

```csharp
struct Counter
{
    public int Value;
}

static void Reset(ref Counter c)
{
    c.Value = 0;               // змінює структуру викликаючого
}

Counter counter = new Counter { Value = 9 };
Reset(ref counter);
Console.WriteLine(counter.Value);     // 0
```

## out: родич ref

`out` схожий, з однією відмінністю: змінна **не потребує** значення перед викликом, але метод **мусить присвоїти** її, перш ніж повернутися. Його вживають, щоб повернути більше одного результату:

```csharp
static bool TryDivide(int a, int b, out int result)
{
    if (b == 0)
    {
        result = 0;
        return false;
    }
    result = a / b;
    return true;
}

int q;
if (TryDivide(10, 2, out q)) Console.WriteLine(q);     // 5
```

## Коли вживати ref

- коли метод мусить **змінити** змінну викликаючого (`Swap`, `Double` вище);
- коли структура велика і копіювати її при кожному виклику марнотратно. Тоді вживайте `in` (C# 7.2) або звичайний `ref`.

Не вживайте `ref` лише для того, щоб метод здавався розумним. Метод, що повертає нове значення, зазвичай зрозуміліший.
