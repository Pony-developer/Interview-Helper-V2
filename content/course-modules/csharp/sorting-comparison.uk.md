Єдиного «найкращого» алгоритму сортування не існує. Кожен має ціну в часі, пам'яті та поведінці, і добрий програміст знає, що обрати і коли просто викликати бібліотеку.

## Таблиця

| Алгоритм | Найкращий | Середній | Найгірший | Додаткова пам'ять | Стабільний |
| --- | --- | --- | --- | --- | --- |
| **Бульбашка** | O(n) | O(n²) | O(n²) | O(1) | так |
| **Вибір** | O(n²) | O(n²) | O(n²) | O(1) | ні |
| **Вставки** | O(n) | O(n²) | O(n²) | O(1) | так |
| **Злиття** | O(n log n) | O(n log n) | O(n log n) | O(n) | так |
| **Швидке** | O(n log n) | O(n log n) | O(n²) | O(log n) | ні |
| **Пірамідальне** | O(n log n) | O(n log n) | O(n log n) | O(1) | ні |
| **Підрахунком** | O(n + k) | O(n + k) | O(n + k) | O(n + k) | так |
| **Порозрядне** | O(d · (n + k)) | O(d · (n + k)) | O(d · (n + k)) | O(n + k) | так |

(`k` — діапазон значень, а `d` — кількість цифр.)

## Що означають стовпчики

**На місці.** Алгоритм, якому потрібно лише O(1) або O(log n) додаткової пам'яті, сортує **на місці**. Сортуванню злиттям потрібен допоміжний масив розміру `n`. Коли пам'яті мало, це важливо.

**Стабільний.** Стабільне сортування зберігає рівні елементи в їхньому початковому порядку. Це важливо, коли записи сортують за кількома полями по черзі або коли елементи — об'єкти, що відрізняються в інших полях, а ви сортуєте за одним ключем:

```text
за оцінкою (стабільно):    (Ann,5) (Bo,4) (Cy,5) (Di,4)   ->   (Bo,4) (Di,4) (Ann,5) (Cy,5)
за оцінкою (нестабільно):  результат може бути   (Di,4) (Bo,4) (Cy,5) (Ann,5)
```

Для простих чисел стабільність не має значення: рівні числа невідрізнювані.

**Адаптивний.** Алгоритм, що швидший на **вже майже відсортованих** даних. Сортування вставками та бульбашка (з прапорцем) — O(n) на відсортованих даних. Швидке сортування з наївним опорним елементом — навпаки: воно **найповільніше** на відсортованих даних.

## Нижня межа для сортування порівняннями

Кожен алгоритм, що дізнається про дані **лише порівнюючи пари**, потребує принаймні близько **n log n** порівнянь у найгіршому випадку. Аргумент короткий: існує `n!` можливих порядків вхідних даних. Кожне порівняння має два результати, тож після `c` порівнянь алгоритм може розрізнити щонайбільше `2ᶜ` випадків, а мусить розрізнити всі `n!`:

```text
2ᶜ ≥ n!   =>   c ≥ log₂ (n!) ≈ n · log₂ n − 1.44 · n
```

Отже, сортування злиттям, пірамідальне та середній випадок швидкого **оптимальні** серед сортувань порівняннями. Щоб зробити краще, алгоритм має використовувати не лише порівняння, як сортування підрахунком і порозрядне.

## Сортування без порівнянь

**Сортування підрахунком** працює для цілих чисел у малому діапазоні `0..k`. Порахуйте, скільки разів трапляється кожне значення, а потім випишіть значення по порядку:

```csharp
static int[] CountingSort(int[] a, int max)        // значення від 0 до max
{
    int[] counts = new int[max + 1];
    foreach (int x in a) counts[x]++;

    int[] result = new int[a.Length];
    int k = 0;
    for (int value = 0; value <= max; value++)
        for (int c = 0; c < counts[value]; c++)
            result[k++] = value;
    return result;
}
```

Час — **O(n + k)**, лінійний, коли `k` не надто велике. Сортування мільйона екзаменаційних оцінок від 0 до 100 займає мільйон кроків, без `n log n`. Воно марне, коли значення розкидані на величезному діапазоні (як довільні 32-бітні числа).

**Порозрядне сортування** сортує числа цифра за цифрою, починаючи з наймолодшої, застосовуючи на кожній цифрі стабільне сортування підрахунком.

## Що дає .NET

| Виклик | Алгоритм | Стабільне? |
| --- | --- | --- |
| `Array.Sort(a)` / `list.Sort()` | introsort: швидке + пірамідальне + вставки | **ні** |
| `a.OrderBy(x => x.Key)` (LINQ) | стабільний варіант швидкого сортування | **так** |

```csharp
int[] a = { 5, 2, 9, 1 };
Array.Sort(a);                                  // 1 2 5 9
Array.Sort(a, (x, y) => y.CompareTo(x));        // за спаданням: порівняння як лямбда
Array.Sort(words, StringComparer.Ordinal);      // рядки в точному порядку, незалежному від культури
```

**Порівняння** — це метод, що бере два елементи й повертає від'ємне число, якщо перший має йти першим, нуль, якщо вони рівні, і додатне в іншому разі. Передавши власне, можна сортувати **за будь-яким правилом** (за довжиною, за полем об'єкта, за спаданням).

```csharp
Array.Sort(words, (x, y) => x.Length.CompareTo(y.Length));          // за довжиною
```

Зважайте на культуру: типове порівняння рядків дотримується правил мови, тож для передбачуваного результату вказуйте компаратор явно.

## Вибір

| Ситуація | Добрий вибір |
| --- | --- |
| Звичайні дані в пам'яті | бібліотека: `Array.Sort` |
| Потрібна стабільність | `OrderBy` або сортування злиттям |
| Пам'яті дуже мало | пірамідальне чи швидке |
| Дуже малі або майже відсортовані масиви | сортування вставками |
| Цілі числа в малому діапазоні | сортування підрахунком |
| Дані завеликі для пам'яті | зовнішнє сортування злиттям |
| Зв'язні списки | сортування злиттям |
| Потрібні лише `k` найменших | купа або quickselect: без повного сортування |
| Дані надходять по одному | вставка в відсортовану структуру (`SortedSet<T>` чи купа) |

## Чи потрібно взагалі сортувати?

Сортування — O(n log n), тож перш ніж його писати, перевірте, чи не годиться щось дешевше:

- **мінімум** або **максимум**: один прохід, O(n);
- **k-й** елемент або **медіана**: quickselect, O(n);
- **топ k**: купа розміру `k`, O(n log k);
- перевірки **належності**: `HashSet`;
- дані **вже відсортовані** або майже: не сортуйте знову.

## Поради з реального життя

1. Не пишіть власне сортування для робочого коду. Користуйтеся бібліотекою.
2. Знайте, чи стабільне сортування, яке ви викликаєте, і не покладайтеся на стабільність, якщо його немає.
3. Завжди передавайте явний компаратор для рядків, коли порядок важливий.
4. Сортуйте **один раз**, а потім шукайте багато разів двійковим пошуком.
5. Міряйте, якщо швидкість важлива.
