**Швидке сортування** — це сортування за принципом «розділяй і володарюй», що виконує свою роботу **перед** рекурсивними викликами. Воно обирає **опорний** елемент, **розбиває** масив так, щоб менші елементи були ліворуч від опорного, а більші — праворуч, а потім рекурсивно сортує обидві сторони. Злиття немає: після розбиття опорний елемент уже на своїй **остаточній позиції**.

```text
        [ 8 3 9 1 5 7 2 6 ]        опорний = 6
розбиття:
        [ 3 1 5 2 ] 6 [ 8 9 7 ]    менші за 6 | опорний | більші за 6
сортуємо кожну сторону рекурсивно:
        [ 1 2 3 5 ] 6 [ 7 8 9 ]
```

## Розбиття (схема Ломуто)

Візьміть як опорний **останній** елемент. Тримайте межу `i`: усе до `i` включно — `<=` опорного. Скануйте масив і переміщуйте кожен малий елемент за межу:

```csharp
static int Partition(int[] a, int low, int high)       // діапазон [low, high], обидва включно
{
    int pivot = a[high];
    int i = low - 1;                                   // кінець «малої» частини

    for (int j = low; j < high; j++)
    {
        if (a[j] <= pivot)
        {
            i++;
            Swap(a, i, j);                             // переміщуємо a[j] у малу частину
        }
    }
    Swap(a, i + 1, high);                              // ставимо опорний одразу за малою частиною
    return i + 1;                                      // остаточна позиція опорного
}
```

Трасування для `[8, 3, 9, 1, 5, 7, 2, 6]`, опорний 6:

```text
j=0: 8 > 6    ні                   8 3 9 1 5 7 2 | 6
j=1: 3 <= 6   i=0, swap(0,1)       3 8 9 1 5 7 2 | 6
j=2: 9 > 6    ні
j=3: 1 <= 6   i=1, swap(1,3)       3 1 9 8 5 7 2 | 6
j=4: 5 <= 6   i=2, swap(2,4)       3 1 5 8 9 7 2 | 6
j=5: 7 > 6    ні
j=6: 2 <= 6   i=3, swap(3,6)       3 1 5 2 9 7 8 | 6
завершення: swap(4, опорний)       3 1 5 2 6 7 8 9      опорний на індексі 4
```

Розбиття робить **один прохід**: O(n).

## Весь алгоритм

```csharp
static void QuickSort(int[] a, int low, int high)
{
    if (low >= high) return;                 // 0 або 1 елемент
    int p = Partition(a, low, high);
    QuickSort(a, low, p - 1);                // ліва сторона
    QuickSort(a, p + 1, high);               // права сторона
}

QuickSort(array, 0, array.Length - 1);
```

## Вартість залежить від опорного елемента

Якщо опорний ділить діапазон на **дві половини**, дерево рекурсії має `log₂ n` рівнів, і кожен рівень виконує O(n) роботи в розбиттях:

```text
T(n) = 2 · T(n / 2) + O(n)   =>   O(n log n)
```

Але якщо опорний щоразу **найменший чи найбільший** елемент, одна сторона порожня, а в іншій `n − 1` елементів:

```text
T(n) = T(n − 1) + O(n)   =>   O(n²)
```

З останнім елементом як опорним це стається на **вже відсортованому** масиві або зворотному: саме на вхідних даних, що здаються нешкідливими. Рекурсія також іде на `n` рівнів углиб, тож стек може переповнитися.

| Випадок | Час |
| --- | --- |
| Найкращий і середній | **O(n log n)** |
| Найгірший | **O(n²)** |

## Вибір доброго опорного елемента

- **Випадковий елемент.** Переставте випадковий елемент в останню позицію перед розбиттям. Жодні конкретні дані не погані, а випадок O(n²) стає надзвичайно малоймовірним.
- **Медіана з трьох**: медіана першого, середнього та останнього елементів. Добре впорається з відсортованим входом.
- **Середній елемент** — простий вибір, що справляється з відсортованими та зворотними даними.

```csharp
static readonly Random random = new Random();

int r = random.Next(low, high + 1);
Swap(a, r, high);                  // випадковий опорний, потім звичайне розбиття
```

## Багато рівних елементів

Коли багато елементів рівні, двостороннє розбиття вище може деградувати. **Тристороннє розбиття** (прапор Нідерландів) ділить на `< опорного`, `== опорного`, `> опорного` й рекурсивно йде лише в першу й останню частини. Масиви з багатьма дублікатами тоді стають швидкими.

## Властивості

- **На місці**: допоміжний масив не потрібен. Додаткова пам'ять — лише стек рекурсії: **O(log n)**, якщо завжди йти рекурсією в **меншу** сторону, а більшу обробляти циклом.
- **Нестабільне**: обміни можуть переставити рівні елементи.
- **Швидке на практиці**: внутрішній цикл простий і читає пам'ять послідовно, що добре використовує кеш процесора. Зазвичай воно випереджає сортування злиттям на масивах.

## Quickselect: k-й за величиною

Якщо потрібен лише **k-й за величиною** елемент (скажімо, медіана), усе сортувати не треба. Після розбиття ви знаєте остаточну позицію опорного `p`. Якщо `p == k`, готово. Якщо `k < p`, продовжуйте лише в **лівій** стороні, інакше лише в **правій**.

```text
T(n) = T(n / 2) + O(n)   =>   O(n) у середньому
```

Воно знаходить медіану мільйона чисел за лінійний час, без сортування.

## Що робить бібліотека

`Array.Sort` та `List<T>.Sort` у .NET використовують **introsort**: швидке сортування, що перемикається на **пірамідальне**, якщо рекурсія стає надто глибокою (тож найгірший випадок — O(n log n)), і на **сортування вставками** для малих шматків. Воно **нестабільне**. Для стабільного сортування користуйтеся `OrderBy` з LINQ.
