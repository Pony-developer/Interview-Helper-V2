Саме в розгалуженнях програми найчастіше поводяться хибно: вони компілюються, запускаються, а іноді обирають не ту дорогу. Ось помилки, що повторюються знову й знову.

## 1. `=` замість `==`

```csharp
int x = 5;
if (x = 10) { }    // помилка CS0029: не можна перетворити int на bool
```

З `int` компілятор це помітить. З `bool` — ні, бо присвоєння має значення, яке було присвоєне:

```csharp
bool done = false;
if (done = true)   // компілюється (з попередженням): присвоює true, і умова завжди істинна
{
    Console.WriteLine("always runs");
}
```

## 2. Крапка з комою після умови

```csharp
if (x > 0);
    Console.WriteLine("positive");   // виконується за будь-якого x
```

`;` — це порожня інструкція, тож `if` нічим не керує, а наступний рядок — звичайна інструкція. Компілятор попереджає про «можливу помилкову порожню інструкцію». Читайте попередження.

## 3. Відсутні фігурні дужки

```csharp
if (x > 0)
    Console.WriteLine("positive");
    Console.WriteLine("and I checked");   // НЕ є частиною if
```

Відступи вводять в оману, але компілятор їх ігнорує. Без дужок `if` керує лише **однією** інструкцією. Завжди ставте дужки, навіть для однієї інструкції.

## 4. Висячий else

```csharp
if (a > 0)
    if (b > 0)
        Console.WriteLine("both");
else
    Console.WriteLine("???");
```

`else` належить **найближчому** `if` перед ним, тож цей `else` пов'язаний із `b > 0`, а не з `a > 0`, що б не підказували відступи. Дужки усувають сумнів.

## 5. Умови в неправильному порядку

Гілки перевіряються згори донизу, і перша, що збіглася, перемагає:

```csharp
if (score >= 50) grade = "pass";
else if (score >= 90) grade = "excellent";   // недосяжна: 95 перехоплює перша гілка
```

Починайте з найконкретнішої умови (`>= 90`), а тоді переходьте до ширших.

## 6. Помилка на одиницю на межі

`>` чи `>=`? `<` чи `<=`? Вирішіть, що має статися **на** граничному значенні. Чи дорослий 18-річний (`age >= 18`)? Чи достатньо 1000 балів для бонусу (`> 1000` чи `>= 1000`)? Завжди перевіряйте саму межу та значення по обидва боки від неї.

## 7. Ланцюжкові порівняння та половинчасті умови

```csharp
if (1 < x < 10) { }        // не компілюється
if (x == 1 || 2) { }       // не компілюється
if (x == 1 || x == 2) { }  // правильно
if (x > 1 || x < 10) { }   // компілюється, але істинне для будь-якого x
```

Остання найнебезпечніша, бо вона коректна й хибна водночас. Для «між» використовуйте `&&`.

## 8. Недбале порівняння рядків

```csharp
if (answer == "yes") { }   // "Yes" та "YES" не збігаються
if (answer.ToLower() == "yes") { }
```

Нормалізуйте введене (`Trim`, `ToLower`) перед порівнянням. Перевіряйте на `null`, перш ніж викликати методи.

## 9. Порівняння double через `==`

`0.1 + 0.2 == 0.3` — це `False`. Використовуйте допуск, як описано в лекції про числа з плаваючою комою.

## 10. Шлях без результату

```csharp
static string Sign(int x)
{
    if (x > 0) return "positive";
    if (x < 0) return "negative";
    // помилка CS0161: not all code paths return a value
}
```

Компілятор не може бути певним, що одна з умов істинна, тож вимагає завершального `return` для решти випадку.

## 11. Дублювання коду в гілках

```csharp
if (isMember)
{
    Console.WriteLine("Total: " + price * 0.9);
    Console.WriteLine("Thank you!");
}
else
{
    Console.WriteLine("Total: " + price);
    Console.WriteLine("Thank you!");
}
```

Усе, що однакове в кожній гілці, має стояти **поза** ними. Усередині `if` обчислюйте лише те, що відрізняється.

## Контрольний список для кожного `if`

- Чи перевірив я справді кожен випадок, що є в гілках?
- Чи перевірив я кожне граничне значення та значення по обидва боки?
- Чи гілки охоплюють **усі** можливості, зокрема неочікувану (`else` або `default`)?
- Чи умови стоять у правильному порядку?
- Чи не спростить усе ранній `return`?
