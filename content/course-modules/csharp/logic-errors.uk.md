Логічна помилка — найпідступніша: програма компілюється, доходить до кінця й друкує результат, ось тільки результат хибний. Про неї ніхто не повідомить. Ви помічаєте її лише тому, що знаєте, якою **мала** бути відповідь.

## Починайте з очікуваного результату

Перш ніж налагоджувати, потрібен випадок, у якому ви знаєте правильну відповідь. Порахуйте його вручну:

- середнє арифметичне `4`, `8` та `9` має бути `7`;
- прямокутник 5 × 8 має периметр `26`.

Якщо програма друкує інше, ви маєте відтворюваний баг і спосіб дізнатися, коли його виправлено. Перевіряйте й **граничні випадки**: нуль, від'ємні числа, найменше та найбільше значення, порожній рядок.

## Звичайні підозрювані

**Цілочисельне ділення**

```csharp
double half = 1 / 2;          // 0, а не 0.5
double percent = 1 / 4 * 100; // 0, ділення спершу губить дробову частину
```

**Пріоритет операторів**

```csharp
double average = a + b + c / 3;     // на 3 ділиться лише c
double correct = (a + b + c) / 3.0;
```

**Помилка на одиницю**: коли рахунок іде від 0, остання позиція — це `Length - 1`, а не `Length`.

```csharp
string s = "abc";
char last = s[s.Length - 1];   // 'c'; s[s.Length] кинув би виняток
```

**Не та змінна чи не той оператор**: скопійований рядок, де одне ім'я не змінили, або `-` замість `+`.

**Сюрпризи з плаваючою комою**: `double` зберігає більшість десяткових дробів наближено, тому `0.1 + 0.2 == 0.3` — це `False`. Не порівнюйте `double` на точну рівність, а для грошей беріть `decimal`.

**`=` замість `==`**: `=` присвоює, `==` порівнює.

## Як полювати на логічну помилку

1. **Відтворіть її** на найменших вхідних даних, що ще показують проблему.
2. **Скажіть, чого очікували й що отримали**, і для якого значення різниця з'являється вперше.
3. **Друкуйте проміжні значення.** Найпростіший налагоджувач — це `Console.WriteLine`:

   ```csharp
   int sum = a + b + c;
   Console.WriteLine("sum = " + sum);          // 21
   double average = sum / 3;
   Console.WriteLine("average = " + average);  // 7
   ```

   Знайдіть перший рядок, значення в якому відрізняється від порахованого вручну. Помилка на ньому або безпосередньо перед ним.
4. **Розділяй і володарюй.** Розбийте роботу на менші методи й перевіряйте кожен окремо.
5. **Поясніть код уголос**, рядок за рядком, колезі або гумовій качці. Коли промовляєш, хибне припущення часто виявляється саме.
6. **Змінюйте щось одне за раз** і запускайте після кожної зміни.

Коли помилку виправлено, залиште випадок, що її виявив, як тест. Так вона не повернеться.
