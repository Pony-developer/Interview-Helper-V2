Допоміжний метод `Check` з першої лекції працює, але кожному проєкту довелося б писати його знову, і він не вміє сам знаходити тести, запускати їх ізольовано чи повідомляти про збої у формі, зрозумілій інструментам. **Фреймворк тестування** робить усе це. Ви пишете тестові методи, а фреймворк виявляє, запускає й звітує про них.

> **Примітка.** Онлайн-запускач цього курсу не вміє завантажувати пакети NuGet, тож приклади з фреймворками призначені для вашого комп'ютера. Практичні завдання користуються простим допоміжним методом `Check`, побудованим на тих самих ідеях.

## Три основні фреймворки для .NET

| | xUnit | NUnit | MSTest |
| --- | --- | --- | --- |
| Тестовий клас | будь-який публічний клас | `[TestFixture]` | `[TestClass]` |
| Тест | `[Fact]` | `[Test]` | `[TestMethod]` |
| Тест із даними | `[Theory]` + `[InlineData]` | `[TestCase]` | `[DataRow]` |
| Перед кожним тестом | конструктор | `[SetUp]` | `[TestInitialize]` |
| Перевірка рівності | `Assert.Equal(expected, actual)` | `Assert.That(actual, Is.EqualTo(expected))` | `Assert.AreEqual(expected, actual)` |

Усі три зрілі й широко вживані. Вони відрізняються стилем, а не можливостями. xUnit — типовий у шаблонах `dotnet new` та в багатьох проєктах з відкритим кодом, MSTest постачається з Visual Studio, а NUnit має найдовшу історію. Обирайте той, який уже використовує ваша команда.

## Той самий тест тричі

```csharp
// xUnit
using Xunit;

public class CalculatorTests
{
    [Fact]
    public void Add_TwoNumbers_ReturnsSum()
    {
        int result = Calculator.Add(2, 3);
        Assert.Equal(5, result);
    }
}
```

```csharp
// NUnit
using NUnit.Framework;

[TestFixture]
public class CalculatorTests
{
    [Test]
    public void Add_TwoNumbers_ReturnsSum()
    {
        int result = Calculator.Add(2, 3);
        Assert.That(result, Is.EqualTo(5));
    }
}
```

```csharp
// MSTest
using Microsoft.VisualStudio.TestTools.UnitTesting;

[TestClass]
public class CalculatorTests
{
    [TestMethod]
    public void Add_TwoNumbers_ReturnsSum()
    {
        int result = Calculator.Add(2, 3);
        Assert.AreEqual(5, result);
    }
}
```

Тест — це **метод з атрибутом**. Якщо метод завершився, тест пройдено. Якщо перевірка не спрацювала або виняток вирвався назовні, тест провалено.

## Перевірки (assertions)

**Перевірка** порівнює отримане з очікуваним і провалює тест, коли вони відрізняються. Найпоширеніші в xUnit:

```csharp
Assert.Equal(5, result);                 // рівність: ОЧІКУВАНЕ значення йде першим
Assert.NotEqual(0, result);
Assert.True(list.Contains(3));
Assert.False(string.IsNullOrEmpty(name));
Assert.Null(user);
Assert.Contains("ann", names);
Assert.Empty(items);
Assert.Equal(0.3, 0.1 + 0.2, 10);        // double: порівняння до 10 знаків після коми
Assert.Throws<DivideByZeroException>(() => Calculator.Divide(1, 0));
```

Зважайте на порядок аргументів: **спершу очікуване, потім фактичне**. Якщо поміняти їх місцями, тест усе одно правильно проходить або провалюється, але повідомлення про збій вводитиме в оману («очікувалося 4, а було 5» для протилежної ситуації).

## Звідки беруться бібліотеки: NuGet

Бібліотеки в .NET поширюються як **пакети** в **NuGet**. Проєкт перелічує свої пакети у файлі `.csproj`, а інструменти їх завантажують:

```text
dotnet add package FluentAssertions
```

Тестовий проєкт зазвичай містить:

- фреймворк тестування (наприклад, xUnit та його виконавець);
- `Microsoft.NET.Test.Sdk`, що дозволяє `dotnet test` і Visual Studio запускати тести;
- **посилання** на проєкт, який тестується.

## Допоміжні бібліотеки

| Бібліотека | Призначення |
| --- | --- |
| **FluentAssertions** (або Shouldly) | читабельні перевірки: `result.Should().Be(5)` |
| **Moq**, **NSubstitute** | створюють підроблені об'єкти (mocks) замість бази даних, вебсервісу чи годинника |
| **AutoFixture**, **Bogus** | генерують тестові дані |
| **Coverlet** | вимірює покриття коду |
| **Testcontainers** | запускає справжню базу даних у контейнері для інтеграційних тестів |
| **Playwright**, **Selenium** | керують браузером для наскрізних тестів |

Для початку жодна з них не потрібна. Самого фреймворку вистачає для більшості модульних тестів.

## Вибір бібліотеки

Перш ніж додавати залежність, спитайте:

- Чи її підтримують і чи вона працює з вашою версією .NET?
- Чи знає її команда або може швидко навчитися?
- Чи вона розв'язує справжню проблему, яка є зараз, чи це «про всяк випадок»?

Кожна бібліотека — це додатковий код, який треба вивчати, оновлювати й одного дня замінювати. Починайте з фреймворку, а допоміжні бібліотеки додавайте, коли з'являється реальна потреба.
