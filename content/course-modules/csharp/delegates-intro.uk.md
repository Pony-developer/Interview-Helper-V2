**Делегат** — це тип, що представляє метод з певною сигнатурою. Змінна типу делегата може тримати будь-який метод з тими самими параметрами й типом значення, що повертається.

## Оголошення типу делегата

```csharp
delegate int Operation(int a, int b);     // тип: «метод, що приймає два int і повертає int»

static int Add(int a, int b) { return a + b; }
static int Multiply(int a, int b) { return a * b; }

Operation op = Add;                       // метод присвоюється, а не викликається
Console.WriteLine(op(2, 3));              // 5: виклик делегата викликає Add
op = Multiply;                            // та сама змінна тепер тримає інший метод
Console.WriteLine(op(2, 3));              // 6
```

Оголошення `delegate int Operation(int a, int b);` схоже на метод без тіла, з ключовим словом `delegate` попереду. Воно визначає новий тип, і його можна оголосити всередині класу або поза ним.

## Передача делегата в метод

Тепер попередню проблему розв'язано. Метод отримує правило як параметр:

```csharp
static int Apply(Operation op, int x, int y)
{
    return op(x, y);                      // метод не знає, яку операцію виконує
}

Console.WriteLine(Apply(Add, 10, 4));       // 14
Console.WriteLine(Apply(Multiply, 10, 4));  // 40
```

`Add` і `Multiply` передають за іменем, без дужок. Назва методу, що вживається як значення, перетворюється на тип делегата. Це перетворення називають **перетворенням групи методів** (method group conversion).

## Делегати безпечні за типами

Компілятор перевіряє, що метод має правильну сигнатуру. Передача методу з трьома параметрами чи методу, що повертає `string`, — помилка компіляції. Порівняйте з рядковим прапорцем з попередньої лекції, де помилку з опечаткою знаходили лише під час виконання.

## Виклик делегата

`op(2, 3)` і `op.Invoke(2, 3)` роблять одне й те саме. Коротка форма — звичайна.
