**Поліморфізм** («багато форм») — це можливість використовувати об'єкти різних класів **через той самий тип** і дозволяти кожному об'єктові виконувати дію **по-своєму**.

Першу половину ви вже бачили: змінна `IShape` може тримати `Circle` або `Square`. Друга половина — ключова: коли ви викликаєте `shape.Area()`, **об'єкт сам вирішує**, який код виконається.

```csharp
IShape[] shapes = { new Circle(1), new Square(2), new Circle(0.5) };

foreach (IShape shape in shapes)
{
    Console.WriteLine(shape.Name + ": " + Math.Round(shape.Area(), 2));
}
// Circle: 3.14
// Square: 4
// Circle: 0.79
```

У циклі один рядок коду, а три об'єкти поводяться трьома способами. Цей рядок однаковий для будь-якої фігури й працює для фігури, якої **ще не існує**: додайте `Triangle : IShape`, і цикл не потребуватиме змін.

## Без поліморфізму

Та сама програма без нього потребує **перевірки типу** для кожного випадку:

```csharp
foreach (object shape in shapes)
{
    if (shape is Circle c)
    {
        total += Math.PI * c.Radius * c.Radius;
    }
    else if (shape is Square s)
    {
        total += s.Side * s.Side;
    }
    // Triangle? Знайдіть кожне таке місце в програмі й додайте гілку...
}
```

Такий ланцюжок `if` та `is` — **тривожна ознака**. Кожен новий клас означає правки в кожному місці, де ланцюжок повторюється, а пропущене місце — мовчазна помилка. Поліморфізм замінює ланцюжок **одним викликом**: «скажи йому це зробити, і він знає як».

## Динамічна диспетчеризація

Коли програма виконує `shape.Area()`, компілятор знає лише **статичний** тип, `IShape`. Версію методу вибирають **під час виконання програми** за **динамічним** (справжнім) типом об'єкта. Це називається **динамічною диспетчеризацією**, або **пізнім зв'язуванням**.

```csharp
IShape shape = new Square(2);
shape = new Circle(1);                       // та сама змінна, інший об'єкт
Console.WriteLine(shape.Area());             // виконується Area з Circle
```

## Два шляхи до поліморфізму

1. Через **інтерфейс**: різні класи реалізують той самий контракт (попередні лекції).
2. Через **базовий клас із віртуальними методами**: похідні класи **перевизначають** поведінку базового (наступна лекція).

Для коду, що їх використовує, обидва дають однаковий ефект. Інтерфейс кращий, коли класи непов'язані або мають лише спільну роль. Базовий клас кращий, коли вони також ділять **дані** та частину **коду**.

## Приклад: базовий клас і список

```csharp
var animals = new List<Animal> { new Dog(), new Cat(), new Cow() };
foreach (Animal animal in animals)
{
    Console.WriteLine(animal.Sound());        // Woof, Meow, Moo
}
```

Список має один тип елементів, `Animal`, і тримає об'єкти трьох класів. Кожен відповідає на `Sound()` по-своєму.

## Навіщо це потрібно

- **Менше коду**: немає копій методів для кожного типу, немає ланцюжків `if` / `is`.
- **Легші зміни**: новий вид об'єкта — це новий клас, а старий код не чіпають.
- **Тестування**: справжній об'єкт можна замінити простою підробкою, якщо код просить інтерфейс.

Решта модуля показує, як **створити** метод, що так поводиться: `virtual` та `override`.
