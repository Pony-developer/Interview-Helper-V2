Цикл, що працює, не завжди легко читати. Рефакторинг циклу означає переписати його так, щоб він **робив те саме** у простішій формі. Змінюйте щось одне за раз і після кожного кроку повторно запускайте перевірки.

## 1. Замініть прапорець самою умовою

Булевий прапорець, який існує лише для зупинки циклу, — ознака того, що логіку вивернуто навиворіт:

```csharp
// до
bool finished = false;
int steps = 0;
while (!finished)
{
    if (n == 1)
    {
        finished = true;
    }
    else
    {
        if (n % 2 == 0) n = n / 2;
        else n = 3 * n + 1;
        steps++;
    }
}

// після
int steps = 0;
while (n != 1)
{
    n = n % 2 == 0 ? n / 2 : 3 * n + 1;
    steps++;
}
```

Обидві версії рахують, скільки кроків потрібно послідовності, щоб дійти до 1, але друга каже це однією умовою.

## 2. Приберіть дублювання коду навколо циклу

Коли перше значення потрібно отримати перед циклом і ще раз наприкінці тіла, той самий код записано двічі. Два способи вилікувати:

```csharp
// до
int value = Next();
while (value != 0)
{
    Process(value);
    value = Next();       // той самий виклик, що й вище
}

// після: "do-while"
int value;
do
{
    value = Next();
    if (value != 0) Process(value);
}
while (value != 0);

// або: "while (true)" з break
while (true)
{
    int value = Next();
    if (value == 0) break;
    Process(value);
}
```

Остання форма часто найзрозуміліша: виклик один, а вихід розташований там, де це відбувається.

## 3. Використовуйте `return` чи `break` замість прапорця пошуку

```csharp
// до
bool found = false;
int i = 2;
while (i < n && !found)
{
    if (n % i == 0) found = true;
    else i++;
}
// found каже, чи має n дільник

// після: метод, що повертає, щойно знає відповідь
static bool HasDivisor(int n)
{
    for (int i = 2; i < n; i++)
    {
        if (n % i == 0) return true;
    }
    return false;
}
```

## 4. Перетворіть `while` на `for`, коли лічильник очевидний

Якщо змінну ініціалізовано просто перед циклом, перевіряється в умові й змінюється наприкінці тіла, це `for` у маскуванні:

```csharp
// до
int i = 0;
while (i < 10)
{
    Console.WriteLine(i);
    i++;
}

// після
for (int i = 0; i < 10; i++)
{
    Console.WriteLine(i);
}
```

Початок, умова та крок тепер в одному рядку, і крок неможливо забути.

## 5. Розплющіть вкладеність через `continue`

```csharp
// до
for (int i = 1; i <= 100; i++)
{
    if (i % 3 == 0)
    {
        if (i % 5 == 0)
        {
            Console.WriteLine(i);
        }
    }
}

// після
for (int i = 1; i <= 100; i++)
{
    if (i % 15 != 0) continue;
    Console.WriteLine(i);
}
```

Охоронні умови, що спершу відкидають нецікаві випадки, лишають основну роботу на одному рівні відступу.

## 6. Винесіть незмінну роботу з циклу

```csharp
// до: Math.Sqrt перераховується в кожній ітерації
for (int i = 2; i <= Math.Sqrt(n); i++) { /* ... */ }

// після
int limit = (int)Math.Sqrt(n);
for (int i = 2; i <= limit; i++) { /* ... */ }
```

## 7. Дайте імена умові й тілу

Складна умова може стати методом, а довге тіло теж можна розбити на методи:

```csharp
// до
while (a > 0 && b > 0 && (a % 2 == 0 || b % 2 == 0)) { /* ... */ }

// після
while (CanContinue(a, b)) { /* ... */ }
```

## Безпечний рефакторинг

- Знайте очікуваний результат до початку. Збережіть кілька вхідних даних і виходів, які вони мають давати й надалі, зокрема граничні випадки.
- Змініть щось одне, запустіть і порівняйте. Якщо щось змінилося, скасуйте й зробіть менший крок.
- Не змішуйте рефакторинг зі зміною того, що робить код.
- Зупиніться, коли стало зрозуміло. Цикл не мусить бути хитромудрим.
