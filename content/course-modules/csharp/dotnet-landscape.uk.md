«Яка різниця між .NET Framework і .NET Core?» — одне з найчастіших питань на початку співбесіди. Щоб добре на нього відповісти, потрібна коротка історія платформи і чітке розуміння, що означає кожна назва сьогодні.

## .NET Framework (2002–2019)

Перший .NET. Він працює **лише на Windows** і є **частиною Windows**: на машині одна спільна інсталяція, і нова версія 4.x замінює попередню на місці. Тож оновлення фреймворку для одного застосунку оновлює його для всіх застосунків на машині.

Остання версія — **4.8.1**. Вона досі підтримується як компонент Windows і отримує виправлення безпеки, але не нові можливості. Її можна зустріти в старшому корпоративному коді: ASP.NET Web Forms, служби WCF, Windows Workflow, класичний ASP.NET MVC.

## Mono і Xamarin

**Mono** — відкрита кросплатформна повторна реалізація .NET Framework, яка з'явилася поза Microsoft. На ній працював Xamarin (застосунки для iOS і Android), і вона є середовищем виконання скриптів у Unity. Сьогодні її середовище виконання живе всередині сучасного .NET для мобільних платформ і WebAssembly (Blazor).

## .NET Core (2016–2019)

Переписаний з нуля .NET для епохи хмар:

- **кросплатформний**: Windows, Linux, macOS; x64 і ARM;
- **відкритий** код на GitHub, розробка ведеться публічно;
- **пліч-о-пліч** (side-by-side): кілька версій на одній машині, або середовище виконання всередині застосунку; оновлення одного застосунку ніколи не ламає інший;
- **швидкий**: великий акцент на продуктивності (`Span<T>`, новий JIT, Kestrel);
- **модульний**: бібліотеки постачаються пакетами і спільними фреймворками, а не одним монолітом.

Версії 1.0, 1.1, 2.0, 2.1, 2.2, 3.0 і 3.1. Деякі частини .NET Framework, прив'язані до Windows, так і не перенесли (Web Forms, серверну частину WCF, AppDomains, Code Access Security).

## .NET 5 і далі: один .NET

У 2020 році слово «Core» прибрали: **.NET 5** — це наступна версія .NET Core. Версію 4 пропустили, щоб не плутати з .NET Framework 4.x. Відтоді є одна лінійка: .NET 5, 6, 7, 8, 9, 10…

Коли сьогодні кажуть «.NET», мають на увазі саме її. Неформально її досі часто називають «.NET Core», і ця назва лишилася в іменах на кшталт «ASP.NET Core» і «EF Core».

## Ритм випусків

Нова мажорна версія виходить **щолистопада**:

| Версія | Тип | Підтримка |
| --- | --- | --- |
| Парні (.NET 8, .NET 10) | **LTS**, довгострокова підтримка | 3 роки |
| Непарні (.NET 9, .NET 11) | **STS**, стандартна підтримка | 2 роки |

Щомісяця кожна підтримувана версія отримує **патч** (наприклад, 10.0.3) з виправленнями безпеки та помилок. Робочий застосунок має бути на підтримуваній версії й отримувати патчі. Багато команд переходять з LTS на LTS.

## Порівняння

| | .NET Framework | .NET (Core, 5+) |
| --- | --- | --- |
| Операційні системи | лише Windows | Windows, Linux, macOS |
| Інсталяція | одна на машину, оновлення на місці | багато версій пліч-о-пліч або всередині застосунку |
| Код | лише довідковий (reference source) | відкритий |
| Нові можливості | немає | щороку |
| Веб | ASP.NET (System.Web) | ASP.NET Core |
| Десктоп | WinForms, WPF | WinForms, WPF (лише Windows), MAUI |
| Контейнери, хмара | важкі образи Windows | малі образи Linux |

## Що обрати

- **Новий код**: останній LTS (або останній випуск, якщо можете оновлюватися щороку).
- **Наявний код на .NET Framework**: підтримуйте його роботу і мігруйте, коли є причина (кросплатформний хостинг, продуктивність, кінець підтримки залежності). З механічною частиною допомагає .NET Upgrade Assistant.
- **Код, спільний для обох світів**: бібліотека під .NET Standard 2.0 (див. урок про BCL і NuGet).

## Відповідь для співбесіди

.NET Framework — це оригінальна реалізація лише для Windows, яка встановлюється один раз на машину і зараз лише підтримується. .NET Core, з версії 5 перейменований просто на .NET, — її кросплатформний відкритий наступник: він встановлюється пліч-о-пліч, працює значно швидше, отримує нову версію щороку, і саме на ньому ведеться вся нова розробка.
