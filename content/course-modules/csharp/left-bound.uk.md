Коли відсортований масив має **повторювані** значення, звичайний двійковий пошук повертає якусь позицію значення, але часто потрібна конкретна. **Ліва межа** (її також називають **нижньою межею**) — найкорисніший варіант.

Реалізуйте `LowerBound(sorted, x)`. Він повертає **найменший індекс `i`**, для якого `sorted[i] >= x`. Якщо кожен елемент менший за `x`, повертає `sorted.Length`: позицію одразу після кінця, куди `x` було б вставлено.

Це позиція, де `x` **вперше з'являється**, якщо `x` є, і позиція, куди `x` **було б вставлено**, щоб масив лишився відсортованим, якщо його немає.

Для масиву `{ 1, 2, 2, 2, 5, 8, 8, 10 }`:

| x | `LowerBound` | Чому |
| --- | --- | --- |
| 0 | 0 | усе `>= 0`: початок |
| 2 | 1 | перша двійка за індексом 1 |
| 3 | 4 | перший елемент `>= 3` — це 5 за індексом 4 |
| 8 | 5 | перша вісімка за індексом 5 |
| 11 | 8 | усі менші: кінець |

Пошук має бути **двійковим**: O(log n). Ось форма, у якій важко помилитися, із **напіввідкритим** діапазоном `[lo, hi)`:

```csharp
int lo = 0, hi = sorted.Length;            // відповідь десь у lo..hi
while (lo < hi)
{
    int mid = lo + (hi - lo) / 2;
    if (sorted[mid] < x) lo = mid + 1;     // замале: відповідь праворуч
    else hi = mid;                         // mid може бути відповіддю: лишаємо його
}
return lo;
```

`Main` не змінюйте. Очікуваний вивід:

```text
0 -> 0
1 -> 0
2 -> 1
3 -> 4
5 -> 4
8 -> 5
9 -> 7
10 -> 7
11 -> 8
0
```

Останній рядок — `LowerBound` для порожнього масиву: відповідь 0.

Підказка: інваріант — «усе перед `lo` менше за `x`, а все від `hi` і далі не менше за `x`». Коли `lo == hi`, межу знайдено.
