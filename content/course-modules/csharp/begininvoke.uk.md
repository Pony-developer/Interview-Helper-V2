В застосунку з графічним інтерфейсом (WinForms, WPF) є один особливий потік: **потік UI**. Лише він може торкатися елементів керування: кнопок, міток, текстових полів. Якщо фоновий потік записує в мітку напряму, програма падає з винятком або поводиться випадково.

Фоновий потік мусить передати роботу назад потоку UI. Це називають **маршалінгом**, а методи — `Invoke` (чекає на потік UI) і `BeginInvoke` (не чекає).

```csharp
// WinForms, усередині класу форми. Цей код не виконується в консолі.
void ShowProgress(int percent)
{
    if (label.InvokeRequired)                       // ми в іншому потоці?
    {
        label.BeginInvoke(new Action(() => ShowProgress(percent)));   // просимо потік UI виконати це знову
        return;
    }
    label.Text = percent + "%";                     // тепер ми в потоці UI: з міткою можна працювати безпечно
}
```

## Invoke і BeginInvoke

- `Invoke` передає дію потоку UI і **чекає**, доки її буде виконано. Це просто, але фоновий потік стоїть під час очікування.
- `BeginInvoke` передає дію і **продовжує одразу**. Потік UI виконає її пізніше. Вживайте його, коли фоновий потік має іншу роботу.

## Старий BeginInvoke делегата

`BeginInvoke` — також метод, який мали всі делегати в старих версіях .NET Framework, для асинхронного виклику самого делегата. Сучасний .NET його прибрав. У новому коді для цього вживайте `Task` і `async/await`, як показує останній модуль.

## Навіщо `InvokeRequired`

Перевірка `InvokeRequired` каже коду, чи він виконується в потоці UI. Той самий метод тоді можна викликати з обох місць, а маршалінг відбувається лише тоді, коли він потрібен.
