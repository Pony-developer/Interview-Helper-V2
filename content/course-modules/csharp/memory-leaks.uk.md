«У C# є збирач сміття, тож пам'ять не може витікати». Це не так. GC звільняє лише **недосяжні** об'єкти. Керований витік — це набір об'єктів, які програмі більше не потрібні, але на які вона **досі посилається**, часто випадково. GC не відрізняє «ще потрібне» від «забутого».

## Типові причини

**1. Підписки на події.** Видавець тримає посилання на кожен обробник, а обробник — екземплярний метод — тримає посилання на свій об'єкт. Якщо видавець живе довго (статична подія, сервіс-синглтон), а підписники приходять і йдуть, кожен підписник лишається живим назавжди.

```csharp
class OrderWindow
{
    public OrderWindow(PriceService prices)    // PriceService живе весь час роботи застосунку
    {
        prices.PriceChanged += OnPriceChanged; // вікно ніколи не буде зібрано
    }
}
```

Виправлення: відписуватися, коли підписник закінчив роботу, зазвичай у `Dispose`.

**2. Статичні колекції та кеші, що лише ростуть.** `static Dictionary<int, User> cache` без видалення тримає кожного будь-коли завантаженого користувача. Використовуйте кеш з обмеженнями: `MemoryCache` з терміном життя і лімітом розміру.

**3. Таймери.** Запущений `System.Threading.Timer` тримає свій колбек, а отже, і об'єкт колбека. Звільняйте таймери, які більше не потрібні.

**4. Замикання.** Лямбда, збережена в довгоживучому місці, захоплює змінні, які використовує, включно з великими об'єктами, які ви не збиралися тримати.

**5. Незвільнені некеровані ресурси.** Нативна пам'ять, дескриптори та з'єднання, які ніколи не звільняють.

**6. Необмежені черги.** Виробник, швидший за споживача, нарощує чергу, доки не скінчиться пам'ять. Використовуйте обмежені черги.

## Слабкі посилання

`WeakReference<T>` вказує на об'єкт, **не тримаючи його живим**:

```csharp
var weak = new WeakReference<Image>(bigImage);
// ... пізніше
Image image;
if (weak.TryGetTarget(out image))
    Show(image);   // ще в пам'яті
else
    Reload();      // GC його вже зібрав
```

Це корисно для кешів об'єктів, які дешево створити знову, і для реалізацій «слабких подій».

## Як знайти витік

Симптом: пам'ять росте з часом і не зменшується після повних збирань.

1. Стежте за розміром купи через `dotnet-counters`.
2. Зробіть два знімки купи з проміжком у часі (`dotnet-gcdump`, Visual Studio, dotMemory).
3. Порівняйте їх: знайдіть типи, кількість об'єктів яких постійно росте.
4. Подивіться на **шлях утримання** (retention path) одного такого об'єкта: ланцюжок посилань від кореня. Він точно показує, хто його тримає.

## Правило

Кожен довгоживучий об'єкт, що посилається на короткоживучі, — кандидат на витік. Відписуйтеся від подій, обмежуйте кеші й черги і звільняйте таймери.
