Більшість методів LINQ повертають послідовність, а послідовність має ті самі методи. Тож виклики можна **ланцюжити**, один за одним, будуючи запит крок за кроком:

```csharp
var people = new[] { "Ann:31", "Bob:17", "Cy:45", "Dan:17", "Eve:28" };

var adults = people
    .Select(p => p.Split(':'))              // ["Ann", "31"], ...
    .Select(parts => new { Name = parts[0], Age = int.Parse(parts[1]) })
    .Where(p => p.Age >= 18)
    .OrderBy(p => p.Age)
    .Select(p => p.Name)
    .ToList();                              // Ann, Eve, Cy
```

Кожен рядок — один крок. Читач може стежити за даними згори донизу: розібрати, перетворити, відфільтрувати, відсортувати, взяти імена, зібрати.

## Оформлення ланцюжка

Один метод на рядок, а крапки — на початку кожного рядка. Це стандартний стиль, і він дозволяє легко додати чи прибрати крок.

## Ланцюжки ліниві до кінця

Кожен метод ланцюжка повертає нову послідовність, яка пам'ятає, що робити. Нічого не виконується, доки ланцюжок не **прочитають**. Читають лише `ToList()`, `ToArray()`, `Count()`, `First()`, `Sum()` і `foreach`:

```csharp
var query = people.Where(p => p.Length > 3);   // ще нічого не виконано
people = new[] { "Zed:50" };                  // джерело змінилося
Console.WriteLine(query.Count());              // запит виконується зараз, над новими даними
```

Це ціна лінивості: результат відображає джерело в момент читання, а не в момент створення запиту.

## Читайте ланцюжок як речення

Добрі ланцюжки короткі й мають назви: змінна з ясною назвою для складного кроку. Ланцюжок з десяти кроків і складними лямбдами важко читати. Розбийте його на дві названі частини.
