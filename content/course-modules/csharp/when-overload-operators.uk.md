Оператори роблять код коротким, а короткий код може бути важким для читання. Гарне правило: **перевантажуйте оператор лише тоді, коли він означає саме те, що очікує читач**.

## Добрі кандидати

- **Типи-значення з арифметикою:** `Vector + Vector`, `Money + Money`, `Fraction * Fraction`. Тут читачі очікують, що `+` означає додавання.
- **Порівняння для порядку:** `<` і `>` для типу з природним порядком, наприклад дати чи номера версій. Зазвичай достатньо `IComparable`, а оператори — лише зручність.
- **Рівність об'єкта-значення:** `==` для `Point` чи `Address`, щоб `a == b` означало «те саме значення».

## Погані кандидати

- **Оператори з неясним значенням:** `a + b` для двох об'єктів `Report`. Їх об'єднують чи додають кількості сторінок? Краще метод з назвою: `Merge`, `Combine`.
- **Оператори, що змінюють свої операнди:** `a += b` не повинен змінювати `b`, а `a + b` не повинен змінювати `a`. Читачі не очікують побічних ефектів від арифметичного символу.
- **Оператори для колекцій:** `list + item` схожий на арифметику, але зазвичай означає «додати». Використовуйте `Add`.
- **Оператори, що кидають несподівані винятки:** ділення на нульовий дріб очікуване, але `+`, що кидає виняток для допустимих вхідних даних, — ні.

## Контрольне питання

Перш ніж писати оператор, запитайте себе: «Якщо хтось прочитає `a OP b` у коді, чи вгадає він результат без читання коду оператора?» Якщо ні, напишіть метод.

## Правила узгодженості

- Якщо в вашому типі є `==`, мають бути й відповідні `Equals` та `GetHashCode` (див. лекцію про `Equals`).
- Тримайте пари повними: `==` з `!=`, `<` з `>`.
- Оператори не мають кидати виняток для вхідних даних, які прийняв би їхній метод.

## Примітка про мову

Стандартна бібліотека C# використовує оператори обережно. `string` має `==` і `+`, а `DateTime` має `+` і `-`. Ці приклади — взірець: значення очевидне, а результат — нове значення.
