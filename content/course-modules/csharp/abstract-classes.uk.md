**Абстрактний клас** описує щось **незавершене**: загальну ідею, що не є готовою річчю. «Фігура» має площу, але обчислити площу «просто фігури» неможливо. Площа відома лише для кола, прямокутника, трикутника. Абстрактний клас дозволяє сказати це в коді.

```csharp
abstract class Shape                                  // "abstract": об'єкти цього класу створити не можна
{
    public abstract double Area { get; }              // абстрактний член: лише сигнатура, без тіла
    public abstract string Name { get; }

    public string Describe()                          // звичайний член, з кодом
    {
        return Name + " with the area " + Math.Round(Area, 2);
    }
}
```

## Що може мати абстрактний клас

- **абстрактні члени** (методи, властивості): без тіла, і їх **мусить** перевизначити неабстрактний похідний клас;
- **звичайні члени** з кодом: методи, властивості, поля, конструктори, `virtual` методи. Це **спільні** частини, які всі похідні класи отримують безкоштовно;
- будь-який рівень доступу, зокрема `protected` члени.

## Похідні від нього

```csharp
class Circle : Shape
{
    private readonly double radius;

    public Circle(double radius) { this.radius = radius; }

    public override double Area => Math.PI * radius * radius;     // мусить бути перевизначена
    public override string Name => "Circle";
}

class Square : Shape
{
    private readonly double side;

    public Square(double side) { this.side = side; }

    public override double Area => side * side;
    public override string Name => "Square";
}
```

```csharp
// Shape s = new Shape();                              // помилка CS0144: не можна створити екземпляр абстрактного класу

Shape[] shapes = { new Circle(1), new Square(2) };      // але змінна абстрактного типу — це добре
foreach (Shape shape in shapes)
{
    Console.WriteLine(shape.Describe());                // Describe написано один раз, для всіх
}
```

`Describe()` використовує `Area` і `Name`, які ще не написані, коли компілюється базовий клас. У цьому й суть: **спільний код пишуть проти абстрактних частин**, а кожен похідний клас постачає деталі.

## Правила

- Якщо клас має **хоча б один** абстрактний член, **клас мусить бути `abstract`**.
- Похідний клас мусить **перевизначити всі** абстрактні члени або сам бути `abstract`.
- Абстрактні члени неявно **віртуальні**, а в похідному класі їх пишуть з `override`.
- Абстрактний клас **може** мати конструктор, і він виконується під час створення похідного об'єкта (похідний конструктор викликає його через `: base(...)`). Доступ зазвичай `protected`, щоб показати, що він лише для похідних класів.
- Клас може походити від **одного** абстрактного класу.
- `static`, `sealed` та `abstract` не можна змішувати для того самого класу: `sealed` забороняє похідні класи, а `abstract` їх вимагає.

## abstract чи virtual?

| | `virtual` | `abstract` |
|---|---|---|
| Має типове тіло | Так | Ні |
| Чи мусить бути перевизначений | Ні, це необов'язково | Так, це обов'язково |
| Де може бути оголошений | У будь-якому класі | Лише в абстрактному класі |

Вживайте `virtual`, коли є **розумна типова поведінка**. Вживайте `abstract`, коли **розумної типової поведінки немає**, і кожен похідний клас мусить вирішити сам.

## Коли створювати абстрактний клас

1. Кілька класів **мають спільні код і дані**, а також **спільну роль**.
2. Сам базовий клас як об'єкт **не має сенсу** («тварина», «фігура», «документ»).
3. Ви хочете **примусити** похідні класи надати деякі частини.

Страховка: компілятор повідомить помилкою, якщо хтось забуде реалізувати обов'язкову частину. Це набагато краще за коментар «не забудьте...».
