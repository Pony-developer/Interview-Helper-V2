Клас може мати **лише один** базовий клас. Але реальний об'єкт грає кілька ролей: документ може бути *друкованим*, *зберігальним*, *порівнюваним*. **Інтерфейс** описує одну таку роль як **контракт**: перелік членів, які тип обіцяє мати. Він не каже, **як** вони працюють.

## Оголошення інтерфейсу

```csharp
interface IShape
{
    double Area();                         // без тіла, без модифікатора доступу
    string Name { get; }                   // властивість теж дозволена
}
```

За домовленістю, назви інтерфейсів починаються з **`I`**. Усі члени інтерфейсу автоматично `public` і **не мають коду**. Інтерфейс не має полів і конструкторів.

## Реалізація інтерфейсу

Клас, що **реалізує** інтерфейс, пише всі його члени. Синтаксис — та сама двокрапка, що й для успадкування:

```csharp
class Circle : IShape
{
    private readonly double radius;

    public Circle(double radius) { this.radius = radius; }

    public double Area() { return Math.PI * radius * radius; }
    public string Name { get { return "Circle"; } }
}

class Square : IShape
{
    private readonly double side;

    public Square(double side) { this.side = side; }

    public double Area() { return side * side; }
    public string Name { get { return "Square"; } }
}
```

Якщо клас забуде член, буде помилка компіляції: *«`Circle` does not implement interface member `IShape.Area()`»*. Контракт перевіряє компілятор.

## Інтерфейс — це тип

Змінна може мати тип інтерфейсу й тримати **будь-який об'єкт, чий клас його реалізує**:

```csharp
IShape shape = new Circle(1);
Console.WriteLine(shape.Name + ": " + Math.Round(shape.Area(), 2));    // Circle: 3.14

IShape[] shapes = { new Circle(1), new Square(2), new Circle(0.5) };
double total = 0;
foreach (IShape s in shapes)
{
    total += s.Area();                     // кожен об'єкт рахує свою площу
}
```

Код, що вживає `IShape`, не знає й **не мусить** знати, який клас за ним стоїть. Це та сама ідея, що й з базовим класом, але без спільного коду й без обмеження одним батьком. Приведення з попередньої лекції тут теж працюють: `shape is Circle`, `shape as Square`.

## Кілька інтерфейсів

Клас може реалізувати **скільки завгодно інтерфейсів** і водночас мати один базовий клас. Базовий клас іде першим:

```csharp
class Report : Document, IPrintable, ISavable
{
    // ...
}
```

## Інтерфейс чи базовий клас?

- **Базовий клас** каже, чим об'єкт **є**, і може ділитися з похідними **кодом** і **даними**.
- **Інтерфейс** каже, що об'єкт **вміє**, і ділиться лише **контрактом**. Непов'язані класи (`Report`, `Photo`, `Chair`) можуть реалізувати той самий інтерфейс.

Коли частині програми потрібне лише «щось, що можна порівняти» або «щось із площею», просіть **інтерфейс**. Так код легко розширювати й тестувати.

## Інтерфейси зі стандартної бібліотеки

Ви вже користувалися ними, не помічаючи:

| Інтерфейс | Контракт | Де трапляється |
|---|---|---|
| `IComparable<T>` | «Мене можна порівняти з іншим `T`» | `Array.Sort`, `List.Sort` |
| `IComparer<T>` | «Я порівнюю два об'єкти `T`» | `Array.Sort` із власним порядком |
| `IEnumerable<T>` | «Мене можна обійти» | `foreach`, LINQ |
| `IDisposable` | «Мене треба прибрати» | `using` |

`foreach` працює для масивів, списків і рядків, бо всі вони реалізують `IEnumerable`. Наступні лекції показують, як `IComparable<T>` та `IComparer<T>` задають порядок для ваших власних класів.

## Абстрактні класи: посередині

**Абстрактний клас** — це незавершений базовий клас: деякі члени не мають коду (`abstract`), а об'єктів такого класу створити не можна. Він стоїть між класом та інтерфейсом:

```csharp
abstract class Shape
{
    public abstract double Area();                    // похідні класи мусять це написати
    public string Describe() { return "Area " + Area(); }   // спільний код
}
```

До `abstract` ми повернемося в лекції про віртуальні методи.
