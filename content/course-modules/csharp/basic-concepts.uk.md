Перш ніж порівнювати алгоритми, потрібно домовитися, що саме ми порівнюємо. Ця лекція вводить базовий словник.

## Що таке алгоритм

**Алгоритм** — це точна послідовність кроків, що розв'язує задачу. Рецепт торта в цьому сенсі не алгоритм, а процедура з такими властивостями — алгоритм:

- **Вхід**: вона бере деякі дані (нуль або більше значень).
- **Вихід**: вона створює результат.
- **Визначеність**: кожен крок точний і однозначний.
- **Скінченність**: вона зупиняється за скінченну кількість кроків для кожних коректних вхідних даних.
- **Ефективність**: кожен крок достатньо простий, щоб його можна було виконати.

Програма — це алгоритм, записаний мовою програмування. Один алгоритм можна написати багатьма мовами, а одну задачу можна розв'язати багатьма алгоритмами. Ми порівнюємо **алгоритми**, а не мови.

## Розмір вхідних даних

Робота залежить від того, скільки даних. Цю кількість ми називаємо **n**, **розміром вхідних даних**. Що таке `n`, залежить від задачі:

| Задача | n |
| --- | --- |
| знайти максимум у масиві | кількість елементів |
| знайти слово в тексті | довжина тексту |
| відсортувати список | кількість елементів |
| знайти маршрут на карті | кількість місць і доріг |
| перевірити, чи число просте | кількість **цифр** числа (див. подальшу лекцію) |

Завжди кажіть, що таке `n`, перш ніж казати, наскільки щось швидке.

## Як міряти вартість

Найпростіша ідея — запустити програму із секундоміром:

```csharp
var timer = System.Diagnostics.Stopwatch.StartNew();
Run(data);
timer.Stop();
Console.WriteLine(timer.ElapsedMilliseconds + " ms");
```

Це корисно, але секундомір міряє не менше **комп'ютер**, ніж алгоритм. Результат залежить від процесора, мови, інших запущених програм і самих даних. Час 50 мс на вашому ноутбуці нічого не каже про той самий код на сервері чи про удвічі більше даних.

Тому в теорії ми натомість **рахуємо операції**: порівняння, присвоєння, арифметику. Кількість не залежить від машини й показує, як робота **зростає**, коли зростає `n`.

## Часова складність

**Часова складність** алгоритму — це функція `T(n)`: кількість елементарних операцій для вхідних даних розміру `n`.

```csharp
static int Sum(int[] a)
{
    int sum = 0;                       // 1 операція
    for (int i = 0; i < a.Length; i++) // цикл виконується n разів
    {
        sum += a[i];                   // 1 операція за прохід
    }
    return sum;                        // 1 операція
}
```

Якщо рахувати лише додавання, `T(n) = n`. Якщо рахувати все, зокрема власну роботу циклу, можемо отримати `T(n) = 3n + 2`. Точне число залежить від того, що ми називаємо «операцією». Важливо, що робота зростає **пропорційно n**, а лекції про O-нотацію покажуть, як сказати це формально.

## Просторова складність

**Просторова складність** — це скільки **додаткової пам'яті** потребує алгоритм як функція від `n`.

- `Sum` вище потребує лише двох змінних, яким би не було `n`: стала пам'ять.
- Метод, що будує **копію** масиву, потребує пам'яті пропорційно `n`.

Пам'ять для самих вхідних даних зазвичай не рахують. Часто існує **компроміс**: `HashSet` робить пошук дублікатів швидким, але коштує пам'яті.

## Найкращий, найгірший і середній випадок

Робота може залежати не лише від **розміру** вхідних даних, а й від самих **даних**. Розгляньте лінійний пошук значення в масиві з `n` елементів:

| Випадок | Коли | Порівнянь |
| --- | --- | --- |
| **найкращий** | значення — перший елемент | 1 |
| **найгірший** | значення останнє або відсутнє | n |
| **середній** | значення десь посередині | близько n / 2 |

Який використовувати? Зазвичай аналізують **найгірший випадок**: це гарантія («повільніше за це не буде») і саме те, що важить, коли програма має лишатися чутливою для будь-яких даних. **Середній випадок** потребує припущень про дані, а **найкращий** надто оптимістичний, щоб на нього орієнтуватися.

## Елементарні операції

Ми припускаємо, що «базова» операція займає сталий час незалежно від розміру даних: додавання двох чисел, порівняння, присвоєння, читання `array[i]`, пошук у словнику (в середньому). Така модель. Вона хибна для величезних чисел (додавання двох мільйонозначних чисел — не один крок), і лекція про числа до цього повернеться.

## Що ви вивчили

- Алгоритм оцінюють за тим, **як зростає вартість** разом із розміром входу `n`, а не за секундами на одному комп'ютері.
- Ми рахуємо операції, зазвичай для **найгіршого випадку**.
- Час і пам'ять — два різні ресурси, і іноді одне обмінюють на інше.
