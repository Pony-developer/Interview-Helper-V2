Структури можуть мати властивості й методи, як і класи. Але структура — це **значення**, і це створює одну пастку, яка дивує майже всіх: зміна структури, **отриманої через властивість або список**, може загубитися.

```csharp
struct Point
{
    public int X;
    public int Y;
}

class Shape
{
    public Point Location;
    public Point Center { get; set; }
}
```

## Зміна поля структури, яку повертає властивість

```csharp
var shape = new Shape();
shape.Location.X = 5;          // працює: Location — поле, тобто змінна
// shape.Center.X = 5;         // помилка CS1612: cannot modify the return value of a property,
                               // бо властивість повертає КОПІЮ структури
```

Властивість `Center` повертає копію. Зміна копії нічого не змінює. Правильний спосіб: прочитати копію, змінити її й записати назад:

```csharp
Point c = shape.Center;
c.X = 5;
shape.Center = c;              // тепер зміна збережена
```

## Та сама пастка зі списком

```csharp
var points = new List<Point> { new Point { X = 1 } };
// points[0].X = 5;            // помилка CS1612: індексатор повертає копію
Point first = points[0];
first.X = 5;
points[0] = first;             // записуємо назад
```

**Масив** інший: `points[0].X = 5` працює, бо елемент масиву — це змінна, а не копія, яку повертає метод.

```csharp
Point[] arr = { new Point { X = 1 } };
arr[0].X = 5;                  // працює: елемент масиву — справжнє місце зберігання
```

## Правило

Коли змінюєте частину структури, переконайтеся, що вона є **змінною**: локальною змінною, полем або елементом масиву. Властивість чи значення, що повертає метод, дає копію, яку потім викидають. Тому багато досвідчених програмістів віддають перевагу **незмінним** структурам, без жодних сеттерів.
