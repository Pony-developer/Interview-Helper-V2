**Сортування бульбашкою** — найпростіший для розуміння алгоритм сортування. Він раз за разом проходить масивом і порівнює **сусідів**. Якщо пара в хибному порядку, він міняє її місцями. Найбільший елемент під час кожного проходу «спливає» до кінця.

## Приклад

Сортуємо `[5, 1, 4, 2, 8]`. Кожен прохід порівнює сусідів зліва й міняє пару, якщо лівий більший:

```text
Прохід 1: 5 1 4 2 8   (5,1) обмін   ->  1 5 4 2 8
          1 5 4 2 8   (5,4) обмін   ->  1 4 5 2 8
          1 4 5 2 8   (5,2) обмін   ->  1 4 2 5 8
          1 4 2 5 8   (5,8) ні
          найбільший, 8, наприкінці

Прохід 2: 1 4 2 5 | 8 (1,4) ні
          1 4 2 5     (4,2) обмін   ->  1 2 4 5
          1 2 4 5     (4,5) ні
          другий за величиною, 5, на місці

Прохід 3: 1 2 4 | 5 8 жодного обміну: масив відсортовано
```

Після проходу `p` `p` найбільших елементів стоять на своїх остаточних місцях наприкінці, тож кожен прохід може зупинятися на крок раніше за попередній.

## Код

```csharp
static void BubbleSort(int[] a)
{
    for (int pass = 0; pass < a.Length - 1; pass++)
    {
        bool swapped = false;
        for (int i = 0; i < a.Length - 1 - pass; i++)   // останні "pass" елементів уже на місці
        {
            if (a[i] > a[i + 1])
            {
                int temp = a[i];
                a[i] = a[i + 1];
                a[i + 1] = temp;
                swapped = true;
            }
        }
        if (!swapped) break;       // повний прохід без обмінів: уже відсортовано
    }
}
```

Прапорець `swapped` змушує алгоритм одразу зупинитися, коли масив уже відсортований.

## Інваріант

Після `p` проходів останні `p` елементів — це `p` найбільших, **на їхніх остаточних позиціях**. Кожен прохід бере найбільший елемент невідсортованої частини й переносить його в кінець цієї частини. Після `n − 1` проходів усе на місці.

## Підрахунок роботи

**Порівняння.** Перший прохід робить `n − 1` порівнянь, другий `n − 2` і так далі:

```text
(n − 1) + (n − 2) + ... + 1 = n · (n − 1) / 2
```

Це близько **n² / 2**: для 1 000 елементів близько 500 000; для мільйона елементів близько 5 · 10¹¹.

**Обміни.** Обмін усуває рівно **одну інверсію**: пару елементів у хибному порядку (більший елемент перед меншим). Оскільки відсортований масив інверсій не має, кількість обмінів **завжди дорівнює кількості інверсій** у вхідних даних. Це виконується, як би не були записані цикли. Для `[5, 1, 4, 2, 8]` інверсії — `(5,1)`, `(5,4)`, `(5,2)` та `(4,2)`: чотири, і в трасуванні вище рівно чотири обміни.

| Вхід | Інверсій (обмінів) | Порівнянь |
| --- | --- | --- |
| уже відсортований | 0 | `n − 1` з прапорцем (один прохід), `n(n−1)/2` без нього |
| у зворотному порядку | `n(n − 1) / 2`, максимум | `n(n − 1) / 2` |
| випадковий | близько `n(n − 1) / 4` | близько `n²/2` |

## Складність

| Випадок | Час |
| --- | --- |
| Найкращий (відсортований, з прапорцем `swapped`) | **O(n)** |
| Середній | **O(n²)** |
| Найгірший (зворотний) | **O(n²)** |

Пам'ять — **O(1)**: сортування **на місці**.

Сортування бульбашкою **стабільне**: рівні елементи ніколи не міняються між собою (обмін потребує **строгого** `>`), тож їхній початковий порядок зберігається.

## Чому воно повільне

Кожен елемент бульбашка рухає лише **на одну позицію за раз**. Елемент, якому треба пройти з кінця на початок, потребує `n − 1` проходів, щоб дістатися (малі значення рухаються ліворуч лише на один крок за прохід, тому їх називають «черепахами»). Кращі алгоритми переміщують елементи на великі відстані.

Для 100 000 елементів бульбашці потрібно близько 5 · 10⁹ порівнянь: десятки секунд, коли добре сортування займає кілька мілісекунд. Тому її використовують для **навчання**, а в справжніх програмах майже ніколи.

## Прості родичі

**Сортування вибором** знаходить мінімум невідсортованої частини й міняє його на місце. Воно робить рівно `n(n−1)/2` порівнянь за будь-яких даних, але щонайбільше **n − 1 обмінів**: добре, коли запис дорогий.

```csharp
for (int i = 0; i < a.Length - 1; i++)
{
    int min = i;
    for (int j = i + 1; j < a.Length; j++)
        if (a[j] < a[min]) min = j;
    (a[i], a[min]) = (a[min], a[i]);      // у C# 7 можна міняти дві змінні кортежем
}
```

**Сортування вставками** бере елементи по одному й **вставляє** кожен у відсортовану частину ліворуч, як сортування гральних карт у руці:

```csharp
for (int i = 1; i < a.Length; i++)
{
    int value = a[i];
    int j = i - 1;
    while (j >= 0 && a[j] > value)
    {
        a[j + 1] = a[j];       // зсуваємо більші елементи праворуч
        j--;
    }
    a[j + 1] = value;
}
```

Сортування вставками — O(n²) у найгіршому випадку, але **O(n) для майже відсортованого** масиву, і воно дуже швидке для малих масивів. Тому справжні бібліотеки використовують його як останній крок на малих шматках більших сортувань.

## Підсумок

| | Бульбашка | Вибір | Вставки |
| --- | --- | --- | --- |
| Найкращий | O(n) | O(n²) | O(n) |
| Середній | O(n²) | O(n²) | O(n²) |
| Найгірший | O(n²) | O(n²) | O(n²) |
| Пам'ять | O(1) | O(1) | O(1) |
| Стабільне | так | ні (у простій формі) | так |
| На практиці | лише навчання | мало записів | малі чи майже відсортовані дані |

Усі три квадратичні. Наступні лекції показують, як сортувати за O(n log n).
