Щоб зрозуміти рекурсію, **намалюйте її**. Кожен виклик — це **вузол**, а виклики, що він робить, — його **діти**. Картинка називається **деревом рекурсії**.

## Лінійна рекурсія: ланцюжок

```csharp
static int SumTo(int n) => n == 0 ? 0 : n + SumTo(n - 1);
```

`SumTo(3)` утворює ланцюжок, бо кожен виклик робить рівно ще один:

```text
SumTo(3)
  └─ SumTo(2)
       └─ SumTo(1)
            └─ SumTo(0)       <- листок: базовий випадок
```

Вузлів `n + 1`, а **глибина** теж `n`. Робота лінійна.

## Розгалужена рекурсія: справжнє дерево

Числа Фібоначчі: `Fib(n) = Fib(n − 1) + Fib(n − 2)`.

```csharp
static long Fib(int n) => n < 2 ? n : Fib(n - 1) + Fib(n - 2);
```

Дерево `Fib(4)`:

```text
                    Fib(4)
                  /        \
            Fib(3)          Fib(2)
           /      \         /     \
      Fib(2)    Fib(1)   Fib(1)  Fib(0)
      /    \
  Fib(1)  Fib(0)
```

Порахуйте вузли: 9 викликів, щоб знайти `Fib(4) = 3`. Подивіться на **повторення**: `Fib(2)` розв'язується двічі, а `Fib(1)` — тричі. Та сама підзадача обчислюється знову й знову.

## Підрахунок викликів

Нехай `calls(n)` — кількість викликів. Для `Fib` маємо `calls(n) = 1 + calls(n − 1) + calls(n − 2)`, і воно зростає, як самі числа Фібоначчі:

| n | 5 | 10 | 20 | 30 | 40 |
| --- | --- | --- | --- | --- | --- |
| викликів | 15 | 177 | 21 891 | 2 692 537 | 331 160 281 |

Для `n = 40` це понад 330 мільйонів викликів, щоб обчислити число, яке цикл знаходить за 40 кроків. Зростання **експоненційне**: близько 1.6ⁿ, що ми записуємо як O(2ⁿ).

## Глибина проти кількості вузлів

Дві різні міри:

- **Кількість вузлів** — це загальний **час**.
- **Глибина** (найдовший ланцюжок від кореня до листка) — це **пам'ять стека**, бо в будь-який момент на стеку лише один шлях, від кореня до поточного виклику.

`Fib(40)` робить 331 мільйон викликів, але стек ніколи не містить більш ніж близько **40** кадрів. Отже, рекурсія з експоненційним часом усе ще може бути безпечною для стека, а лінійна (`SumTo(1 000 000)`) може його переповнити.

## Інші форми дерев

| Рекурсія | Дерево | Час |
| --- | --- | --- |
| `F(n) = F(n − 1) + O(1)` | ланцюжок із `n` вузлів | O(n) |
| `F(n) = F(n / 2) + O(1)` | ланцюжок із `log₂ n` вузлів | O(log n) |
| `F(n) = 2 · F(n / 2) + O(1)` | збалансоване дерево з `n` листками | O(n) |
| `F(n) = 2 · F(n / 2) + O(n)` | `log₂ n` рівнів, на кожному `n` роботи | O(n log n) |
| `F(n) = 2 · F(n − 1) + O(1)` | кожен виклик робить два, `n` рівнів | O(2ⁿ) |
| `F(n) = n · F(n − 1)` | `n` дітей, потім `n − 1`, ... | O(n!) |

Щоб отримати загальний час, **додайте роботу всіх вузлів**. Добрий спосіб — за рівнями: скільки вузлів на кожному рівні, скільки робить кожен і скільки рівнів.

## Усунення повторень: мемоїзація

Якщо та сама підзадача з'являється знову й знову, **запам'ятайте відповідь** уперше:

```csharp
static Dictionary<int, long> cache = new Dictionary<int, long>();

static long FibMemo(int n)
{
    if (n < 2) return n;
    long known;
    if (cache.TryGetValue(n, out known)) return known;

    long result = FibMemo(n - 1) + FibMemo(n - 2);
    cache[n] = result;
    return result;
}
```

Тепер кожен `FibMemo(k)` обчислюється **один раз**, а кожен подальший запит — швидкий пошук. Дерево стискається до ланцюжка з короткими гілками: лише близько `2n` викликів. Час змінюється з O(2ⁿ) на **O(n)** ціною O(n) пам'яті. Цей прийом — основа **динамічного програмування**.

(Поле `cache` оголошене поруч із методами, зі `static`, щоб усі виклики ділили його. Це поле класу, а не локальна змінна.)

## Трасування рекурсії

Щоб побачити дерево самому, друкуйте при вході та при виході з відступом:

```csharp
static long Fib(int n, int depth)
{
    string pad = new string(' ', depth * 2);
    Console.WriteLine(pad + "Fib(" + n + ")");
    long result = n < 2 ? n : Fib(n - 1, depth + 1) + Fib(n - 2, depth + 1);
    Console.WriteLine(pad + "= " + result);
    return result;
}
```

Запустіть для малого `n`, і ви побачите порядок викликів: **углиб**, зліва направо. Виклик чекає на всіх своїх дітей, перш ніж повернутися.

## Як читати рекурсію

1. Знайдіть **базові випадки**: листки дерева.
2. Знайдіть **розгалуження**: скільки рекурсивних викликів робить один виклик?
3. Знайдіть, як вхідні дані **зменшуються**: на одиницю, вдвічі, видаленням елемента.
4. З цих трьох ви знаєте **глибину**, **кількість вузлів** і **час**.
5. Шукайте **повторювані** вузли: якщо ті самі аргументи з'являються багато разів, застосуйте мемоїзацію.
