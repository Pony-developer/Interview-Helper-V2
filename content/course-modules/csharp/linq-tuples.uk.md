LINQ часто дає **пари** значень: ім'я і бал, слово і його довжину, ключ і кількість. Кортеж — найпростіший контейнер для такої пари. Фреймворк має узагальнений клас `Tuple<T1, T2>` (і `Tuple<T1, T2, T3>` для трьох значень):

```csharp
var pair = Tuple.Create("Ann", 90);
Console.WriteLine(pair.Item1);            // Ann
Console.WriteLine(pair.Item2);            // 90
```

Елементи називаються `Item1`, `Item2` і так далі, що мало говорить про їхній зміст. Це слабкість `Tuple`.

## Кортежі в LINQ

Проєкція може давати кортежі прямо, і далі їх читає такий метод:

```csharp
var words = new[] { "pear", "fig", "apple" };
var pairs = words.Select(w => Tuple.Create(w, w.Length));

foreach (var p in pairs)
{
    Console.WriteLine(p.Item1 + " " + p.Item2);     // pear 4, fig 3, apple 5
}
```

## Синтаксис кортежів C# 7

Починаючи з C# 7 є короткий синтаксис з іменами, `(string Name, int Score)`, що працює з тією самою ідеєю:

```csharp
// C# 7 і новіші:
var pair2 = (Name: "Ann", Score: 90);
Console.WriteLine(pair2.Name);            // Ann: імена є частиною кортежу
Console.WriteLine(pair2.Item2);           // 90: імена Item також працюють
```

Цей синтаксис зручний для методу, що повертає два значення. Він побудований на `ValueTuple`, тобто структурі, тож не створює виділень у купі. У задачах курсу вживається `Tuple.Create`, що доступний у кожній версії.

## Рівність

`Tuple` порівнює елементи за значенням: два кортежі з рівними елементами рівні, тож добре працюють як ключі словника чи в `Distinct`.

```csharp
Console.WriteLine(Tuple.Create(1, "a").Equals(Tuple.Create(1, "a")));   // True
```

## Коли кортеж, а коли клас

Кортеж добрий для короткого локального результату. Коли пара використовується в багатьох місцях або має зміст, який варто назвати, зрозумілішим буде малий клас чи структура з іменованими полями (`Score`, `Name`).
