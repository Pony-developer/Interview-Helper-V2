Властивість може перевіряти кожну зміну, але один момент усе ще небезпечний: **створення** об'єкта. Якщо об'єкт починає порожнім (`new Order()`), то якийсь час він не має ні кількості, ні ціни, і інваріанти ще не виконуються. **Конструктор** закриває цю прогалину: він робить об'єкт **коректним від першої миті його життя**.

```csharp
class Order
{
    public int Quantity { get; }
    public decimal PricePerItem { get; }

    public Order(int quantity, decimal pricePerItem)       // єдиний спосіб створити Order
    {
        if (quantity <= 0) throw new ArgumentOutOfRangeException("quantity");
        if (pricePerItem < 0) throw new ArgumentOutOfRangeException("pricePerItem");
        Quantity = quantity;
        PricePerItem = pricePerItem;
    }
}

var order = new Order(3, 9.99m);                           // добре
// var empty = new Order();                                // помилка: конструктора без аргументів немає
// var bad = new Order(-1, 5m);                            // виняток: об'єкт ніколи не створюється
```

Якщо конструктор кидає виняток, об'єкт **ніколи не створюється**: жоден код не може отримати недобудований чи некоректний `Order`. Це найсильніша гарантія й головна причина віддавати перевагу конструкторам із параметрами для **обов'язкових** даних.

## Типовий конструктор зникає

Якщо в класу **немає жодного конструктора**, C# створює порожній без параметрів. Щойно ви пишете **будь-який** конструктор, порожній **не створюється**. Це корисно: оголосивши конструктор із параметрами, ви забороняєте `new Order()`.

## Кілька конструкторів: перевантаження

Клас може мати багато конструкторів з різними параметрами:

```csharp
class Point
{
    public double X { get; }
    public double Y { get; }

    public Point(double x, double y) { X = x; Y = y; }
    public Point() : this(0, 0) { }                        // делегує першому конструктору
    public Point(double both) : this(both, both) { }
}
```

**`: this(...)`** викликає **інший конструктор того самого класу**. Вживайте його, щоб не копіювати перевірки: уся логіка живе в **одному** головному конструкторі, а інші лише підставляють типові значення. Порівняйте з `: base(...)`, що викликає конструктор **базового класу**.

## Конструктори та `readonly`

Конструктор — місце, де задають поля `readonly` і властивості лише для читання. Після його завершення вони не можуть змінюватися (наступна лекція).

## Фабричні методи

Іноді конструктор — не найкращий спосіб. **Статичний фабричний метод** має **назву**, і вона може пояснити, **що** створюється, або метод може повернути `null`, або вибрати між типами:

```csharp
class Temperature
{
    public double Celsius { get; }

    private Temperature(double celsius) { Celsius = celsius; }       // приватний: користуйтеся фабриками

    public static Temperature FromCelsius(double c) { return new Temperature(c); }
    public static Temperature FromFahrenheit(double f) { return new Temperature((f - 32) * 5 / 9); }
}

var t = Temperature.FromFahrenheit(212);                   // зрозуміліше, ніж new Temperature(100)
```

Два конструктори не можуть бути обидва `Temperature(double)` — для Цельсія й для Фаренгейта, бо матимуть однакову сигнатуру. Іменовані фабрики усувають проблему.

## Що має робити конструктор

- **Задавати поля** й перевіряти аргументи.
- **Не** виконувати важкої роботи (жодної мережі, жодного довгого читання файлів) і **не** викликати `virtual` методи (похідний клас ще не готовий).
- Якщо об'єкт має багато необов'язкових налаштувань, можна вжити ініціалізатор об'єкта після конструктора обов'язкових:

```csharp
var report = new Report("Sales") { Landscape = true, Copies = 2 };
```

## Порядок подій під час створення об'єкта

1. Виділяється пам'ять, і всі поля отримують **типові** значення (`0`, `false`, `null`).
2. Виконуються ініціалізатори полів (`private int count = 5;`).
3. Виконується конструктор **бази**.
4. Виконується тіло вашого конструктора.

До кінця кроку 4 об'єкт мусить задовольняти всі свої інваріанти.
