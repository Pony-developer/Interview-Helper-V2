Тип-значення (`int`, `double`, структура) живе всередині змінної. Змінна `object`, однак, мусить тримати **посилання** на об'єкт у купі. Тож коли значення кладуть в `object`, C# створює на купі об'єкт-обгортку й копіює туди значення. Це **boxing** («упаковка»).

```csharp
int n = 42;
object o = n;                  // boxing: новий об'єкт у купі тримає копію 42
n = 7;
Console.WriteLine(o);          // 42: у коробки своя копія
```

Назад — **unboxing** («розпакування»): явне приведення з `object` до типу-значення.

```csharp
object o = 42;
int n = (int)o;                // unboxing: копіює значення з коробки
Console.WriteLine(n + 1);      // 43
```

## Чому це важливо

Boxing **непомітний**. Багато викликів упаковують значення, і ви цього не бачите:

```csharp
Console.WriteLine("{0} and {1}", 1, 2.5);   // обидва числа упаковуються в object[]
```

Кожна упаковка виділяє пам'ять, а збирач сміття має її потім прибрати. У циклі з мільйонами ітерацій це стає повільним. Ліки — уникати `object` для значень:

```csharp
var numbers = new List<int>();      // без boxing: List<int> зберігає int напряму
var old = new ArrayList();          // boxing: кожне int стає об'єктом
```

`List<int>` — **узагальнена** колекція: вона зберігає прості цілі. `ArrayList` зберігає `object`, тож кожне число упаковується. Віддавайте перевагу узагальненим колекціям.

## Упаковка в інтерфейси

Структура, що реалізує інтерфейс, упаковується, коли її використовують через цей інтерфейс:

```csharp
IComparable c = 5;             // boxing: int потрапляє в об'єкт у купі
```

Це той самий механізм, і тому узагальнений `IComparable<int>` ефективніший за старий `IComparable`.
