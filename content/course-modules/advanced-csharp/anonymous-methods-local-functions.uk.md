## Анонімні методи: предок лямбд із C# 2

```csharp
Func<int, int> square = delegate (int x) { return x * x; };
```

Лямбди їх витіснили, але одна можливість унікальна: список параметрів можна **повністю пропустити**, і тоді анонімний метод підходить під будь-яку сигнатуру делегата.

```csharp
button.Click += delegate { Console.WriteLine("clicked"); };   // ігнорує sender і e
```

Анонімні методи не можна перетворити на дерева виразів, і вони не мають тіла-виразу. У новому коді беріть лямбди (з відкинутими параметрами `(_, _) => ...` для непотрібних аргументів).

## Локальні функції (C# 7)

Локальна функція — іменований метод, оголошений усередині іншого методу:

```csharp
public static IEnumerable<int> Range(int start, int count)
{
    if (count < 0) throw new ArgumentOutOfRangeException(nameof(count));   // виконується одразу
    return Iterate();

    IEnumerable<int> Iterate()            // локальна функція-ітератор
    {
        for (int i = 0; i < count; i++) yield return start + i;
    }
}
```

Порівняно з лямбдою, локальна функція:

- має **ім'я** і може бути **рекурсивною** без хитрощів;
- може бути **узагальненою**, мати параметри `ref`/`out`/`params`, бути **ітератором** чи `async`;
- її можна викликати **до** оголошення в методі;
- **дешевша**: якщо її не перетворюють на делегат, захоплені змінні живуть у структурі в стеку, тож алокації в купі немає.

Приклад показує класичне використання: перевірка аргументів відбувається одразу в зовнішньому методі, а тіло ітератора — відкладено.

```csharp
int Fibonacci(int n)
{
    return Fib(n);
    static int Fib(int k) => k < 2 ? k : Fib(k - 1) + Fib(k - 2);
}
```

## Статичні лямбди та статичні локальні функції

Позначка `static` на лямбді чи локальній функції (C# 8 для локальних функцій, C# 9 для лямбд) забороняє захоплювати локальні змінні, параметри чи `this`:

```csharp
int threshold = 10;
Func<int, bool> big = static x => x > 10;         // нормально
// Func<int, bool> bad = static x => x > threshold;  // помилка: захоплює threshold
```

Переваги:

- жодної алокації замикання, і це гарантує компілятор;
- намір зрозумілий: цей код залежить лише від своїх входів.

Типове використання — колбек, що отримує стан явно:

```csharp
cache.GetOrAdd(key, static (k, factory) => factory.Create(k), factory);
```

## Як обрати

| Ситуація | Що брати |
| --- | --- |
| Короткий колбек на місці для LINQ чи подій | лямбда |
| Допоміжний код лише в одному методі, можливо рекурсивний чи ітератор | локальна функція |
| Гаряче місце, де не можна алокувати | `static`-лямбда чи `static`-локальна функція |
| Обробник події, що ігнорує аргументи | лямбда з відкиданням `(_, _) => ...` |

## Що сказати на співбесіді

- Анонімні методи — спадщина; їхній єдиний трюк — пропущений список параметрів.
- Локальні функції можуть бути рекурсивними, узагальненими, ітераторами, async і уникають алокацій.
- `static` запобігає випадковому захопленню і прихованій алокації, що з ним приходить.
