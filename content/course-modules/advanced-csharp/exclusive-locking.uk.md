## Навіщо блокування

Коли кілька потоків читають і пишуть спільні дані, операції перемежовуються непередбачувано. Навіть `count++` — це три кроки (прочитати, додати, записати), тож два потоки можуть обидва прочитати 5 і обидва записати 6. **Ексклюзивне блокування** гарантує, що критичну секцію одночасно виконує лише один потік.

## lock і Monitor

```csharp
private readonly object _gate = new();
private decimal _balance;

public void Deposit(decimal amount)
{
    lock (_gate)
    {
        _balance += amount;
    }
}
```

`lock` — скорочення для `Monitor.Enter`/`Monitor.Exit` у `try/finally`:

```csharp
bool taken = false;
try { Monitor.Enter(_gate, ref taken); _balance += amount; }
finally { if (taken) Monitor.Exit(_gate); }
```

Правила:

- **Блокуйтеся на приватному окремому об'єкті.** `lock(this)`, `lock(typeof(X))` чи `lock("name")` дозволяють сторонньому коду захопити те саме блокування і спричинити конкуренцію чи взаємоблокування.
- **Кожен** доступ до спільного стану (читання теж) має йти через те саме блокування.
- Тримайте критичні секції короткими; ніколи не викликайте невідомий код (події, колбеки, віртуальні методи), тримаючи блокування.
- Блокування **повторно входимі**: той самий потік може увійти в блокування, яке вже тримає.
- `Monitor.TryEnter(_gate, timeout)` здається замість вічного очікування.
- .NET 9 додає `System.Threading.Lock`, окремий тип блокування; інструкція `lock` використовує його, коли він доступний.

## Взаємоблокування

Два потоки тримають блокування, потрібні один одному:

```
Потік 1: lock(A) … lock(B)        Потік 2: lock(B) … lock(A)
```

Обидва чекають вічно. Запобігання:

1. **Порядок блокувань**: завжди захоплюйте кілька блокувань в одному глобальному порядку (за id, за назвою).
2. Тримайте якомога менше блокувань; уникайте вкладених.
3. Використовуйте тайм-аути (`TryEnter`), щоб виявити проблему й відступити.
4. Ніколи не блокуйтеся на асинхронному коді всередині lock і не тримайте блокування через `await` (компілятор забороняє `await` усередині `lock`).

## Mutex

`Mutex` схожий на lock, але, маючи ім'я, працює **між процесами**:

```csharp
using var mutex = new Mutex(initiallyOwned: false, name: @"Global\Shop.Importer");
if (!mutex.WaitOne(TimeSpan.Zero))
{
    Console.WriteLine("Another instance is already running");
    return;
}
try { RunImport(); }
finally { mutex.ReleaseMutex(); }
```

Він приблизно в 50 разів повільніший за `lock` (об'єкт ядра) і має звільнятися тим потоком, що його захопив. Якщо процес помре, тримаючи його, наступний, хто чекає, отримає `AbandonedMutexException`.

## SpinLock

`SpinLock` крутиться в очікуванні замість блокування. Він виправданий лише для надзвичайно коротких критичних секцій з низькою конкуренцією в дуже гарячому коді; інакше `lock` кращий.

## Що сказати на співбесіді

- `lock` = `Monitor.Enter/Exit` у try/finally, на приватному об'єкті, для всіх доступів до спільного стану.
- Взаємоблокування виникають через неузгоджений порядок блокувань; запровадьте глобальний порядок.
- `Mutex` синхронізує процеси; `lock` — потоки в межах одного процесу.
