## Навіщо конкурентність

Конкурентність означає, що одночасно відбувається більше однієї речі. У .NET вона потрібна для:

- **чуйного UI**: тримати потік UI вільним, поки робота відбувається деінде;
- **масштабованих серверів**: обробляти багато запитів одночасно без потоку на кожен запит, що очікує;
- **паралельних обчислень**: використати кожне ядро процесора для важкої роботи;
- **спекулятивної роботи**: почати щось заздалегідь на випадок, якщо знадобиться.

## Створення потоку

```csharp
var worker = new Thread(() =>
{
    for (int i = 0; i < 3; i++) Console.WriteLine($"worker {i}");
});
worker.Name = "worker";
worker.Start();
worker.Join();                     // блокує, доки він не завершиться (Join(timeout) повертає false при тайм-ауті)
Console.WriteLine("main continues");
```

Потік має власний **стек**: локальні змінні приватні для кожного потоку й кожного виклику. Потоки ділять **купу**: будь-який об'єкт, досяжний із двох потоків, обидва можуть читати й писати.

```csharp
bool done = false;                 // захоплена обома лямбдами → спільна
void Work() { if (!done) { done = true; Console.WriteLine("done"); } }
new Thread(Work).Start();
Work();                            // може надрукувати "done" один чи два рази: стан гонитви
```

## Потокобезпечність: перше знайомство

Виправлення гонки вище — взаємне виключення:

```csharp
var gate = new object();
void SafeWork()
{
    lock (gate)
    {
        if (!done) { done = true; Console.WriteLine("done"); }
    }
}
```

`lock` пускає в блок лише один потік за раз. Спільний змінний стан потребує синхронізації; модуль про просунуті потоки докладно розбирає блокування.

## Передача даних

```csharp
string message = "hello";
var t = new Thread(() => Print(message));        // лямбда, що захоплює потрібне
var t2 = new Thread(state => Print((string)state!)); t2.Start("hi");   // ParameterizedThreadStart
```

Стережіться захоплення змінних циклу `for` (пастка замикань): кожен потік може побачити кінцеве значення.

## Основні та фонові потоки

- **Основні** потоки (за замовчуванням) тримають процес живим, доки не завершаться.
- **Фонові** потоки (`IsBackground = true`; усі потоки пулу) різко вбиваються, коли завершується останній основний потік: їхні блоки `finally` не виконуються.

## Винятки

Необроблений виняток у будь-якому потоці **завершує процес**. `try/catch` навколо `thread.Start()` не може його перехопити, бо виняток стається в іншому потоці. Кожен вхідний метод потоку потребує власної обробки (або використовуйте задачі, що зберігають винятки за вас).

## Інші члени

- `Thread.Sleep(ms)` блокує; `Thread.Sleep(0)`/`Thread.Yield()` віддають решту кванту часу.
- `Thread.CurrentThread.ManagedThreadId` ідентифікує поточний потік.
- `Priority` існує, але рідко допомагає; `Abort` у .NET Core більше не працює (використовуйте токени скасування).

## Блокування проти очікування в циклі

**Заблокований** потік чекає, не використовуючи CPU (Sleep, Join, очікування lock чи I/O). Потік, що **крутиться** (spinning), у циклі перевіряє умову й спалює CPU. Крутитися варто лише для очікувань у кілька мікросекунд (`SpinWait`, `SpinLock`).

## На практиці

Сирі `Thread` у сучасному коді рідкісні: вони дорогі (близько 1 МБ стеку, планування ОС). Для більшості конкурентності беріть **задачі** та **async/await**, а окремі потоки залиште для довготривалих циклів.

## Що сказати на співбесіді

- Кожен потік має власний стек (локальні змінні), але ділить купу (об'єкти).
- Спільний змінний стан + відсутність синхронізації = стани гонитви.
- Необроблені винятки в будь-якому потоці обвалюють процес; фонові потоки помирають разом із процесом.
