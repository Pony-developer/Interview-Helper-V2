## Яку проблему розв'язав .NET Standard

До .NET 5 існувало кілька рантаймів поруч: .NET Framework, .NET Core, Xamarin, UWP. Автор бібліотеки хотів написати код один раз, щоб він працював на всіх. **.NET Standard** — це *специфікація*: перелік API, які обіцяє надати кожен рантайм, що реалізує цю версію.

| Ціль | Можна використати з |
| --- | --- |
| `netstandard1.x` | Дуже старі рантайми; невеликий набір API. Сьогодні краще уникати. |
| `netstandard2.0` | .NET Framework 4.6.1+, .NET Core 2.0+, .NET 5+, Mono, Xamarin, Unity |
| `netstandard2.1` | .NET Core 3.0+, .NET 5+ (**не** .NET Framework) |

Правило: багаторазова бібліотека, яка має працювати ще й на .NET Framework, націлюється на `netstandard2.0`. Бібліотека лише для сучасних застосунків націлюється на `net6.0` (або новіший), де доступний увесь API.

## Моніки цільових фреймворків (TFM)

Елемент `TargetFramework` у `.csproj` задає, під що ви збираєте:

```xml
<PropertyGroup>
  <TargetFramework>net6.0</TargetFramework>
</PropertyGroup>

<!-- або кілька одразу: окремий результат для кожної цілі -->
<PropertyGroup>
  <TargetFrameworks>net6.0;netstandard2.0;net48</TargetFrameworks>
</PropertyGroup>
```

| TFM | Значення |
| --- | --- |
| `net6.0`, `net8.0` | Сучасний .NET |
| `net6.0-windows` | Сучасний .NET плюс API лише для Windows (WPF, WinForms) |
| `netcoreapp3.1` | .NET Core 3.1 |
| `netstandard2.0` | Контракт .NET Standard 2.0 |
| `net48`, `net472` | .NET Framework 4.8, 4.7.2 (цифри без крапок) |

З багатьма цілями можна писати `#if NET6_0_OR_GREATER`, щоб викликати новіший API там, де він є, і запасний варіант деінде.

## Референсні збірки

Коли ви компілюєте під `netstandard2.0`, компілятор не бачить справжньої реалізації BCL. Він бачить **референсні збірки**: збірки, що містять лише публічні сигнатури без коду. Під час виконання реалізацію надає справжній рантайм. Саме це дозволяє одній скомпільованій DLL працювати на кількох рантаймах.

## Версія мови проти версії рантайму

Компілятор C# обирає версію мови за замовчуванням за ціллю:

| Ціль | C# за замовчуванням |
| --- | --- |
| .NET 6 | C# 10 |
| .NET 5 | C# 9 |
| .NET Core 3.x, .NET Standard 2.1 | C# 8 |
| .NET Framework, .NET Standard 2.0 | C# 7.3 |

Її *можна* підняти через `<LangVersion>`, і багато можливостей (record, `init`, switch-вирази) тоді працюватимуть на старших цілях, бо це суто трюки компілятора. Інші потребують підтримки рантайму й не працюватимуть: наприклад, члени інтерфейсів за замовчуванням вимагають рантайму, що їх розуміє.

## Що сказати на співбесіді

- .NET Standard — це контракт, а не рантайм. `netstandard2.0` — корисна ціль з найширшим охопленням.
- TFM у файлі проєкту визначає, які API можна викликати, і версію C# за замовчуванням.
- Деякі можливості мови — суто компіляторні; інші вимагають новішого рантайму.
