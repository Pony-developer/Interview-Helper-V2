## Три шари під кожною програмою на C#

```
  Ваш код  (C#, скомпільований в IL)
  ─────────────────────────────────────────
  Прикладні шари  (ASP.NET Core, WPF, MAUI, ...)
  Base Class Library  (System.*, колекції, I/O, LINQ, HTTP, ...)
  Common Language Runtime  (JIT, GC, завантажувач типів, винятки, потоки)
  ─────────────────────────────────────────
  Операційна система
```

### CLR: двигун

**Common Language Runtime** завантажує ваші збірки та виконує їх. Його завдання:

- **JIT-компіляція.** Компілятор C# видає **IL** (Intermediate Language), байт-код, незалежний від процесора, і **метадані**, що описують кожен тип і член. Коли метод викликають уперше, JIT перетворює його IL на нативний код для конкретного процесора.
- **Збирання сміття** в керованій купі.
- **Типобезпечність і верифікація**, обробка винятків, керування потоками, межі безпеки.

Оскільки C#, F# і VB.NET компілюються в IL, вони мають спільний рантайм і можуть вільно викликати одна одну. Код, що виконується під CLR, називають **керованим кодом**.

### Багаторівнева компіляція та компіляція наперед

JIT-компіляція коштує часу під час запуску. .NET зменшує ці витрати кількома способами:

- **Tiered compilation**: метод спершу компілюється швидко й майже без оптимізацій; якщо він виявляється «гарячим», його перекомпільовують з повною оптимізацією.
- **ReadyToRun**: збірки постачаються з уже скомпільованим нативним кодом, тож при старті JIT майже не потрібен. IL залишається як запасний варіант.
- **Native AOT** (повністю наперед): уся програма стає одним нативним виконуваним файлом без JIT. Швидший старт і менше пам'яті ціною обмежень на рефлексію та динамічну генерацію коду.

### BCL: ящик з інструментами

**Base Class Library** — набір збірок, який кожна .NET-програма отримує задарма: примітивні типи, рядки й текст, колекції, LINQ, введення-виведення, мережа, потоки й задачі, рефлексія, криптографія, XML і JSON. Більша частина цього курсу саме про BCL.

### Середовища виконання

*Рантайм* — це CLR разом із BCL, зібрані для певної родини платформ.

| Рантайм | Де працює | Примітки |
| --- | --- | --- |
| **.NET 6** (і новіші) | Windows, macOS, Linux | Сучасна кросплатформна лінійка з відкритим кодом. Наступник .NET Core. |
| **.NET Framework 4.x** | Лише Windows | Початковий рантайм. Підтримується, але без нових можливостей. |
| **Mono / Xamarin** | Мобільні, Unity, WebAssembly | Тепер злитий з родиною .NET 6+ для мобільних і Blazor. |
| **UWP** | Пристрої з Windows 10+ | Застаріла модель застосунків у пісочниці. |

Після .NET Core 3.1 вийшов .NET 5 (слово «Core» прибрали, щоб показати, що він замінює .NET Framework), а потім .NET 6 — реліз із довгостроковою підтримкою.

### Self-contained чи framework-dependent

- **Framework-dependent**: програмі потрібен встановлений на машині відповідний рантайм .NET. Невелике розгортання.
- **Self-contained**: рантайм копіюється поруч із програмою. Більший розмір, зате працює на машині, де нічого не встановлено. Можна обрізати (trimming), щоб викинути невикористаний код бібліотек.

## Що сказати на співбесіді

- C# → IL + метадані → JIT → нативний код. CLR також дає GC, винятки й типобезпечність.
- BCL — стандартна бібліотека; прикладні шари (ASP.NET Core, WPF) стоять над нею.
- ReadyToRun і Native AOT переносять роботу на етап збирання заради швидшого старту.
