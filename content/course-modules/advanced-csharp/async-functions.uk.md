## async і await

```csharp
public async Task<decimal> GetOrderTotalAsync(int id, CancellationToken ct)
{
    Order order = await _repo.LoadAsync(id, ct);          // тут може призупинитися
    decimal tax = await _taxService.GetRateAsync(order.Country, ct);   // і тут
    return order.Subtotal * (1 + tax);                     // стає результатом Task
}
```

- `async` дозволяє `await` у методі й змушує компілятор загорнути результат у задачу.
- `await` бере очікуване значення (зазвичай `Task`) і, якщо воно ще не завершене, **повертається до викликача**, продовжуючи метод, коли задача завершиться.
- Винятки, кинуті всередині, потрапляють у повернуту задачу й кидаються знову на `await` викликача.

## Типи результату

| Тип результату | Коли |
| --- | --- |
| `Task` | без результату |
| `Task<T>` | результат типу T |
| `ValueTask` / `ValueTask<T>` | гарячі шляхи, що часто завершуються синхронно |
| `IAsyncEnumerable<T>` | асинхронний потік (C# 8): `await foreach` |
| `void` | **лише** обробники подій |

## Що генерує компілятор

Асинхронний метод стає **машиною станів** (структура з локальними змінними як полями та методом `MoveNext`). На кожному `await`:

1. викликається `GetAwaiter()` на очікуваному значенні;
2. якщо `IsCompleted` уже true, виконання продовжується синхронно без додаткових витрат;
3. інакше зберігається стан, `MoveNext` реєструється як продовження, і метод повертається;
4. коли очікувана операція завершується, `MoveNext` продовжує зі збереженої точки й викликає `GetResult()`, що повертає значення або кидає виняток.

Очікувати можна будь-що з відповідним методом `GetAwaiter()`, зокрема власні типи.

## Де виконується продовження

Перед паузою `await` захоплює поточний **`SynchronizationContext`** (або `TaskScheduler`):

- **WPF / WinForms / MAUI**: контекст UI, тож код після `await` виконується в потоці UI;
- **ASP.NET Core, консольні застосунки**: контексту немає, тож продовження виконуються в будь-якому потоці пулу.

`await task.ConfigureAwait(false)` відмовляється від захоплення. Використовуйте в **бібліотечному** коді, що ніколи не торкається UI, щоб уникнути зайвих перестрибувань між потоками і класичного взаємоблокування. У прикладному коді ASP.NET Core різниці немає.

### Класичне взаємоблокування

```csharp
void Button_Click(object s, EventArgs e)
{
    var text = LoadAsync().Result;   // потік UI блокується в очікуванні задачі
}
async Task<string> LoadAsync()
{
    var t = await _client.GetStringAsync(url);   // продовження хоче потік UI → взаємоблокування
    return t;
}
```

Виправлення: зробити обробник асинхронним і використати `await`. (`ConfigureAwait(false)` усередині `LoadAsync` теж цього уникає, але справжнє виправлення — async до самого верху.)

## Асинхронні лямбди

```csharp
Func<Task<int>> fetch = async () => await GetCountAsync();
button.Click += async (s, e) => await SaveAsync();       // async void: нормально для обробників подій
var results = await Task.WhenAll(ids.Select(async id => await LoadAsync(id)));
```

Обережно, коли передаєте асинхронну лямбду в параметр типу `Action`: вона стає `async void`, і ніхто її не очікує й не бачить її винятків (наприклад, `list.ForEach(async x => await ...)`).

## Async void

Методи `async void` не можна очікувати; винятки кидаються в захопленому контексті синхронізації (обвалюючи консольний процес чи процес ASP.NET Core). Вони існують лише для того, щоб обробники подій могли бути асинхронними. Скрізь інде повертайте `Task`.

## Пропуск async

```csharp
public Task<string> GetAsync(string url) => _client.GetStringAsync(url);   // без async/await: повертає задачу напряму
```

Трохи дешевше, але винятки проявляються інакше, а блоки `using` закінчилися б зарано. Пропускайте лише в тривіальних методах-перехідниках.

## Що сказати на співбесіді

- `await` повертається до викликача на першій незавершеній задачі; компілятор будує машину станів.
- Продовження відновлюються в захопленому контексті (потік UI), якщо не `ConfigureAwait(false)`.
- Блокування на асинхронному коді (`.Result`) у потоці UI дає взаємоблокування; `async void` — лише для обробників подій.
