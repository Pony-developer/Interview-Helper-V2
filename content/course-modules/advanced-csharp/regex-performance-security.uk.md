## Як працює рушій

Рушій .NET за замовчуванням — **з бектрекінгом**: він намагається зіставити шаблон крок за кроком і, коли шлях не вдається, повертається й пробує наступну альтернативу (коротший жадібний збіг, іншу гілку `|`). Саме це уможливлює зворотні посилання й lookaround, і саме це може зробити деякі шаблони надзвичайно повільними.

## Чотири способи виконати regex

| Підхід | Створення | Зіставлення | Для чого |
| --- | --- | --- | --- |
| `new Regex(p)` (інтерпретований) | швидке | найповільніше | одноразові шаблони |
| `RegexOptions.Compiled` | повільне (генерує IL) | швидке | гарячі шаблони, що багато разів повторюються |
| `[GeneratedRegex]` (.NET 7) | під час збирання | швидке, без витрат при старті | відомі шаблони; працює з Native AOT |
| `RegexOptions.NonBacktracking` (.NET 7) | помірне | гарантовано лінійний час | недовірений ввід |

```csharp
public static partial class Patterns
{
    [GeneratedRegex(@"^\d{4}-\d{2}-\d{2}$", RegexOptions.CultureInvariant)]
    public static partial Regex IsoDate();
}

bool ok = Patterns.IsoDate().IsMatch(input);
```

У всіх випадках створюйте `Regex` один раз (статичне поле) і повторно використовуйте; екземпляри потокобезпечні.

## Катастрофічний бектрекінг і ReDoS

Деякі шаблони на деяких входах змушують рушій з бектрекінгом перепробувати **експоненційну** кількість шляхів:

```csharp
var evil = new Regex(@"^(a+)+$");
evil.IsMatch(new string('a', 30) + "!");   // практично ніколи не завершиться
```

Вкладені квантифікатори над тими самими символами (`(a+)+`, `(\w+\s?)*`, `(.*,)*`) можуть розбити вхід незліченними способами, і коли загальний збіг не вдається, рушій пробує їх усі. Якщо вхід контролює зловмисник, це **Regular expression Denial of Service (ReDoS)**: один запит повністю займає ядро процесора.

Захист:

1. **Завжди задавайте тайм-аут** для шаблонів, що застосовуються до недовіреного вводу:

```csharp
var rx = new Regex(pattern, RegexOptions.None, matchTimeout: TimeSpan.FromMilliseconds(100));
try { rx.IsMatch(input); }
catch (RegexMatchTimeoutException) { /* відхилити ввід */ }
// або на весь процес: AppContext.SetData("REGEX_DEFAULT_MATCH_TIMEOUT", TimeSpan.FromSeconds(1));
```

2. **Пишіть однозначні шаблони**: уникайте вкладених квантифікаторів над наборами символів, що перекриваються; віддавайте перевагу конкретним класам (`[^,]*` замість `.*`); ставте якорі.
3. Використовуйте **атомарні групи** `(?>...)` (або присвійну поведінку), щоб заборонити бектрекінг усередину підзбігу.
4. Для недовіреного вводу в .NET 7+ використовуйте **`RegexOptions.NonBacktracking`**: він гарантує лінійний час (зворотні посилання й lookaround заборонені).
5. Ніколи не будуйте шаблони з введення користувача без `Regex.Escape`.

## Інші поради з продуктивності

- Використовуйте `RegexOptions.CultureInvariant` разом з `IgnoreCase`, щоб уникнути сюрпризів культури (турецька i).
- `ExplicitCapture` (або `(?:...)`) уникає алокації непотрібних груп.
- `Regex.EnumerateMatches` (.NET 7) і `IsMatch(ReadOnlySpan<char>)` уникають алокації об'єктів `Match`.
- Для простих перевірок звичайні методи рядків (`StartsWith`, `IndexOfAny`, цикли з `char.IsDigit`) швидші за регулярні вирази й легше читаються.

## Що сказати на співбесіді

- Рушій за замовчуванням використовує бектрекінг; вкладені неоднозначні квантифікатори можуть займати експоненційний час.
- Захист від ReDoS: тайм-аути, однозначні шаблони, атомарні групи, `NonBacktracking`, екранування введення користувача.
- Повторно використовуйте екземпляри `Regex`; для відомих шаблонів віддавайте перевагу `[GeneratedRegex]`.
