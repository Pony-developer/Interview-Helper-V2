## Делегат — типобезпечний вказівник на метод

**Тип** делегата описує сигнатуру методу. **Екземпляр** делегата посилається на один чи кілька методів із такою сигнатурою і може їх викликати.

```csharp
delegate int Transformer(int x);          // тип делегата

static int Square(int x) => x * x;

Transformer t = Square;                   // екземпляр, що вказує на Square
int result = t(3);                        // 9: те саме, що t.Invoke(3)
```

Оскільки методи стають значеннями, поведінку можна передавати в інші методи:

```csharp
static void TransformAll(int[] values, Transformer t)
{
    for (int i = 0; i < values.Length; i++) values[i] = t(values[i]);
}

int[] data = { 1, 2, 3 };
TransformAll(data, Square);               // { 1, 4, 9 }
```

Це суть **методу-плагіна**: `TransformAll` не знає і не переймається, яке саме перетворення.

## Цілі екземпляра та статичні цілі

Делегат, що вказує на метод екземпляра, запам'ятовує ще й об'єкт:

```csharp
var counter = new Counter();
Action tick = counter.Increment;
tick(); tick();
Console.WriteLine(tick.Target == counter);   // True: Target — це об'єкт
Console.WriteLine(tick.Method.Name);         // Increment
```

Це також означає, що делегат **тримає живим** свій цільовий об'єкт: довгоживучий делегат (наприклад, у статичній події) може спричинити витік пам'яті.

## Мультикаст-делегати

Будь-який делегат може містити список методів. `+=` додає, `-=` прибирає, а виклик запускає їх **по черзі**.

```csharp
Action<string> log = Console.WriteLine;
log += s => File.AppendAllText("log.txt", s + "\n");
log("started");                             // пише в консоль І у файл

log -= Console.WriteLine;                   // прибрати один
```

Що варто знати:

- **Делегати незмінні.** `+=` створює новий делегат, що поєднує старий список і новий метод. Інша змінна, що посилалася на старий делегат, не змінюється.
- Якщо прибрати останній метод, змінна стає **null**.
- Якщо делегат повертає значення, виконуються всі методи, але викликач отримує **лише останнє значення**. Мультикаст призначений для `void`-делегатів.
- Якщо один метод кидає виняток, решта **не виконуються**. Щоб виконати всі, пройдіться по `GetInvocationList()` і обгорніть кожен виклик у `try`.

## Узагальнені типи делегатів

```csharp
public delegate T Transformer<T>(T arg);
Transformer<double> half = x => x / 2;
```

Власні оголошувати доводиться рідко: `Func` і `Action` (наступна лекція) покривають майже всі сигнатури.

## Делегати проти інтерфейсів

Усе, що робить делегат, можна зробити інтерфейсом з одним методом. Делегат кращий, коли:

- інтерфейс мав би лише один метод;
- викликач може захотіти передати **кілька** реалізацій (мультикаст);
- реалізація природно є лямбдою чи методом непов'язаного класу.

Інтерфейс кращий, коли контракт має кілька пов'язаних методів чи несе стан та ідентичність.

## Що сказати на співбесіді

- Тип делегата — це сигнатура; екземпляр — посилання на методи, яке можна викликати.
- Делегати незмінні й мультикастні; `+=` будує новий делегат.
- Не-void мультикаст-делегат повертає лише останній результат.
- Делегат тримає живим свій цільовий об'єкт.
