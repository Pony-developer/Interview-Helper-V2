## Форма інструкції try

```csharp
try
{
    // код, що може кинути виняток
}
catch (FileNotFoundException ex)               // найконкретніші першими
{
    // обробити один вид помилки
}
catch (IOException ex) when (IsTransient(ex))  // фільтр винятків (C# 6)
{
    // обробити лише коли умова виконується
}
catch (Exception)                              // найзагальніші останніми; змінна необов'язкова
{
    // ...
}
finally
{
    // виконується завжди: звільнити ресурси, відновити стан
}
```

`try` потребує принаймні одного `catch` або `finally`.

## Як рантайм шукає обробник

Коли кинуто виняток, CLR піднімається стеком викликів у пошуках `catch`, чий тип підходить (тип винятку чи базовий тип) і чий фільтр, якщо є, повертає `true`. Блоки catch перевіряються **по черзі**, тож компілятор відхиляє загальний catch, поставлений перед конкретнішим.

Якщо обробника немає, виняток **необроблений**: процес друкує виняток і завершується (в ASP.NET Core фреймворк ловить його для кожного запиту й повертає HTTP 500).

## Фільтри винятків

```csharp
catch (HttpRequestException ex) when (ex.StatusCode == HttpStatusCode.ServiceUnavailable)
{
    // повторити
}
```

Фільтр обчислюється **до** розкручування стеку. Це має два корисні наслідки:

- якщо фільтр `false`, catch ніби не існує: стек, зокрема локальні змінні в місці кидання, лишається цілим для налагоджувача й дампів;
- можна **логувати, не перехоплюючи**:

```csharp
catch (Exception ex) when (Log(ex)) { }   // Log повертає false, тож нічого не перехоплено
```

## finally

`finally` виконується, коли керування залишає блок `try` з **будь-якої** причини: нормальне завершення, `return`, `break`, `continue`, `goto` чи виняток (перехоплений чи ні). Не виконується, якщо процес вбито, при `Environment.FailFast` чи переповненні стеку.

Типові застосування: закрити файли та з'єднання, звільнити блокування, скинути прапорець «зайнято». Здебільшого `finally` самі не пишуть; це робить `using`.

## Інструкція using

```csharp
using (var reader = new StreamReader(path))
{
    Console.WriteLine(reader.ReadLine());
}

// using-оголошення C# 8: звільняється наприкінці охопної області
using var writer = new StreamWriter(output);
writer.WriteLine("done");
```

`using` компілюється в `try { ... } finally { if (x != null) ((IDisposable)x).Dispose(); }`.

## Вартість

- Вхід у блок `try` практично безкоштовний.
- **Кидання** дороге: у сотні разів повільніше за повернення з методу, бо рантайм збирає стек викликів і проходить по стеку. Тому винятки — для виняткових ситуацій, а не для звичайного потоку керування.

## Що сказати на співбесіді

- Спершу ловіть конкретні винятки; загальні — останніми (якщо взагалі).
- Фільтри (`when`) вирішують до розкручування і придатні для логування без перехоплення.
- `finally` виконується завжди, крім збоїв рівня процесу; зазвичай його отримують через `using`.
