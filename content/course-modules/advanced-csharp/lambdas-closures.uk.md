## Синтаксис лямбд

Лямбда — безіменний метод, записаний на місці: `(параметри) => вираз-або-блок`.

```csharp
Func<int, int> square = x => x * x;                    // один параметр, тіло-вираз
Func<int, int, int> add = (a, b) => a + b;             // кілька параметрів
Func<string, int, bool> longer = (string s, int n) => s.Length > n;   // явні типи
Action greet = () => Console.WriteLine("hi");          // без параметрів
Func<int, string> describe = n =>
{
    if (n < 0) return "negative";
    return n == 0 ? "zero" : "positive";
};                                                     // тіло-блок
Func<int, int, int> first = (a, _) => a;               // відкинутий параметр (C# 9)
```

Лямбда не має власного типу: компілятор перетворює її на **делегат** (`Func`, `Action`, ...) або на **дерево виразів** (`Expression<Func<...>>`) залежно від цілі.

### Природні типи (C# 10)

```csharp
var parse = (string s) => int.Parse(s);    // виведено як Func<string, int>
var choose = object (bool b) => b ? 1 : "one";   // явний тип результату
```

## Замикання: захоплення зовнішніх змінних

Лямбда може використовувати локальні змінні й параметри методу навколо неї. Це **захоплені змінні**, а лямбда разом із ними — **замикання**.

```csharp
int factor = 3;
Func<int, int> multiply = x => x * factor;
factor = 10;
Console.WriteLine(multiply(2));   // 20, а не 6
```

Ключовий факт: **захоплюються змінні, а не значення**. Лямбда бачить поточне значення змінної в момент, коли *виконується*. Компілятор переносить захоплені змінні в прихований клас, тож їхній час життя подовжується до часу життя делегата.

```csharp
static Func<int> MakeCounter()
{
    int count = 0;
    return () => ++count;          // count живе довше за MakeCounter
}

var next = MakeCounter();
Console.WriteLine(next());         // 1
Console.WriteLine(next());         // 2
```

### Пастка циклу

```csharp
var actions = new List<Action>();
for (int i = 0; i < 3; i++)
    actions.Add(() => Console.Write(i));
foreach (var a in actions) a();    // 333: одна змінна i, що закінчується на 3
```

Виправлення — скопіювати в змінну, оголошену **всередині** циклу:

```csharp
for (int i = 0; i < 3; i++)
{
    int copy = i;
    actions.Add(() => Console.Write(copy));   // 012
}
```

З C# 5 `foreach` оголошує **нову змінну на кожній ітерації**, тож `foreach (var x in items) actions.Add(() => Use(x));` працює очікувано. Цикли `for` досі мають одну спільну змінну.

## Ціна замикань

Кожне замикання — це алокація в купі для прихованого класу і ще одна для делегата. У гарячих місцях:

- уникайте захоплення (передавайте стан параметром);
- використовуйте `static`-лямбди (наступна лекція), щоб компілятор не дозволив випадкового захоплення;
- лямбди, що нічого не захоплюють, компілятор кешує, і вони алокуються лише раз.

## Що сказати на співбесіді

- Лямбда стає делегатом чи деревом виразів залежно від того, чому її присвоюють.
- Замикання захоплюють змінні, тож бачать пізніші зміни й подовжують час життя змінної.
- Змінна циклу `for` спільна для всіх ітерацій; змінні `foreach` — ні (з C# 5).
