## Два ключі

Криптографія з відкритим ключем (асиметрична) використовує **пару ключів**:

- **відкритий ключ** можна давати будь-кому;
- **закритий ключ** ніколи не залишає власника.

Те, що зробив один ключ, може скасувати лише інший:

| Операція | Робиться | Перевіряється/скасовується | Дає |
| --- | --- | --- | --- |
| Шифрування | **відкритим** ключем отримувача | **закритим** ключем отримувача | прочитати може лише отримувач |
| Підпис | **закритим** ключем підписувача | **відкритим** ключем підписувача | будь-хто може перевірити, хто підписав і що нічого не змінено |

Асиметричні операції **повільні**, а RSA може шифрувати лише невеликі дані (кілька сотень байтів), тож справжні системи поєднують їх із симетричною криптографією.

## Підпис і перевірка

```csharp
using ECDsa signer = ECDsa.Create(ECCurve.NamedCurves.nistP256);
byte[] publicKey = signer.ExportSubjectPublicKeyInfo();          // цим діляться

byte[] document = Encoding.UTF8.GetBytes("{\"orderId\":42,\"total\":99.5}");
byte[] signature = signer.SignData(document, HashAlgorithmName.SHA256);

// деінде, маючи лише відкритий ключ
using ECDsa verifier = ECDsa.Create();
verifier.ImportSubjectPublicKeyInfo(publicKey, out _);
bool ok = verifier.VerifyData(document, signature, HashAlgorithmName.SHA256);
```

Насправді підписується **хеш** даних. Застосування: JWT, підписані RS256/ES256 (постачальник ідентичності підписує, ваш API перевіряє опублікованим відкритим ключем), підпис коду, підписані оновлення ПЗ, підписи документів, ланцюжки сертифікатів.

Підписи проти HMAC: той, хто перевіряє HMAC, має **той самий** секрет і міг би підробити мітку; той, хто перевіряє підпис, має лише відкритий ключ, тож підпис доводить, що його створив власник закритого ключа (**неможливість відмови**).

## Шифрування RSA

```csharp
using RSA rsa = RSA.Create(3072);
byte[] wrappedKey = rsa.Encrypt(aesKey, RSAEncryptionPadding.OaepSHA256);   // лише невеликі дані
byte[] aesKeyAgain = rsa.Decrypt(wrappedKey, RSAEncryptionPadding.OaepSHA256);
```

Використовуйте доповнення **OAEP** (а не PKCS#1 v1.5 для шифрування) і ключі щонайменше 2048 бітів (3072+ для довгострокового використання).

## Гібридне шифрування

Щоб зашифрувати велике повідомлення для когось:

1. згенерувати випадковий ключ AES;
2. зашифрувати повідомлення через AES-GCM;
3. зашифрувати (обгорнути) ключ AES відкритим ключем RSA отримувача;
4. надіслати обидва. Отримувач розгортає ключ AES своїм закритим ключем, потім розшифровує.

Так працюють TLS, PGP, S/MIME і «конвертне шифрування» в хмарних системах керування ключами. Сучасний TLS здебільшого використовує **узгодження ключів Діффі-Геллмана** (`ECDiffieHellman`) замість передачі ключа через RSA, що дає пряму секретність (forward secrecy).

## Сертифікати

Сертифікат (`X509Certificate2`) пов'язує відкритий ключ з ідентичністю (домен, компанія) і підписаний центром сертифікації. Довіра спускається ланцюжком від кореневого CA, якому довіряє ОС.

```csharp
using var cert = new X509Certificate2("api.pfx", password);
using RSA? privateKey = cert.GetRSAPrivateKey();
Console.WriteLine($"{cert.Subject}, valid until {cert.NotAfter:d}");
```

Завантажуйте сертифікати з безпечних сховищ (сховище сертифікатів Windows, Azure Key Vault), а не з файлів з паролями в конфігурації.

## Що сказати на співбесіді

- Відкритий ключ шифрує / перевіряє; закритий розшифровує / підписує.
- Підписи дають цілісність + автентичність + неможливість відмови; HMAC неможливості відмови не дає.
- Справжні системи гібридні: асиметрична криптографія для обміну ключем, симетрична — для даних.
