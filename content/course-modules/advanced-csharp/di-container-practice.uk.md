## Завдання

Кожен застосунок ASP.NET Core спирається на DI-контейнер. Побудуйте крихітний на рефлексії, щоб побачити, як він працює всередині.

`Register<TService, TImpl>(singleton)` уже написано: він зіставляє тип сервісу з типом реалізації. Реалізуйте **`Resolve(Type type)`**:

1. Якщо для `type` уже є екземпляр-синглтон, поверніть його.
2. Знайдіть реалізацію: зареєстрований тип або сам `type`, якщо це конкретний клас, якого не реєстрували. Незареєстрований **інтерфейс чи абстрактний клас** кидає `InvalidOperationException("No registration for " + type.Name)`.
3. Оберіть публічний конструктор з **найбільшою кількістю параметрів** (`GetConstructors()` + `GetParameters().Length`).
4. **Розв'яжіть кожен параметр рекурсивно**, потім викличте `ctor.Invoke(args)`.
5. Якщо сервіс зареєстровано як синглтон, запам'ятайте екземпляр на наступний раз.

`Report` потребує `OrderService`, якому потрібні `IRepository` (transient: щоразу новий) та `IClock` (singleton: завжди той самий об'єкт).

Очікуваний результат:

```
order#7 (repo 1) at 2024-03-05 10:00
order#8 (repo 2) at 2024-03-05 10:00
same clock: True
same repo: False
No registration for IDisposable
```
