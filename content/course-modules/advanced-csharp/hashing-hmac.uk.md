## Криптографічні хеші

Хеш-функція відображає будь-який вхід у **дайджест** фіксованого розміру. Криптографічний хеш створено так, щоб:

- той самий вхід завжди давав той самий дайджест;
- крихітна зміна входу повністю змінювала дайджест;
- з дайджесту не можна було відновити вхід (**односторонність**);
- не можна було знайти два входи з однаковим дайджестом (**стійкість до колізій**).

```csharp
byte[] data = Encoding.UTF8.GetBytes("hello");
byte[] digest = SHA256.HashData(data);                        // .NET 5+
string hex = Convert.ToHexString(digest).ToLowerInvariant();  // 2cf24dba5fb0a30e...

using var sha = SHA256.Create();                              // старіший стиль; працює й з потоками
using var file = File.OpenRead("installer.msi");
byte[] fileHash = sha.ComputeHash(file);
```

Застосування: перевірка цілісності файлів, сховища й кеші з адресацією за вмістом (ETag), дедуплікація, ідентифікатори комітів (git використовує SHA-1/SHA-256), будівельний блок підписів.

| Алгоритм | Дайджест | Стан |
| --- | --- | --- |
| MD5 | 128 бітів | **зламаний**: колізії знайти легко; лише для контрольних сум без вимог безпеки |
| SHA-1 | 160 бітів | **зламаний** щодо стійкості до колізій |
| SHA-256 / SHA-384 / SHA-512 | 256–512 бітів | безпечні; SHA-256 — вибір за замовчуванням |

`GetHashCode()` — **не** криптографічний хеш: він маленький, швидкий і не призначений протистояти атакам.

## HMAC: хешування з ключем

Звичайний хеш нічого не доводить про те, **хто** його створив: зловмисник, що змінив дані, просто перерахує хеш. **HMAC** домішує в хеш секретний ключ, тож дійсну мітку можуть створити лише власники ключа:

```csharp
byte[] key = RandomNumberGenerator.GetBytes(32);
byte[] tag = HMACSHA256.HashData(key, Encoding.UTF8.GetBytes(payload));   // .NET 6

bool valid = CryptographicOperations.FixedTimeEquals(tag, receivedTag);    // порівняння за сталий час
```

Типові застосування: підписи вебхуків (Stripe, GitHub підписують свої виклики HMAC-SHA256), підписані cookie та URL, JWT з алгоритмом HS256, підпис запитів до API.

**Порівняння за сталий час** важливе: звичайний цикл, що виходить на першому відмінному байті, через час виконання видає, скільки початкових байтів правильні, і зловмисник може вгадати дійсний підпис байт за байтом.

## Хешування паролів

Швидкий хеш на кшталт SHA-256 — **неправильний** інструмент для паролів: зловмисники обчислюють мільярди хешів на секунду на GPU. Функції хешування паролів навмисно **повільні** й **посолені**:

```csharp
byte[] salt = RandomNumberGenerator.GetBytes(16);                 // унікальна для кожного пароля
byte[] hash = Rfc2898DeriveBytes.Pbkdf2(password, salt, iterations: 600_000,
                                        HashAlgorithmName.SHA256, outputLength: 32);   // .NET 6
string stored = $"{600_000}.{Convert.ToBase64String(salt)}.{Convert.ToBase64String(hash)}";
```

- **Сіль** (випадкова, для кожного пароля, зберігається поруч із хешем) робить марними заздалегідь обчислені rainbow-таблиці й дає однаковим паролям різні хеші.
- **Кількість ітерацій** (робочий фактор) робить кожну спробу дорогою; з часом її підвищують, тому вона зберігається разом із хешем.
- Для перевірки перерахуйте зі збереженими сіллю та ітераціями й порівняйте за сталий час.
- Альтернативи: bcrypt, scrypt, **Argon2id** (вимоглива до пам'яті; сучасна рекомендація) через бібліотеки. `PasswordHasher<T>` в ASP.NET Core Identity реалізує PBKDF2 за вас.

## Що сказати на співбесіді

- SHA-256 — для цілісності; MD5/SHA-1 зламані з погляду безпеки.
- HMAC = хеш із ключем, що доводить цілісність + автентичність через спільний секрет; порівнюйте мітки за сталий час.
- Паролі: повільні функції із сіллю (PBKDF2, bcrypt, Argon2), ніколи не простий SHA-256 і ніколи не шифрування.
