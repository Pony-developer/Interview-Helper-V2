## Ідентичність із чотирьох частин

Повне ім'я збірки має чотири складники:

```
Shop.Core, Version=2.0.0.0, Culture=neutral, PublicKeyToken=b77a5c561934e089
```

| Частина | Значення |
| --- | --- |
| Просте ім'я | зазвичай ім'я файлу без розширення |
| Версія | `major.minor.build.revision` (`AssemblyVersion`) |
| Культура | `neutral` для коду; культура на кшталт `uk-UA` для сателітних збірок ресурсів |
| Токен публічного ключа | 8-байтовий хеш публічного ключа строгого імені або `null`, якщо не підписано |

```csharp
var name = new AssemblyName("Shop.Core, Version=2.0.0.0, Culture=neutral, PublicKeyToken=null");
Console.WriteLine(name.Name);         // Shop.Core
Console.WriteLine(name.Version);      // 2.0.0.0
AssemblyName mine = typeof(Program).Assembly.GetName();
```

## Три версії

| Атрибут | Для чого | Порада |
| --- | --- | --- |
| `AssemblyVersion` | **зв'язування**: що записують і запитують збірки, які посилаються | змінюйте рідко, наприклад лише на мажорних версіях, щоб уникнути конфліктів зв'язування |
| `AssemblyFileVersion` | версія файлу Win32, яку показує Провідник | збільшуйте на кожному збиранні |
| `AssemblyInformationalVersion` | «версія продукту» для людей, може містити будь-який текст (`2.1.0-beta+sha`) | те, що показуєте в «Про програму» |

У .NET Core/5+ зв'язування поблажливе: доступна вища версія задовольняє посилання на нижчу. У .NET Framework посилання зі строгими іменами вимагали точних версій, якщо їх не перенаправили в конфігурації (binding redirects), — часте джерело помилок «Could not load file or assembly».

## Строге ім'я

Строге ім'я підписує збірку приватним ключем; публічний ключ потрапляє в ідентичність.

```xml
<SignAssembly>true</SignAssembly>
<AssemblyOriginatorKeyFile>shop.snk</AssemblyOriginatorKeyFile>   <!-- створено через sn -k shop.snk -->
```

Що воно дає:

- **унікальну ідентичність**: два різні видавці не можуть створити те саме повне ім'я;
- **виявлення підробок**, коли рантайм перевіряє підпис (.NET Core пропускає перевірку заради продуктивності).

Чого воно не дає: довіри. Будь-хто може створити пару ключів; строге ім'я нічого не каже про те, **хто** ви. У .NET Core воно важливе переважно для сумісності (збірка зі строгим іменем у .NET Framework може посилатися лише на інші збірки зі строгими іменами), тому багато бібліотек з відкритим кодом досі підписуються публічно доступним ключем.

## Підписування Authenticode

Authenticode доводить, **хто опублікував файл**, за допомогою сертифіката підпису коду X.509, виданого довіреним центром сертифікації:

```
signtool sign /fd SHA256 /a /tr http://timestamp.example /td SHA256 MyApp.exe
```

- Windows показує видавця у вікнах UAC, а SmartScreen більше довіряє підписаним файлам із доброю репутацією.
- **Мітка часу** зберігає підпис дійсним після закінчення терміну сертифіката.
- NuGet має власне підписування пакетів (підписи автора й репозиторію).

| | Строге ім'я | Authenticode |
| --- | --- | --- |
| Доводить | унікальність ідентичності | ідентичність видавця |
| Ключ з | власноруч згенерований | центр сертифікації |
| Використовує | завантажувач CLR | Windows, браузери, користувачі |

## Що сказати на співбесіді

- Повне ім'я = просте ім'я + версія + культура + токен публічного ключа.
- `AssemblyVersion` — для зв'язування; `FileVersion` і `InformationalVersion` — для людей та інструментів.
- Строге ім'я = унікальна ідентичність, а не довіра; Authenticode = перевірений видавець.
