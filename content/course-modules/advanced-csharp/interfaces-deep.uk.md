## Що таке інтерфейс

Інтерфейс — це **контракт**: набір членів, які тип обіцяє надати. Він не має полів екземпляра, тож не несе стану.

```csharp
public interface IShippingCalculator
{
    decimal Calculate(Order order);
    string Carrier { get; }
}
```

- Клас чи структура може реалізувати **багато** інтерфейсів, але успадкувати лише один клас.
- Члени інтерфейсу неявно `public` і абстрактні (якщо не мають тіла за замовчуванням).
- Інтерфейс може розширювати інші інтерфейси: `interface IRepository<T> : IReadRepository<T>`.

## Неявна та явна реалізація

```csharp
public class FileLogger : ILogger, IDisposable
{
    public void Log(string msg) { /* ... */ }   // неявна: доступна на FileLogger і ILogger
    void IDisposable.Dispose() { /* ... */ }    // явна: лише через посилання IDisposable
}

var logger = new FileLogger();
logger.Log("hi");                  // ок
// logger.Dispose();               // помилка: не видно на FileLogger
((IDisposable)logger).Dispose();   // ок
```

Явну реалізацію використовують, коли:

- два інтерфейси мають члени з однаковою сигнатурою, але різним змістом;
- член — деталь реалізації, яку не хочеться показувати в публічній поверхні класу;
- потрібен строго типізований публічний член і слабко типізований інтерфейсний (наприклад, `IEnumerable.GetEnumerator` проти `IEnumerable<T>.GetEnumerator`).

## Інтерфейси та віртуальні члени

Неявно реалізований член інтерфейсу за замовчуванням **запечатаний**. Позначте його `virtual`, якщо підкласи мають змогу його перевизначати. Інакше підклас може лише **повторно реалізувати** інтерфейс, а це працює тільки для викликачів, що йдуть через інтерфейс.

## Інтерфейси та пакування

Приведення структури до інтерфейсу її пакує. Виклик методу інтерфейсу через обмеження узагальнення (`where T : IComparable<T>`) — ні.

## Члени інтерфейсу за замовчуванням (C# 8)

```csharp
public interface ILogger
{
    void Log(string message);
    void LogError(Exception ex) => Log("ERROR: " + ex.Message);   // тіло за замовчуванням
}
```

Суть — **версіонування**: можна додати `LogError` до інтерфейсу, який уже реалізують сотні класів, і нічого не зламати. Член за замовчуванням доступний лише через інтерфейс (`((ILogger)x).LogError(...)`). Інтерфейси також можуть мати статичні члени, зокрема статичні поля; полів екземпляра в них, як і раніше, бути не може.

## Статичні абстрактні члени (C# 11, preview у C# 10)

```csharp
public interface IParsable<TSelf> where TSelf : IParsable<TSelf>
{
    static abstract TSelf Parse(string s);
}
```

Вони дозволяють узагальненому коду викликати статичні методи й оператори на `T`: це основа generic math у .NET 7.

## Клас чи інтерфейс?

- **Класи** (та успадкування) — для типів зі спільною реалізацією та ідентичністю («`Report` — це `Document`»).
- **Інтерфейси** — для можливостей, спільних для непов'язаних типів («можна зберегти», «можна порівняти»).
- На межах (репозиторії, зовнішні сервіси) залежте від інтерфейсів, щоб у тестах можна було підставити фейки.

## Що сказати на співбесіді

- Абстрактний клас: спільний стан і код, одиничне успадкування. Інтерфейс: контракт, багато на тип.
- Явна реалізація ховає член з поверхні класу та розв'язує конфлікти імен.
- Члени інтерфейсу за замовчуванням існують для розвитку вже опублікованих інтерфейсів.
