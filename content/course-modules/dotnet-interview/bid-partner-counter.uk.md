## Завдання

Задача на проєктування рівня Senior: «Біди живуть у сервісі торгів, партнери — в сервісі партнерів. Перший екран показує кількість партнерів для кожного біда». Рекомендований дизайн (див. лекцію про проєктування систем) — **локальна read-модель** у сервісі торгів, яку живлять події із сервісу партнерів. Події приходять **щонайменше раз** і **не обов'язково по порядку** — модель однаково має стати правильною.

Допишіть `BidReadModel` (додайте потрібні поля):

1. **`Apply(e)`**:
   - якщо подію з таким самим `Id` уже застосовано, ігноруйте її й збільште `Ignored`;
   - для пари `(BidId, PartnerId)` зберігайте стан події з **найбільшою `Version`**; подія, чия версія не новіша за вже застосовану для цієї пари, застаріла — ігноруйте її й збільште `Ignored`;
   - інакше збережіть прапорець `Added` і версію пари.
2. **`PartnersCount(bidId)`** — скільки пар цього біда зараз у стані «додано».

Саме зберігання стану для кожної пари (замість `count++` / `count--`) робить дублікати й зміну порядку нешкідливими: у тесті `e5` (партнера 201 видалено, версія 2) приходить раніше за `e4` (додано, версія 1), і запізніла `e4` не повинна «воскресити» партнера.

Очікуваний вивід:

```
e1 -> bid 1: 1, bid 2: 0
e2 -> bid 1: 2, bid 2: 0
e3 -> bid 1: 1, bid 2: 0
e1 -> bid 1: 1, bid 2: 0
e5 -> bid 1: 1, bid 2: 0
e4 -> bid 1: 1, bid 2: 0
e6 -> bid 1: 1, bid 2: 1
e7 -> bid 1: 2, bid 2: 1
e8 -> bid 1: 3, bid 2: 1
bid 3: 0, ignored: 2
```
