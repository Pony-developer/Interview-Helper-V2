## Завдання

Практична задача зі списку Middle: «Сутність треба записати в базу й надіслати подію в брокер повідомлень. Як зробити це з мінімальним ризиком утратити дані?» Реалізуйте **transactional outbox** від початку до кінця на підробках у пам'яті.

`Db.InTransaction` відкочує все, що дія додала, якщо вона кинула виняток. `Broker.Publish` доставляє споживачу, але може впасти до доставки (`FailNext`) або загубити підтвердження після доставки (`LoseAckNext`) — саме ті ситуації, що призводять до втрачених чи продубльованих повідомлень у реальних системах.

Допишіть:

1. **`OrderService.PlaceOrder(db, id, failAfterSave)`** — усередині **однієї** `db.InTransaction(...)` додайте id замовлення в `db.Orders` і `OutboxMessage` з тілом `"OrderPlaced:<id>"` у `db.Outbox`. Якщо `failAfterSave` дорівнює true, киньте `InvalidOperationException` після додавання обох: транзакція має відкотити обидва, тож ніколи не буде події без замовлення чи замовлення без події.
2. **`OutboxRelay.RunOnce(db, broker)`** — опублікуйте невідправлені повідомлення по порядку; позначайте повідомлення `Sent` **лише після** того, як `Publish` повернув керування. Якщо `Publish` кинув виняток, зупиніться й поверніть, скільки вже відправлено, — решта повториться на наступному запуску.
3. **`Consumer.Handle(message)`** — оскільки ретранслятор може опублікувати повідомлення знову (підтвердження загубилося після доставки), обробляйте кожне різне повідомлення лише раз.

Стежте за виводом: запуск 1 падає до доставки; запуск 2 доставляє `OrderPlaced:1`, але губить підтвердження, тож воно не позначене відправленим; запуск 3 доставляє його **знову** (разом 3 доставки) плюс `OrderPlaced:2`; споживач усе одно обробляє кожне замовлення один раз.

Очікуваний вивід:

```
order 3 failed
orders: 1,2, outbox: 2
run 1: 0
run 2: 0
run 3: 2
run 4: 0
deliveries: 3
handled: OrderPlaced:1, OrderPlaced:2
```
