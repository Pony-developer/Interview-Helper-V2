## Завдання

Питання 68–69: «Чому в чергах з'являються дублікати?» і «Як будувати ідемпотентні сервіси?» Тут брокер доставляє повідомлення про поповнення **щонайменше раз**, тож `m1` і `m2` приходять двічі. Поповнення — *відносна* операція (`balance += amount`): застосувавши її двічі, гроші зарахують двічі.

Допишіть `AccountService`:

1. **`Handle(message)`**:
   - недодатна сума → поверніть `"rejected"` (не записуйте її як оброблену: пізніше може прийти виправлене повідомлення з тим самим id);
   - id повідомлення, яке вже застосовано → поверніть `"duplicate"` і нічого не змінюйте;
   - інакше додайте суму до балансу рахунку, запам'ятайте id і поверніть `"applied"`.
   Порада: `HashSet<string>.Add` повертає `false`, якщо id уже є — один виклик і перевіряє, і записує.
2. **`Balance(account)`** — поточний баланс, `0` для невідомого рахунку.

У реальному сервісі множина оброблених id — це **таблиця inbox** з унікальним ключем, записана в **тій самій транзакції БД**, що й зміна балансу, інакше падіння між двома кроками ламає ідемпотентність.

Очікуваний вивід:

```
m1: applied
m2: applied
m1: duplicate
m3: applied
m2: duplicate
m4: rejected
A = 150
B = 70
C = 0
processed: 3
```
