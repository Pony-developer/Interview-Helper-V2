## Generics під час виконання, рефлексія (П83–84)

Узагальнені типи компілюються в IL **один раз**, як відкриті generic-типи (``List`1``). Конкретні типи створює **під час виконання** CLR/JIT: для кожного аргументу — **типу значення** — генерується власний спеціалізований нативний код (`List<int>`, `List<double>`: без упакування), а всі аргументи — **типи посилань** — ділять одну реалізацію (`List<string>` і `List<object>` використовують той самий код). На відміну від Java, інформація про типи не стирається: `typeof(List<int>)` існує під час виконання.

**Рефлексія** досліджує й використовує метадані типів під час виконання: `GetType()`, `typeof`, `Type.GetProperties()`, `MethodInfo.Invoke`, `Activator.CreateInstance`, читання атрибутів. Її використовують серіалізатори, ORM, DI-контейнери, тестові фреймворки й завантажувачі плагінів. Вона повільна й обходить перевірки компілятора; на гарячих шляхах кешуйте `PropertyInfo`, використовуйте скомпільовані дерева виразів або генератори коду.

## LinkedList, індексатори, незмінність, StringBuilder (П85–88)

- **`LinkedList<T>`** — двозв'язний список об'єктів `LinkedListNode<T>`. O(1) вставлення/видалення біля вузла, який ви вже маєте (`AddAfter`, `Remove(node)`), O(n) доступ за позицією, немає індексатора, погана локальність кешу й додатковий об'єкт на кожен елемент. `List<T>` виграє майже в усіх реальних сценаріях; зв'язний список добрий для LRU-кешів (разом зі словником вузлів).
- **Індексатор** дозволяє звертатися до об'єкта через `[]`: `public T this[int index] { get { … } set { … } }`. Приклади: `List<T>`, `Dictionary<K,V>`, `string`.
- **Незмінний** об'єкт не може змінитися після створення. Переваги: потокобезпечний без блокувань, безпечний як ключ словника, не потребує захисних копій, про нього легше міркувати. Реалізація: поля `readonly`, властивості лише з get або `init`, усе задається в конструкторі, змінний внутрішній стан не «витікає» назовні (`ImmutableList`/`IReadOnlyList` або копії), методи «зміни» повертають новий екземпляр. Типи `record` і вирази `with` у C# роблять більшість цього за вас: `var older = person with { Age = 31 };`.
- **`StringBuilder`** тримає список шматків символів; `Append` пише в поточний шматок і додає новий, коли той заповнився, тож немає копіювання всього рядка при кожному додаванні. Використовуйте його, коли збираєте рядок у циклі або з багатьох частин; `string` (`+`, інтерполяція, `string.Join`, `string.Concat`) — для кількох конкатенацій.

## Дерева, ключ-значення й хешування (П89–90, 100–103)

**Балансування дерева** тримає висоту двійкового дерева пошуку на рівні O(log n), повертаючи вузли (ротації) після вставлень і видалень (АВЛ-дерева, червоно-чорні дерева). Без нього вставлення відсортованих даних перетворює дерево на зв'язний список з операціями O(n). `SortedDictionary` і `SortedSet` — червоно-чорні дерева.

**Структури ключ-значення** відображають ключі на значення: `Dictionary`, `SortedDictionary`, `SortedList`, `ConcurrentDictionary`, а також зовнішні сховища на кшталт Redis.

**Хеш-функція** відображає ключ на число фіксованого розміру. **Хеш-таблиця** використовує його, щоб обрати кошик (bucket), і дає в середньому O(1) для пошуку, вставлення й видалення. Ідеальна хеш-функція **детермінована** (рівні ключі → рівні хеші, тож `Equals` і `GetHashCode` перевизначають разом), **рівномірна** (розкладає ключі рівно), **швидка** і сильно змінюється від малої зміни входу (лавинний ефект). Використовуйте `HashCode.Combine(a, b)`. Ніколи не допускайте, щоб хеш ключа змінився, поки той лежить у словнику.

**Колізія** — два ключі потрапили в один кошик. Розв'язання: **ланцюжки** (кожен кошик містить ланцюжок записів — так робить `Dictionary` у .NET, з масивом `entries` та індексами `next`) або **відкрита адресація** (перебір наступних слотів: лінійне чи квадратичне зондування, подвійне хешування). Коли коефіцієнт заповнення росте, таблиця **збільшується** (до наступного простого розміру) й перехешовує все.

CRUD у `Dictionary<K, V>`: додавання, пошук, оновлення, видалення — **O(1) у середньому**, O(n) у найгіршому випадку (усі ключі в колізії); `Add` зрідка коштує O(n) через збільшення, амортизовано O(1).

## Масиви та списки (П104–106)

Масиви — типи посилань: **кожен масив живе в купі**, зокрема `int[]`. Масив типу значення зберігає значення безпосередньо в одному суцільному блоці (чудово для кешу); масив типу посилання зберігає посилання. Масиви від 85 000 байтів потрапляють у LOH.

`T[]` має фіксовану довжину й трохи швидший; `List<T>` обгортає масив і збільшує його (подвоюючи місткість і копіюючи), коли той заповнився. Задавайте розмір заздалегідь через `new List<T>(capacity)`, якщо знаєте його.

`IEnumerable<T>` дозволяє лише послідовний `foreach` уперед (він може бути лінивим, нескінченним або запитом до бази). `IList<T>` додає `Count`, доступ за індексом, `Add`, `Insert`, `Remove`. Приймайте найменш конкретний інтерфейс, який вам потрібен (`IEnumerable<T>`, `IReadOnlyCollection<T>`), а повертайте найкорисніший.

## Pull і push; IEnumerable і IQueryable; прапорці (П107–109)

| Інтерфейс | Модель | Споживач |
|---|---|---|
| `IEnumerable<T>` | **pull**, синхронна | `foreach` просить наступний елемент |
| `IAsyncEnumerable<T>` | **pull**, асинхронна | `await foreach` просить і чекає наступний елемент (потокове читання з БД/HTTP) |
| `IObservable<T>` | **push** | джерело саме викликає `OnNext/OnError/OnCompleted` у підписників (Rx, події) |

**`IEnumerable<T>`** виконується в пам'яті з делегатами (`Func<T, bool>`). **`IQueryable<T>`** містить **дерево виразів** (`Expression<Func<T, bool>>`), яке провайдер (EF Core) перекладає в SQL, тож фільтрація, сортування й пагінація відбуваються в базі. Завчасний виклик `AsEnumerable()` чи `ToList()` затягує всю таблицю в пам'ять.

**Прапорці в переліках** комбінують значення побітовими операціями:

```csharp
[Flags]
enum Permissions { None = 0, Read = 1, Write = 2, Execute = 4, All = Read | Write | Execute }

var p = Permissions.Read | Permissions.Write;
bool canWrite = p.HasFlag(Permissions.Write);   // або (p & Permissions.Write) != 0
p &= ~Permissions.Write;                         // прибрати прапорець
Console.WriteLine(p);                             // "Read"
```

Використовуйте степені двійки як значення; `[Flags]` ще й змушує `ToString()` друкувати `"Read, Write"`.
