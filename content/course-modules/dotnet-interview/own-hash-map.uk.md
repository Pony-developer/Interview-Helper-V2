## Завдання

Питання 100–103 — хеш-функції, колізії та складність `Dictionary`. Збудуйте невелику хеш-таблицю з **ланцюжками**, щоб побачити все це в роботі.

`buckets` — масив зв'язних списків вузлів `Entry`; `BucketOf(key, size)` відображає ключ на індекс кошика. Допишіть:

1. **`Put(key, value)`** — пройдіть ланцюжок кошика ключа; якщо ключ є (порівнюйте через `Equals`), замініть значення. Інакше вставте новий запис на початок ланцюжка й збільште `Count`. Після додавання **нового** ключа, якщо `Count > Capacity * 3 / 4` (коефіцієнт заповнення 0,75), викличте збільшення, що подвоює масив і **перехешовує** кожен запис у нові кошики (кошик запису залежить від розміру масиву).
2. **`TryGet(key, out value)`** — знайдіть ключ у ланцюжку його кошика.
3. **`Remove(key)`** — вилучіть запис із ланцюжка (обережно з головою ланцюжка); поверніть, чи він там був.
4. **`LongestChain()`** — довжина найдовшого ланцюжка.

Клас `BadKey` повертає той самий хеш-код для кожного ключа: усі записи потрапляють в один кошик, тож таблиця досі працює правильно (завдяки `Equals`), але вироджується у зв'язний список — O(n) на операцію. Саме це робить зі справжнім `Dictionary` поганий `GetHashCode` чи атака hash flooding.

Місткість росте 4 → 8 → 16 → 32, поки додаються 20 ключів.

Очікуваний вивід:

```
20 32
20 500
False
True False 19
True 19
5 8 5 C
4 False
```
