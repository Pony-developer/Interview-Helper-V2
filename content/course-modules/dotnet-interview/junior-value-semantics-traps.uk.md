## Передача значень і посилань

```csharp
void Change(int n, int[] arr, List<int> list, ref int r)
{
    n = 100;            // змінна викликача не змінюється (копія)
    arr[0] = 100;       // викликач це бачить: той самий об'єкт масиву
    list = new();       // викликач цього не бачить: змінилося лише локальне посилання
    r = 100;            // викликач бачить: ref передає саму змінну
}
```

Практичне правило: можна змінити *об'єкт*, на який указує посилання, але не те, *на який об'єкт* указує змінна викликача — хіба що через `ref`/`out`.

## Рівність: чотири різні питання

| Вираз | Клас | Структура | Record | Рядок |
|---|---|---|---|---|
| `a == b` | те саме посилання (якщо не перевантажено) | не компілюється без перевантаження | ті самі значення | ті самі символи |
| `a.Equals(b)` | те саме посилання (якщо не перевизначено) | поле за полем (через рефлексію, повільно) | ті самі значення | ті самі символи |
| `ReferenceEquals(a, b)` | те саме посилання | завжди false (упакування) | те саме посилання | те саме посилання |

Перевизначайте `Equals` + `GetHashCode` (і `==`) разом або використовуйте `record` / `record struct`. Реалізуйте `IEquatable<T>` у структурах, щоб уникнути упакування.

## Null

```csharp
string? name = GetName();                  // nullable-тип посилання: компілятор попереджає про небезпечне використання
int length = name?.Length ?? 0;            // null-умовний + null-об'єднувальний
name ??= "guest";                          // присвоїти, якщо null
ArgumentNullException.ThrowIfNull(order);  // захисна перевірка
if (order is null) …                       // безпечніше за == null (не можна перевантажити)
if (shape is Circle { Radius: > 0 } c) …   // зіставлення зі зразком ніколи не збігається з null
```

`int?` (структура `Nullable<int>`) і `string?` (анотація на типі посилання) виглядають схоже, але це зовсім різні можливості.

## Числа

```csharp
Console.Write(0.1 + 0.2 == 0.3);       // False: double — двійкова рухома кома
Console.Write(0.1m + 0.2m == 0.3m);    // True: decimal — десятковий
Console.Write(7 / 2);                  // 3: цілочисельне ділення
Console.Write(7 / 2.0);                // 3.5
int big = int.MaxValue; big++;         // тихо переходить у int.MinValue; checked { } кине виняток
Console.Write((int)3.99);              // 3: відкидання, а не округлення
Console.Write(Math.Round(2.5));        // 2: «банківське» округлення за замовчуванням (MidpointRounding.ToEven)
```

## Пастки generics

- `List<object>` **не є** `List<string>` і навпаки (класи інваріантні); `IEnumerable<object> e = new List<string>();` працює (коваріантність).
- `default(T)` — `null` для типів посилань і нуль для типів значень; `if (value == null)` на необмеженому `T` працює, а для порівняння з `default` потрібен `EqualityComparer<T>.Default.Equals(value, default)`.
- `typeof(List<>)` — відкритий тип; `typeof(List<int>)` — закритий.
- Статичні поля — свої для кожного закритого типу: `Cache<int>.Count` і `Cache<string>.Count` різні.

## Пастки колекцій

- Зміна `List<T>` під час перебору через `foreach` кидає виняток — перебирайте копію (`ToList()`), використовуйте `RemoveAll` або цикл `for` у зворотному напрямку.
- Індексатор `Dictionary` кидає `KeyNotFoundException` для відсутнього ключа — використовуйте `TryGetValue`.
- Ключ `HashSet`/`Dictionary`, чий хеш змінився після вставлення, «губиться».
- `Array.Sort` і `List.Sort` нестабільні; `OrderBy` стабільний.

У практиці ви напишете невеликий узагальнений репозиторій з обмеженнями (`where T : class, IEntity`) і узагальнений `MaxBy` з `where TKey : IComparable<TKey>`.
