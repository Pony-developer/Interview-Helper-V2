## Винятки (П13–15)

**Виняток** — об'єкт, похідний від `System.Exception`, що сигналізує про помилку й розкручує стек викликів, доки не знайдеться відповідний `catch`. Якщо такого немає, процес аварійно завершується.

```csharp
try
{
    var text = File.ReadAllText(path);
}
catch (FileNotFoundException ex)   // спершу найконкретніші типи
{
    logger.LogWarning(ex, "Missing {Path}", path);
}
finally
{
    // виконується завжди: звільняємо ресурси (або просто використовуємо `using`)
}
```

- `try` обгортає код, що може зламатися; `catch` обробляє конкретні типи винятків (із фільтрами: `catch (HttpRequestException ex) when (ex.StatusCode == HttpStatusCode.NotFound)`); `finally` виконується незалежно від того, чи був виняток, навіть після `return`.
- `finally` **не** виконається, якщо процес загине: `Environment.FailFast`, примусове завершення процесу, `StackOverflowException`, зникло живлення.
- Перекидайте виняток через `throw;` (зберігає початковий стек), а не `throw ex;`.

**Стек викликів** — стек кадрів кожного потоку, по одному кадру на кожен метод, що зараз виконується. Кадр містить адресу повернення, аргументи й локальні змінні. Пов'язані ключові слова: `throw`, `try/catch/finally`, `return`, `stackalloc`; `Exception.StackTrace` показує стек у місці кидка.

## Платформа (П16–24)

- **ASP.NET (Core)** — вебфреймворк .NET: MVC-контролери, Razor Pages, minimal API, Blazor і SignalR, побудовані на сервері Kestrel і конвеєрі middleware.
- **Фільтри** в ASP.NET Core MVC виконуються навколо дії в такому порядку: **авторизації** → **ресурсу** → (прив'язка моделі) → **дії** → (виконується дія) → **винятків** → **результату**. Це місце для наскрізної функціональності: валідації, кешування, перетворення помилок.
- **Веб-сервіс** — компонент, що надає функціональність через мережу в стандартному форматі: SOAP/WSDL (старі ASMX, WCF), REST/JSON (Web API), gRPC.
- **CLR** (Common Language Runtime) завантажує збірки, JIT-компілює IL у нативний код, керує пам'яттю через GC, забезпечує типобезпеку, обробляє винятки, потоки й безпеку.
- **Збирач сміття** звільняє об'єкти в керованій купі, до яких уже не можна дістатися з коренів (статичні поля, локальні змінні в стеках потоків, регістри процесора, GC-дескриптори). Він поколіннєвий (Gen 0, 1, 2 плюс Large Object Heap) і ущільнює пам'ять. Некеровані ресурси він не звільняє: для цього є `IDisposable`.
- **Делегат** — типобезпечне посилання на метод (або на кілька: multicast). `delegate int Op(int a, int b);` оголошує тип делегата. **`Action<...>`** (повертає `void`) і **`Func<..., TResult>`** — готові узагальнені типи делегатів, тож власні потрібні рідко. `System.Delegate` — абстрактний базовий клас усіх типів делегатів.
- **LINQ** (Language Integrated Query) дає оператори запитів над будь-яким `IEnumerable<T>` (у пам'яті) або `IQueryable<T>` (перекладається, наприклад, у SQL через EF Core):

```csharp
var topCustomers = orders
    .Where(o => o.Total > 100)
    .GroupBy(o => o.CustomerId)
    .Select(g => new { Customer = g.Key, Sum = g.Sum(o => o.Total) })
    .OrderByDescending(x => x.Sum)
    .Take(5);
```

- **Простір імен** групує пов'язані типи й запобігає конфліктам імен (`System.Threading.Timer` і `System.Timers.Timer`). Він суто логічний: одна збірка може містити багато просторів імен, а один простір імен може охоплювати кілька збірок.
