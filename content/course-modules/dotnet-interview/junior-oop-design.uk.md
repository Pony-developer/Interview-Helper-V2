«Спроєктуйте паркінг / бібліотеку / торговий автомат» — часта задача рівнів Junior–Middle, що перевіряє класи, успадкування, інтерфейси й інкапсуляцію разом. Інтерв'юера більше цікавить ваш **процес**, ніж фінальна діаграма.

## 1. Запитайте про вимоги

- Які транспортні засоби? (мотоцикли, авто, автобуси) Які розміри місць? Чи може малий транспорт стати на велике місце?
- Як рахується ціна? За кожну розпочату годину? Різні тарифи для різних типів?
- Кілька поверхів? В'їзди? Оплата, квитки, бронювання? (Зазвичай: «тримайте простіше».)

Запишіть погоджений обсяг: *місця трьох розмірів; транспорт стає на найменше вільне місце, що підходить; оплата за кожну розпочату годину, щонайменше одна година, тариф залежить від типу транспорту.*

## 2. Знайдіть іменники й дієслова

- Іменники → кандидати в класи: `ParkingLot`, `Spot`, `Vehicle` (`Motorcycle`, `Car`, `Bus`), `Ticket`.
- Дієслова → методи: `Park(vehicle)`, `Leave(plate)`, `FreeSpots(size)`, `CalculateFee(...)`.

## 3. Вирішіть, що змінюється

Між типами транспорту різняться **дані** (розмір, погодинний тариф), тож підходить абстрактна база з абстрактними властивостями:

```csharp
public abstract class Vehicle(string plate)
{
    public string Plate { get; } = plate;
    public abstract SpotSize Size { get; }
    public abstract decimal HourlyRate { get; }
}
public sealed class Car(string plate) : Vehicle(plate)
{
    public override SpotSize Size => SpotSize.Medium;
    public override decimal HourlyRate => 20m;
}
```

Згадайте альтернативу: якщо відмінності лише в значеннях, простіше мати один клас `Vehicle` з `VehicleType` і таблицею тарифів — успадкування виправдане, коли різниться **поведінка**. Якщо правила ціноутворення ростимуть (нічні тарифи, абонементи), винесіть `IPricingPolicy` (Strategy).

## 4. Інкапсулюйте правила

```csharp
public sealed class ParkingLot
{
    private readonly List<Spot> _spots;                       // ніхто ззовні не змінить список
    public int Park(Vehicle v, DateTime at) { … }             // тут живе правило «найменше місце, що підходить»
    public decimal Leave(string plate, DateTime at) { … }     // тут живе правило оплати
}
```

Викликач не зможе поставити автобус на мале місце чи забути звільнити місце, бо змінити стан можна лише через ці методи.

## 5. Обговоріть граничні випадки й розширення

- Той самий номер паркується двічі; виїзд із невідомим номером (виняток або тип-результат).
- Час: впроваджуйте `TimeProvider`/`IClock` замість `DateTime.Now`, щоб оплату можна було тестувати.
- Конкурентність: два в'їзди одночасно викликають `Park` → блокування навколо виділення місця або база з унікальним обмеженням.
- Збереження й API: доменні класи лишаються тими самими; навколо них додаються репозиторій і контролер.

## Типові помилки

- Почати з коду, не погодивши вимоги.
- Глибокі ієрархії (`Vehicle → MotorVehicle → FourWheeler → Car → Sedan`).
- Публічні сетери всюди, тож будь-який код може зламати інваріанти.
- Усе в одному «божественному» класі `ParkingLotManager`.

Практика дає готові класи транспорту; ви реалізуєте правила `ParkingLot`.
