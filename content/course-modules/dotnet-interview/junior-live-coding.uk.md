Практичні задачі зі списку DOU (калькулятор, прості числа, мінімум, FizzBuzz, дерево папок) зазвичай розв'язують наживо — у спільному редакторі чи на дошці. Те, як ви працюєте, важить не менше за результат.

## Процес, що працює

1. **Перекажіть задачу й поставте питання.** «Тобто на вході рядок без цифр, а я повертаю закодований рядок? А порожній рядок? Великі й малі літери — різні символи?»
2. **Запишіть 2–3 приклади, зокрема граничні**, до написання коду: `"aaab" → "a3b"`, `"" → ""`, `"a" → "a"`, серія з 12 символів.
3. **Озвучте план і його складність.** «Один прохід із двома індексами, O(n) часу, O(n) на результат».
4. **Спершу напишіть просту версію.** Зрозумілі назви, маленькі допоміжні методи, жодної передчасної хитрості.
5. **Протестуйте вручну** своїми прикладами — проговоріть цикл уголос.
6. **Покращіть і обговоріть**: граничні випадки, складність, що б ви зробили в продакшні (тести, валідація, `StringBuilder`, `Span<T>`).

## Говоріть, поки думаєте

Мовчання — найгірший сигнал. Коментуйте: «Мені треба знати, де закінчується серія… рухатиму `j`, поки символ той самий». Якщо застрягли, скажіть, що вже спробували, і попросіть підказку — уміння добре скористатися підказкою теж позитивний сигнал.

## Перелік граничних випадків

- порожній вхід, `null`, один елемент;
- усі елементи однакові, усі різні;
- від'ємні числа, нуль, `int.MaxValue` / переповнення;
- дублікати; уже відсортовано / відсортовано навпаки;
- дуже великий вхід (чи вкладається алгоритм у час і пам'ять?);
- Unicode й регістр для рядків.

## Звички в C#, що добре виглядають на співбесіді

```csharp
ArgumentNullException.ThrowIfNull(text);                 // захисні перевірки
if (text.Length == 0) return string.Empty;               // ранній вихід для граничних випадків
var sb = new StringBuilder(text.Length);                  // StringBuilder для побудови рядків
foreach (var (key, count) in counts) { … }               // деконструкція
return items.Where(x => x > 0).OrderBy(x => x).ToList(); // LINQ, коли зрозуміліше; цикли, коли швидше
```

А погано виглядає: однолітерні назви всюди, величезний `Main`, поглинання винятків, «магічні» числа, ігнорування граничних випадків, які ви ж самі перелічили.

## Шпаргалка зі складності

| Шаблон | Типова складність |
|---|---|
| один прохід по входу | O(n) |
| вкладені цикли по входу | O(n²) |
| сортування, потім прохід | O(n log n) |
| пошук у хеш-множині / словнику в циклі | O(n) |
| двійковий пошук | O(log n) |
| перебір усіх підмножин / перестановок | O(2ⁿ) / O(n!) |

Практика — кодування довжинами серій — типова задача на 15–20 хвилин живого кодування: просто сформулювати, але є кілька граничних випадків (серії з одного символу, багатоцифрові лічильники, некоректний вхід).
