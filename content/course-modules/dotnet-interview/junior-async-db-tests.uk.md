## Асинхронність (П45–47)

**Асинхронність** — це не блокувати потік, поки чекаємо на щось повільне (диск, мережу, базу даних). **Багатопотоковість** — виконувати роботу на кількох потоках одночасно. Асинхронному I/O *не потрібен* потік, поки операція триває: ОС повідомляє про завершення, і продовження виконується пізніше. Паралелізм — для роботи, обмеженої процесором, асинхронність — для роботи, обмеженої введенням-виведенням.

Ключові слова: **`async`** позначає метод, у якому можна використовувати `await` (і змушує компілятор побудувати скінченний автомат); **`await`** чекає на `Task` без блокування: якщо задача не завершена, метод повертає керування викликачу, а решта планується як продовження. Пов'язані типи: `Task`, `Task<T>`, `ValueTask<T>`, `CancellationToken`, `IAsyncEnumerable<T>` з `await foreach`.

```csharp
public async Task<Order?> GetOrderAsync(int id, CancellationToken ct)
{
    using var response = await _http.GetAsync($"orders/{id}", ct);
    if (!response.IsSuccessStatusCode) return null;
    return await response.Content.ReadFromJsonAsync<Order>(cancellationToken: ct);
}
```

Практичні правила: асинхронність «до кінця» (жодних `.Result` чи `.Wait()`, які можуть спричинити взаємне блокування й марнують потоки), повертайте `Task`, а не `void` (крім обробників подій), передавайте `CancellationToken`.

## Бази даних (П48–50)

**Реляційні** (SQL Server, PostgreSQL, MySQL): таблиці з фіксованою схемою, ключі та зв'язки, SQL зі з'єднаннями, ACID-транзакції. Переваги: узгодженість, потужні довільні запити, зріле інструментування. Недоліки: зміни схеми потребують міграцій; горизонтальне масштабування (шардинг) складне.

**Нереляційні (NoSQL)**: документні (MongoDB, Cosmos DB), ключ-значення (Redis), колонкові (Cassandra), графові (Neo4j). Переваги: гнучка схема, просте горизонтальне масштабування, швидкий доступ за ключем. Недоліки: слабші з'єднання й транзакції, часто кінцева узгодженість (eventual consistency), дублювання даних.

**Індекс** — додаткова структура даних (зазвичай B-дерево), що відображає значення колонок на рядки, тож база знаходить рядки без сканування всієї таблиці й може повертати їх упорядкованими. Ціна: місце на диску й повільніші `INSERT/UPDATE/DELETE`. **Кластерний** індекс зберігає саму таблицю в порядку індексу (один на таблицю); **некластерний** — окрема структура, що вказує на рядки.

**JOIN-и**: `INNER JOIN` (лише рядки зі збігом), `LEFT [OUTER] JOIN` (усі ліві рядки, NULL там, де праворуч нічого немає), `RIGHT JOIN`, `FULL [OUTER] JOIN` (усі рядки обох сторін), `CROSS JOIN` (декартів добуток) і самоз'єднання (таблиця з'єднується сама із собою, наприклад працівник → керівник).

## Модульні тести (П51–53)

Навіщо: одразу ловити регресії, безпечно рефакторити, документувати очікувану поведінку й підштовхувати до слабко зв'язаного дизайну (клас, який важко тестувати, зазвичай має забагато залежностей).

Недоліки: час на написання й підтримку; тестують одиниці, а не систему загалом; погано написані тести (перевіряють деталі реалізації, забагато моків) сповільнюють роботу.

Структура: **Arrange – Act – Assert** (підготувати – виконати – перевірити).

```csharp
[Fact]
public void Withdraw_more_than_balance_throws()
{
    // Arrange
    var account = new BankAccount(balance: 100);
    // Act
    var act = () => account.Withdraw(150);
    // Assert
    Assert.Throws<InvalidOperationException>(act);
}
```

Фреймворки: xUnit, NUnit, MSTest; моки — Moq або NSubstitute; перевірки — FluentAssertions.
