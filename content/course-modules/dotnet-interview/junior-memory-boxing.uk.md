## Семантика копіювання в коді (П28–29)

```csharp
struct PointS { public int X; }
class  PointC { public int X; }

var s1 = new PointS { X = 1 };
var s2 = s1;          // копіюється все значення
s2.X = 9;             // s1.X досі 1

var c1 = new PointC { X = 1 };
var c2 = c1;          // копіюється лише посилання
c2.X = 9;             // тепер c1.X дорівнює 9: один об'єкт, два посилання
```

Те саме з параметрами методів: аргумент-структура копіюється (метод змінює свою копію), аргумент-клас передає копію **посилання** (метод може змінити об'єкт, але присвоєння параметру нового об'єкта не впливає на викликача). `ref` передає саму змінну.

```csharp
void Reset(PointC p) { p.X = 0; p = new PointC(); }   // викликач побачить X = 0, а не новий об'єкт
```

## Де що живе

```text
void M()
{
    int n = 5;                 // стек (або регістр)
    var p = new PointC();      // посилання в стеку → об'єкт у купі
    var arr = new int[3];      // посилання в стеку → масив (усі 3 int усередині) в купі
    var s = new PointS();      // стек
}
class Holder { PointS pos; }   // pos живе всередині об'єкта Holder, у купі
```

Точне правило: **об'єкти типів посилань** завжди живуть у керованій купі; **типи значень живуть там, де їхній контейнер** — локальна змінна в кадрі стеку, поле всередині свого об'єкта, елемент усередині свого масиву.

## Ціна упакування (П32)

```csharp
int n = 42;
object o = n;                 // упакування: виділити об'єкт у купі, скопіювати туди 42
int m = (int)o;               // розпакування: перевірка типу + копіювання назад

IComparable c = n;            // теж упакування: перетворення структури на інтерфейс
string.Format("{0}", n);      // упакування: params object[]
var list = new ArrayList { n };   // упакування; List<int> не пакував би
```

Кожна «коробка» — це виділення в купі (≈24 байти на 64 бітах), яке GC потім мусить зібрати. У циклі на мільйони елементів це видно в профайлері. Generics, `$"{n}"` (обробники інтерполяції в сучасному C#) і перевантаження, що приймають `int`, цього уникають.

## Nullable-типи значень (П27)

```csharp
int? age = null;
if (age.HasValue) Console.WriteLine(age.Value);
int years = age ?? 18;               // значення за замовчуванням, коли null
int? next = age + 1;                 // піднятий оператор: null + 1 = null
bool adult = age >= 18;              // false, коли null (порівняння з null — false)
```

`Nullable<T>` — це структура `{ bool hasValue; T value; }`, без виділення в купі. Упакування null-ового `int?` дає справжнє `null`-посилання; упакування не-null — упаковує сам `int`. **Nullable-типи посилань** (`string?`, C# 8) — інша можливість: анотації й попередження на етапі компіляції, під час виконання нічого не змінюється.

## Рядки (П29–30)

- Незмінні: кожна «зміна» (`Replace`, `ToUpper`, `+`) повертає **новий** рядок. Тому рядки потокобезпечні й безпечні як ключі словника.
- `==` порівнює **вміст** (оператор перевантажено); `ReferenceEquals` порівнює посилання.
- **Інтернування**: рядкові літерали зберігаються в процесі один раз (`"abc"` і `"abc"` — той самий об'єкт); рядки, побудовані під час виконання, не інтернуються, якщо не викликати `string.Intern`.
- Порівнюйте з явним правилом: `string.Equals(a, b, StringComparison.OrdinalIgnoreCase)`.
- Збирання тексту в циклі: `StringBuilder`, `string.Join`, `string.Concat` або `string.Create` для гарячих шляхів.
