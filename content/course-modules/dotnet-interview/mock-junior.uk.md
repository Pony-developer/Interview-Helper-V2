**Інтерв'юер:** Розкажіть про себе за хвилину.

**Кандидат:** «Я закінчив дворічний курс C# і зробив пет-проєкт: API бронювання на ASP.NET Core з EF Core і PostgreSQL, покритий тестами xUnit і розгорнутий у Docker. > *Перевіряє:* чіткість, доречність, щось конкретне, у що можна заглибитися пізніше.

---

**Інтерв'юер:** Які принципи ООП? Наведіть приклад зі свого проєкту.

**Кандидат:** «Інкапсуляція, успадкування, поліморфізм і абстракція. У моєму API бронювання `Booking` має приватний сетер для `Status` і методи `Confirm()` та `Cancel()`, що перевіряють дозволені переходи, — це інкапсуляція. Сповіщення йдуть через інтерфейс `INotifier` з реалізаціями для email і SMS — абстракція й поліморфізм. Успадкування використовував менше; надаю перевагу композиції, якщо це не справжнє «є»».

> *Перевіряє:* визначення плюс реальний приклад; бонус за «композицію замість успадкування».

---

**Інтерв'юер:** Типи значень і типи посилань — де вони живуть? `string` — тип значення?

**Кандидат:** «Типи значень містять самі дані; присвоєння їх копіює. Типи посилань містять посилання на об'єкт у купі. Локальний `int` — у стеку, але поле `int` класу — в купі всередині об'єкта, тож «типи значень живуть у стеку» — спрощення. `string` — тип посилання, але незмінний, а `==` порівнює вміст, тож він поводиться як значення».

---

**Інтерв'юер:** Що надрукує? `var list = new List<int> { 1, 2 }; var q = list.Where(x => x > 1); list.Add(3); Console.WriteLine(q.Count());`

**Кандидат:** «2. `Where` відкладений, тож виконується в `Count()` і бачить додану 3».

> *Перевіряє:* відкладене виконання — дуже поширена пастка.

---

**Інтерв'юер:** Яка складність пошуку елемента в `List` і в `HashSet`?

**Кандидат:** «O(n) для `List.Contains` — він сканує; O(1) у середньому для `HashSet` — він хешує в кошик. Якщо перевіряю належність у циклі, спершу перетворю на `HashSet`, інакше вийде O(n²)».

---

**Інтерв'юер:** `async`/`await` — що насправді робить `await`?

**Кандидат:** «Якщо задача не завершена, метод повертається до викликача, а решта методу планується як продовження; потік не блокується. Для I/O взагалі жоден потік не чекає. Тож у веб-API потік повертається в пул і може обслуговувати інші запити. І не варто використовувати `.Result` — він блокує й може спричинити взаємне блокування».

---

**Інтерв'юер:** Який JOIN поверне всіх клієнтів, навіть без замовлень?

**Кандидат:** «`LEFT JOIN orders`. А щоб правильно порахувати їхні замовлення, використаю `count(o.id)`, а не `count(*)`, тож клієнти без замовлень отримають 0».

---

**Інтерв'юер:** Навіщо писати модульні тести? Як виглядає тест?

**Кандидат:** «Щоб швидко ловити регресії й безпечно рефакторити. Тест має Arrange, Act, Assert. Наприклад, `Cancel_after_check_in_throws`: підготувати бронювання зі статусом `CheckedIn`, викликати `Cancel()`, перевірити, що кинуто `InvalidOperationException`».

---

**Інтерв'юер:** Практична задача: перевірте, чи є число простим.

**Кандидат (міркує вголос):** «Числа, менші за 2, не прості, 2 — просте, інші парні — ні. Далі перевіряю непарні дільники до квадратного кореня — якщо `n` має дільник, більший за √n, то має й менший. Складність O(√n). Напишу `d * d <= n` з `long`, щоб уникнути переповнення біля `int.MaxValue`».

```csharp
static bool IsPrime(int n)
{
    if (n < 2) return false;
    if (n % 2 == 0) return n == 2;
    for (long d = 3; d * d <= n; d += 2)
        if (n % d == 0) return false;
    return true;
}
```

«Перевірив би: −1, 0, 1, 2, 3, 4, 9, 97, `int.MaxValue`».

> *Перевіряє:* спершу граничні випадки, складність, увага до переповнення, ручне тестування.
