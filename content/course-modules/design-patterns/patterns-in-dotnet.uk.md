Ви користуєтеся патернами проєктування з першої програми на C#; просто .NET не називав їх на ім'я. Уміння їх розпізнавати робить фреймворк зрозумілішим, і це найкращий матеріал для відповіді на співбесіді.

## Коротка мапа

| Ви пишете... | Патерн | Чому це саме він |
| --- | --- | --- |
| `foreach`, `IEnumerable<T>`, `yield return` | **Iterator** | Обхід колекції без знання, як вона зберігається |
| `button.Click += Handler;` `event` | **Observer** | Багато підписників, один видавець, що їх не знає |
| `new GZipStream(new BufferedStream(fileStream))` | **Decorator** | Кожен потік обгортає інший і додає одну можливість |
| `list.Sort(comparer)`, `OrderBy(x => x.Name)` | **Strategy** | Алгоритм порівняння передається ззовні |
| `new StringBuilder().Append(...).ToString()` | **Builder** | Складаємо крок за кроком, потім отримуємо результат |
| `WebApplication.CreateBuilder(args)` ... `builder.Build()` | **Builder** | Налаштовуємо застосунок, потім будуємо його |
| `HttpClient` + `DelegatingHandler` | **Decorator / Chain** | Обробники обгортають один одного навколо HTTP-виклику |
| Middleware в ASP.NET Core, `app.Use(...)` | **Chain of Responsibility** | Кожна ланка обробляє запит або викликає `next()` |
| `IHttpClientFactory.CreateClient()` | **Factory** | Одне місце вирішує, як створювати клієнти й тримати їх у пулі |
| `Lazy<T>` | **Proxy** (віртуальний) | Справжній об'єкт створюється під час першого `.Value` |
| `services.AddSingleton<T>()` | **Singleton** (безпечний різновид) | Один екземпляр, але впроваджений, а не глобальний |
| `File.ReadAllText(path)` | **Facade** | Один виклик приховує потоки, кодування й закриття |
| Продовження `Task.ContinueWith`, `async/await` | схоже на **Command** | Робота, запакована в об'єкти й виконана пізніше |
| Ліниве завантаження в Entity Framework | **Proxy** | Пов'язані дані завантажуються під час першого звернення |
| `DbContext` | **Unit of Work + Repository** | Відстежує зміни й зберігає їх за один раз |
| `ExpressionVisitor`, `SyntaxVisitor` у Roslyn | **Visitor** | Операції над стабільним деревом типів вузлів |

## LINQ: кілька патернів одночасно

```csharp
var bigCustomers = orders
    .Where(o => o.Total > 10000)       // Strategy: фільтр передається ззовні
    .GroupBy(o => o.CustomerId)        // Strategy: селектор ключа
    .Select(g => g.Key)
    .ToList();                         // Iterator: до цього місця нічого не виконувалося (відкладене виконання)
```

Кожен оператор LINQ обгортає попередню послідовність новим ітератором, тобто це ідея Decorator, застосована до послідовностей.

## Як це використати на співбесіді

Коли питають про патерн, пов'яжіть його з тим, що робить .NET: «Decorator — це те, як працюють потоки: `GZipStream` обгортає `FileStream`». Це показує, що ви розумієте ідею, а не лише UML-діаграму.

## Запам'ятайте

Патерни — не щось екзотичне, що додають у проєкт: фреймворк, яким ви вже користуєтеся, з них і складається. Навчіться їх бачити, і нові бібліотеки здаватимуться знайомими.
