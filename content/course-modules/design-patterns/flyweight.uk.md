**Простими словами:** Flyweight економить пам'ять, коли маєте **величезну кількість схожих об'єктів**. Спільна для них частина зберігається **один раз** і використовується всіма; кожен об'єкт тримає лише те, що унікальне саме для нього.

## Картинка з життя

Бібліотека не друкує окрему копію правил для кожного читацького квитка. На стіні одна книжка правил; кожен квиток містить лише ім'я та номер читача.

## Проблема

Мапа показує 1 000 000 дерев. Кожне дерево має позицію (унікальну) і вид із назвою, кольором і текстурою на 2 МБ (однаковою для всіх дубів). Якщо кожен об'єкт дерева зберігає власну текстуру, знадобляться гігабайти пам'яті.

## На C#

```csharp
class TreeType                                   // спільна незмінна («внутрішня») частина
{
    public string Species { get; private set; }
    public byte[] Texture { get; private set; }

    public TreeType(string species, byte[] texture) { Species = species; Texture = texture; }
}

class TreeTypeFactory                            // видає один спільний об'єкт на вид
{
    private readonly Dictionary<string, TreeType> types = new Dictionary<string, TreeType>();

    public TreeType Get(string species)
    {
        TreeType type;
        if (!types.TryGetValue(species, out type))
        {
            type = new TreeType(species, LoadTexture(species));
            types[species] = type;
        }
        return type;
    }

    private static byte[] LoadTexture(string species) { return new byte[2000000]; }
}

class Tree                                       // унікальна («зовнішня») частина маленька
{
    public int X, Y;
    public TreeType Type;                        // посилання на спільну частину
}
```

Мільйон об'єктів `Tree` тепер ділять кілька об'єктів `TreeType`.

## Де ви вже це бачите

- **Інтернування рядків** у .NET: однакові рядкові літерали вказують на один рядковий об'єкт у пам'яті.
- Кешовані запаковані значення й дрібні об'єкти, які повторно використовують фреймворки, гліфи під час відмальовування тексту.

## Коли застосовувати, а коли ні

- **Пасує:** справді дуже багато об'єктів, виміряний тиск на пам'ять і чітка спільна незмінна частина.
- **Зайве:** кілька тисяч об'єктів. Це оптимізація, тож спершу виміряйте. Спільна частина **мусить бути незмінною**, інакше зміна виду одного дерева змінить усі.

## Запам'ятайте

Flyweight = «спільне — ділимо, унікальне — зберігаємо окремо». Це єдиний структурний патерн, що стосується лише продуктивності.
