Майже кожен патерн цього курсу складено з тих самих кількох ідей. Засвойте їх один раз, і патерни перестануть виглядати як 23 окремі речі, які треба зазубрити.

## Ідея 1. Програмуй на рівні інтерфейсу, а не реалізації

**Простими словами:** залежте від того, *що об'єкт уміє*, а не від того, *який це клас*.

```csharp
// Прив'язано до одного класу: щоб надсилати SMS, доведеться правити цей код
class OrderService
{
    private readonly EmailSender sender = new EmailSender();
}

// Залежить лише від уміння «надсилати»: підійде будь-який відправник
interface INotifier { void Send(string to, string text); }

class OrderService
{
    private readonly INotifier notifier;
    public OrderService(INotifier notifier) { this.notifier = notifier; }
}
```

Гарна картинка — електрична розетка: їй байдуже, чи ввімкнете ви чайник, чи ноутбук, головне, щоб пасувала вилка. Інтерфейс — це форма вилки.

## Ідея 2. Композиція замість успадкування

**Простими словами:** замість того щоб *бути* чимось (успадковувати), об'єкт може *мати* щось (тримати інший об'єкт) і просити його виконати роботу.

Успадкування фіксується на етапі компіляції й розростається в глибокі дерева: `Coffee`, `CoffeeWithMilk`, `CoffeeWithMilkAndSugar`, `CoffeeWithSugar`... Композиція дозволяє комбінувати частини під час виконання: кава *має* список добавок. На цій ідеї стоять Decorator, Strategy, Bridge, State і Composite.

## Ідея 3. Інкапсулюй те, що змінюється

**Простими словами:** знайдіть частину коду, яка постійно змінюється, і покладіть її в окрему коробку, щоб решта коду стояла на місці.

Правила знижок змінюються щомісяця, а процес оформлення замовлення — ні? Винесіть правило знижки в окремий клас (Strategy). Постійно змінюється спосіб створення об'єктів? Зберіть створення в одному місці (Factory).

## Ідея 4. SOLID по одному рядку

Патерни часто є *практичним способом* дотримуватися SOLID:

| Принцип | Одним рядком | Патерни, що допомагають |
| --- | --- | --- |
| **S**ingle responsibility | Клас має одну причину для змін | Facade, Command |
| **O**pen/closed | Нова поведінка додається новими класами, а не правкою старих | Strategy, Decorator, Observer |
| **L**iskov substitution | Підклас можна підставити замість базового класу без сюрпризів | Template Method, Composite |
| **I**nterface segregation | Багато малих інтерфейсів кращі за один товстий | Adapter |
| **D**ependency inversion | Залежте від абстракцій; отримуйте залежності ззовні | Factory, Dependency Injection |

## Запам'ятайте

Коли патерн здається заплутаним, поставте три питання: *Що тут змінюється? Який інтерфейс це приховує? Хто кого тримає?* Відповіді майже завжди пояснюють увесь патерн.
