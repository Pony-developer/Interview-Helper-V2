**Простими словами:** Template Method записує **кроки алгоритму один раз, у базовому класі**, і дає підкласам **заповнити деякі кроки**. Порядок кроків зламати не можна; змінюються лише подробиці.

## Картинка з життя

Рецепт будь-якого супу: закип'ятити воду, додати основу, додати овочі, приправити, подати. Борщ і курячий суп ідуть за одним планом; різниться лише те, *що саме* кладуть на кроках «основа» та «овочі».

## Проблема

Три імпортери (CSV, Excel, JSON) кожен відкриває файл, читає рядки, перевіряє їх, зберігає й пише звіт. Відрізняється лише «прочитати рядки», але код скопійовано тричі, і виправлення в перевірці доводиться робити в трьох місцях.

## На C#

```csharp
abstract class Importer
{
    // Шаблонний метод: фіксований порядок кроків. Не virtual, тож ніхто не змінить порядок
    public void Import(string path)
    {
        var rows = ReadRows(path);              // крок, який підкласи МУСЯТЬ надати
        var valid = rows.Where(IsValid).ToList();
        Save(valid);
        AfterImport(valid.Count);               // «гачок»: перевизначати необов'язково
    }

    protected abstract List<string[]> ReadRows(string path);

    protected virtual bool IsValid(string[] row) { return row.Length > 0; }
    protected virtual void AfterImport(int count) { }

    private void Save(List<string[]> rows) { /* спільний код збереження */ }
}

class CsvImporter : Importer
{
    protected override List<string[]> ReadRows(string path)
    {
        return File.ReadAllLines(path).Select(line => line.Split(',')).ToList();
    }
}
```

## Template Method проти Strategy

| | Template Method | Strategy |
| --- | --- | --- |
| Побудований на | **успадкуванні** | **композиції** |
| Що змінюється | окремі **кроки** фіксованого алгоритму | **весь** алгоритм |
| Коли вибирається | на етапі компіляції (який підклас) | під час виконання (який об'єкт передали) |

## Де ви вже це бачите

- `Stream`: `CopyTo` і `ReadByte` написано один раз поверх абстрактного `Read`, який реалізує кожен потік.
- `BackgroundService` в ASP.NET Core: ви перевизначаєте `ExecuteAsync`, а запуском і зупинкою займається базовий клас.
- **Плагіни Dynamics:** спільний клас `PluginBase` реалізує `IPlugin.Execute` (отримати контекст, створити сервіси, перехопити й записати помилки) і викликає абстрактний `ExecuteCore`, який заповнює кожен плагін.

## Запам'ятайте

Template Method = «**план належить базовому класу, підкласи заповнюють пропуски**». Робіть шаблонний метод невіртуальним, щоб план не можна було зламати.
