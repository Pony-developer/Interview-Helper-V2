**Простими словами:** проксі — це **замісник** справжнього об'єкта. Він має той самий інтерфейс, але **контролює доступ** до справжньої речі: створює її лише коли треба, перевіряє права або пересилає виклики на іншу машину.

## Картинка з життя

Банківська картка — це проксі вашого рахунку. Ви платите карткою так, ніби це гроші, але картка перевіряє PIN і ліміт і лише потім звертається до справжнього рахунку.

## Види проксі

| Вид | Що робить | Приклад |
| --- | --- | --- |
| **Віртуальний** (лінивий) | Створює дорогий справжній об'єкт лише під час першого використання | Завантаження великого зображення чи пов'язаних даних запису на вимогу |
| **Захисний** | Перевіряє права, перш ніж пропустити виклик | «Видаляти можуть лише адміністратори» |
| **Віддалений** | Виглядає локальним, але надсилає виклик мережею | Згенерований клієнт веб-сервісу, клієнт WCF/gRPC |
| **Кешувальний** | Запам'ятовує результати | (перетинається з кешувальним декоратором) |

## На C#

```csharp
interface IDocumentStore
{
    void Delete(Guid id);
}

class DocumentStore : IDocumentStore
{
    public void Delete(Guid id) { /* справді видаляє */ }
}

class SecureDocumentStore : IDocumentStore      // захисний проксі
{
    private readonly IDocumentStore real;
    private readonly ICurrentUser user;

    public SecureDocumentStore(IDocumentStore real, ICurrentUser user) { this.real = real; this.user = user; }

    public void Delete(Guid id)
    {
        if (!user.IsInRole("Admin")) throw new UnauthorizedAccessException("Only admins can delete documents");
        real.Delete(id);
    }
}
```

А лінивий різновид .NET дає готовим: `Lazy<T>` створює об'єкт лише під час першого звернення до `.Value`.

## Де ви вже це бачите

- **Проксі лінивого завантаження** в Entity Framework: `order.Customer` завантажується з бази, коли ви вперше до нього звертаєтеся.
- Згенеровані **клієнти сервісів** (`IOrganizationService`, що говорить із Dataverse по HTTP з вашого консольного застосунку, — віддалений проксі).
- Бібліотеки моків, як-от Moq і Castle DynamicProxy, створюють класи-проксі під час виконання.

## Proxy проти Decorator

Обидва обгортають об'єкт тим самим інтерфейсом, тож код виглядає майже однаково. Різниця в **намірі**: декоратор **додає можливості**, і їх нашаровує клієнт; проксі **контролює доступ** до справжнього об'єкта й часто сам вирішує, коли (і чи взагалі) його створювати чи викликати.

## Запам'ятайте

Proxy = «замісник, що вирішує, як і коли дістатися до справжнього об'єкта».
