**Простими словами:** запит мандрує **ланцюжком обробників**. Кожен обробник або **обробляє його**, або **передає наступному**. Відправник не знає, хто врешті ним займеться.

## Картинка з життя

Дзвінок на лінію підтримки: спершу голосове меню намагається допомогти, потім оператор першої лінії, потім спеціаліст, потім керівник. Кожен або розв'язує вашу проблему, або передає вас далі.

## Проблема

Погодження витрат: суми до 1 000 може погодити тимлід, до 10 000 — менеджер, до 50 000 — директор. Перед цим треба перевірити чек. Великий ланцюжок `if / else if` в одному методі змішує всі правила, а змінити порядок чи додати рівень означає його правити.

## На C#

```csharp
abstract class Approver
{
    private Approver next;

    public Approver SetNext(Approver handler) { next = handler; return handler; }

    protected string PassOn(Expense e)
    {
        return next != null ? next.Handle(e) : "Rejected: nobody can approve " + e.Amount;
    }

    public abstract string Handle(Expense e);
}

class TeamLead : Approver
{
    public override string Handle(Expense e)
    {
        if (e.Amount <= 1000) return "Approved by team lead";
        return PassOn(e);                       // не мій рівень: передаю далі
    }
}

var chain = new ReceiptCheck();
chain.SetNext(new TeamLead()).SetNext(new Manager()).SetNext(new Director());
chain.Handle(expense);
```

Кожен обробник знає одне правило. Ланцюжок складається в одному місці, і його можна переставляти чи доповнювати.

## Два різновиди

1. **Зупинитися на першому, хто може обробити**: погодження, ескалація в підтримці.
2. **Кожен робить свою частину й передає далі** (*конвеєр*): middleware в ASP.NET Core, де кожна ланка викликає `await next()`; **конвеєр подій** Dynamics 365, де повідомлення проходить PreValidation, PreOperation, основну операцію й PostOperation, і будь-який плагін на шляху може його зупинити, кинувши виняток.

## Коли застосовувати, а коли ні

- **Пасує:** кілька незалежних перевірок чи обробників, порядок і кількість яких змінюються; хочеться додати один, не чіпаючи інших.
- **Обережно:** запит може «випасти» з кінця ланцюжка, і ніхто його не обробить. Завжди вирішуйте, що робить кінець ланцюжка. Довгі ланцюжки ще й важче налагоджувати.

## Запам'ятайте

Chain of Responsibility = «**обробив або передав далі**». Middleware і конвеєр плагінів — приклади, які варто назвати на співбесіді.
