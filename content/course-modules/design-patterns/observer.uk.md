**Простими словами:** Observer дає змогу одному об'єкту (**видавцю**) **сповіщати багатьох інших** (**підписників**), коли щось стається, не знаючи, хто вони. Підписники самі підписуються й відписуються.

## Картинка з життя

YouTube-канал. Ви натискаєте «Підписатися», і коли виходить нове відео, отримуєте сповіщення. Автор не дзвонить кожному глядачеві й навіть не знає їхніх імен.

## Проблема

Коли замовлення оплачено, склад має зарезервувати товар, бухгалтерія — створити рахунок, а клієнт — отримати лист. Якщо `Order.Pay()` викликає всі три напряму, клас замовлення знає про все, а додати реакцію «бонусні бали» означає знову його правити.

## На C#: події — це Observer, вбудований у мову

```csharp
class Order
{
    public event EventHandler<decimal> Paid;     // точка підписки

    public void Pay(decimal amount)
    {
        // ... списуємо гроші ...
        var handler = Paid;
        if (handler != null) handler(this, amount);   // сповіщаємо всіх (Paid?.Invoke у новіших C#)
    }
}

var order = new Order();
order.Paid += (sender, amount) => Console.WriteLine("Warehouse: reserve items");
order.Paid += (sender, amount) => Console.WriteLine("Accounting: invoice for " + amount);
order.Pay(1500m);
```

`Order` нічого не знає про склад чи бухгалтерію. Нові реакції додаються ззовні через `+=`.

## Класична помилка: забути відписатися

Видавець тримає посилання на кожного підписника. Якщо короткоживучий об'єкт (форма, view model) підписався на довгоживучий (глобальний сервіс) і ніколи не зробив `-=`, його **ніколи не прибере збирач сміття**, і він далі реагуватиме на події. Відписуйтеся в `Dispose` або тримайте підписку не довше, ніж живе підписник.

## Де ви вже це бачите

- `event` у WinForms/WPF (`button.Click += ...`), `INotifyPropertyChanged` у прив'язці даних.
- `IObservable<T>` / `IObserver<T>` і Rx (Reactive Extensions).
- У більшому масштабі: черги повідомлень і pub/sub (топіки Azure Service Bus), вебхуки, надсилання подій із Dataverse у Service Bus.

## Коли застосовувати, а коли ні

- **Пасує:** одна зміна має запускати відкритий список реакцій.
- **Обережно:** забагато подій роблять потік важким для розуміння («хто на це реагує і в якому порядку?»). Підписники не повинні залежати від порядку, в якому їх викликають.

## Запам'ятайте

Observer = «**підпишись і отримуй сповіщення**». У C# це `event` з `+=` і `-=`, а правило таке: хто підписався, той і відписується.
