Плагінам потрібні налаштування: поріг, URL API, ключ, id черги. Якщо їх зашити в код, кожна зміна потребуватиме нового збирання, а кожне середовище — інших значень. Dataverse пропонує кілька місць для конфігурації.

## Конфігурація кроку: unsecure і secure

Кожен крок має два рядки конфігурації, які передаються в **конструктор** плагіна:

```csharp
public class CreditLimitAuditPlugin : IPlugin
{
    private readonly decimal threshold;
    private readonly string apiKey;

    public CreditLimitAuditPlugin(string unsecureConfig, string secureConfig)
    {
        threshold = string.IsNullOrWhiteSpace(unsecureConfig)
            ? 100000m
            : decimal.Parse(unsecureConfig, CultureInfo.InvariantCulture);
        apiKey = secureConfig;
    }
}
```

- **Unsecure configuration** зберігається в кроці, її бачить кожен, хто може читати кроки, і вона **експортується з рішенням**.
- **Secure configuration** зберігається окремо, її можуть читати лише адміністратори, і вона **не експортується** з рішенням: її треба задати в кожному середовищі після імпорту.

Конструктор виконується, коли платформа створює (і кешує) екземпляр, тож розбирайте рядки там один раз і тримайте їх у полях `readonly`. Це єдиний вид стану в полях, який для плагіна нормальний. Багато команд кладуть у рядок JSON чи XML для кількох значень.

## Змінні середовища

**Змінні середовища** (environment variables) — компоненти рішення з визначенням (ім'я, тип, типове значення) і **значенням для кожного середовища**. Вони підходять для налаштувань, які змінюють адміністратори, а конвеєри задають для кожного середовища через файл налаштувань розгортання. Плагіни читають їх запитом до таблиць `environmentvariabledefinition` і `environmentvariablevalue` (значення перекриває типове) або через повідомлення `RetrieveEnvironmentVariableValue`. **Секретні** змінні середовища вказують на Azure Key Vault, і їх читають через `RetrieveEnvironmentVariableSecretValue`.

## Конфігураційна таблиця

Власна таблиця (`contoso_configuration` з `contoso_key` і `contoso_value`) — класичний варіант «зроби сам». Адміністратори редагують її в застосунку, ролі безпеки визначають, хто її бачить, а плагіни й workflow шукають у ній за ключем. Модуль про власні workflow її створює.

## Як обрати

| Налаштування | Де |
| --- | --- |
| Поріг чи прапорець поведінки одного кроку | Unsecure configuration |
| Ключ API для одного кроку | Secure configuration (або секретна змінна середовища) |
| Значення, спільне для плагінів, flow і застосунків, різне для середовищ | Змінна середовища |
| Багато значень, списків, правил, якими опікується бізнес | Конфігураційна таблиця |

## Кешування

Читання конфігурації коштує запиту. Значення з таблиць чи змінних середовища кешуйте в **статичному потокобезпечному** словнику з коротким терміном дії (кілька хвилин) з ключем за id організації, щоб зміну було підхоплено без розгортання:

```csharp
private static readonly ConcurrentDictionary<string, (string Value, DateTime Expires)> Cache = new();
```

Ніколи не кешуйте дані конкретного користувача й пам'ятайте, що кожен процес пісочниці має власну копію кешу.

## На співбесіді

- Поясніть unsecure проти secure configuration і що з них переїжджає з рішеннями.
- Поясніть, чому конфігурацію розбирають у конструкторі.
- Порівняйте конфігурацію кроку, змінні середовища та конфігураційну таблицю.
- Поясніть, як і навіщо кешувати конфігурацію в плагіні.
