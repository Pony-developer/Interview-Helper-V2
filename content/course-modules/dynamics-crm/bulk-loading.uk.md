Міграція кількох мільйонів рядків має бути достатньо швидкою, щоб вміститися у вікно cutover, і достатньо точною, щоб її прийняли. Для цього потрібні правильні API, контрольована паралельність, спосіб обійти бізнес-логіку, якій не слід виконуватися, і звірка наприкінці.

## Масові повідомлення

| API | Що робить | Примітки |
| --- | --- | --- |
| `Create` / `Update` по одному | Один запит на рядок | Просто, найповільніше |
| `ExecuteMultipleRequest` | До 1000 різних запитів за один виклик | Економить мережеві виклики; на сервері кожен запит усе одно виконується окремо |
| `CreateMultipleRequest`, `UpdateMultipleRequest`, `UpsertMultipleRequest` | Багато рядків **однієї таблиці** за одну операцію | Найшвидший варіант для стандартних таблиць; плагіни можна реєструвати на повідомлення `*Multiple`, щоб обробляти весь пакет одразу |
| `ExecuteTransactionRequest` | До 1000 запитів, усе або нічого | Для даних, що мають бути узгодженими, а не для пропускної здатності |

Типові розміри пакета — від 100 до 1000 рядків; міряйте, бо широкі таблиці й важкі плагіни краще працюють із меншими пакетами.

## Паралельність

Dataverse створений для паралельної обробки запитів. Однопотоковий завантажувач лишає більшість потужності невикористаною.

- Надсилайте пакети з кількох потоків чи задач. З `ServiceClient` дайте кожному потоку власний `Clone()` клієнта.
- Поважайте **ліміти захисту сервісу** (на користувача, на веб-сервер: кількість запитів, сумарний час виконання й одночасні запити в ковзному 5-хвилинному вікні). На помилку 429 чекайте тривалість із `Retry-After`; `ServiceClient` повторює автоматично.
- Беріть `RecommendedDegreesOfParallelism` з `ServiceClient` (заголовок відповіді `x-ms-dop-hint`) як відправну точку для кількості потоків.
- Розподіл навантаження між кількома користувачами застосунку множить ліміти на користувача, але погодьте це з командою платформи: середовище легко перевантажити.

## Обхід бізнес-логіки

Плагіни й потоки, написані для користувачів, часто не мають виконуватися під час міграції: вітальні листи 200 000 мігрованих контактів, перерахунки на кожному рядку, інтеграційні повідомлення в ERP.

- Необов'язковий параметр **`BypassBusinessLogicExecution`** зі значенням `CustomSync`, `CustomAsync` або обома пропускає власну синхронну та/або асинхронну логіку для цього запиту (`BypassCustomPluginExecution = true` — старіший параметр для синхронної логіки). Викликач потребує привілею `prvBypassCustomBusinessLogic`.
- **`BypassBusinessLogicExecutionStepIds`** пропускає лише перелічені кроки плагінів.
- Хмарні потоки можна пропустити параметром `SuppressCallbackRegistrationExpanderJob`.
- Системна логіка (безпека, rollup, налаштування виявлення дублікатів, власні плагіни Microsoft) усе одно виконується.

```csharp
var request = new CreateMultipleRequest { Targets = batch };
request.Parameters["BypassBusinessLogicExecution"] = "CustomSync,CustomAsync";
service.Execute(request);
```

Документуйте, що ви обходите: усе, що обчислила б пропущена логіка (суми, номери, стани), має задати сама міграція.

## Помилки та журналювання

Ніколи не зупиняйте весь запуск через один поганий рядок. Записуйте кожен відхилений рядок із legacy id, таблицею та повідомленням про помилку, продовжуйте, а дані виправляйте в staging до наступного запуску. З `ExecuteMultipleRequest` задайте `ContinueOnError = true` і читайте `Fault` кожної відповіді; з повідомленнями `*Multiple` один невдалий рядок валить увесь пакет, тож повторіть цей пакет по рядку, щоб знайти винуватця.

## Звірка

Бізнес приймає міграцію на основі доказів:

- **Кількість рядків** на таблицю в джерелі, staging і Dataverse, з відхиленими рядками, що пояснюють різницю.
- **Суми** грошових і кількісних стовпців (сума рахунків, відкритих угод).
- **Вибірки**: набір записів, які бізнес-користувачі перевіряють поле за полем.
- **Перевірки посилань**: жодних «сиріт» там, де мав бути заданий lookup.

Рядки в Dataverse рахуйте через `RetrieveTotalRecordCountRequest` (швидко, зі знімка) або агрегатним запитом FetchXML, пам'ятаючи про ліміт 50 000 рядків для агрегатних запитів на великих таблицях.

## На співбесіді

- Порівняйте ExecuteMultiple, повідомлення `*Multiple` і ExecuteTransaction.
- Поясніть, як розпаралелити завантаження, не порушуючи ліміти захисту сервісу.
- Поясніть, як обійти власні плагіни і що тоді має зробити сама міграція.
- Опишіть, як ви звіряєте міграцію й обробляєте відхилені рядки.
