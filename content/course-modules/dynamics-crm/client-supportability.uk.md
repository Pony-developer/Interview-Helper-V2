Model-driven застосунки оновлюються кілька разів на рік, не питаючи вас. Скрипти, що використовують лише **підтримувані** API, далі працюють; скрипти, що покладаються на внутрішню будову, ламаються одного вівторкового ранку. Ця лекція — про скрипти, які виживають.

## Підтримуване й непідтримуване

**Підтримуване**: усе, що задокументовано в довіднику Client API: `executionContext`, `formContext`, `Xrm.*` та Web API.

**Непідтримуване**, і часта причина збоїв після оновлень:

- читання чи зміна **HTML** форми (`document.getElementById`, `querySelector`, jQuery на елементах форми, вставлений CSS);
- виклики **недокументованих** функцій чи об'єктів, знайдених у скриптах сторінки;
- залежність від **порядку**, в якому платформа завантажує власні ресурси;
- звертання до вікон `parent` чи `top`, щоб дістати внутрішні об'єкти.

Якщо вимога ніби потребує чогось із цього, шукайте підтримувану альтернативу: PCF-контрол, custom page, команду, бізнес-правило.

## Застарілі API, які варто замінити

| Застаріле | Що використати |
| --- | --- |
| `Xrm.Page` | `executionContext.getFormContext()` / `primaryControl` |
| `Xrm.Utility.alertDialog`, `confirmDialog` | `Xrm.Navigation.openAlertDialog`, `openConfirmDialog` |
| `Xrm.Utility.openEntityForm`, `openWebResource` | `Xrm.Navigation.openForm`, `navigateTo` |
| `context.getUserRoles()` | `Xrm.Utility.getGlobalContext().userSettings.roles` |
| `context.getServerUrl()` | `getClientUrl()` |
| Синхронний `XMLHttpRequest`, SOAP-ендпоінт із JavaScript | `Xrm.WebApi` / `fetch` до Web API |
| `parent.Xrm` з HTML веб-ресурсів | Передавати `Xrm` і контекст форми через `getContentWindow()` |

Microsoft публікує список застарілих клієнтських API з кожним релізом; **solution checker** автоматично позначає багато таких шаблонів. Зробіть його частиною конвеєра.

## Локалізація

Користувачі бачать застосунок своєю мовою; ваші повідомлення мають робити так само.

1. Створіть **RESX** веб-ресурси для кожної мови: `contoso_/strings/account.1033.resx` (англійська), `contoso_/strings/account.1058.resx` (українська).
2. Додайте їх як **залежності** бібліотеки скрипту у властивостях форми чи веб-ресурсу.
3. Читайте рядки за ключем:

```javascript
const text = Xrm.Utility.getResourceString("contoso_/strings/account", "CreditHold");
formContext.ui.setFormNotification(text, "WARNING", "credit-hold");
```

Платформа обирає файл мовою користувача (`userSettings.languageId`), а якщо його немає — базовою мовою. Форматуйте числа й дати через `Intl` чи налаштування користувача, а не склеюванням рядків.

## Доступність

Використовуйте сповіщення й діалоги платформи замість власних спливних вікон: вони працюють з екранними читачами й клавіатурою. В HTML веб-ресурсах і PCF-контролах підписуйте поля введення, підтримуйте клавіатуру й поважайте висококонтрастні теми.

## Власність і документація

Кожен скрипт має в коментарі чи README казати, на яких подіях і формах він зареєстрований. Використовуйте **attribute dependencies** у властивостях обробників подій форми для стовпців, потрібних скрипту, щоб ніхто не прибрав ці стовпці з форми, не побачивши попередження.

## На співбесіді

- Наведіть три приклади непідтримуваних клієнтських налаштувань і підтримувані альтернативи.
- Назвіть застарілі клієнтські API та їхні заміни.
- Поясніть, як локалізувати повідомлення в скриптах форм.
- Поясніть, як attribute dependencies захищають скрипт.
