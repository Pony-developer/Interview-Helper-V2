Dataverse — це більше, ніж таблиці та API. Набір вбудованих сервісів закриває потреби, які команди часто намагаються відтворити власним кодом: історію змін, дублікати, пошук, інкрементну синхронізацію, особливі типи таблиць і сховище. Знання про них заощаджує тижні роботи й трапляється в питаннях з архітектури.

## Аудит

Аудит записує, хто, що й коли змінив, зі **старими й новими значеннями**. Його вмикають на трьох рівнях, і всі три мають бути ввімкнені: **середовище**, **таблиця** і кожен **стовпець**. Якщо налаштовано, аудит також журналює входи, видалення, надання доступу та зміни ролей.

- Користувачі бачать історію на вкладці *Audit history* запису.
- Код читає її через `RetrieveRecordChangeHistoryRequest` або запитом до таблиці `audit`.
- Дані аудиту займають **ємність журналів**; задайте **термін зберігання**, щоб вони не росли безкінечно.

Аудит потрібен для відповідності вимогам і підтримки («хто очистив це поле?»). Це не потік змін для інтеграцій: для цього є відстеження змін.

## Виявлення дублікатів

**Правила виявлення дублікатів** визначають, що робить два записи дублікатами (однаковий email, однакові ім'я та місто). Опубліковані правила попереджають користувачів під час збереження в інтерфейсі, а **завдання виявлення дублікатів** сканують наявні дані.

Виклики API за замовчуванням **пропускають** виявлення дублікатів. Щоб застосувати його, запит має про це попросити:

```csharp
var create = new CreateRequest { Target = contact };
create.Parameters["SuppressDuplicateDetection"] = false;   // помилка, якщо дублікат існує
service.Execute(create);
```

У Web API надішліть заголовок `MSCRM.SuppressDuplicateDetection: false`. Інтеграції зазвичай віддають перевагу **альтернативним ключам і Upsert**, які роблять дублікати неможливими, а не лише виявляють їх.

## Пошук Dataverse

**Пошук Dataverse** (relevance search) індексує вибрані таблиці в окремому пошуковому індексі й шукає в усіх одразу, з толерантністю до одруківок і ранжуванням. Які стовпці доступні для пошуку, береться з **подання Quick Find** кожної таблиці. Розробники можуть викликати його через search API. Індекс оновлюється невдовзі після змін, а не всередині транзакції.

## Відстеження змін

Для інкрементної синхронізації увімкніть на таблиці **відстеження змін** (change tracking). Перший запит повертає всі рядки плюс **токен даних**; наступний запит із цим токеном повертає лише рядки, **створені, змінені чи видалені** відтоді:

- SDK: `RetrieveEntityChangesRequest` з `DataVersion`.
- Web API: заголовок `Prefer: odata.track-changes`, далі переходьте за отриманим `@odata.deltaLink`.

Фільтр за `modifiedon` виглядає схоже, але ніколи не покаже видалених рядків.

## Особливі типи таблиць

| Тип | Що це | Для чого |
| --- | --- | --- |
| Стандартна | Рядки в реляційній базі Dataverse | Майже для всього |
| Еластична | Рядки в Azure Cosmos DB за тим самим API | Величезні обсяги, багато записів за секунду, рядки, що застарівають за часом життя (time to live); менше реляційних можливостей (наприклад, немає зв'язків N:N) |
| Віртуальна | Дані лишаються в зовнішньому джерелі (SQL, SharePoint, OData) і читаються через провайдер даних | Показ зовнішніх даних без копіювання; без аудиту, rollup і відстеження змін |

## Ємність сховища

Тенант купує три види ємності:

- **База даних**: рядки таблиць і метадані.
- **Файли**: вкладення нотаток і листів, стовпці file та image.
- **Журнали**: історія аудиту та журнали трасування плагінів.

Масове очищення даних звільняє ємність. Використовуйте завдання **bulk delete** (запит FetchXML, що виконується як системне завдання один раз або за розкладом), щоб прибирати старі рядки, і **довгострокове зберігання** (long-term retention), щоб переносити закриті записи в дешевше сховище лише для читання.

## Системні завдання

Асинхронна робота виконується як **системні завдання** (`asyncoperation`): асинхронні плагіни, класичні workflows, bulk delete, завдання виявлення дублікатів, обчислення rollup та імпорт. Коли щось «не спрацювало», список системних завдань зі статусом і повідомленням про помилку — перше місце, куди варто зазирнути. Невдалі й завершені завдання треба регулярно прибирати; для цього часто налаштовують bulk delete.

## На співбесіді

- Поясніть три рівні, на яких вмикається аудит, і чого він коштує.
- Поясніть, чому інтеграція створює дублікати попри правила виявлення дублікатів.
- Опишіть інкрементну синхронізацію з відстеженням змін і чому `modifiedon` недостатньо.
- Порівняйте стандартні, еластичні та віртуальні таблиці.
- Назвіть три види ємності та що заповнює кожен.
