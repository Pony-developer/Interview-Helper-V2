Скомпільований код нічого не робить, доки платформа про нього не знає. Розгорнути плагін — означає **зареєструвати збірку**, а потім **зареєструвати крок**, що каже конвеєру, коли викликати ваш клас.

## Plug-in Registration Tool

**Plug-in Registration Tool** (PRT) — інструмент Microsoft для реєстрації збірок, пакетів, кроків, образів, service endpoints, webhooks і Custom API. Запустіть його так:

```text
pac tool prt
```

Увійдіть через **Office 365** і виберіть середовище розробки.

## Реєстрація збірки

1. **Register → Register New Assembly**, виберіть `bin/Debug/net462/Contoso.Plugins.dll`.
2. Інструмент покаже знайдені класи `IPlugin`; залиште вибраним `HelloWorldPlugin`.
3. Isolation mode **Sandbox** і location **Database** — єдині варіанти online.
4. **Register Selected Plugins**.

(**Пакет плагіна** реєструють через **Register New Package**.)

## Реєстрація кроку

Клацніть правою кнопкою на типі плагіна → **Register New Step**:

| Поле | Значення | Чому |
| --- | --- | --- |
| Message | `Create` | Виконувати, коли створюється запис |
| Primary Entity | `account` | Лише для акаунтів |
| Event Pipeline Stage | PreOperation | Змінюємо Target до збереження |
| Execution Mode | Synchronous | Опис має зберегтися разом із записом |
| Execution Order | 1 | Порядок серед кроків того самого етапу |
| Run in User's Context | Calling User | Привілеї того, хто створює акаунт |
| Deployment | Server | Виконувати на сервері (Offline — для старого клієнта Outlook) |
| Unsecure / Secure Configuration | порожньо | Рядки, що передаються в конструктор плагіна |

Для кроків на Update ви б також вибрали **Filtering Attributes** і додали **образи** з контекстного меню кроку.

## Перевірка

1. Відкрийте model-driven застосунок, створіть акаунт **Contoso** і збережіть.
2. В описі тепер `Hello, Contoso! …`.
3. Створіть акаунт і іншим шляхом (імпортом, flow чи через Web API): плагін спрацює й там, бо живе на сервері.

## Журнал трасування

Увімкніть трасування в **System Settings** (класичні налаштування: **Administration → System Settings**, вкладка **Customization**): задайте **Enable logging to plug-in trace log** значення **All** у розробці та *Exception* у продакшні. Потім відкрийте таблицю **Plug-in Trace Log** (через розширений пошук або **Settings → Plug-in trace log**). Кожне виконання показує повідомлення, етап, тривалість і ваші рядки `Trace`. Коли синхронний плагін падає, діалог помилки також пропонує файл журналу з тими самими рядками.

## Зміна й повторне розгортання

- Перезберіть, потім у PRT виберіть збірку й натисніть **Update**. Кроки лишаються зареєстрованими, доки не змінилися major і minor версії.
- Або з командного рядка: `pac plugin push --pluginId <assembly id>`.
- Кроки можна тимчасово **вимкнути** в PRT, не скасовуючи реєстрації.

## Додайте до рішення

Реєстрація лише додає компоненти в середовище. Щоб розгорнути в тестування й продакшн, додайте до рішення **збірку плагіна** й **кожен крок** (SDK message processing steps). Кроків, яких немає в рішенні, після імпорту просто не буде — найпоширеніша проблема «у dev працює».

## Налагодження

Для складної помилки **plug-in profiler** у PRT записує виконання в справжньому середовищі й відтворює його у Visual Studio з точками зупину. Встановіть профайлер, почніть профілювати крок, відтворіть проблему, потім **Debug** зі збереженим профілем.

## На співбесіді

- Перелічіть поля кроку й що ви оберете для конкретної вимоги.
- Поясніть, як дізнатися, що плагін зробив у продакшні.
- Поясніть, як оновити збірку, не втративши її кроків.
- Поясніть, чому плагін може працювати в розробці й нічого не робити після імпорту рішення.
