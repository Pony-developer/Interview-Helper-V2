**Хмарні потоки** (cloud flows) Power Automate — це low-code спосіб автоматизувати Dataverse: вони реагують на зміни даних, викликають сотні конекторів і не потребують розгортання коду. Кожен розробник Dynamics працює поруч із потоками, тож інтерв'юер очікує, що ви знаєте, що вони вміють, як запускаються і де перестають бути правильним інструментом.

## Будова потоку

Потік — це **тригер**, за яким ідуть **дії**. Вихід кожної дії можна використати в наступних через **динамічний вміст** або **вирази** (мова формул Workflow Definition Language: `concat()`, `addDays()`, `coalesce()`, `items('Apply_to_each')`). Потоки виконуються в хмарі, **асинхронно**, поза транзакцією Dataverse.

## Тригер Dataverse

«When a row is added, modified or deleted» має такі налаштування:

| Налаштування | Що робить |
| --- | --- |
| Change type | Added, Modified, Deleted або їх поєднання |
| Table name | Таблиця, за якою стежать |
| Scope | Чиї рядки запускають потік: *User* (рядки власника потоку), *Business unit*, *Parent: Child business unit* або *Organization* |
| Select columns | Для оновлень: запускати лише тоді, коли змінився один із цих стовпців. Без цього кожне збереження рядка запускає потік |
| Filter rows | OData-фільтр рядка: `statecode eq 1 and estimatedvalue gt 10000` |
| Run as | Від чийого імені виконуються дії Dataverse: власника потоку, власника рядка чи користувача, що змінив рядок |

**Select columns** і **filter rows** — два налаштування, що не дають потоку тисячі разів запускатися даремно. Для того, чого не виразити фільтром, додайте **умови тригера** (trigger conditions — вирази в налаштуваннях тригера).

Інші тригери: *When an action is performed* (виконався Custom API чи bound action), *When a flow step is run from a business process flow*, ручні тригери, розклад і тригери інших конекторів (новий лист, HTTP-запит).

## Дії Dataverse

- **Add a new row**, **Update a row**, **Delete a row**, **Get a row by ID**, **Upsert** через альтернативні ключі.
- **List rows** з *Select columns*, *Filter rows* (OData), *Sort by*, *Expand query* або повним **запитом FetchXML**. Повертає до 5000 рядків, якщо в налаштуваннях не ввімкнути **пагінацію**, і не бачить рядків, які не може читати користувач з'єднання.
- **Relate rows** і **Unrelate rows** для зв'язків N:N.
- **Perform a bound action** або **Perform an unbound action**: виклик Custom API та повідомлень, як-от `WinOpportunity`.
- **Upload or download a file or an image**.

Lookup задають через ім'я набору сутностей та id: `accounts(00000000-0000-0000-0000-000000000001)`. Choice задають цілими значеннями.

## Цикли та умови

- **Condition** і **Switch** розгалужують за значеннями.
- **Apply to each** обходить масив. Він виконує **по одному елементу**, якщо не ввімкнути *Concurrency control* (до 50 паралельно), і тоді порядок уже не гарантовано.
- **Do until** повторює, доки умова не стане істинною або не вичерпається лічильник чи час.
- **Compose**, **Select** і **Filter array** перетворюють дані без циклів, що швидше й дешевше.

## Дочірні потоки та повторне використання

Миттєвий потік із тригером *Manually trigger a flow* і дією *Respond to a PowerApp or flow* можна викликати з інших потоків того самого рішення як **дочірній потік** (child flow): low-code аналог спільної функції.

## Потоки чи класичні workflows?

Класичні фонові workflows досі працюють, але для нової асинхронної автоматизації Microsoft радить хмарні потоки. Класичні workflows **реального часу** виконуються всередині транзакції й не мають аналога серед потоків; для такої потреби беріть плагін (або лишайте real-time workflow). **Desktop flows** у Power Automate автоматизують застарілі інтерфейси — це інший інструмент.
