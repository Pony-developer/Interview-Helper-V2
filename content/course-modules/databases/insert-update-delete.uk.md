Дані змінюють три інструкції: `INSERT` додає рядки, `UPDATE` змінює їх, а `DELETE` видаляє.

## INSERT

```sql
-- один рядок; завжди перелічуйте стовпці
INSERT INTO customers (id, name, email, city, created_at)
VALUES (7, 'Bohdana Lysenko', 'bohdana@example.com', 'Dnipro', current_date);

-- кілька рядків в одній інструкції: значно швидше, ніж окремий INSERT на кожен рядок
INSERT INTO categories (id, name)
VALUES (5, 'Toys'), (6, 'Music');

-- результат запиту
INSERT INTO archived_orders (id, customer_id, status, ordered_at)
SELECT id, customer_id, status, ordered_at
FROM orders
WHERE ordered_at < '2024-07-01';
```

- Стовпці, яких ви не вказали, отримують свій `DEFAULT` або `NULL`, якщо його немає.
- `DEFAULT` можна написати явно: `VALUES (DEFAULT, 'x')`.
- Identity-стовпець, оголошений як `GENERATED ALWAYS`, відмовляється приймати явні значення, якщо не написати `OVERRIDING SYSTEM VALUE`; `GENERATED BY DEFAULT` їх приймає.
- Для масового завантаження тисяч рядків `COPY` (або `\copy` у psql) значно швидший за `INSERT`.

## UPDATE

```sql
UPDATE products
SET price = price * 0.9,
    stock = stock + 5
WHERE category_id = 3;
```

Усі вирази праворуч бачать **старий** рядок, тож `SET a = b, b = a` міняє два стовпці місцями.

Оновлення з іншої таблиці через `FROM` (розширення PostgreSQL; стандартний шлях — підзапит):

```sql
-- позначити замовлення клієнтів з Одеси як скасовані
UPDATE orders AS o
SET status = 'cancelled'
FROM customers AS c
WHERE c.id = o.customer_id
  AND c.city = 'Odesa';
```

## DELETE

```sql
DELETE FROM orders WHERE status = 'cancelled';

-- видалення з умовою по іншій таблиці
DELETE FROM order_items AS oi
USING orders AS o
WHERE o.id = oi.order_id AND o.status = 'cancelled';
```

## Забутий WHERE

`UPDATE products SET price = 0;` і `DELETE FROM orders;` — коректні інструкції, що зачіпають **кожен** рядок. Звички, що рятують кар'єри:

- пишіть `WHERE` першим або виконайте ту саму умову як `SELECT count(*)` перед зміною;
- у консолі відкрийте транзакцію (`BEGIN`), зробіть зміну, перевірте результат, а тоді `COMMIT` або `ROLLBACK`;
- `psql` повідомляє `UPDATE 1000000`: читайте це число.

## М'яке видалення

Багато систем ніколи не виконують `DELETE` для бізнесових рядків. Вони додають `deleted_at timestamptz` і заповнюють його, тож дані можна відновити й перевірити. Ціна: кожен запит має пам'ятати про `WHERE deleted_at IS NULL`, унікальні обмеження мають стати частковими (`UNIQUE … WHERE deleted_at IS NULL`), а таблиця постійно росте. Приховати видалені рядки може представлення або row-level security.

## Великі зміни партіями

Один `UPDATE` на 50 мільйонів рядків тримає блокування на всіх них до фіксації, роздуває таблицю і породжує величезний обсяг журналу попереднього запису, який мають наздогнати репліки. Великі заповнення роблять партіями:

```sql
UPDATE products SET sku = 'P-' || id
WHERE id IN (SELECT id FROM products WHERE sku IS NULL LIMIT 5000);
-- повторювати, доки не оновиться 0 рядків
```
