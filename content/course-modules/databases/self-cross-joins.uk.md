## Самоз'єднання

Таблицю можна з'єднати саму із собою. Класичний випадок — ієрархія в одній таблиці, де `manager_id` вказує на інший рядок `employees`:

```sql
SELECT e.name AS employee, m.name AS manager
FROM employees AS e
JOIN employees AS m ON m.id = e.manager_id;
```

Два псевдоніми — це дві «копії» однієї таблиці: `e` грає роль працівника, `m` — керівника. Без псевдонімів запит був би неоднозначним. Внутрішнє самоз'єднання відкидає генерального директора, в якого немає керівника; `LEFT JOIN` зберігає його з `NULL`.

Самоз'єднання також порівнюють рядки однієї таблиці між собою:

```sql
-- пари працівників з одного відділу (кожна пара один раз)
SELECT a.name, b.name, a.department
FROM employees a
JOIN employees b ON b.department = a.department AND b.id > a.id;
```

`b.id > a.id` не дає поєднати працівника із самим собою і показати і (Ann, Bob), і (Bob, Ann).

Самоз'єднання проходить **один** рівень ієрархії. Для будь-якої глибини («усі підлеглі Богдана») потрібен рекурсивний CTE з модуля про підзапити.

## CROSS JOIN

`CROSS JOIN` повертає всі комбінації рядків, декартів добуток: 3 розміри × 4 кольори = 12 рядків.

```sql
SELECT s.size, c.color
FROM sizes AS s
CROSS JOIN colors AS c;
```

Це корисно для генерування комбінацій, як-от кожен день × кожен магазин для звіту, щоб дні без продажів теж з'являлися:

```sql
SELECT d.day::date, s.store
FROM generate_series('2024-09-01'::date, '2024-09-07', interval '1 day') AS d(day)
CROSS JOIN (VALUES ('Kyiv'), ('Lviv')) AS s(store);
```

А потім до цієї сітки через `LEFT JOIN` приєднують справжні продажі. Випадкове перехресне з'єднання — катастрофа: дві таблиці по 100 000 рядків дають 10 мільярдів.

## USING і NATURAL

Коли стовпці з'єднання мають однакові назви в обох таблицях, `USING` скорочує умову й виводить стовпець один раз:

```sql
SELECT order_id, product_id, quantity, shipped_at
FROM order_items
JOIN shipments USING (order_id);   -- обидві таблиці мають order_id
```

`NATURAL JOIN` автоматично з'єднує за **всіма** стовпцями з однаковими назвами. Уникайте його: додавання стовпця на кшталт `created_at` до обох таблиць мовчки змінює умову з'єднання.

## Алгоритми з'єднання

Ви їх не обираєте, але побачите в `EXPLAIN` (читання планів — у модулі про індекси):

| Алгоритм | Як працює | Добрий, коли |
|---|---|---|
| Nested loop | Для кожного рядка зовнішнього боку шукає збіги у внутрішньому (бажано через індекс) | Зовнішній бік малий |
| Hash join | Будує хеш-таблицю з меншого боку й перевіряє її рядками іншого | Великі невпорядковані входи, умови рівності |
| Merge join | Іде паралельно двома входами, відсортованими за ключем з'єднання | Обидва входи вже відсортовані (напр. індексом) |

## LATERAL

Підзапит `LATERAL` у `FROM` може посилатися на стовпці таблиць перед ним, як цикл `for each`:

```sql
-- два найновіші замовлення кожного клієнта
SELECT c.name, o.id, o.ordered_at
FROM customers c
CROSS JOIN LATERAL (
    SELECT id, ordered_at FROM orders
    WHERE customer_id = c.id
    ORDER BY ordered_at DESC
    LIMIT 2
) AS o;
```

Використовуйте `LEFT JOIN LATERAL (…) ON true`, щоб зберегти клієнтів без замовлень. «Перші N у групі» — дуже поширена задача на співбесідах; віконні функції далі в курсі дадуть ще один розв'язок.
