Анна й Богдан обоє відкрили документ «Release notes», коли той мав **версію 1**. Анна зберігає першою; потім зберігає Богдан. З наївними `UPDATE` у редакторі Богдан мовчки перезаписує роботу Анни: втрачене оновлення.

Перепишіть скрипт з **оптимістичним блокуванням** через стовпець `version`:

1. **Анна зберігає** (вона завантажила версію 1): встановіть `body` у `Draft + Ann's changes`, збільште `version` на одиницю, але лише якщо версія досі 1. Поверніть `id, version`.
2. **Богдан зберігає** (він теж завантажив версію 1) текст `Draft + Bob's changes` так само. Його оновлення має не змінити **нічого**, бо версія тепер 2: `RETURNING` не повертає рядків, і саме так застосунок виявляє конфлікт.
3. **Богдан перезавантажує** документ: виберіть його `body` і `version`.
4. **Богдан зберігає об'єднаний текст** `Draft + Ann's and Bob's changes`, цього разу з версією, яку він щойно прочитав.

Пам'ятайте, що одинарна лапка всередині SQL-рядка пишеться двічі: `'Draft + Ann''s changes'`.

Очікуваний вивід:

```text
 id | version
----+---------
  1 |       2
(1 row)

 id | version
----+---------
(0 rows)

         body          | version
-----------------------+---------
 Draft + Ann's changes |       2
(1 row)

 id | version
----+---------
  1 |       3
(1 row)

 id |     title     |              body               | version
----+---------------+---------------------------------+---------
  1 | Release notes | Draft + Ann's and Bob's changes |       3
(1 row)
```

Тут два «користувачі» діють один за одним в одному скрипті, але той самий `UPDATE … WHERE version = …` працює й за справжньої паралельності: перевірка й запис відбуваються в одній атомарній інструкції.
