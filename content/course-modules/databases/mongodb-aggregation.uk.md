`find` фільтрує й проєктує документи однієї колекції. Для групування, з'єднання та перетворення в MongoDB є **конвеєр агрегації**: масив **етапів**, кожен з яких отримує потік документів і передає новий потік наступному, як конвеєр у Unix.

```js
db.orders.aggregate([
  { $match: { status: { $ne: "cancelled" } } },                 // WHERE
  { $unwind: "$items" },                                         // по документу на кожен елемент масиву
  { $group: {                                                    // GROUP BY
      _id: "$items.category",
      revenue: { $sum: { $multiply: ["$items.quantity", "$items.price"] } },
      orders: { $addToSet: "$_id" }
  } },
  { $project: { _id: 0, category: "$_id", revenue: 1, orders: { $size: "$orders" } } },  // SELECT
  { $sort: { revenue: -1 } },                                    // ORDER BY
  { $limit: 5 }                                                  // LIMIT
])
```

## Основні етапи та їхні SQL-двійники

| Етап | Що робить | SQL |
|---|---|---|
| `$match` | Фільтрує документи | `WHERE` (або `HAVING` після `$group`) |
| `$project`, `$set` / `$addFields`, `$unset` | Змінює форму документів, обчислює поля | Список `SELECT` |
| `$group` | Групує за `_id` і обчислює акумулятори | `GROUP BY` + агрегати |
| `$sort`, `$skip`, `$limit` | Порядок і посторінковість | `ORDER BY`, `OFFSET`, `LIMIT` |
| `$unwind` | По вихідному документу на кожен елемент масиву | `CROSS JOIN LATERAL unnest(…)` |
| `$lookup` | Підтягує відповідні документи з іншої колекції в поле-масив | `LEFT JOIN` |
| `$count` | Рахує документи | `count(*)` |
| `$facet` | Кілька підконвеєрів над тими самими вхідними даними | Кілька запитів одразу |
| `$bucket`, `$bucketAuto` | Кошики гістограми | `GROUP BY width_bucket(…)` |
| `$setWindowFields` | Наростаючі суми, ранги, ковзні середні | Віконні функції |
| `$merge`, `$out` | Записує результат у колекцію | `INSERT INTO … SELECT`, матеріалізоване представлення |

Акумулятори в `$group`: `$sum`, `$avg`, `$min`, `$max`, `$count`, `$first`, `$last`, `$push` (зібрати в масив), `$addToSet` (зібрати унікальні значення). `{ $sum: 1 }` рахує документи.

`"$field"` зі знаком долара у виразах означає «значення цього поля»; без долара це буквальний рядок.

## $lookup: з'єднання існують

```js
db.orders.aggregate([
  { $match: { status: "shipped" } },
  { $lookup: {
      from: "customers",
      localField: "customerId",
      foreignField: "_id",
      as: "customer"
  } },
  { $unwind: "$customer" },            // результат lookup — масив; перетворюємо на об'єкт
  { $project: { _id: 1, "customer.name": 1, total: 1 } }
])
```

`$lookup` — це ліве зовнішнє з'єднання, і з індексом на `foreignField` воно досить швидке. Але MongoDB сильна не цим: якщо кожен запит потребує `$lookup`, модель даних, мабуть, має вкладати чи дублювати ці дані (наступна лекція). З'єднання між шардами мають додаткові обмеження.

## Як писати ефективні конвеєри

- Ставте **`$match` і `$sort` якомога раніше**, щоб вони могли використати індекси, а кожен наступний етап обробляв менше документів. Оптимізатор переставляє деякі етапи сам, але не покладайтеся на це.
- **Прибирайте проєкцією** непотрібні поля перед важкими етапами.
- `$group` і `$sort`, що не вміщуються в 100 МБ пам'яті, виливаються на диск (`allowDiskUse`, у нових версіях увімкнено за замовчуванням) і сповільнюються.
- Перевіряйте план: `db.orders.explain("executionStats").aggregate([...])`. Шукайте в першому етапі `IXSCAN` (використано індекс) проти `COLLSCAN` (повне сканування) і кількість переглянутих документів.

## Той самий звіт у SQL і MongoDB

```sql
SELECT category, count(*) AS products, avg(price) AS avg_price
FROM products
GROUP BY category
ORDER BY category;
```

```js
db.products.aggregate([
  { $group: { _id: "$category", products: { $sum: 1 }, avg_price: { $avg: "$price" } } },
  { $sort: { _id: 1 } }
])
```

Конвеєр багатослівніший, але добре компонується і будується з даних (масиву об'єктів), що спрощує генерування запитів у коді. У практиці цього модуля ви перекладатимете запити MongoDB на SQL з `jsonb` у PostgreSQL і побачите, наскільки близькі насправді ці дві моделі.
